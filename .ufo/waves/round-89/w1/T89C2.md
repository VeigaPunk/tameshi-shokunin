## Axes

| axis | question |
|---|---|
| A1 forgery→PASS | can a crafted trace make a counterfeit audit PASS? |
| A2 honest→FAIL | can a legitimate runner/trace make an honest run FAIL? |

## Method

Driver: `T89C2-driver.py` (this directory). It materialises the fixture in `/fast/scratch/...`,
perturbs **one** trace feature per case, and audits with

```
python3 -I <witness> --audit --runner <root>/runner.sh --fleet <root>/fleet \
    --trace <root>/trace.txt --workdir <root>/wd --stdout <root>/stdout.txt --rc <runner rc>
```

Saved per case in `T89C2-fixtures/<case>/`: `runner.sh`, `trace.txt`, `stdout.txt`,
`meta.txt` (opts, expected verdict, `LEDGER_WITNESS` line, findings). Git repos are
rebuilt deterministically (fixed identity `ctl <ctl@fixture.invalid>`, fixed commit
dates) so REVs and PINs replay.

```
python3 -I T89C2-driver.py                 # build + audit + save fixtures (writes T89C2-results.tsv)
python3 -I T89C2-driver.py --replay        # re-audit saved bytes with the frozen witness
python3 -I T89C2-driver.py --replay --witness <patched copy>   # measure a candidate fix
```

## Fidelity: what strace actually emits (measured, not assumed)

Commands used (ground truth for every fixture below):

```
strace -f -q -y -v -s 4096 -e signal=none -e trace=execve,openat,write -o tr.txt \
  bash -c 'exec 9>>"wd/leg-a/m.sh"; bash "wd/leg-a/m.sh"; mv wd/leg-a wd/leg-a2; printf z >&9'
```

| feature | observed bytes |
|---|---|
| `-y` annotation, `>` `<` `"` `\` newline | `>`→`\076`, `<`→`\074`, `"`→`\"`, `\`→`\\`, newline→`\n`; three-octal-digit form when a digit follows (`g>123` → `g\076123`) |
| quoted string (argv, paths) | `<`/`>` raw, `"`→`\"`, `\`→`\\` |
| `-s 4096` truncation | `"<4096 chars>"...` — **the dots are outside the closing quote** |
| unfinished syscall | `PID execve("/usr/bin/bash", [...], [...]) <unfinished ...>` then `PID <... execve resumed>)            = 0` (result column padded) |
| `write` on an fd whose inode moved | annotated with the path **at print time**: `write(1</.../wd/leg-a2/m.sh>, "z", 1) = 1` |
| case dir is a symlink | `openat(..., "wd/leg-a/mut.sh", ...) = 3</.../prep/mut.sh>` — the result annotation is the **resolved** path, the argument keeps the spelling |

Control `C0_real` closes the fidelity loop: a **real** strace run of a lite honest runner
(`git show`, redirect writes, `env -i … sandbox-$DEFECT_ID`, exit codes, the three stdout
lines) audits `legs=2 witnessed=2 findings=0 checks=- PASS`.

## Confirmed misparses

### D3 (reachable, highest severity): W_ORDER matches path spelling, not object identity

`ledger-witness.py:585` — `hits = [p] if p in exec_idx_by_path else []`, i.e. an exact
absolute string compare; the only fallback (basename) is reserved for `REL:` paths
(lines 581-583). strace does **not** print a stable spelling: it prints the inode's path
at print time, and it prints the **resolved** path for a symlinked ancestor.

C13 trace (exact bytes; the `wd` root elided as `/…/wd`):

```
105 execve("/usr/bin/bash", ["bash", "/…/wd/leg-a/mutant-A1.target.a.sh", "--selftest"], …) = 0
150 rename("/…/wd/leg-a", "/…/wd/leg-a2") = 0
105 write(1</…/wd/leg-a2/mutant-A1.target.a.sh>, "x", 1) = 1
150 rename("/…/wd/leg-a2", "/…/wd/leg-a") = 0
```

Neither `rename` names an audited *file* (`anchored_paths` yields the two directory
paths), and the write's path is the moved spelling. `LEDGER_WITNESS: legs=2 witnessed=2
findings=0 checks=- PASS`. C12 is the same defect without a rename (`ln -s` case dir):

```
105 execve("/usr/bin/bash", ["bash", "/…/wd/leg-a/mutant-A1.target.a.sh", …]) = 0
105 write(1</…/prep/leg-a/mutant-A1.target.a.sh>, "x", 1) = 1
```

Both are reachable with plain bash, and both defeat the only check that ties the bytes
present at audit time (W_CONTENT hashes the *spelling*) to the bytes the kernel executed:
create a stub at the mutant path, exec it (W_EXEC/W_VERDICT satisfied by the stub's exit
code), then rewrite the pinned mutant bytes through an fd opened before the exec, with a
directory rename or a symlinked case dir between. W_CONTENT then hashes the restored
bytes; W_ORDER — the check written for exactly this — sees nothing. The ledger case name
stays ordinary (`leg-a`); nothing in the runner text has to look suspicious.

Smallest safe correction (measured): give fd-decoded paths the same basename fallback the
code already gives unanchored relative paths — 3 lines at `ledger-witness.py:585`:

```python
            else:
                hits = [p] if p in exec_idx_by_path else []
                if not hits:            # path spelling != object identity
                    b = os.path.basename(p)
                    hits = [q for q in exec_idx_by_path if os.path.basename(q) == b]
```

Measured on a scratch copy (fixtures unchanged, frozen file untouched):
witness selftest `21/21 pass`; C12 and C13 now `W_ORDER FAIL`; C0_base and C0_real still
`PASS`; every other case's verdict unchanged. If the basename fallback is judged too
broad (two legs may audit same-named files), the narrower alternative is to flag any
`rename/renameat/renameat2` whose source **or** destination is an ancestor directory of an
audited path after that path's first exec — covers C13 but not C12.

The fallback alone is **not** sufficient for the whole family: a hard link to a decoy (the
T89E2 `hardlink` counterfeit) gives the write a spelling with a *different* basename, so
basename matching still misses. Inode identity is not in the text trace (strace prints
paths only), so the substrate needs a precondition instead: before auditing, require every
audited path to be a regular file with `st_nlink == 1`, its case directory to be a real
directory below the workdir (not a symlink), and the workdir components likewise. That is
cheap, fails closed, and costs an honest run nothing (the round-89 workdir is a fresh
`mktemp` tree). Recommended pair: **(a)** basename fallback for fd-decoded paths and
**(b)** the nlink/symlink precondition. (b) alone already refuses C12 and T89E2's
`hardlink`/`symlink`; (a) catches the mid-run rename that (b) cannot see.

### D1 (latent): the resumed line's call name is ignored

`ledger-witness.py:279-283` stores the pending half by pid and, on a resume, concatenates
it with whatever the resume line says, ignoring the resumed call name:

```python
pending[pid] = body[: -len("<unfinished ...>")]
...
body = pending.pop(pid, rm.group(1) + "(") + rm.group(2)
```

C2 (`execve(…) <unfinished ...>` closed by `<... openat resumed>)            = 0`) yields a
successful exec of a path that never completed an exec; C3b (unfinished exec, pid killed,
pid reused, a bare resume with no unfinished half) yields the same phantom. Both audit
PASS. Real strace always repeats the pending call's own name, so this needs trace
corruption/pid bookkeeping outside the model (L1-adjacent) — reported for the record:
a resume whose name differs from the pending half should be dropped, not stitched.

### D2 (latent): an undecoded environment is treated as "no steering, no difference"

`ledger-witness.py:555` (`raw = exec_env.get(path) or []`) and `:560` (`cenv is not None`)
mean `env is None` silently disables both the deny-list scan and the control/mutant
comparison. C5b (array abbreviated `[..., ...]` with `BASH_ENV=/dev/null` behind the dots —
`_str_array` skips `...` and returns a *complete-looking* shorter list) and C10
(`0x… /* 3 vars */`) both audit PASS. Not produced under this witness's own flags
(`-v` forces full arrays; a per-string `-s` cut keeps the name and is decoded correctly,
C5 passes), so latent — but the code should fail closed on an unparsed env, e.g. a
finding for `env is None` on an audited interpreter exec.

### D4 (conservative): execveat takes the first quoted string as the filename

`ledger-witness.py:243` — `STR_RE.search(args)`; with `execveat(3</…/q\"x>, "/usr/bin/bash", …)`
the first match starts inside the `\"` of the dirfd annotation, the filename becomes
`x>, ` and the exec is lost: C11 audits `W_CONTROL … pristine never exec'd` (FAIL) for an
exec that did happen. `execveat`'s pathname is the first string *after* the dirfd, not the
first string in the args. Direction is fail-closed; requires a quoted directory in the
runner's own environment. Related, same area: a dirfd-relative `execveat(3<dir>, "pristine…")`
is never matched against the leg (C7b, `W_CONTROL`) because `interp_match` realpath-resolves
the bare relative name against the witness's cwd.

## Hypothesis tested and refuted

"`>` inside a `-y` annotation truncates the decoded path (`[^>]*`), hiding the post-exec
write" is **false for real traces**: strace escapes `>` as `\076` (measured; also `\074`
for `<`), and `c_unescape` decodes it correctly, so W_ORDER fires. My first fixture wrote a
raw `>` and produced a false PASS; after re-rendering faithfully the same scenario is
`W_ORDER FAIL` (C6), as is the `truncate` variant (C6c). Recorded so the L1 does not spend
a round on it: the escaping is faithful, the parser is right, the fixture was wrong.

## Honest-run FAIL surface (what a fix must not widen)

- `execveat` with a quoted dirfd (C11) and dirfd-relative execs (C7b) fail closed today.
- An undecoded env (D2) fails *open*; making it fail closed adds honest-failure surface
  only if strace can abbreviate under `-v` (it cannot, measured).
