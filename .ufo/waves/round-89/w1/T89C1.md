## The experiment that decides most of the review

The claim's work is: *run the ledger under strace(1) and audit the trace*. §9 requires, before
the freeze, "the cheapest control that skips the claimed work, scored with the frozen counter …
if it meets the target, the counter or target is wrong." The lane's only no-work control is the
base commit, where the file is absent (`pre-freeze/nowork-base.out`: `witness=absent …
C1_R89_PASS=false`, exit 1) — a check that the file exists, not that it works. I built the
control the lane did not: a witness that calls no `subprocess`, starts no strace, opens neither
the runner nor a trace, and decides only from the basename it is handed
(`src/mutate-and-run.sh` or `honest-*` → the frozen PASS line; anything else → the frozen FAIL
line).

Scored with the frozen counter, from a fixture repo carrying the base runner
`61990f3d:tools/mutate-and-run.sh` and the two committed generators, and the counterfeit as
`tools/ledger-witness.py`:

```

  real=PASS(legs=11) honest_accepted=2/2 forgeries_refused=12/12 capability_row=1
  C1_R89_PASS=true
```

(`T89C1-measure.out`, nonce `c62a8ed1971f938d`.) And with the same file printing

The fixture REV is not the landing commit; that is the point. The predicate's five witness-facing

## Objections

### 1. FATAL — a counterfeit witness meets the frozen target; the counter certifies a file's output, not its work

Evidence. `T89C1-measure.out` above. The counterfeit has 0 code references to `subprocess`,
`os.system`, `popen`, `fork`, `exec` or `strace` (the only matches for `strace` in the file are
its own docstring lines 6–7), 53 lines, and it never opens the runner or a trace. It is the exact
class r86 rejected: "The counter's arm class is disclosed in its own bytes … so the certification
cannot be established" (`round-86-verifier-spotcheck.md`, R86-C1), where the closure graded
operability **unprovable** although the real instrument did the work.

Why the frozen predicate cannot see it. `measure.sh` has exactly five witness-facing signals:
`witness=present` (file exists), `selftest=<p>/<n>` (a printed line, see objection 3),
`real`/`honest-*` accepted (exit 0 and one printed line), `forgeries_refused` (exit 1 and one
printed line), and the SCORECARD row. Every one is satisfied by a file that computes nothing.
The counter never derives any of them itself; it does not parse the trace, does not run `--audit`
on a trace it produced, and does not compare the witness's findings to an independent
expectation.

Impact. R89-C1's predicate cannot establish "the witness binds the declared ledger to what the
kernel observed". Per the frozen rule ("the claim is judged on the counter, kill rule and
predicate declared before data"), the axis verdict is **unprovable** — the same ruling r86 gave
the same structure. The kill rules (a)–(c) do not reach it: (b) and (c) are about *runner*
variants, and a substituted witness is neither.

Smallest safe correction (next round; not applicable after data). Make the counter derive the
audit itself: generate the trace from committed bytes, then require `--audit` output to equal the
counter's own independently computed finding set, and randomise the runner's *file name* per
measurement. Keep this control file (`T89C1-counterfeit-witness.py`) in the committed control set
as the required §9 no-work control.

### 2. FATAL — the §9 pre-freeze control obligation was not met for the claimed work

Evidence. The plan says "Controls committed before this freeze. No-work: the base (above)" and
presents `pre-freeze/nowork-base.out` as "the do-nothing control". That control skips the work by
*not having an artifact*; it exercises one conjunct, `witness=present`. §9's clause is about a
control that "skips the claimed work" — i.e. an artifact that exists and produces the shippable
output without doing the work. The lane built twelve such controls for the **runner** (its
declared ledger) and none for the **witness** (the round's actual acquisition). Objection 1 is
that missing control, and it meets the target, which §9 says means "the counter or target is
wrong — fix it before data". It was not fixed before data, and the rule "a rule changed after
any seat has scored is not the claim's rule" bars repairing it now.

Answering the question as posed: a capability-acquisition claim whose before-state is "tool
absent" is **legitimate in form** (§2.6 admits capability acquisition; absence at the base is its
natural before-state and the target is unreachable by doing nothing). It is **not** a substitute
for the §9 work-skipping control, and the plan's use of the phrase "the do-nothing control" for
it misstates what was built.

### 3. SERIOUS — predicate identity drift: the counter's selftest conjunct is degenerate and `legs=11` is a printed constant

Evidence. Plan predicate: "its `--selftest` passes every arm"; target: `selftest=21/21`. Counter
code (`measure.sh`, pass condition):

```sh
if [[ -n "$st" && "${st%/*}" == "${st#*/}" && $real == PASS && … ]]; then pass=true; fi
```

`${st%/*} == ${st#*/}` is numerator-equals-denominator for **any** pair, so `21/21`, `1/1` and
`0/0` all pass; the 21 arms and the arm ids are never compared. `T89C1-measure-selftest00.out`
prints `selftest=0/0 … C1_R89_PASS=true`. Also `echo "… real=$real(legs=11) …"` writes `legs=11`
as a literal in the format string (also visible in `pre-freeze/measure-a65e11c0.out` where the
conjunct was otherwise unproven); the leg count is never derived from the witness's output. The
rule "the same condition in the counter's code" is therefore not met. Grade serious rather than
fatal only because objection 1 makes the distinction moot for this round.

Smallest safe correction: parse `LEDGER_WITNESS_SELFTEST: (\d+)/(\d+)`, require the numerator to
equal the committed arm list (`BASE` + 15 checks + 4 sub-arms + `SETUP` = 21, compared as a set of
`SELFTEST_ARM <id> ok` lines), and derive `legs=` from the witness's own `LEDGER_WITNESS:` line
instead of printing it.

### 4. SERIOUS — L2 is a trace-coverage gap, not a model boundary: the committed `late-write` forgery has a one-line `mmap` twin the witness accepts

Evidence. `late-write` is refused only because its post-exec edit is a *write-class syscall*
(`W_ORDER`), and `STRACE_FLAGS` traces `write,pwrite64,writev,pwritev2,ftruncate,fallocate,…` but
**not** `mmap/mmap2/mprotect`. Compose it with `copy-sweep`: exec the mutant path holding
*unmutated* bytes, write a table of all `SURVIVED` (the table is the runner's own declaration, so
`W_VERDICT` agrees with the observed exit 0), then after the exec restore the spec-exact bytes
through `mmap(fd, MAP_SHARED, PROT_WRITE)` + `memcpy`, so `W_CONTENT` — which hashes the kept
workdir at `--audit` time — sees the expected digest. No traced write syscall is emitted, so
`W_ORDER` is silent; the sweep tested nothing. Declaring this L2 does not make it a boundary of
the model: it is a gap in the trace set (`W_ORDER` assumes "writes go through write-class
syscalls"), and L2 is exactly the exemption kill rule (b) would invoke for the variant.

[INFERENCE] I did not run this: it needs a real `--run` pass (10–12 min, ~1.6 GB) and the
outcome is decidable from `STRACE_FLAGS` (no `mmap` in `trace=`) and `mmap(2)` (writes through a
shared mapping never appear as `write`).

Smallest safe correction: add `mmap,mmap2,mprotect` to `trace=`, and emit a finding for any
`MAP_SHARED|PROT_WRITE` mapping of an audited path (before or after its exec). Then delete L2.

### 5. SERIOUS — L3 exempts the cheapest in-model fabrication, and it makes "the ledger's real work" in kill rule (b) unfalsifiable

Evidence. `norm_env` rewrites the per-defect id token to `<ID>` (`(?<=[-/_])<id>(?=/|$)`), so a
runner that names a per-defect sandbox (`HOME=$WORKDIR/case/sandbox-<id>`) passes the
environment-parity check on every exec while planting arbitrary files in it; `L3` puts those
files out of model. The same clause covers `cwd`, inherited fds, signal dispositions and an
inherited rlimit. A runner can therefore exec every spec-exact mutant with the declared argv,
get `witnessed=11 findings=0`, and record verdicts its sandbox produced rather than the gate's.
[INFERENCE] from `norm_env` and `L3`'s text; I did not build such a runner this seat.
Kill rule (b) then cannot fire: "unless the variant works only through a declared limit below" —
and this variant works *only* through L3.

This does not falsify the claim's literal sentence (the kernel did observe the execs and the
exits), but it does falsify the sentence the round-88 routing asked for and the claim's
rhetorical frame ("not to what the runner prints"): the verdict is bound to the kernel, and the
kernel's exit is not bound to the mutant's behaviour.

Smallest safe correction: state the limit as a limitation of the *claim*, not of the model — the
claim is "the declared leg set is executed on pinned bytes with the declared argv and recorded
exits", not "the ledger's real work is proven". If the stronger reading is wanted, the witness
needs an unnameable sandbox (a fresh directory the runner cannot predict, or a tmpfs whose
contents are hashed before and after each exec), which is a design change, not a check.

### 6. SERIOUS — the `--selftest` arms are labelled by their path, so even the selftest cannot distinguish an auditor from a label-reader

Evidence. `build_fixture` materialises each arm at `root = os.path.join(tmp, arm)` and hands the
witness `--audit --runner <root>/runner.sh`; the arm name (`W_DUP`, `W_ENV:rlimit`, …) is
literally in the path the witness is given, and the two-leg fixture runner is fixed. A witness
that reads `<…>/W_DUP/` and prints `WITNESS_FINDING W_DUP …` satisfies that arm without parsing a
trace. Combined with objection 3 (`0/0` passes), the whole selftest conjunct is free for a
counterfeit. This is the same disclosed-label pattern r86 recorded for `measure.py:148-151`.

Smallest safe correction: name the fixture directories with a per-run random token and keep the
arm id only inside the expected-output file, so the arm is discoverable only by auditing.

### 7. MINOR — the "fresh nonce" defence is aimed at the wrong attack

Evidence. The plan says "Every generated runner carries a fresh random nonce line per
measurement"; `make-forgeries.py`'s docstring draws the conclusion "so no file's bytes are known
in advance". True of the bodies and
irrelevant to the counterexample: the counter hands the witness a path whose **basename** is the
fixed family name (`stub-lines.sh`, …, `parked.sh`, `dupbase.sh`, `honest-reorder.sh`,
`honest-rename.sh`), and the honest ones are additionally prefixed `honest-` so a name oracle
accepts exactly the two positive controls. My two receipts use different nonces
(`c62a8ed1971f938d`, `39cc7a31e1855fd1`) and the same verdicts. Recommendation: randomise names
too, but do not mistake that for a fix — objection 1's correction (independent derivation) is the
load-bearing one.

### 8. MINOR — L1 has no mechanism behind it; the trace sits next to the runner's workdir

Evidence. `main_run` puts the trace at `<scratch>/trace.txt` and passes `--workdir
<scratch>/wd`; the audited process owns the parent of its own workdir and runs as the same uid,
so `ls ..` reaches the trace and the witness file. L1 declares this out of model, correctly, but
the claim "binds … to what the KERNEL observed" then rests on an assumption the witness cannot
test and the runner can break in one line. This is a **host need, not a lane defect**: run the
audit under a separate uid (or with the trace on a fd/path the runner's namespace cannot reach)
so the trace is append-only to the runner. Recorded here rather than attempted, per the seat's
no-host-mutation rule.

## Considered and not sustained (so the ledger shows the counterexample was hunted)

- **Declaration-side argv steering** (a runner that declares a bogus suite tail and records
  `KILLED` for everything): I expected this in-model hole. It is closed by `W_CONTROL` — the
  pristine must be run by the *same* interpreter with the *same* declared tail and exit 0, and
  `W_PIN` pins the blob — so a tail that kills every mutant but not the pristine must be
  mutation-sensitive, i.e. the real work. `expected.tsv`'s `argv-steer` row is the runtime half
  and is rightly refused. Not sustained.
- **Axis naming (§9: name the axis by the surface, not the number).** The claim names the new
  tool as its surface and records a capability row; compliant.
- **"Tool absent" as the before-state.** legitimate per §2.6 (objection 2 is about the *control*
  set, not the before-state).
- **Routed round-88 items.** `W_TABLE` (values in {KILLED, SURVIVED}), `W_PATH` (no `''`, `.`,
  `..`, fleet root excluded) and `W_DUP` (names, `(repo,path)`, pins distinct) are implemented in
  `audit()` and exercised by the selftest arms; nothing to add.
