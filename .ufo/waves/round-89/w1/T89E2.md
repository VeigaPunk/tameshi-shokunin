(sha256 `0839f5875a7a3baf694d993316a2cca6b38b449561a76e0bf54dd1988ebf8d37`, frozen) against
`tools/mutate-and-run.sh --regression` (base `61990f3d`, blob sha256

nothing outside `.ufo/waves/round-89/w1/T89E2*` was written.

**Result: three new counterfeit runners are ACCEPTED by the landed witness** (`LEDGER_WITNESS:
legs=11 witnessed=11 findings=0 checks=- PASS`, exit 0) while no gate suite ever runs. Two
boundary probes that install the same bytes through a *named* path are refused by `W_ORDER`,
which localizes the hole: `W_ORDER` matches write-class syscalls on the audited path **as
spelled**, so any second name for the same inode, a renamed parent directory, or a symlink
target escapes it while the audited path resolves to the spec-exact bytes at audit time.

## What the counterfeits keep (so this is not a grammar trick)

Every output is generated from the base blob by `T89E2-make-counterfeits.py`, which lifts
verbatim and re-asserts byte-identity of:

* the `PIN_*` / `REV_*` / `TABLE_*` block (the real pins and the real measured verdict tables),
* the eleven embedded `cat >"$d/<leg>.spec" <<'EOT'` spec blocks (the real pre-registered specs),
* the eleven `regression_case_git` call statements (the real leg names, paths, suites, tables).

So `W_PARSE/W_TABLE/W_PATH/W_DUP/W_PIN/W_SPEC` are satisfied by the ledger's own declarations;
the witness's independent `git cat-file` reads the real blobs. The runners print the runner's
own success figure — `REGRESSION_CASE <leg>: PASS` once per leg and
`REGRESSION: PASS (cases=11 passed=11; ledger legs exact: …)` — and exit 0.

## What they skip

At the instant the leg's interpreter is exec'd on an audited path (`pristine.target.<f>` or
`mutant-<id>.target.<f>`), that path holds a **one-line stub** whose only job is to exit with the
recorded verdict: `process.exit(0|1)` (node), `exit 0|1` (bash), `sys.exit(0|1)` (python3). The
spec-exact mutant bytes (computed by the runner itself from `git show REV:PATH` + the embedded
spec) are installed **after** the exec, out of band. 126 audited files × 0 real gate runs.

## The shared root cause

`W_ORDER` builds `exec_idx_by_path` from the *expected path strings* and matches write-class
events by `os.path.normpath(path)` equality (or basename for an unanchored relative path). The
guarantee it is meant to give — "the bytes the interpreter read are the bytes audited" — needs
**object identity**, not spelling. Three independent spellings defeat it:

1. a hard link (same inode, different dentry name) — the decoy name is what `-y` reports;
2. a renamed parent directory — the trace names directories, never the files inside;
3. a symlink (different inode, resolved at audit by `sha256_file`).

The two probes show the check is not dead: an fd opened on the audited path is decoded by `-y`
to the audited path, and a `link`/`rename` that spells the audited path after its exec is
caught. The escape is specifically *aliasing*.

## Why L1–L4 do not cover this

* **L1** ("a process that edits the trace file, the kept workdir *after the run*, or the witness
  itself"): the installs happen *during* the traced run, by the runner itself, and are visible in
  the trace — under a different name. Nothing is edited after the run and the trace is untouched.
* **L2** (MAP_SHARED write mapping of a mutant): the installs are `write(2)`/`cat`/`mv`/`ln`, no
  mapping.
* **L3** (per-defect steering through process state or file content the trace does not carry —
  cwd, inherited fd table, signal dispositions, inherited rlimit, files planted in a per-defect
  sandbox dir): none used. The exec environment is byte-identical to the control's after the
  witness's own `MUTANT`/`DEFECT_ID` normalization, no rlimit is set, no sandbox file is read,
  and the cwd is irrelevant (all paths absolute). The attack is not steering the suite; it is
  choosing what bytes sit at the audited path, and the trace *does* carry those writes — the
  witness just matches them by spelling.
* **L4** (a runner that does all the real work): by construction it does none of it — the
  interpreter is exec'd on a 16-byte stub for every one of the 126 audited files.
