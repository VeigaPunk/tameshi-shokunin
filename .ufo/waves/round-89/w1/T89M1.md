## 2. Method

Each mutant is a fresh byte copy of the pinned pristine with exactly one edit (the runner asserts
`count==1` and refuses no-ops; all 23 applied — no `APPLY FAIL`, no `MUTATE: SETUP`). The detector is
the witness's own selftest: an arm passes only when `rc` and the **exact set of fired checks** match
the arm's expectation (`ok = p.returncode == 1 and fired == {arm.split(":")[0]}`), so both a missing
finding and an extra finding kill an arm. A mutant is KILLED when `--selftest` exits non-zero.

The spec is generated from the pristine bytes, not retyped: `T89M1-make-spec.py` extracts each
`@old` as a single-line substring and asserts `count==1` before writing; the runner re-asserts it.
Spec sha256 `4cad6c298e242ac52ea4e8b645efd43901d1fa1675c8a3dbf633ee02002aaa31` (96 lines, 23 defects),
written before the first sweep.

## 4. What the kill mechanisms say about the selftest

- 11 of the 15 kills are **branch-targeted**: the check's own arm (or its extra `:` arm) goes red
  because the weakened check stops firing — D01, D04, D05, D07, D08, D10, D11, D12, D13, D14, D15.
- 2 kills are **neighbouring-check** kills: D03 is still refused as `W_MAT`, D06 as `W_CONTENT`.
  The mutant is detected, but not by the check that was weakened; the arm's exact-set assertion is
  what fails. These still count as killed (the suite refuses the mutant), with the nuance recorded.
- 2 kills are **over-firing** kills and carry much less information: D02 (inverted vocabulary check)
  and D19 (see §5) fire on nearly every leg, so `BASE` goes red. They prove the check's *match path*
  is exercised on the fixture, not that its discrimination is.
- Arm load-bearing summary: 20 of the 21 arms appear as the failing arm for at least one defect
  (D02 alone fails all 20 non-`SETUP` arms; D19 fails 19). Excluding the two over-firing kills, the
  failing arm is the mutant's own check arm for 11 defects (D01, D04, D05, D07, D08, D10…D15) and a
  directly related arm for two more (D03 → `W_MAT`, D06 → `W_CONTENT`). `SETUP` (a CLI refusal, not a
  check) was not probed: it has no check code to weaken.

## 5. D19 was killed for the wrong reason (instrument note)

The intended defect was "accept a `git show` of any revision naming the path". The edit I wrote
(`os.path.basename(path) in d[1]`) instead makes the predicate never true, because `d[1]` is the argv
**list** and `d[1]` elements are `"<rev>:<path>"`, not `"<path>"`. Consequence, visible in the kept
output: `BASE` fails with `WITNESS_FINDING W_MAT leg=leg-a no `git show <rev>:a.sh` exec observed`,
and every other arm gains `W_MAT`. So D19 is a KILLED verdict for a false-positive storm, not a
targeted kill. The intended weakening is R01 below, and it survives.
