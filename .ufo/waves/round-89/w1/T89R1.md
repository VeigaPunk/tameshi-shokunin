## Findings — kill

### K1 — W_ORDER is blind to same-inode writes through a hardlink alias, and to any write outside the traced syscall set; W_CONTENT hashes end-of-run bytes only → a forged verdict table PASSES with doctored exec bytes
`witness-frozen.py:575-590` (W_ORDER keys exec'd files by exact `normpath` string; the `REL:`
fallback at `:580-582` is basename-only for *unanchored* relative paths), `:89-93`
(`STRACE_FLAGS` trace set), `:93-96` (`WRITE_FD_CALLS`/`PATH_WRITE_CALLS`), `:612-615`
(W_CONTENT = `sha256_file(mp)` at audit time, i.e. after the run), `:496-519` (pre-first-exec
writes are not examined at all).

The audited facts per mutant are: (a) file bytes at **audit end** (W_CONTENT), (b) no
write-class syscall naming that exact path **after** its first exec (W_ORDER), (c) interp/argv/env
of the first matching exec and that pid's kernel exit (W_EXEC/W_ENV/W_VERDICT). Pre-exec writes
are wholly unguarded — they are how the runner legitimately creates the mutant — so the *bytes the
exec actually loaded* are pinned only by the combination "final bytes exact ∧ no post-exec write
on the exact path". Both halves break together:

1. **Hardlink alias.** The runner creates `mutant-A1.target.a.sh` with the spec-exact bytes
   (satisfies W_CONTENT forever after), `ln` it to `alias.sh` — `linkat` is a `PATH_WRITE_CALL`
   (`:95`) but it happens **pre-exec**, so W_ORDER's `idx > exec_idx` test (`:587`) never fires.
   It then writes doctored bytes through `alias.sh` (pre-exec — unguarded), execs
   `mutant-A1.target.a.sh` with the declared interpreter/argv/env — the kernel loads the *same
   inode*, i.e. the doctored bytes — and restores the spec-exact bytes through the alias
   (post-exec). Empirically (probe under my scratch, since removed):

   ```
   write(1</…/probe/alias.sh>, "HACKED\n", 7) = 7          # hardlink write decodes as the ALIAS
   write(1</…/probe/mutant.target.a.sh>, "HACKED\n", 7) = 7 # symlink write decodes as the TARGET
   ```

   strace `-y` reports the dentry path the fd was opened under: a symlink write decodes to the
   target (would be caught), a **hardlink** write decodes to the link name and never matches
   `exec_idx_by_path` (`:585`). W_ORDER sees nothing; W_CONTENT sees exact final bytes; W_VERDICT
   binds the exit of an exec that ran arbitrary doctored bytes. The forger authors its own spec
   and table, so every verdict is forgeable (e.g. record `A1:SURVIVED` for a mutation that really
   kills, doctoring the mutant to `exit 0`). Not L1 (trace/workdir/witness untouched), not L2 (no
   `MAP_SHARED`), not L3 (the trace *does carry* the alias write; the witness fails to correlate
   it — L3 covers process state/files the trace does not carry), not L4 (the real work — exec of
   the spec mutation — was skipped).
2. **Untraced write channels.** The trace set (`:89-93`) omits `io_uring_enter` (submits kernel
   -side writes with no traced syscall), `open_by_handle_at`, `unlink` family (unlink alone is
   harmless — W_CONTENT flags a missing file — but unlink+recreate via a *different* path spelling
   that normalizes differently is covered only by the exact-string keying above). A restore via
   io_uring needs no alias at all. Same exploit shape, same non-declared status.

Minimal fix direction (for the L1 to weigh, not applied): flag any write-class syscall whose
anchored path resolves into a leg's case dir after that leg's pristine exec and whose target
basename matches the `mutant-*/pristine.*` convention *or* whose decoded path is not an
`expected_paths` key; plus add `io_uring_*` to the refused-syscall set (fail W_ORDER/W_ENV on
`io_uring_setup` anywhere in the trace).

## Findings — defect

### D1 — Only the FIRST matching exec per path is audited; W_EXTRA's documented guarantee is not implemented
`:515-519` (`if tgt in expected_paths and tgt not in first_exec` — later matching execs never
update `first_exec`/`exec_env`), `:521-524` (W_EXTRA exempts any path already in
`expected_paths`), docstring `:40-42` ("W_EXTRA no interpreter exec of a mutant/pristine path
under the workdir **that the declared legs do not account for**").

The code accounts *paths*, not *(path, interpreter, argv, env) tuples*: after the audited exec, a
runner may re-exec the same mutant through any interpreter with any argv and any environment —
`node "$MUTANT" --grade`, `BASH_ENV=… bash "$MUTANT" --selftest` (argv unchanged → this one would
actually be caught as the first exec; use a differing argv to dodge), etc. — with no finding.
Under the frozen kill rule (b) this cannot launder the audited facts (the first exec still pins
bytes-with-K1-caveat + argv + env + exit), so it is not a kill; but the W_EXTRA contract as
written in the docstring is false, and W_ENV's per-exec env audit is first-exec-only as well
(`exec_env` captured at `:518`, consumed at `:548-561`).

### D2 — `--run` hands the untrusted runner write access to real sibling repos, and W_PIN accepts any self-consistent (REV, PIN) the runner chooses
`:706-709` (symlink loop links the *real* sibling repos into the scratch fleet — only the lane
repo is shadowed, `:696-699`), `:365-381` (`git_blob` requires only "repo is its own toplevel" +
`cat-file blob REV:path` success; PIN equality is checked against the runner-declared PIN,
`:466-467`).

Two coupled gaps. (a) Blast radius: a forgery (or any buggy runner) executed by `--run` can write
through the symlinks into real lane working trees (or `git commit` into them) mid-audit; L1
declares only "the trace file, the kept workdir, or the witness itself" as out of model — real
sibling repos are not covered by any declared limit. (b) Authenticity: nothing anchors REV to the
frozen base. A runner that commits a weakened blob into a real sibling repo and sets
`REV_X=<new-head>`/`PIN_X=sha(weakened)` produces a fully self-consistent ledger: W_PIN,
W_SPEC, W_CONTENT, W_CONTROL all validate against the blob the forger chose, and the leg
"passes" having never tested the real pinned target. The plan's predicate inherits this
(the counter runs at a lane REV but the target repos are live). Fix direction: pass an
expected base rev per repo (or read-only copies instead of symlinks) and fail W_PIN when
REV is not an ancestor of it.

### D3 — The rlimit rule is permeable to pid reuse
`:562-565`: `audited_pids` maps pid→first-exec idx and an rlimit event is allowed whenever
`pid in audited_pids and idx > audited_pids[pid]`. Any *later* process that inherits a recycled
audited pid may `prlimit64`/`setrlimit` undetected, i.e. runner-set rlimits after the interpreter
exits are unflagged — the exact class the check exists for (the `rlimit-steer` forgery arm).
`exit_after` itself (`:567-570`) is reuse-*safe*: it takes the first exit strictly after the exec
idx, so a stale pre-exec exit of the same pid is never used and a post-exit recycled pid cannot
displace the real one. Feasibility is capped by `/proc/sys/kernel/pid_max = 4194304` on this host
(~4M spawns to force a specific wrap; heavy but not impossible inside a 10-minute run budget),
hence defect, not kill.

## Findings — note (false-accept surface, ordered by the brief's coverage list)

- **N1 parse_trace unfinished/resumed joining** `:276-281`: one pending slot per pid — adequate,
  since a pid (thread) has at most one unfinished syscall; a resumed line with no pending
  degrades to `call(` + rest and yields an empty write event (harmless). Exit lines are joined
  before EXIT_RE, so an exit inside a resumed body is still seen.
- **N2 the ` = ` result split** `:286-290`: `rsplit(" = ", 1)` picks the true separator for any
  argv/env containing ` = ` (result comes last) but misparses a syscall whose *decoded fd path*
  contains ` = ` (file literally named `a = b`) — that event's path decode is garbage; contrived,
  and the error direction is a missed write (K1-adjacent), not a false finding.
- **N3 failed execs** `:291-292`: `= -1`/`= ?` events are dropped — correct; a failed
  `execve` cannot be an audited exec, and the retry-after-EINTR pattern parses as a second
  successful exec of the same pid (pid unchanged per S313 — exit binding unaffected).
- **N4 signal lines** `:261, :620-622`: `killed by SIGX` → INCONCLUSIVE; with
  `-e signal=none` the delivery lines vanish but the exit-status line remains (verified shape in
  the fixture arms). Matches the runner's oracle (`runner-base.sh:564-569`: 124/126/127 →
  INCONCLUSIVE; KILLED = exit ∉ {0,124,126,127}; `:994-995` "verdict oracle = exit status only"),
  so no honest refusal from the exit map.
- **N5 exec_strings/_str_array tokenizing** `:214-238, :240-250`: escape-aware; `-s 4096`
  truncation (`:89`) can equate two distinct >4 KiB env values in the W_ENV diff — deny-list
  names are caught by prefix, so ENV_DENY is intact; execveat dirfd-relative filenames
  (`:240-250` takes the first quoted string, `:398-399` realpaths it against `shutil.which`)
  never match — a false-*refuse* only, and no honest leg execs that way (bash/env -i resolve
  through PATH to absolute filenames).
- **N6 interp_match / shutil.which** `:392-400`: sound for `--run` (runner env PATH is the
  witness's own, `:715-716`); in `--audit` of a kept run performed under a different PATH every
  exec fails `realpath(filename) == realpath(which(interp))` → mass W_CONTROL/W_EXEC "never
  exec'd" false-refuse. The public `--audit` path is selftest-only today; the harness re-runs via
  `--run`. Worth a comment on the flag.
- **N7 first_exec selection** `:515-519`: "first matching" is order-controllable by the runner;
  with K1 closed, the first exec is still a sound audit anchor (bytes-with-content-check, argv,
  env, exit all pinned). INTERP_RE takes the **last** interpreter match in the suite string
  (`:88, :165-171`): a suite ending `… || bash "$MUTANT" --selftest` shifts the audited exec to
  the fallback interpreter — verdict semantics then follow that interpreter's exit, which is
  consistent with the runner's own oracle (the sweep records the suite exit) but is a
  grammar-level subtlety an honest variant could trip over.
- **N8 W_ORDER anchoring** `:575-590`: normpath on both sides (`:575`, and decoded fd paths at
  `:312, :353`); REL fallback is basename-against-every-audited-file — conservative
  (false-refuse direction only, and basenames are specific enough). The real hole is the
  exact-string keying itself → K1. `-y`-anchored relative writes with a decoded dirfd are
  anchored correctly (`:333-346`).
- **N9 norm_env** `:529-547`: MUTANT/DEFECT_ID normalize only on exact equality; the
  `[-/_]<id>(?=/|$)` token is normalized in **every** value, wider than the docstring's
  "sandbox-<id> dirs" (`:537`) — e.g. `HOOK=/wd/<case>/sandbox-A1/hook.js` vs
  `sandbox-CONTROL/hook.js` compares equal. The underlying steering class (files planted in a
  per-defect dir the environment names) is L3-declared, so note, not defect. Verified the frozen
  suites normalize cleanly: sandbox legs (`runner-base.sh:1573-1595`) export only
  PATH/HOME/TMPDIR/LC_ALL/GIT_* via `env -i`, non-sandbox legs export
  MUTANT/TARGET/PRISTINE/WORKDIR/DEFECT_ID (`:474`), all of which the witness handles.
- **N10 the rlimit rule** `:300-311` (parse: `setrlimit` always counts; `prlimit64` counts unless
  new-limit is NULL — struct args contain `, ` and still land on a non-NULL `parts[2]`, so the
  split at `:307` is safe) plus the pid-reuse permeability above → D3.
- **N11 W_EXTRA** `:521-524`: besides D1, the `unaudited_cases` carve-out excuses ghost execs
  under a case whose leg already failed W_PARSE/W_PIN — sound, since those legs already carry
  findings (`:644` requires zero findings).
- **N12 the witnessed counter** `:630-632`: counts legs with no *leg-attributed* finding;
  global findings (leg `-`: W_RUN, W_EXTRA, rlimit) never decrement it. It cannot flip PASS —
  `report` requires `not findings` *and* `witnessed == len(legs)` (`:644`) — but a FAIL line may
  print `witnessed=N` with every leg counted while global findings exist. Cosmetic; the
  predicate's `witnessed=11` figure is only read under `findings=0`.

## Honest-refusal assessment (paths by which an honest runner would be refused)

Verified clean for the frozen runner shape: W_RUN regexes accept the runner's exact lines
(`runner-base.sh:1625` summary `cases=11 passed=11;` matches `:415`; `REGRESSION_CASE <n>: PASS (band: …)`
matches `:413`); LEG_RE matches all 11 legs and not the runner's fixture-mode
`regression_case_git fixture-*` selftest calls (`runner-base.sh:1912-1998`, unquoted
second arg → no LEG_RE match); the embedded spec escape table (`\n \t \r \\`,
`runner-base.sh` `unescape()`) is exactly the witness's `unescape_spec` table (`:80-99`);
`blob.replace(old, new, 1)` on both sides (`:483` vs `runner-base.sh:446`); mutant/pristine
naming `mutant-<id>.target.<basename>` / `pristine.target.<basename>` matches the sweep's
`$cwd/target.<basename>` materialization + `mutant-$id.$(basename TARGET)` (`runner-base.sh:1369,
533, 560`); the sweep never writes mutants/pristine after their execs (`MUTATE_RESTORE` is
verify-only, `runner-base.sh:575-586`), so W_ORDER stays clean; sandbox envs normalize
(N9). Residual false-refuse edges are all variant-facing and listed as N5/N6/N7 and the
order-sensitive spec-ids comparison `:472-473` (the runner's own table comparison is per-id via
`table_lookup`, `runner-base.sh:1418-1424` — a variant with a reordered table passes its own
band but fails W_SPEC; the frozen tables align, pre-freeze receipts prove it).
