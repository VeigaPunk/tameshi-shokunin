## 2. H1 — the mechanism

The witness checks the *exec* of each mutant (interpreter, script argument, argv tail,
environment, bytes, write-after-exec) and takes the *kernel exit* of that pid as the
verdict. It never models **why** the process exited. The forgery therefore leaves the
exec pristine and attacks the exit:

```sh
# run_one(), KILLED-recorded defects only (CONTROL and SURVIVED-recorded run untouched):
timeout "$TIMEOUT_S" bash -c "mkdir -p \"$WORKDIR/sandbox-$3/home\" \"$WORKDIR/sandbox-$3/tmp\"; umask 0777; $SUITE" \
  </dev/null >/dev/full 2>&1
```

- The suite string is the leg's own; `exec env -i … node|bash|python3 "$MUTANT" --selftest`
  still runs the spec-exact mutant with the declared argv and the leg's exact environment.
- The prefix pre-creates the per-defect sandbox dirs **under the normal umask** so the
  suite's own `mkdir -p`/`cd` still succeed and the interpreter really execs (otherwise
  `W_EXEC` would fire — this was the first design bug and is why the prefix exists).
- `umask 0777` makes every file the gate creates mode 000; the gate's own read-back then
  fails. `fd 1/2 → /dev/full` makes any output write fail.
- Neither `umask` nor the fd table appears in `STRACE_FLAGS`
  (`execve,execveat,openat,openat2,open,creat,rename,…,write,…,setrlimit,prlimit64`),
  and neither is in argv or the environment.

Why the two channels: pre-flight probes on the pinned pristine of each gate (materialized
with `git show REV:PATH`, run in the leg's exact suite form) show that **neither channel
alone covers the ledger**:

| gate (leg) | honest | fd 1/2→/dev/full only | umask 0777 only | both |
|---|---|---|---|---|
| kimi-census | 0 | **0 (resists)** | 1 | 1 |
| surface-census | 0 | 1 | 1 | 1 |
| tsukuroi-census | 0 | 1 | **0 (resists)** | 1 |
| mado-verify | 0 | **0 (resists)** | 2 | 2 |
| claims-check | 0 | **0 (resists)** | 1 | 1 |
| round-gate | 0 | 1 | 1 | 1 |
| sources-check | 0 | 1 | 1 | 1 |
| cite-check | 0 | 1 | 1 | 1 |
| kake-guard | 0 | 120 | 1 | 120 |
| checklist-run, drift-pins | 0 in the sandbox form | not measured cleanly in pre-flight (their selftest re-execs `$SELF`, so the probe needs the blob's 100755 bit and the sandbox env) | — | — |

The pre-flight table is an estimate; the authoritative evidence is the witness run, where
every KILLED-recorded defect of all 11 legs produced a non-zero kernel exit (otherwise
`W_VERDICT` would have fired).

### 2.3 Two refused intermediates (negative controls)

Both use the same idea and differ only in shell plumbing; both are refused by `W_ENV`,
which is why the accepted form is not an artefact of a sloppy check:

| variant | shape | result |
|---|---|---|
| subshell (`h1a`) | `( mkdir …; umask 0777; timeout … bash -c "$SUITE" ) >/dev/full` | `findings=40 checks=W_ENV FAIL`, exit 1 — `SHLVL` 2 (control) vs 1 (defect) |
| deleted cwd (`h1c`) | `bash -c "dc=$(mktemp -d …); cd "$dc" && rmdir "$dc"; $SUITE"` | `findings=40 checks=W_ENV FAIL`, exit 1 — `OLDPWD` absent (control) vs `OLDPWD=` (defect) |

Both failed **only** on `W_ENV`; `W_EXEC`, `W_CONTENT`, `W_VERDICT`, `W_ORDER`, `W_EXTRA`
were clean on all 11 legs in both runs (`witnessed=11`). So the witness's environment
equality is doing real work — it rejects shell-level side effects — and the accepted
variant passes because it leaves the environment byte-identical.

The `delcwd` variant is also why "strictly the enumerated L3 instances" is not reachable
here: a deleted cwd necessarily perturbs `PWD`/`OLDPWD` (and the sandbox legs' own `cd`
re-perturbs them), so the working-directory channel cannot be used without an env
difference the witness sees. Only the fd-table + umask pair survives.

## 3. H2 — per-defect environment variable, value differing only by the id path token

Witness normalization (`ledger-witness.py`, `norm_env`):

```python
tok = re.compile(r"(?<=[-/_])%s(?=/|$)" % re.escape(did))
```

so `SANDBOX_ROOT=<wd>/sb-A1` (defect) and `SANDBOX_ROOT=<wd>/sb-CONTROL` (control) both
become `sb-<ID>` and the two environments compare equal.

`T89E4-make-forge-h2.py` builds a real fixture: one leg `fleetrep/gate.sh`, suite

```sh
h="$WORKDIR/sb-$DEFECT_ID"; mkdir -p "$h" || exit 2; \
if [[ "$DEFECT_ID" == A1 ]]; then : >"$h/poison"; fi; \
exec env -i PATH="$PATH" SANDBOX_ROOT="$h" bash "$MUTANT" --selftest
```

The gate exits 1 iff `$SANDBOX_ROOT/poison` exists; both mutations are cosmetic. The
runner plants the poison only for A1, so A1 reports KILLED while its mutation survives.

```
$ python3 -I …/ledger-witness.py --run --runner …/h2/forge-h2-runner.sh --fleet …/h2/fleet --scratch …/h2scratch
WITNESS_RUN: runner_sha256=83c4986103e19bf470c0a6846b93d07736252b0cc549c387878ae1b9b3eaa871 rc=0 …
WITNESS_LEG leg-a ok
LEDGER_WITNESS: legs=1 witnessed=1 findings=0 checks=- PASS
EXIT=0
```

Manufactured-verdict proof on the kept workdir:

```
$ SANDBOX_ROOT=<clean dir> bash h2scratch/wd/leg-a/mutant-A1.target.gate.sh --selftest ; echo rc=$?
alpha1 beta
rc=0                     # A1 SURVIVES honestly (sha256 eb357c60…, spec-exact)
$ mkdir -p $T; : > $T/poison; SANDBOX_ROOT=$T bash …/mutant-A1.target.gate.sh --selftest ; echo rc=$?
gate: poisoned sandbox
rc=1                     # what the runner records as KILLED
```

**Classification: L3.** The variable's value differs only by the id path token, which is
exactly the documented normalization ("the sandbox id token"); the steering is file
content in a per-defect directory the environment names — L3's last clause verbatim. The
only wording gap: L3's example says "a sandbox HOME/TMPDIR", while a runner may name *its
own* per-defect variable (`SANDBOX_ROOT`) and still pass. The clause's general wording
("a per-defect directory the environment names") already covers it; naming the general
case would remove the ambiguity. No `W_ENV` change is warranted: the normalization is
what lets the *honest* runner's per-defect `HOME`/`TMPDIR` pass, so tightening it would
refuse the honest variants.

| channel | in the trace? | in argv/env? | accepted? |

| cwd of the exec'd interpreter | **no** | partially (`PWD`/`OLDPWD`) | only if the env is left identical — not reachable in this shape |

## 5. Kill-rule reading (advisory for L1; no edits made)

Kill rule (b), verbatim: *"any committed runner variant … that does not perform the
ledger's real work — for at least one declared leg, some mutant is not exec'd by the leg's
interpreter on its spec-exact bytes with the declared argv and environment, with a kernel
exit equal to the recorded verdict — is accepted …, unless the variant works only through
a declared limit below"*.

The accepted H1 runner satisfies **every** conjunct of that definition, for every leg:

- every mutant is exec'd by the leg's interpreter (the witness itself says `witnessed=11`),
- on its spec-exact bytes (`W_CONTENT` clean),
- with the declared argv and the leg's environment (`W_EXEC`, `W_ENV` clean),
- with a kernel exit equal to the recorded verdict (`W_VERDICT` clean).

So the operational definition in (b) does not distinguish "the suite judged the mutant"
from "the process was made to fail". Two readings follow, and the L1 must pick one:

1. **L3 governs** (recommended): L3 already declares "per-defect steering through process
   state … the trace does not carry" out of model; `umask` is such state (the example list
   is introduced as illustrative: "— the working directory, the inherited fd table (e.g. a
   closed stdout), signal dispositions, …"). Under this reading H1 is inside the declared
   limits, does not kill R89-C1, and the only action is a declaration sharpening: add
   `umask` (and "the fd table beyond stdout") to L3's example list.
2. **The limit list is exhaustive**: then `umask` is not declared, H1 is a hole, and
   kill rule (b) fires — but note it would fire through the escape clause, not through the
   em-dash definition, which the runner satisfies.

Either way, the class cannot be closed by the witness: distinguishing a coerced non-zero
exit from a genuine one requires modelling the suite's own logic, which is exactly what
L4 ("a runner that does all the real work") and L3 concede. The honest statement of the
capability is: *the witness proves the ledger's exec shape and bytes, not the provenance
of the verdict.*

## 6. Risks / notes for the L1

- The fixture variants (`h1fixture`, `h2`) break the runner's own `--selftest`: the base
  selftest greps `local nlegs=11` and the 11 `st_*` names, which the leg surgery removes.
  Irrelevant to `--run` (the witness only runs `--regression`), but a re-runner should not
  expect `--selftest` to pass on those two artifacts.
- Both fixture generators (`h1fixture`, `h2`) create a fresh fixture repo, so the runner
  they emit embeds a new commit id per invocation and is not byte-reproducible across
  runs; the sha256 in the table is the artifact that was actually measured. The `umask`
  and `delcwd` runners are byte-reproducible from the frozen base (verified: 4 diff hunks,
  sha256 `48cf8389…`).
- The accepted H1 runner does not "print a figure without the work" in the round-85–88
  sense: it runs the real suites. Its counterfeit is narrower and more interesting — it
  keeps the work and forges the verdict. Any future counter should say which of the two it
  is testing.
- No host state was touched; no pacman transaction; nothing installed.
