## One bounded proposed move
Reuse a **late-invalid / earlier-effect sentinel fixture recipe**, not a shared validator or shared alphabet. In a supplemental fixture owned by L1 (outside the frozen counter), place a schema-valid first row whose measurement would leave a scratch-only sentinel, followed by one invalid identity. Assert the exact public-CLI refusal channel tuple `(exit2, stdout=b'', escaped diagnostic, no traceback)` **and sentinel absence**; keep a valid-only sibling that actually creates the sentinel to prove it was armed. For selfstate, use its existing scratch instrument facility; for defect-bind, an observable checker/read sentinel would need a contained fixture adapter rather than changing production behavior. This is a reusable method proposal only, not a request to mutate sibling gates.

The non-obvious point is that empty stdout alone establishes no verdict-stream effect, not necessarily no earlier instrument execution. The armed valid sibling plus late-invalid placement distinguishes those properties without treating a malformed fixture or unarmed sentinel as success. Existing full-population validation offers the right insertion point; sibling patterns contribute exact record grammar and evaluate-before-emit discipline.
