## Findings

### F1 — the receipt's `tool_sha256_at_rev` header binds a **blob** digest to a **worktree** execution (severity: high; live now)

`.ufo/evidence/round-99/pre-freeze-run.sh:23` computes the digest from the committed blob —

```
sha=$(/usr/bin/git -C "$L" show "$I:$tool" | sha256sum | cut -d' ' -f1)
```

— while `rec` then executes the **worktree** file (`rec c1-population "$T1" python3 -I "$T1" --repo "$L" --rev "$I" $POP`, with `cd "$L"` and `$T1=tools/tally-reconcile.py`). The two differ whenever the worktree tool differs from the blob at `I`.

This is not hypothetical. The L1 is amending the worktree tools right now, so **both** new tools already mismatch their pinned blob:

| tool | header digest (blob at `I`) | bytes actually executed (worktree) |
|---|---|---|
| `tools/tally-reconcile.py` | `60d59bea…566bf40c` | `c78e0c630aeda375dae0e6a3c9c9a75ec90356756ed2238f2526562a77f70f56` |
| `tools/control-assertion-audit-v2.py` | `acd67ab67acf011d50952886afe284d331da424360d9a7a79f391284ecfaceb6` | `27e1473484e36394759a7aacbd625b2645f371b73ac44c837f5511c19a8193ca` |

· `R99SN1-provenance-gap-live.txt`

Exploit path, demonstrated end-to-end in a scratch clone with no tampering by me beyond a one-line edit to a *clone's* worktree copy: changing the frozen C1 grader's `if all(o == (n, m) for o in obs):` to `if True:` makes the **round-94 pair** — the one pair the entire claim exists to detect — print `TALLY matched … observed=9/9 detail=equal` and **exit 0**, while the receipt header still names the pristine blob digest `60d59bea…`. The unmodified blob-at-`I` tool, run side by side, prints `mismatched` and exits 1. The receipt is therefore not evidence about the run that produced it. · `R99SN1-tool-provenance-mismatch.txt`

No lane instrument catches this. The lane's own binder, `tools/receipt-bytes-bind.py`, expects the round-78 header names `# measured_rev:` / `# tool:` / `# tool_sha256:`; the round-99 receipts use `# instrument_rev:` / `# tool:` / `# tool_sha256_at_rev:`, so the binder refuses the whole directory with `RECEIPT_BIND error=setup:receipt-header-incomplete:…/c1-before-token.out` (rc 2) — before it ever compares a digest. · `R99SN1-receipt-binding-coverage.txt`

Smallest remediation: execute the pinned blob rather than the worktree file — `git -C "$L" show "$I:$tool" > "$S/$tool" && python3 -I "$S/$tool" …` — so the bytes that run are the bytes the header names; and/or have the runner assert `sha256(worktree) == sha` before each invocation and refuse otherwise. (Inherited, not new: the round-98 precedent `.ufo/evidence/round-98/records-run.sh` executes worktree bytes with no digest binding at all, so the round-99 runner is a partial improvement that still leaves the gap.)

### F2 — the tools are directly executable without isolation, so `PYTHONPATH` can forge a verdict (severity: medium)

Both tools carry `#!/usr/bin/env python3` and mode `100755`. The frozen command form is `python3 -I tools/…`, and `-I` holds: under a hostile `PYTHONPATH` the `-I` runs are byte-identical to the clean runs. But the executable path is not isolated:

`PYTHONPATH=<dir with a delegating fake `subprocess` that forges the round-94 receipt> python3 tools/tally-reconcile.py … --record corpus/lessons/round-94.md` prints

```
TALLY matched corpus/lessons/round-94.md:66 token DISPOSITION_SELFTEST claimed=8/8 receipt=.ufo/evidence/round-94/pre-freeze/c2-selftest.out observed=8/8 detail=equal
TALLY_RECONCILE records=1 tallies=1 pairs=1 matched=1 mismatched=0 unbound=0 uncited=0
```

— **exit 0** where the truth is `mismatched`, exit 1. Under `-I` the same injection yields `mismatched`, exit 1. · `R99SN1-silent-verdict-injection.txt`

On the twelve-record population the injection is worse than a crash: the **summary line is unchanged** (`records=12 tallies=28 pairs=9 matched=2 mismatched=1 unbound=6 uncited=19`, exit 1) while the **identity of the mismatched pair silently swaps** from round-94 to round-93 — because the forged blob (`DISPOSITION_SELFTEST: 8/8 pass`) satisfies round-93's `6/6` claim's *absence* and breaks its match. A verdict-checker that reads only the summary line sees a pass. · `R99SN1-mismatched-identity.txt`

A hostile `re` module is louder but also reachable: it aborts the interpreter with `AttributeError: module 're' has no attribute 'ASCII'` (exit 1). · `R99SN1-fake-re-injection.txt`

Smallest remediation (both verified on this host): change the shebang to `#!/usr/bin/env -S python3 -I` (`env -S python3 -I` shebang → `sys.flags.isolated == 1`, rc 0), or add a guard `if not sys.flags.isolated: sys.stderr.write(…); sys.exit(64)` (rc 64 without `-I`, rc 0 with `-I`). · `R99SN1-remediation-feasibility.txt`

### F3 — a non-UTF-8 byte inside the N/M digits hides a contradicting observation; amendment A2 does **not** close it (severity: medium)

C1 decodes receipts with `out.decode("utf-8", "replace")` (`tools/tally-reconcile.py:109` at the pinned blob). A receipt line whose N/M contains one non-UTF-8 byte decodes to a string whose digits no longer match `(\d+)/(\d+)`, so the line is not an observation at all.

Fixture: receipt bytes `X_SELFTEST: 9/9 pass\nX_SELFTEST: 8\xff/8 pass\n`; record claims `X_SELFTEST 9/9` citing that receipt.

- Pinned blob (sha `60d59bea`): `TALLY matched … claimed=9/9 receipt=…/dig.out observed=9/9 detail=equal`, rc 0.
- Worktree copy after amendment A2 (sha `c78e0c63`): **the same** — `matched`, rc 0.

· `R99SN1-nonutf8-digit-residual.txt`

The decoded text a reader sees is `X_SELFTEST: 8�/8 pass` — a contradicting observation that no reader, and no regex, can treat as `9/9`. A2 removes the `pass`-suffix requirement from the receipt regex, which closes the `8/8 fail` / bare `8/8` shapes (`R99SN1-contradicting-line-falsification.txt`) but not this one, because the byte breaks the *digits*, not the suffix.

This is a distinct vector from R99R1's F1 (which used a semantic suffix change); the difference is that here the receipt is not even a well-formed text file, and the tool accepts it silently.

Smallest remediation: decode receipts strictly and refuse a non-UTF-8 receipt, the way C2 v2 already refuses a non-UTF-8 driver (`AUDIT_SETUP driver-not-utf8`, rc 2 — `R99SN1-nonutf8-receipt-evasion.txt`). One line at the pinned blob's `tools/tally-reconcile.py:109`: `out.decode("utf-8")` inside a `try`, raising `Setup("receipt-not-utf8")` on `UnicodeDecodeError`. The asymmetry is the tell: the driver reader is strict, the receipt reader is not.

### F4 — no per-call timeout, and the receipt blob is re-read per pair (severity: medium/low)

Neither new tool passes `timeout=` to any of its git subprocesses (0 occurrences in all three of `tally-reconcile.py`, `control-assertion-audit-v2.py`, `control-assertion-audit.py`), while 23 of the lane's 61 tools do. C1's `Tree.read` is called once per pair with no caching, so a receipt cited by N lines is fetched and regex-scanned N times.

| 42 MB (same receipt, 8 pairs) | 8 | 3.09 s | 355 MB | — |

· `R99SN1-memory-amplification-table.txt`, `R99SN1-re-read-amplification.txt`, `R99SN1-fixture-symlink-binary-huge.txt`

A hostile or merely corrupt blob in the tree therefore costs gigabytes and minutes with no ceiling. The wording makes no performance promise, so this falsifies nothing — it is a hardening gap with a one-line fix each: `timeout=` on every `subprocess.run`, and a per-path cache in `Tree.read`.

### F7 — `--repo` confinement differs between the two tools (severity: low; informational)

C1 refuses a non-top-level `--repo` with `TALLY_SETUP repo-not-toplevel` (rc 2). C2 v2 has no top-level check: `--repo <lane>/tools` (a subdirectory) is accepted and audits the lane's blobs, and `--repo ''` falls through to the usage path (rc 64). Both tools read only the named repository's blobs, and `--repo` is the operator's choice of subject, so neither is an escape; but the asymmetry means a typo'd `--repo` is a hard refusal under C1 and a silent success under C2. Also observed: C2 resolves `--rev` with `rev-parse --verify --end-of-options <rev>^{commit}` and prints the **resolved** commit on its `CONTROL_ASSERT_DRIVER rev=` line — a good disclosure that C1's stricter 40-hex-commit check does not need. · `R99SN1-repo-paths.txt`, `R99SN1-bare-and-hostile-repo.txt`, `R99SN1-rev-and-driver-forms.txt`
