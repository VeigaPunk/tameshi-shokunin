**Axes: calibration (primary), coverage (secondary).** No other round axis is touched.

Take the two registry surfaces the round's `After` lines currently leave outside the lane's
self-description: add `tools/registry.json` rows for `tally-reconcile-selftest`
(`python3 -I -X utf8 tools/tally-reconcile.py --selftest` → `TALLY_RECONCILE_SELFTEST: 17/17
pass`, exit 0) and `control-assertion-audit-v2-selftest`
(`python3 -I tools/control-assertion-audit-v2.py --selftest` → `CONTROL_ASSERT_V2_SELFTEST:
27/27 pass` at the pinned blob, `36/36` in the amended worktree — the row must pin whichever
bytes land at R, exit 0 either way), plus the two sweep rows once R exists (`--repo . --rev R …` /
`--driver .ufo/evidence/round-99/c2/alias-driver.py`), and add the matching
`registry-figure-bind.json` entries in the `registry-json` surface. That is the same
compensation round 90 paid for `ledger-witness` (SKILL.md:2360-2365), and it is the only
in-lane mechanism that re-runs a pinned tally on demand: today `TALLY_RECONCILE_SELFTEST` and
`CONTROL_ASSERT_V2_SELFTEST` are pinned by nothing, so both can go stale exactly the way
round-98 D2 did — and F6 is the first instance: the pinned `27/27` is already stale against
the worktree's `36/36`, and no gate in the lane notices.

Why calibration and not depth: the gain is a *measurable* surface for the lane's own newest
tallies (the counter exists, nothing reads it), which is C1's own axis applied one level up.
Coverage gains the gate binding for the alias-sweep counter line.

Risks/declared costs: `registry-check.py` replays every active row, so two selftest rows add
runtime and two sweep rows re-run the audits against the records revision (the sweep rows must
be added only after R is named, or they would pin a moving argument); the `source:` cell must
name the SKILL.md line that is added in the same revision (criterion 103's rule); and a future
edit to either tool's arm count breaks the row — which is the point, but it is a new
maintenance obligation on every successor. No frozen claim reads the registry, so no
predicate is harmed.

Verification: `python3 tools/registry-check.py --rev R` must print `REGISTRY_CHECK: held=N/N`
with N including the new rows, and `python3 -I -X utf8 tools/registry-figure-bind.py --repo .`
must stay all-`match` with the population 9 → 13. If either new row is added without its
SKILL statement, criterion 103's own check is what fails — a bounded, observable failure.

### F2 — The lane now carries two incompatible citation-resolution grammars, with no shared helper

`quoted-line-exists.py` resolves a **bare basename uniquely anywhere** under
`.ufo/evidence/`+`tools/` and *skips* on ambiguity (0 or 2+ matches → `skipped-ambiguous`, counted).
`tally-reconcile.py` resolves a citation as a tree blob, else **only at the top** of
`.ufo/evidence/round-NN` / `.ufo/waves/round-NN`, and grades `unbound unresolved`.

Measured on the four basenames C1 leaves unresolved (`c2-selftest.out` r95:99,
`selftest.txt` r96:44, `c1-selftest.out` r97:89, `c2-selftest.out` r97:99): they occur 13, 11,
9 and 13 times respectively at `46651051`, so `quoted-line-exists` would skip all four as
ambiguous — the two rules agree on this population and C1's `unbound=6` is therefore not an
artefact of the stricter rule. The risk is maintenance: a later citation written as
`pre-freeze/x.out` resolves under `tally-reconcile` (round dir + relative subpath) and is
invisible to `quoted-line-exists` (not `.ufo/`-rooted, not a bare basename), and the
reverse holds for a unique bare basename elsewhere in the tree. Nothing shares the
resolution code.

### F4 — v2 duplicates a binding taxonomy beside v1's `collect_scopes`; the alias layer and the grading layer use different models of the same driver

`recorder_names()` (`tools/control-assertion-audit-v2.py:253-317` at the pinned blob) re-walks the module and
binds `ast.arg`, `For`/`comprehension`, `withitem`, `ExceptHandler`, `Import`/`ImportFrom`,
`NamedExpr`, `FunctionDef`/`ClassDef`, `AnnAssign` (including value-less) and `AugAssign` as
`other`. The reused `collect_scopes()` (`tools/control-assertion-audit.py:73-139`) records
only `Assign` (direct/tuple/attribute targets), `AnnAssign` *with a value*, `AugAssign`, and
`For`/`comprehension` targets — and records function args as kind `loop`, not `other`. The
ambiguity set is computed from the former, the site grading from the latter. They agree on
the committed drivers (F1 in the receipt: 15 site lines identical on `controls98`/
`controls97`), but they can drift silently, and a fix to one walker does not reach the other.

Separately, the git-sealed environment helper is copied verbatim in four tools:
`sealed_env()` has the identical source sha in `control-assertion-audit.py:46`,
`control-assertion-audit-v2.py:72`, `registry-cell-immutability.py:39`,
`tally-reconcile.py:71` (plus a per-tool `git()` wrapper). No `tools/_*.py` shared module
exists.

### F5 — Measured asymmetry (undeclared): rebinding the base recorder is invisible to v2, rebinding an alias is not

Fixture repo, commit `042bbfd7` (`R99CN1-rebound-recorder-fixture.txt`):

| fixture | v1 | v2 |
|---|---|---|
| `add = print; add("rebound-add-measured", p.returncode, …)` | sites=1 measured=1, rc 0 | sites=1 measured=1, rc 0 — `names=add`, `ambiguous=0` |
| control (no rebinding) | sites=1 measured=1, rc 0 | identical to the row above |
| `rec = add; rec = print; rec(…)` | sites=0, rc 0 (vacuous) | site counted, `class=unresolved`, `ambiguous-recorder:rec`, rc 1 |

`recorder_names()` skips `name == "add"` (`…-v2.py:300-301` at the pinned blob) and `audit_text()` never puts
`add` into `ambiguous`, so a driver that reassigns the base recorder is graded exactly like a
clean one. C2's kill rule (d) — “a call of a name never bound from a recorder is counted as a
site” — is not literally reached (`add` was bound from a recorder by its `def`), and the
declared limits name wrappers, `getattr`, and recorder-by-parameter but not this case. The
sibling precedent is explicit that a static site walk is defeated by exactly this: kaidoku
`tools/round58-battery-exec-check.py:1-8` replaced the round-57 “syntactic call-site walk …
(which dead code, an unused function, an early return or a rebound `run` all satisfy)” with an
executed battery. This is a candidate for a declared limit, not a claim falsification.
The worktree amendment now *declares* exactly this case — “The base name `add` is always a
recorder: rebinding it (`add = print`) is not detected, exactly as in v1” — while the
behaviour is unchanged (the amended worktree still prints `measured=yes`, rc 0 on `f1`; see
`R99CN1-concurrent-amendment.txt`). So the finding becomes a declared limit in the amended
bytes and remains undeclared only against the pinned instrument (F6).
