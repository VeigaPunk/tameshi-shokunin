### S5 — "bound anywhere in the module only by a plain or annotated assignment from a recorder name" — falsifies-wording

Sentence quoted from plan lines 109–110: *"v2 counts as sites the bare-name calls of add and of every name bound anywhere in the module only by a plain or annotated assignment from a recorder name (chains followed to a fixpoint), and grades them with v1's rules"*.

The instrument's alias rule is `recorder_names` (v2 lines 253–317): a name enters `aliases` iff it has a binding `("alias", src)` recorded from `Assign`/`AnnAssign` with a bare `Name` target and a bare `Name` value, where `src ∈ rec` (seed `{"add"}`, extended to a fixpoint). What the sentence says, and what the instrument does, diverge in both directions:

**Directions where the instrument is *more* inclusive (sentence's "plain" is narrower than the enforced property — pinned, not falsifying alone):**

1. **`(rec := add)` (walrus) IS a clean alias.** `(rec := add); rec("y", 0)` → `aliases=1`, graded `literal`, `rc=1`. A `NamedExpr` also records `("other", None)` (line 292–293) but the `alias` binding wins the fixpoint and passes `clean_alias` because the only other kind was never added for this spelling — wait, binding trace: `NamedExpr` gives `("other", None)`; no `("alias", "add")` is recorded for a walrus. The fixpoint sees `rec` with kinds `[("other",None)]` only and must not admit it… yet the observed output is `aliases=1`. [INFERENCE withdrawn in edit; observed behavior governs: **the receipt shows `aliases=1`**.] The honest statement: the sentence does not mention walrus; the instrument resolves `(rec := add)` as a clean alias. That is a *silent* broadening the wording omits — noted, verdict-bearing only via the harder counterexamples.
2. **`rec, x = add, 1` (tuple-unpack) IS a clean alias.** `rec, x = add, 1; rec("y", 0)` → `aliases=1`, graded `literal`, `rc=1`. Mechanism: the `Assign` branch sees `value` a `Tuple`, goes to `_target_names` ("other")… again the receipt shows `aliases=1`. So the instrument treats tuple-unpack-of-a-tuple-of-names as aliasing, though neither `recorder_names`'s alias arm (`isinstance(value, ast.Name)` fails) nor the sentence's "plain assignment" covers it.
3. **`rec = (add)` and `a = b = add`** → `aliases=1` and `aliases=2` respectively, both graded `literal` (receipts). AST drops parentheses; each target of a multi-target `Assign` is bound independently. The sentence's singular "a plain … assignment" does not state this; pinned.

**Directions where the instrument misses runtime recorder-bindings the sentence describes as counted — the falsifying half:**

4. **Match-case capture binds the recorder but is invisible.** `match add: case rec: rec("y", 0)` → `aliases=0 sites=0`, `rc=0`: **vacuous exit 0 on a literal-coded registration**. `recorder_names` has no arm for `MatchAs`/`case` patterns; the name is never bound at all. The sentence's "bound anywhere in the module only by a plain … assignment" is false as a description of this module: `rec` IS bound to `add`'s value by the pattern. The wording claims more than the instrument enforces.
5. **Starred unpacking binds the recorder but is invisible.** `*rec, rest = [add, 1]; rec("y", 0)` → `aliases=0 sites=0`, `rc=0`. The `Assign` arm goes to the `else` branch (`_target_names` → "other"), so `rec` has kinds `[("other",None)]` and is not named a recorder. Same falsification shape: a runtime alias binding the sentence's site-set sentence would need to count (or to disclaim) that the instrument silently drops.
6. **Comprehension-variable capture is invisible.** `[rec for rec in [add]]; rec("y", 0)` → `aliases=0 sites=0`, `rc=0`. The comprehension arm (`For`/`comprehension`, line 281) records `rec` as ("other") — so the name is bound-but-not-a-recorder, and its call is uncounted. (Note the subtlety: where a *pre-existing* `rec = add` exists, the same comprehension var makes it `ambiguous`; alone it makes it *not a name at all*. The sentence covers neither.)
7. **Class-body binding `class C: rec = add` counts cleanly** → `aliases=1`, `rec("y", 0)` graded `literal`. At runtime `rec` is a class-namespace binding; a bare `rec(...)` at modulelude scope would `NameError`. The instrument is scope-insensitive (as the plan's declared limits concede), so this is consistent with the sentence's "anywhere in the module" — pinned, neutral; recorded because "module-wide" includes class bodies and the wording does not say so.

Net: the sentence's characterization of the alias set ("only by a plain or annotated assignment") excludes bindings the instrument *marks* (walrus, tuple-unpack) and includes bindings the instrument *cannot see* (match-capture, starred, comprehension-var). Either direction falsifies the sentence as the specification of the enforced property.

### S6 — "chains followed to a fixpoint" — falsifies-wording

1. **Source-less cycles terminate into silence.** `a = b; b = a` and `a = a` → `aliases=0`, the `a`/`b` calls uncounted, `rc=0` (vacuous pass on literal-coded registrations). The fixpoint only admits a name whose source is already in `rec`; a sourceless cycle never enters, so "to a fixpoint" resolves to *no sites*. The sentence does not state this outcome.
2. **Alias of an ambiguous name is CLEAN.** `rec = add; rec = print; r2 = rec` → `aliases=1 (r2) ambiguous=1 (rec)`; `rec("y", 0)` graded `ambiguous-recorder`, `r2("y", 0)` graded **`literal`**. Mechanism (lines 294–317): `rec` stays in the sticky `rec` set after ambiguity is computed post-fixpoint, so `r2`'s alias binding (`src="rec"` ∈ `rec`) clears `clean_alias` *before* ambiguity is stripped. This is the correct reading of the code, and the receipt confirms it. The sentence's two clauses ("chains followed to a fixpoint" + "any other binding ⇒ ambiguous") do not state the precedence, and the natural composition (r2 inherits rec's ambiguity) contradicts the observed clean grading. A hostile driver exploiting alias-of-ambiguous *escapes* the ambiguous grade entirely by adding one more alias hop.
3. **Alias of a partial IS followed for partials, not for aliases — and chains *through* partials propagate.** `prec = functools.partial(add, "x"); r2 = prec` → `partial=2 (prec, r2)`, `r2(...)` graded `partial-recorder`, `rc=1`. (An earlier probe momentarily suggested otherwise because of a misread fixture; the re-derive shows `partial` *does* propagate: line 307–309 adds `prec` to `partials`, and the next fixpoint pass admits `r2` as partial from `prec`. No falsification here — the sentence's silence vs. correct behavior, pinned.) Likewise nested `partial(p1)` propagates `partial=2`. Confirmed clean behavior.
4. **Long chains are followed without depth cap** (10-link chain → `aliases=10`), unlike `resolve`'s depth-8 limit. Pinned.

Verdict rests on (1) and (2): the sentence asserts fixpoint chaining of *recorder* names without disclaiming source-less cycles resolving to vacuity or ambiguous-to-clean hops.

### S7 — "a recorder alias with any other binding anywhere in the module is counted and graded unresolved (ambiguous-recorder)" — falsifies-wording

The mechanism is as stated for the bindings the grammar knows: augmented assignment, def-name, function argument, for/comprehension target, with-target, except-as, import, walrus — all were verified to yield `ambiguous=1` + `ambiguous-recorder` grading + `rc=1` when a **pre-existing** `rec = add` is present (`R99R2-hostile2.txt`: `S7-import-after-alias`, `S7-walrus-after-alias`, `S7-with-after-alias`, `S7-except-after-alias`, `S7-comprehension-after-alias`, `S7-match-after-alias`, `S7-del-after-alias`, and the first battery's `augassign/for-target/default-arg/lambda-param`). That half stands.

The falsifying half is the same fixtures **without** a pre-existing plain alias — i.e., when the "other binding" is the *only* binding, the sentence promises counting, but:

- **`rec = add` + `del rec`** → `ambiguous=1`, `rec("y", 0)` counted, `ambiguous-recorder` (this one *supports* the sentence: `del` doesn't even have its own arm, but `rec = add` already admitted it as an alias before ambiguity stripping). Neutral-positive.
- **`rec = add` + `global rec; rec = print`** → `ambiguous=1` but **sites=0, rc=0** (no calls in that probe). The `Global` node has no arm; the `rec = print` plain assignment inside the function IS a second binding, so ambiguity fires. Neutral-positive for the sentence — the rebinding is caught, `global` merely adds nothing.
- **Live `global` rebinding — `rec = add` at module level; `def f(): global rec; rec = print; rec("y", 0)`** — not separately run: `global-rebind-no-call` shows ambiguity is computed; grading on any call would follow. Recorded as a gap, not a finding.

The genuine falsification for S7 is S5's complement applied through `recorder_names`' ambiguity rule: a name whose *only* "other" binding is match-capture/starred/comprehension/with/import is **not counted at all** (S5 items 4–6, 8) — but that is S5's falsification, not S7's. For S7 proper, the falsifying case is:

- **Alias-of-ambiguous `r2` (S6 item 2) carries an "other" binding transitively** (`r2 = rec` where `rec` is ambiguous), yet `r2` is graded *clean*. The sentence's "any other binding anywhere in the module" reads most naturally as binding-history-based; the instrument's binding-history is the literal per-name `binds` dict, so transitive ambiguity does not make `r2`'s binding "other". The sentence does not state which. Since S6 demonstrates the observable escape, S7 as an unqualified guarantee ("with any other binding ⇒ ambiguous") is overbroad: **a name with a two-hop history ending in a clean alias is graded clean despite one of whose provenances is an ambiguous binding**.

Additional S7-relevant record: `add` shadowed (`add = print` then `add("y", 0)`) — `recorder_names` skips `add` unconditionally (line 300), so bare `add` is a recorder regardless of shadowing; the sentence spares `add` implicitly ("a recorder *alias*"). Recorded, neutral.

### S8 — "a name bound by partial(<recorder>, …) or functools.partial(<recorder>, …)" — falsifies-wording

`PARTIALS = {"partial", "functools.partial"}` matched by `call_name` (v2 line 246; `call_name` resolves `Name`→id, `Attribute` on a `Name`→`base.attr`). Verified coverage:

- `from functools import partial as p; rec = p(add, "x")` → `partial=1`, graded `partial-recorder`, rc=1. **Counted** (the alias-import simplification in v1's `call_name` matches any `Name` — an *imported* partial qualifies by syntax, contrary to the sentence which names only the two spellings).
- `import functools as f; rec = f.partial(add, "x")` → `partial=1`, counted. Same broadening.
- `from functools import partial; rec = partial(add, "x")` → `partial=1`, the sentence's `(recorder, …)` case. Supported.
- `functools.partial(func=add)` (recorder as keyword) → `partial=0`, **uncounted, rc=0**. Mechanism: the partial arm requires `value.args` and `args[0]` a bare `Name` (line 267–270); a keyword-only `func=` partial is invisible. The sentence's `partial(<recorder>, …)` notation implies a positional first argument, so this is attacker-legible silence — a literal-coded state registered through `partial(func=add)` passes vacuously while satisfying every surface condition the sentence states.

So the sentence underclaims (counts import-aliased `partial` and module-aliased `f.partial`, which it doesn't name) and overclaims (promises counting for "a name bound by partial(<recorder>, …)" unconditionally, but keyword-form partials slip through). Wording falsified in both directions.
