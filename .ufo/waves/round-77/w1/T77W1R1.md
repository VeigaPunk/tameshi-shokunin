## Findings by severity

### Low — separability prose overstates counter input independence

The frozen plan's final no-harm bullet says “Neither claim's counter reads the
other's files.” This is literally false in the C2-to-C1 direction. At base,
`.ufo/evidence/round-21/coldread/ledger.json:402640` (JSON path
`entries[926].inputs["tools/wave-reconcile.py"]`) pins C1's tool to
`ca05ec154454d57902313dcddd3c1e6980628bb352f57344afdcd820db5767e3`.
The canonical `.ufo/evidence/round-18/measure.py:344-349` reads the pinned blob
and produces `input-drift` on a hash mismatch. The portable counter names that
canonical implementation at `tools/coldread-precheck-portable.py:53`.
Thus C1 can change C2's pre-rekey input validity; strict bidirectional
read-independence is not established. Suggested record wording: independent
attainability after rekey, not disjoint counter inputs.

This does NOT falsify the plan's narrower causal-separability construction:
C1 never reads the ledger, and C2 can rekey the actual uncredited set with or
without C1. The plan itself prices C1 edits into its coldread forecast. I did
not run C2 to infer a particular coverage delta.

No high/medium implementation defect found in the frozen candidate.
