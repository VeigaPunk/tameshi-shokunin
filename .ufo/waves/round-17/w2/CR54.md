## Findings

**1. wrong-expectation — assemble row's exit-1 clause is false.**
The row states `1 a bucket uncovered or a report rejected`. In normal mode a
report whose `skill_sha256` matches no supplied skill is printed as `REJECTED`
and the run continues; with every bucket covered it exits **0** (receipt 12:
`coverage: 3/3 sections covered`, `REJECTED … SeatBad`, internal
`reports_rejected=1`, child exit 0). A heading-mismatched report exits **2**
(receipt 14), not 1. The tool's own docstring agrees with its code and not with
the row: “Exits 1 when any section lacks an entry.” Exit 1 is reachable only
through `_meta.missing` (receipt 13). The false clause predates wave 1
(present at `c699c8c`, retained by `2a22ade`). Severity is low for running the
gate, but a caller wiring on this map will read exit 0 as “no report rejected”
and mis-handle a rejected seat.

**2. minor gap — command column vs exit column (assemble row).**
The only listed invocation is `--selftest`, but the exit map describes normal
assembly mode. `--selftest` exits 0 when its internal checks pass (receipt 03)
and reaches 1 only via a failed self-check (source: `_selftest` return), never
for an uncovered bucket or an invalid override. The map is asserted in-process
but not reproducible from the documented command.

**3. minor gap — measure row's `--rev` defaults to the live lane.**
`measure.py` hardcodes `DEFAULT_REPO = '/home/vgpnk/Projects/shokunin/tameshi-shokunin'`
(line 53). The documented command run from a clone therefore reads the live
tree: receipt 05 shows `live_lane_reads=17` (live `.git/objects`, `packed-refs`,
`multi-pack-index`). Passing the undocumented `--repo DIR` pins the clone and
gives the same measurement with `live_lane_reads=0` (receipt 16). Under this
wave's clone contract, receipt 05 is not provenance; the row should name
`--repo`, or the default should anchor on the script/cwd.
