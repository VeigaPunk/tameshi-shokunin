## Findings

### 1. [WRONG EXPECTATION] POLICY's declared shape `exit 2` is false for the row's own "hashing a no-hash path" instance

The table cell (SKILL.md:505) assigns the POLICY arm the shape *"exit 2, structural, before exec"* and lists *"hashing a no-hash path"* among the acts it covers. `drift-pins.sh:142-148` prints `POLICY … baseline sha must be '-' (secret-bearing path is never hashed)`, does **not** hash, then `continue`s; the summary at `drift-pins.sh:252-258` prints `DRIFT_PINS: DRIFT (…)` and returns **1**. The gate's own header (`drift-pins.sh:19`) says `Exit 0 clean · 1 any drift · 2 usage/setup error (nothing written)`.

Receipt 5 isolates the branch (symbols clean: `symbols_ok=1 symbols_bad=0`) and gets exit 1 with the POLICY line. The refusal is structural and before the effect, as the cell says — but the exit code is 1, not 2. A reader who follows the page's preamble ("Exit 2 is not one class … read the arm") and the Shape column will misread a `POLICY` + `DRIFT_PINS: DRIFT` run as a taxonomy violation rather than a designed drift exit. Blast radius is small (the token still names the arm, as Rule 2 asks), but this cell is self-inconsistent: its Fires-when example does not have its stated Shape.

Suggested correction: `exit 2` → `exit 2, or exit 1 when the refusal is reported as a drift row (drift-pins)`, or move the drift-pins example out of this row.

### 2. [MINOR] Rule 3's BREADTH-EXCEEDS example names the wrong counter and conflates untriggered with unfireable

SKILL.md:519-522 says *"`BREADTH-EXCEEDS` never fires while live child counts sit far below their pins"*. In code, the arm is `if (( live_declared > ${b_declared[$i]} ))` (`scope-gate.sh:593-596`), where `live_declared` counts children that match a census row (`:573-582`) and `b_declared` is the pinned declared count. Live *children* are the counter for the sibling arm `BREADTH-CHILDREN-DRIFT` (`:588-591`). So the child counts do not gate `BREADTH-EXCEEDS`; the declared counts do.

The live run (receipt 8) shows `exceeds=0` with declared counts 1/0/1 against pins 4/2/1 (all ≤), while the child counts 3/47/2 are separately below pins 20/105/4. The observation is true, but the stated trigger is not the one that would change it: appending one declared census row fires the arm (`scope-gate.sh:800-802`, falsify case expecting exit 1; `:779` does the same by editing the pin) with live child counts unchanged. As a live-data statement "it has not fired" is right; as the illustration of "an arm that cannot fire on this host is an unknown" it names the wrong counter and cannot separate "untriggered by the committed census" from "unfireable".
