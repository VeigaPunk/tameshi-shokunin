## Findings

### F1 (minor) — pin probe's exit 0 cannot distinguish "clean" from "all legs unavailable" in a symlinked fleet

The row names `--root /home/vgpnk/Projects/shokunin` and gives only "as the round-13 row" for exits.
Executed through the clone+symlink fleet layout this wave mandates, the probe refuses every symlinked
sibling repo (`reason: repo_symlink`) and reports `counts.unavailable: 6` while **still exiting 0**
(receipt 8). The literal live-root invocation returns `unavailable: 0` (receipt 18) — so the row's literal
command is right, but a reader in the sandbox sees green on zero observations. The row would be gradeable
if it carried the success needle the registry row uses (`"unavailable": 0`) or stated that a symlinked
fleet is unprobeable. Evidence: `.ufo/evidence/round-17/coldread/traces/CR56/8.json`, `18.json`.

### F2 (minor, harness interaction) — `registry-check --rev` false-reds under the cold-read trace wrapper

One active registry row, `trace-inputs-round17-selftest`, is itself a tracer: its command is
`.ufo/evidence/round-17/coldread/trace-inputs.py --selftest`. Under the interface's required wrapper the
inner `strace` cannot attach beneath the outer `strace -f`; every positive-trace case fails
(`SELFTEST: 4/27`, only the two expected-error cases and two file-hygiene cases pass), the row reports
`got=1`, and the gate exits 1 at the landing rev (receipts 4, 6, 7). Unwrapped, the same row holds
`27/27` and the full gate reports `held=28/28 superseded=1`, exit 0. The page's exit semantics are not
wrong (a row genuinely differs *in that environment*, so 1 is correct), but a cold read that follows both
the page and the wrapper gets a false red. The page could state that this gate must not be nested inside
an outer tracer, or the registry row could use a strace-free assertion. Evidence: receipts `4.json`,
`6.json`, `7.json`; unwrapped control above.
