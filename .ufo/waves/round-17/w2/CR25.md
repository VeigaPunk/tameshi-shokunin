## Calibration observations (verification-fixture craft)

- **Section-sha normalization is load-bearing.** A verifier hashing the raw
  `sed` range gets `6aab26e9…`, not `f22547b4…`. The declared digest is the
  harness sectionizer's (trailing whitespace-only lines stripped, `\n`
  join). Any independent checker must use the same normalization or it will
  report a false drift.
- **The mechanical command detector misses this bucket's only command.**
  `.ufo/evidence/round-17/coldread/bucket-commands.json` records
  `executes_commands: false`, `executes_commands_incl_numbered_steps: true`
  (`mechanical_vs_ledger: disagree`). Cause: the only command is a backtick
  span broken across lines 1002-1003 (`bash tools/mutate-and-run.sh` /
  `--selftest`), so a per-line inline-command regex cannot see it. The
  command is real, and it ran (receipt 10). The numbered-steps secondary flag
  catches it; the per-line primary rule undercounts the bucket.
- **Trace-receipt binding forces the replay to run inside the read-rev
  root.** `assemble.py` A4 rejects a receipt whose `rev != read_rev`. My
  first pass executed the pinned tool in a clone checked out at `9f1d3c3`
  (receipts 02-05, now superseded and unreferenced); those receipts carry
  `rev=9f1d3c3…` and cannot bind to a report read at `eb7838b`. The bound
  form used here: materialize the pinned bytes as untracked copies inside the
  `eb7838b` clone (`tools/mutate-cf41efaa.sh`, and the two one-line probe
  variants) and run them there, so receipts 06-10 carry
  `rev=eb7838b…`. Byte identity stays checkable twice: the tool's own
  `REGRESSION_TOOL … sha256=cf41efaa…` line and the receipt's `untracked`
  map (`cf41efaa…`, `0b027a3d…`, `cbd5da60…`).
- **The negative probes are reproducible from the pinned blob** by the two
  one-line edits named above; nothing else differs. Their file shas:
  doctored `0b027a3dc8f5768f96195fa2e4cb17189d03acbf2d9c0f56959de2f2d62d0b74`,
  pin-mismatch `cbd5da6094f1ce4654a3a3051192b3f3e6a4da1db4ba0b35e99063bdc0dd9445`.
