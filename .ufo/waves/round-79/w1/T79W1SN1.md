### MUST-FIX: malformed duplicate headers escape C1 setup refusal

On the originally frozen design bytes (initial tools/design comparison: all five files identical; design SHA256SUMS: all five OK), a valid receipt plus `# tool: tools/path with spaces.py` passes as bound, exit 0. The frozen contract requires duplicate/malformed header setup refusal, exit 2. Impact: ambiguous/malformed provenance accepted. This is not shell injection.

### MUST-FIX: selfstate fixture builders lacked root assertions

Original design/selfstate-freshness.py arm11 lines 599–603, arm13 667–671, and new arm14 756–760 initialize/add/commit without checking `rev-parse --show-toplevel`. Receipt-bind and wave fixture builders do check. Impact: violates the explicit fixture-root rule; a misdirected Git environment can target a repository other than the intended scratch fixture. Smallest remediation: assert realpath(top)==realpath(fixture) before add/commit in each builder. L1 acknowledged and is remediating; this report does not certify the changed bytes. I guarded selftest Git mutations externally (driver below), verifying 4/8/6 add/commit operations respectively.

### MUST-FIX containment caveat (static, not exploited): inherited Git environment

Wave and selfstate Git helpers inherit GIT_DIR/GIT_WORK_TREE/GIT_INDEX_FILE and Git configuration; receipt-bind removes GIT_* and disables global/system configuration. Thus even an assertion after init cannot prevent a redirected `git init` from writing elsewhere first. No GIT_* variables were present in this seat's environment (`GIT_ENV_NAMES=[]`). No offensive redirect was executed. Smallest remediation: apply receipt-bind's isolated Git environment to wave/selfstate fixture Git calls before init as well as later mutations. Existing trusted local hooks/configuration are also an execution boundary; these tools are not sandboxes.

### NIT / documented input semantics

* Absolute tool and any `..` segment: setup exit 2, no row output.
* Directory tool path: exit 1, `state=unbound detail=tool-absent` (tree is not a blob).
* Literal newline in the supplied tool value becomes a line-delimited header plus body: first line `tools/toy.py` binds, remainder `../outside.py` is ignored body. No newline reaches Git argv. There is no encoded multiline-path support; reject malformed recognized headers as above rather than asserting this body line is a filesystem escape.
* Symlinked --root is followed and reads the selected target; no write mechanism in receipt sweep. Root is an explicitly selected population, not a sandbox. File symlinks are also followed by isfile/open; if strict population containment is desired, reject them or require resolved targets beneath resolved root. Not a frozen requirement to reject explicit root symlinks.
* Colon and leading-dash paths are safe here: Git gets one `<resolved-hex-revision>:<path>` argument through a list argv, never a shell; colon remains in the tree path, and leading `-` is after the revision separator, never an option. Both direct cat-file probes return the intended blob, exit 0.

## Exact guarded driver

```python
import importlib.util, os, pathlib, subprocess, sys
root=pathlib.Path(os.environ['TMPDIR']).resolve()
original=subprocess.run
checks=0
def guarded(args,*a,**kw):
    global checks
    if isinstance(args,(list,tuple)) and args and args[0]=='git' and '-C' in args and any(x in args for x in ('add','commit')):
        repo=pathlib.Path(args[args.index('-C')+1]).resolve()
        assert repo.is_relative_to(root), (repo,root)
        p=original(['git','-C',str(repo),'rev-parse','--show-toplevel'],capture_output=True,text=True,env=kw.get('env'))
        assert p.returncode==0 and pathlib.Path(p.stdout.strip()).resolve()==repo, p.stdout
        checks+=1
    return original(args,*a,**kw)
subprocess.run=guarded
spec=importlib.util.spec_from_file_location('seat_tool',sys.argv[1])
m=importlib.util.module_from_spec(spec); spec.loader.exec_module(m)
rc=m.main(['--selftest'])
print('SEAT_GUARD: verified_fixture_mutations='+str(checks))
print('LEFTOVER_ENTRIES: '+repr(sorted(x.name for x in root.iterdir())))
sys.exit(rc)
```
