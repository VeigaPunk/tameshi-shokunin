## Findings

### 1. Medium correctness / low security — trailing LF passes the new id alphabet

**Demonstrated.** `selfstate-freshness.py:122,277-280` uses `^[A-Za-z0-9._-]{1,64}$` with `.match()`. Python `$` permits a position before one final LF. A committed manifest containing id `"trailing\n"`, bound to its own revision, was accepted with exit **0** and stdout:

```text
SELFSTATE_ROW trailing
 expect=match measured=match ok span_figure=TOY: 1/1 pass measured_figure=TOY: 1/1 pass instrument_exit=0
SELFSTATE: rows=1 match=1 stale=0 unexpected=0
```

**Exploit path:** manifest author supplies an otherwise valid row whose id ends in LF. `emit()` at lines 431-443 writes that id raw, splitting the promised row line. This contradicts C1's full alphabet/line-safety predicate and the kill-rule wording about a newline id reaching a verdict. **Bound:** this particular input cannot place attacker-controlled content after the LF or forge a green summary; the real measurement remained correct. No broader verdict-forgery claim is made.

**Smallest remediation:** use `ROW_ID_RE.fullmatch(rid)` (or strict `\Z` anchoring), with trailing-LF and 64-characters-plus-LF regression cases.

### 2. Medium conditional — receipt type checks and content reads are non-atomic

**[INFERENCE], not a won race.** `receipt-bytes-bind.py:306,314` performs `os.lstat(path)` then `parse_receipt(path)`, which opens the pathname at line 169. `receipt-revision-gate.py:111,120` similarly calls `p.lstat()` then `p.read_bytes()`.

**Exploit path:** a process able to rename entries in the receipt directory replaces a regular receipt with a symlink between those calls. The subsequent open follows the link and can consume a valid outside target's bytes despite the initial regular-file check. Replacing it with a FIFO could instead block the read. Ancestor directory replacement is another instance of the same resolution gap. No live attack loop or fault-injection harness was run.

**Impact:** static leaf symlinks are refused, but the unconditional statement “never reads its target's bytes” is not established against concurrent local writers. This is a conditional integrity/availability limit, not evidence that the committed fixture refusal fails.

**Smallest remediation:** open once using no-follow/nonblocking flags, validate the opened descriptor with `fstat`, and parse bytes from that descriptor. If ancestor symlinks are excluded too, use descriptor-relative traversal or a beneath/no-symlinks resolution policy; leaf-only `O_NOFOLLOW` does not secure ancestors.

### 3. Medium scoped population limit — directory symlinks are not leaf symlinks

**Demonstrated, three distinct cases:**

1. Receipt binder root containing `visible.receipt` plus `linked-dir -> external/` (which contains `hidden.receipt`) returned exit **0**, `RECEIPT_BIND: receipts=1 bound=1 corrected=0 design=0 unbound=0`. No row/refusal represents `linked-dir`. This confirms frozen C3 limit (b), not a newly closed class.
2. Setting `--root` itself to a symlink to `external/` returned exit **0**, binding `root-link/hidden.receipt`. `os.path.isdir(root)` follows the root link, and `os.walk` traverses the supplied root even with its default `followlinks=False`.
3. Passing `directory-probe/linked-dir/gate.receipt:positive` to the gate returned exit **0**, `GATE: receipts=1 ok=1 refused=0 codes=none verdict=PASS`. The terminal component is regular; `lstat()` does not forbid symlink ancestors.

**Exploit path/impact:** a caller or directory writer can hide receipts in linked child directories from the sweep, or place bound/passing receipts outside the apparent path tree via a linked root/ancestor. No escalation beyond existing file access was demonstrated. These are population/containment limits, not failure of leaf-symlink rejection.

**Smallest remediation:** explicitly define whether symlink roots/ancestors are allowed; if not, refuse linked directory entries/root and resolve beneath an opened directory descriptor. Do not simply enable `followlinks=True` (would expand scope and introduce loops).

### 4. Low compatibility / medium semantic ambiguity — manifest path has two coordinate systems

**Demonstrated.** `GitReader.tree_mode()` matches the literal repo-root tree name, whereas `open(a.manifest)` at line 1516 is relative to process cwd, not `--repo`.

A fixture repo's on-disk `manifest.json` was replaced with `{"rows": []}`. From its parent directory, with a separate parent `manifest.json` equal to the committed bytes, `--repo <fixture> --manifest manifest.json --manifest-rev <fixture HEAD>` still returned exit **0**, rows=1. Thus the caller-selected cwd manifest was bound; the repo worktree manifest was not checked. **Bound:** the measured bytes still equal the named object; this is not an object-byte binding bypass. It limits interpretations that `--repo` selects the manifest's worktree root.

Direct calls to `tree_mode(rev,path)` returned `100644` for `manifest.json`, but `None` for `./manifest.json`, its absolute path, `../fixture/manifest.json`, and `*.json`. Literal name comparison prevents wildcard-selected other entries from being accepted, but ordinary equivalent path spellings are not normalized.

**Smallest remediation:** define a single canonical repo-relative tree path and a corresponding worktree read path; normalize safe paths once, document cwd semantics if intentionally retained, and refuse escapes before reading.
