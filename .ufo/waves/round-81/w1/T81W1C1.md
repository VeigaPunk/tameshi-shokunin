## Strongest counterexample: D2 can close without its claimed erratum

**Impacted axes:** calibration and sizing/semantic correspondence. **Fixable defect**, not merely the disclosed C3 tradeoff.

Frozen population describes D2 as: “the SCORECARD erratum span must carry `24/24` and `17/17`, and both tokens must be byte substrings of [the receipt].” But `tools/defect-bind.py:158–172` checks only:

1. the literal span marker occurs anywhere in committed SCORECARD bytes;
2. both tokens occur in committed receipt bytes.

It never checks that the erratum itself contains those tokens. In a scratch clone of `1415fb65`, I replaced the entire `## Round-81 erratum (D2)` section body with nothing, retaining only its heading, and committed that synthetic candidate. Instrument and manifest were unchanged. The original six-row command still emitted:

```text
DEFECT_BIND_ROW D2-before-tokens kind=receipt-tokens expect=closed state=closed detail=tokens-in-receipt
DEFECT_BIND: rows=6 closed=6 open=0 unexpected=0
exit 0
```

Thus even the full exact after-state is reachable while skipping D2's declared correction. This is not a manifest-tampering attack: it uses the frozen original manifest and instrument over committed candidate bytes. The real landing erratum does contain the tokens; this finding concerns what the gate proves, not an assertion that those real bytes are missing.

**Smallest safe correction:** require each token inside the bounded erratum section as well as the receipt, and add a negative arm with marker-only doc plus token-bearing receipt. Because C1 freezes its instrument after declaration, L1 must explicitly disposition/redeclare an instrument correction, not silently present corrected bytes as the frozen measurement. Routed directly to TameshiR81.

### One-command / committed-byte boundary

C1 offers one counting command. C2 offers one pin-audit command but also requires a separate standing sweep. C3 expressly offers **two** battery commands, with control/restore and selftest conjuncts. Under a strict “each after-state one command” rule, C3 is not a single-command claim as written; C2's entire kill-rule conjunction also exceeds its headline command. Smallest operational correction is one explicit entry command aggregating all required results, or an explicit coordinator disposition of the conjunction sizing—not silent narrowing to one headline.

All three interfaces execute/read working-tree instrument or manifest/spec paths. C1 and C2 use git object reads for compared artifacts, but that alone does not establish committed provenance of the running script or population. For C3 I materialized targets/specs from named committed revisions into scratch; this is the safe committed-byte execution boundary. A clean, pinned clone/materialization check is a prerequisite, not something proven by the printed counters.
