## 3. Rule probes (exact command + output)

Fixture: `$S/fx`, three commits. `rev0` = artifacts absent/empty; `rev1` = artifacts
present; `rev2` = forged symlink entry. All commands are
`python3 -I -X utf8 "$S/lane/tools/defect-bind.py" --repo "$S/fx" --manifest "$S/out/<name>.json"`.

### 3.1 `tree-bytes` with `min_bytes: 0`

Row `{"id":"p1a","kind":"tree-bytes","rev":"HEAD","paths":["empty.txt"],"min_bytes":0}`:

```
DEFECT_BIND_ROW p1a kind=tree-bytes expect=closed state=closed detail=min-bytes-met
DEFECT_BIND: rows=1 closed=1 open=0 unexpected=0
exit=0
```

A 0-byte committed blob satisfies `min_bytes: 0` (`len >= min`). The same row over a
missing path is a setup refusal, not a verdict:

```
$ ... paths:["missing.txt"], min_bytes:0
defect-bind: blob-unresolvable:<rev>:missing.txt
exit=2
```

Ordering observation: a valid row before an unresolvable `tree-bytes` row prints its
row line before the exit-2 refusal:

```
DEFECT_BIND_ROW ok-first kind=tree-paths expect=closed state=closed detail=paths-present
defect-bind: blob-unresolvable:<rev>:missing.txt
exit=2
```

The docstring's "setup exit 2 *before* any row effect" is inaccurate for this input
class: the summary line is the verdict, the row prefix is not atomic. (The
uncommitted worktree docstring already amends this; committed bytes do not.)

### 3.2 `receipt-tokens` span that occurs only after CRLF normalisation

CRLF blob (`doc-crlf.md`, blob retains `\r\n`; `od -c` shows `\r \n`). Span is the
LF-normalised form, then the raw CRLF form:

```
$ ... doc:"doc-crlf.md", span:"BETA 17/17.\n", receipt:"receipt.txt", tokens:["24/24"]
DEFECT_BIND_ROW p2a kind=receipt-tokens expect=closed state=open detail=span-absent:doc-crlf.md
exit=1

$ ... span:"BETA 17/17.\r\n"
DEFECT_BIND_ROW p2b kind=receipt-tokens expect=closed state=closed detail=tokens-in-receipt
exit=0
```

The instrument reads raw blob bytes: no CRLF normalisation. A span that exists only
after normalisation does **not** count (correct for a byte-binding gate).

### 3.3 Token as a proper substring of a longer token

Receipt contains `EXTENDED: live 124/24`. Token `124/2` exists only inside `124/24`:

```
$ ... span:"The before row reads", receipt:"receipt.txt", tokens:["124/2"]
DEFECT_BIND_ROW p3b kind=receipt-tokens expect=closed state=closed detail=tokens-in-receipt
exit=0
```

It counts, and that **is** the declared semantics: the docstring says "every token
must be a byte substring of the `receipt` blob". Consequence: numeric tokens have no
boundary check — `24/24` would be satisfied by `124/24` if the exact figure were
absent. The frozen D2 receipt carries the exact figures today, so the after-state is
not affected, but the semantics cannot distinguish them.

### 3.7 `rev` = short sha of a tree object (not a commit)

`TREE_SHORT=1d8bdea` (`git rev-parse --short HEAD^{tree}`):

The `^{commit}` peel in `resolve_rev` rejects tree ids: setup refusal, not a row

### 3.8 `tree-paths` path naming a directory

Fixture has `dir/nested.txt`; `dir` is a tree:

## 4. Cheats against the counter

| cheat | command row | result | passes? |
|---|---|---|---|
| `tree-bytes` over a git symlink entry | `paths:["link.txt"]` (10-byte target), `min_bytes:1` | `state=closed detail=min-bytes-met`, exit 0 | **yes** (measures the target string, not file content) |
| symlink entry inflated to fake a 1 MB receipt | forged mode-120000 entry `fake-link` with a 2 MiB target string (`git update-index --cacheinfo 120000,<sha>,fake-link`), `min_bytes:1000000` | `state=closed detail=min-bytes-met`, exit 0 | **yes** — the exact D1b cheat: a dangling symlink target string satisfies the size gate with no receipt bytes |
| `receipt-tokens` with an empty `receipt` file | `receipt:"receipt-empty.txt"`, `tokens:["24/24"]` | `state=open detail=token-absent:24/24`, exit 1 | no (empty tokens are refused at setup, so no vacuous pass) |
| row id containing a space | `id:"row with space"` | accepted, prints `DEFECT_BIND_ROW row with space kind=…`, exit 0 | **yes** (id charset unchecked; line parsers cannot tokenise the id) |
| two ids differing only by case | `ids:["Dup","dup"]` | both rows measured, `rows=2`, exit 0 | **yes** (duplicate check is case-sensitive) |

Additional counter-integrity probes (same fixture unless noted):

- **Manifest relaxation is invisible to the counter.** All six frozen rows with
  `expect` flipped to `open`, run at the base: `rows=6 closed=0 open=6
  unexpected=0`, exit 0. A one-row narrowed population with `expect:"open"`:
  `rows=1 … unexpected=0`, exit 0. The kill rule is textual; the instrument cannot
  self-authenticate its manifest (no manifest hash pinning).
- **Self-receipt.** `doc == receipt` (`doc.md`) with `tokens:["24/24"]` closes:
  `state=closed detail=tokens-in-receipt`, exit 0. No independence check between the
  record and its receipt.
- **Minimal span.** `span:" "` (single space) closes: `state=closed`, exit 0. The
  span gate is satisfiable by any document containing a space.
- **`sources-cell` empty used-by fallback.** Fixture row `| S292 | … | 180d | |`
  (empty used-by) with token `180d` (the recheck cell) closes: `state=closed
  detail=cell-carries`, exit 0. `_sources_cell` pops trailing empty cells and takes
  the last non-empty cell, so an empty used-by silently measures the previous cell.
- **`id_ref` overrides the validated `source_id`.** Row with `source_id:"S289"`
  (validated) and `id_ref:"S290"` (measured) behaves as S290: token
  `corpus/lessons/round-81.md` is `cell-absent`, exit 1. `source_id:"S999"`
  (format-valid, unheld) + `id_ref:"S289"` closes, exit 0. Validation and
  measurement read different fields.
- **Output injection.** A newline in the row id emits a forged summary-looking line
  into stdout: `DEFECT_BIND_ROW a` / `DEFECT_BIND: rows=9 closed=9 open=0
  unexpected=0 kind=…`, exit 0. A newline in a missing path is space→underscore
  mangled (`DEFECT_BIND:_rows=6_…`) but still breaks the row line. Exit codes remain
  authoritative; line-parsing consumers are not safe.
- **`#`-starting non-heading line ends a section.** `#not-a-heading` inside
  `## Search log` terminates the section (level 1 ≤ 2), so a token after it is
  `section-token-absent` (exit 1) while a token before it counts. False-open
  direction only, but a doc with `#`-starting lines can be mis-measured.
- **Trailing slash path** `dir/` is refused `invalid-path:paths:escape`, exit 2.
- **D2 row design gap (the important one).** A fixture doc whose span says
  "The before row reads 23/23 and 14/14" while the receipt carries `24/24` and
  `17/17` closes the row: `state=closed detail=tokens-in-receipt`, exit 0. The D2 row
  only checks (a) the span heading exists in the doc and (b) the tokens exist in the
  receipt; it does **not** bind the doc's claimed figures to the receipt's. At the
  actual after bytes the erratum body states `24/24` (verified line 5130), so the
  after-state is substantively correct — but the instrument would not have caught the
  round-80 D2 defect class if the erratum had stated the wrong figures.

## 5. Instrument change after the declaration (kill-rule wording)

The plan's kill rule reads "with the instrument and the manifest unchanged after this
declaration". Measured:

- Manifest: **unchanged** — sha256 `6dbc4d1a…` at both `1b115ba` and `1415fb65`.
- Instrument: **changed once**, commit `e27f28e8` — `sweep(repo, manifest_path,
  rev=None, …)` → `sweep(repo, manifest_path, …)` plus a docstring paragraph. The
  removed `rev` parameter was never referenced in the body (each row resolves its own
  `rev`), so the change is behaviourally neutral. Proof: the declaration instrument
  and the committed-after instrument produce byte-identical row output and the same
  `closed=6` exit 0 at `1415fb65`; both selftests are 11/11.

So the after-state is not dependent on the instrument edit, but the literal "instrument
unchanged" condition is not met. The L1 should record the declared-instrument revision
(or revert the edit) so the kill rule's wording and the measured bytes agree.
