## 2. Source audit — five weakness classes (tool bytes = declaration bytes)

1. **A row that can pass while its artifact is absent — FAIL (defect exists).**
   `check_tree_paths` (defect-bind.py:135-138) accepts `git cat-file -e` on ANY
   object; the docstring (line 17) says so: "blob or tree". Demonstrated in a
   throwaway fixture (mktemp dir, init, commit a *directory* at the bound
   path): `git cat-file -e HEAD:receipt.html` → exit 0, `cat-file -t` →
   `tree`. A `tree-paths` row (D1a, D5) measures `closed` while the receipt
   FILE is absent. Every other kind reads blob bytes; a missing blob is
   `blob-unresolvable` SetupError → exit 2 (defect-bind.py:54-58; selftest
   arm A11, line 607-610), not a pass. The selftest never exercises a tree at
   a bound path (A1/A2 use blobs only).
2. **An exit-code path reporting success on a setup error — PASS.**
   `main` (635-650) catches `SetupError` → 2; argparse misuse → 2; missing
   `--manifest` → 2; `sweep` returns 0 only when `unexpected == 0` (348). No
   exit-0-on-setup-error found. Two adjacent notes: (i) `.decode("utf-8")` at
   199 (sources-cell) and 233 (doc-contains) is uncaught for non-UTF-8
   committed bytes → traceback, interpreter **exit 1** with no summary line —
   a crash indistinguishable by exit code from a legitimate claim failure;
   latent (current SOURCES.md is UTF-8). (ii) The docstring (28-31) claims
   refusals happen "BEFORE any row effect", but `blob-unresolvable` fires
   mid-sweep after earlier rows have printed (A11 codifies it as intended).
3. **An `expect` arm that can never fail — PASS.** Arms A1–A11 bind exit code
   AND stdout on a real hermetic fixture; A7 (543-545) exercises
   `expect=open` in BOTH directions; A8/A9/A11 assert refusal prefixes via
   `_expect_setup`, which returns False when nothing raises (443-450). No
   tautology found. Selftest total is enforced (`passed == total == 11`).
4. **Span/token normalization: bytes or decoded text — MIXED, disclosed.**
   `receipt-tokens` is genuinely byte-level: `span.encode("utf-8") not in
   doc_bytes` (166) and `t.encode("utf-8") not in receipt_bytes` (168-169) —
   no case/whitespace/EOL/BOM normalization; matches the plan's "byte
   substrings". `tree-bytes` uses raw blob length. `sources-cell` (199) and
   `doc-contains` (233) compare **decoded str** (strict UTF-8) after
   cell-strip / ATX-section slicing (175-191, 209-225); no fold/collapse that
   could fabricate a match; a token can never match across a line break. CRLF
   headings still match (`line.strip()`); CRLF inside tokens cannot. The only
   decode hazard is the crash path in item 2(i).
5. **A manifest that silences a row by renaming it — FAIL tool-side,
   mitigated process-side.** Row `id` is unconstrained free text (load_manifest
   254-283 checks presence, duplicates, kind, expect, rev — not format); the
   output carries **no manifest digest** (343-347), so a receipt alone cannot
   prove which manifest bytes produced it; `rows=6` is the only population
   witness. Renaming D5 and re-pointing its paths at always-present artifacts
   would keep `rows=6 closed=6` while measuring nothing. The real guards are
   external: the manifest is frozen at declaration commit `1b115ba` (hashes
   above) and the plan's kill rule ("any row removed, `expect` relaxed, or
   population narrowed"). The instrument itself cannot defend this.
