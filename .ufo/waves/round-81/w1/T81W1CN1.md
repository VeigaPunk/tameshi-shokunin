## 3. Shared conventions, and where tameshi diverges

**Shared** (each verified by reading the sibling's own header/print site):

- *Committed bytes only, never the worktree*: `git cat-file blob REV:path`
  into a fresh temp dir — tameshi `defect-bind.py` (S289), `selfstate-freshness.py`
  "Measurement", souji `souji-citation-reconcile.py`, tsukuroi
  `check-r75-routed-r76.py`, kake `c1_count.py`.
- *Machine summary, one line, `NAME: k=v`*: tameshi `DEFECT_BIND: rows=…`,
  `SELFSTATE_PINS: …`, `RECEIPT_EXISTS: …`, `SETTLEMENT:`-style rows in
  kotodama; kumitate `CAP_RUN_SELFTEST: 12/12 pass`; the same shape unprefixed
  in tsukuroi (`ROUTED_STALE=0 ROUTED_OK=8/8`) and souji
  (`SUMMARY cells=11 mismatches=0`).
- *Exit map 0 met / 1 not met / 2 could-not-evaluate*, with an absent input
  being a finding, not rc 2 — tsukuroi states it verbatim ("An absent file is
  a stale finding (rc 1), never rc 2"); tameshi's `defect-bind.py` and
  `selfstate-freshness.py` implement it.
- *`--selftest` hermetic*: in-memory fixtures plus one `mktemp` git repo, a
  declared arm count so a deleted arm fails (`selfstate`:
  `ok == total == SELFTEST_ARMS`; tsukuroi: pinned `DECLARED` case-id manifest
  in `check-selftest-tally.py`; kake: the selftest sha as a precondition).

**Divergences (findings; R-labels are local to this report):**

- **D-CN1 — failed selftest has three codes inside one lane.**
  `tools/defect-bind.py:613` returns 1 on a failed selftest, which is the same
  code the frozen C1 *before-state* uses (`open=6`, exit 1): a consumer keying
  on rc cannot tell a broken suite from an open register.
  `tools/selfstate-freshness.py:1203` also returns 1; `tools/receipt-exists.py`
  puts a bad selftest in 2; tsukuroi reserves **3** for a failed selftest and
  keeps 1 for findings (`check-r75-routed-r76.py:339`). The summary line does
  distinguish (`DEFECT_BIND_SELFTEST: 11/11 pass`), so this is a
  consumer-facing hazard, not a silent pass.
- **D-CN2 — arm naming, two families in one lane, neither the fleet idiom.**
  `A1..A11` (`defect-bind.py:472-604`) vs `ARM1..ARM21`
  (`selfstate-freshness.py`); the fleet's committed idiom is
  `PASS (SELFTEST-<ID>)` with a pinned `DECLARED` id manifest (tsukuroi) or
  `C1..C6` labels (kaidoku). `grep -rIn 'ARM[0-9][0-9]*_'` over the fleet
  returns **zero** hits outside tameshi. The mutant-spec prose doubles the
  prefix (`arm21-ARM21_selftest_text_pin`, `arm15-ARM15_decode_refusals`) —
  but that template is the lane's own pre-existing dialect in older spec rows,
  so it is not a round-81 defect; only the arm-name vocabulary is a finding.
- **D-CN3 — the population is not revision-bound; the fleet already filed
  this.** souji's r37 closure found "the register was working-tree-read" and
  its repair is `--register-rev` (its `LOG.md:1861` records the finding, the
  forged pass and the fix; r39 made `--register-rev` resolve-or-refuse).
  `defect-bind.py` accepts only `--repo/--manifest/--selftest`; `sweep()`
  loads the manifest from the given path. `selfstate-freshness.py` binds
  `--doc-rev` and `--pin-rev` but its `--manifest` defaults to a worktree
  path. Consequence: C1's kill rule clause "any row removed, `expect`
  relaxed, or population narrowed" is enforced by prose, not by the
  instrument — a narrowed manifest re-runs green with a smaller `rows=`; C2's
  23-row population has the same hole. This is the same defect class the round
  is closing, one level up (the fixture's own population).
- **D-CN4 — two opposite pin doctrines under one word.** `arm-liveness.json`
  states "Instrument revisions are pinned at the round-65 tip … so rows stay
  reproducible across later tool edits", and `arm-liveness.py` says "pin the
  revision you verified against, not 'tip'". C2 requires the reverse
  (`settled` = pinned blob == tip blob). Both are right for their object
  (re-execution vs self-description), but a reader who applies the
  arm-liveness rule to `selfstate-freshness` rows would call the C2 re-pin
  wrong. Not to be smoothed: the two rules must stay separately named.
- **D-CN5 — the declaration commit carries C3's repair.** Fleet pattern: the
  counter is frozen at the declaration and the repair lands later (kake
  round-40 froze `c1_count.py`; `scripts/sitemap_audit.py` was repaired
  afterwards). At `1b115ba0` the declaration already contains
  `tools/wave-reconcile.py` +28 (arm 25 + `SELFTEST_TEXT_SHA256`) and
  `tools/selfstate-freshness.py` +186 (`--pin-audit`, ARM18-21), and both
  constants match their tips (measured above). So C3's after-state is
  reachable *at the declaration commit*; the `c3-base-*.txt` receipts on base
  tool bytes are the only base-vs-tip discriminator. C2 by contrast keeps its
  repair (`tools/selfstate-freshness.json` re-pins, still `M` in the
  worktree) out of the declaration. Not a kill-rule violation (the rule
  freezes the instrument *after* the declaration), but the landing should
  disclose it, or a reader will read the declaration tip's green as a later
  repair.
- **C3 fragility (risk, not defect).** `inspect.getsource` returns the file's
  own lines for the function block, indentation included, and
  `co_firstlineno` reaches the decorator line — so reindenting the module, or
  decorator-wrapping `selftest`, changes the digest with no assertion change.
  That is consistent with the declared class ("any arm-text edit"), but the
  pin is a hostage of the module's layout, not only of its assertions; the
  arm's failure detail prints only 12 hex chars on each side, which is enough
  to see *that* it moved and not *where* (a reviewer must diff
  `inspect.getsource`, no tool prints it).

## 4. Proposed move (one, bounded)

**Evidence-level population binding now; a `--manifest-rev` flag next round.**
In the landing evidence for C1 and C2, record
`git rev-parse 1b115ba038e3d3bffc1432e62bbe5eb422c81266:tools/defect-bind.json`
and `…:tools/selfstate-freshness.json` beside the tip's blob for the same two
paths, and have the reviewer check byte equality before the `rows=6`/`rows=23`
counts are read. Reason: it turns the frozen kill rule's "population narrowed"
clause into a measured fact without touching a frozen instrument or figure,
and it reuses the sibling's already-filed repair (`--register-rev`) rather
than inventing a mechanism. Adding the flag *this* round would change the
instrument after the declaration, i.e. would itself need a disclosed
amendment; the flag is the correct round-82 shape
(`--manifest-rev` defaulting to the declaration commit, refusing an
unresolvable rev as exit 2).

- Affected axes: calibration (C1's population becomes measurable rather than
  asserted), freshness (C2's population likewise), verification surface (the
  fixture's own precondition). No axis is harmed: no printed figure changes.
- Risks: an evidence-only binding is still reader-enforced, so it is weaker
  than the flag; and a future `--manifest-rev` whose default is the
  declaration commit will make every later legitimate manifest edit require a
  re-pin (the C2 re-pin already is one) — that cost must be declared with the
  flag.
- Verification: `git rev-parse 1b115ba…:tools/defect-bind.json` and
  `git rev-parse 1b115ba…:tools/selfstate-freshness.json` against the same two
  paths at the landing tip must print identical 40-hex shas; the two counting
  commands' summary lines must be unchanged (`rows=6 … unexpected=0`, exit 0;
  `rows=23 settled=23 stale=0`, exit 0).
