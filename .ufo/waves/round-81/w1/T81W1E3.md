## The pin's limits (each demonstrated by execution above)

1. **No single-edit escape inside the digest region.** The digest covers the
   whole `inspect.getsource(selftest)` block; ANY byte change inside it fails
   the pin — case G shows even a semantically vacuous comment addition is
   caught (over-kill, not under-kill). So "an edit inside the selftest the
   pin does NOT catch" does not exist for single edits that touch the region.
2. **The real single-edit misses live outside the region** (the digest is of
   the function block only; module-level bytes are invisible):
   - H: editing the module-level `BOM` constant changes real behavior (the
     refusal trigger prefix) yet the suite stays `18/18` green and the pin
     passes, because fixture creation and the decode guard read the same
     edited constant and `getsource(selftest)` is unchanged.
   - I: editing the module-level `REV` fixture constant likewise stays
     `25/25` green with the pin passing.
   Both are single edits, semantically non-vacuous, invisible to the pin —
   this is the honest coverage boundary of any `getsource(selftest)` pin.
3. **Two-edit evasion (the plan's declared class boundary) is real and
   reproducible**: J = weaken ARM15's assertion AND recompute the pin constant
   over the weakened source → `18/18` green. The pin defends the single-edit
   class only; a deliberate weaken+recompute walk-through defeats it, exactly
   as the plan's kill rule declares. (Any second edit that does not fix the
   constant — e.g. deleting the pin arm — still fails the suite, via the
   count check or the remaining pin, so "recompute" is the working evasion.)
