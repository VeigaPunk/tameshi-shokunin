## 1. Rule as I implemented it (my own derivation)

For every row of `tools/wave-reconcile.json`:

1. Resolve the record root: `lane` = the lane repo; `fleet` = the `--extra-root fleet=PATH` path. Read the record
   blob with `git -C <repo> cat-file blob <rev>:<path>` after `git rev-parse --verify <rev>^{commit}`.
2. Locate the declared `record.span` as a **byte substring** of that blob, recording the byte offset and the number
   of occurrences. Absent span = setup error.
3. Decode artifacts as strict UTF-8; a leading `EF BB BF` BOM is refused (setup error), a decode failure is a setup
   error. The manifest gets the same treatment.
4. Re-derive the artifact side:
   - `seats`: `printed == len(results[]) == results.seats`.
   - `seat_reports`: `printed ==` number of `*.md` entries at the **top** of `wave.dir` at `wave.rev`
     (`git ls-tree -r --name-only <rev> -- <dir>`, keep remainder without `/`, suffix `.md`).
   - `roles`: declared multiset vs. `Counter(r["agent"] for r in results[])`.
     - `form=spec-items`: declared multiset = `Counter(item["role"] for item in spec.items[])` at the
       declaration's own root/rev/path.
     - `form=text-tokens`: every declared `N role` pair must occur in the record span as a delimited pair
       (`(?<![0-9A-Za-z_-])N role(?![0-9A-Za-z_-])`); absence is a setup error, never a pass. Then compare the
       declared multiset with the agents.
   - `attack_share`: `|{seat : seat.agent ∈ named}| * 100 >= floor_pct * |seats|` (floor is inclusive).
5. `measured = meet|drift`, `ok = measured == expect`; the row is a sweep failure iff `ok` is false.

Delimited-token check for the printed integer (seats / seat_reports / attack_share rows):
`(?<![0-9A-Za-z_])<printed>(?![0-9A-Za-z_])` inside the span.

`roles` rows use the declaration as the claim, not `record.printed`; this is forced by the frozen manifest itself
(`r72-spec-roles` has `printed=12` and span `b'"T72W1S01"'`, which contains no `12`) and matches the plan's table
(`roles`: "a record span declares a role multiset"). The lane tool agrees with this scoping — see §5.

`oracle.py` prints one `ORACLE_SPAN` + one `ORACLE_ROW` per row, then one `CMP` per row after the single tool run,
then `ORACLE rows=6 met=6 unexpected=0`.

## 5. Calibration observations (what the differential does and does not prove)

1. **Independence is real, not an import.** `oracle.py` uses only stdlib (`argparse, json, os, re, subprocess,
   sys, collections.Counter`). It has its own `git` wrapper, its own BOM/UTF-8 refusal, its own `ls-tree`
   top-level `.md` counter, its own `Counter` comparison, and its own span byte search. It never imports or reads
   function bodies from `tools/wave-reconcile.py`. The only shared textual input is the frozen manifest and the
   plan/docstring rule.
2. **The six-row sweep is two-sided.** Four green rows measured `meet` and two standing red arms measured `drift`
   (`11 reports` vs 12 files; `labrat` vs `revenger`). A vacuous always-`meet` oracle would have failed the two
