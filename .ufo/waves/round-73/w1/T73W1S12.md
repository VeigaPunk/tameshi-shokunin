## Answers

### What `seats` counts

`finalize()` writes one record per name in `w['names']` and
`'seats': len(res)` (`inline-dispatcher.py:288-296`); `w['names']` is the
dispatch's `taskCall.tasks` names (`:226`, `:268`). The validator emits
`taskCall.tasks` from spawn lanes only; resumes ride `resumeSends` and
`counts.total = spawn + resume` (`ufo-swarm-wave.mjs:1370`, `:1458-1466`).

**`seats` = dispatched spawn lanes (the roster), not live/settled/reports/total
lanes.** Census: `seats == len(results) == len(dispatch.taskCall.tasks)` in
351/351 joined artifacts; results names == dispatch names in 351/351; 0 waves
with `resumeSends`.

### Is a dead seat a record

**A spawned seat that dies: yes** — `finalize()` iterates every dispatch name,
not the live set. `seat_output()` (`:279-286`) returns the handle's text
(`str(h.output())[:20000]`) if a handle exists; `None` only when the handle was
lost (`_Spawned`/adopt). The `note` is set **only** when output is `None`
(`:294-295`), i.e. for kernel-loss/adopted waves — not for death.

**Never-spawned:** normally no artifact at all (`.dispatched` and finalize
require a full fill, `:262-273`, `:326-330`); round 60 is the hand-settled
counterexample (2 spawned per `.partial`, 32 records, 30
`dead_or_never_spawned`). **Resume:** never in results (code; 0 observed).

### Empty output / notes

Yes, both: 118 empty-string outputs (note `null`), 1,556 `null` outputs (all
with a note: 1,161 restart, 103 never-spawned, 292 other), 1,708 notes total
(152 with output too), 12 outputs truncated at exactly 20,000 chars, 2
`<output unavailable: …>` strings. Record key sets vary (canonical 332 files;
`{name,agent,id,output}` 9 files; `report_file*` 8 files; one file with no
`results` list). Output/note are outside the reconciler's measured contract —
its selftest records carry only `{name, agent}`.

### Registry vs results

Registry carries per member `kind`, `agentId`, `role`, `item`, `axes`,
`milestone`, `modelAlias`, `card`, `member` (resume owner), and document
`wave/createdAt/updatedAt/reportDir/priorRegistries`; results carries none of
these, and has `output`/`note` which the registry lacks. Two traps: the
registry is a **cumulative union** across re-runs (kotoba r73: 55 members vs
36 spec/dispatch/results; 19 extras with `item:null`), and the current
orchestration never fills `agentId` (r72 0/12; 0 of 281 adjacent registries;
335/974 fleet-wide from older runs).

### Dispatcher on seat death

Liveness per handle id; `finalize()` only at `nlive == 0` (`:326-330`). No
respawn, no replacement, no status field, no early finalize. Kernel loss →
adopt as `_Spawned`, all records `output:null` + restart note. L1 dead →
finalize still happens, WAVE-DONE fails/logs. Wave never fills → no artifact.

## Dead-seat impact — six rows × one column

| row (kind) | dead-seat impact |
|---|---|
| `r72-report-seats` (seats) | none: `printed=12 seats=12 records=12` unchanged; the dead seat keeps its record and its `seats` slot |
| `r72-report-seatreports` (seat_reports) | the only movable kind: a dead seat that wrote no report lowers `files` by one (12→11), so a claim of 12 then drifts, a claim of 11 meets |
| `r72-plan-seats` (seats) | none (same derivation as row 1) |
| `r72-spec-roles` (roles) | none: `agent` is copied from the dispatch map; undefined only on hand-settled records with null `agent` (`results-agent-absent`, exit 2) |
| `r72-plan-roles` (roles) | none; its red arm is plan-declared `labrat` vs executed `revenger`, not death |
| `r72-attack-share` (attack_share) | none — the gap: a dead attacker still counts; fixture meets `4/12=33.3%` at floor 30 while live-only `3/12=25%` would drift |

Kind summary: `seats` death-blind; `seat_reports` death-sensitive (file count
only); `roles` death-blind (dispatch identity, card name under alias);
`attack_share` death-blind (composition, not executed work).

## Well-definedness / proposal

All six rows are well-defined against the committed r72 artifact (sweep
`rows=6 met=6 unexpected=0`, exit 0; selftest 12/12). **No row is undefined on a
wave with a dead spawn seat** — the artifact simply has no death field, so
death cannot make a row uncomputable. Genuinely undefined (setup exit 2)
cases are artifact shapes, not death: no `-results.json` (never filled), null
`agent`, no `results` list, resume-only lanes. The `seats` row is
self-referential (`printed == seats == len(records)`, where the latter two are
one emitter expression) and the reconciler never reads the dispatch
(`grep -c dispatch` → 0), so fixture wave B (dispatch 12, results 11/`seats:11`)
reads `printed=11 seats=11 records=11` meet.

Proposal (**proposal only; manifest not edited**): row-level field
**`population: "results" | "dispatch" | "settled"`** (absent = results, so the
six committed rows are unchanged). `dispatch` takes the roster from
`taskCall.tasks` (role from the registry when `agent` is a card name);
`settled` requires a per-record boolean `settled` and exits 2 when absent.
Falsifier: absent → sweep byte-identical; `dispatch` on r72 → unchanged
(12 tasks, `attack=3/12`); on fixture B `dispatch` seats/roles → drift while
`results` → meet; `settled` over any current artifact → exit 2. If fixture B
`dispatch` meets or `settled` meets, P1 is refuted.
