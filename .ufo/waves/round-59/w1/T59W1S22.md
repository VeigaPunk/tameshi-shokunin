## Can the frozen counter misclassify this cell?

Reviewed against the frozen `measure.py` for path index 3:

1. **Option/pathspec injection — none possible.** The path string is `tools/-runner.py`; the dash is not the first character of any argv element. The counter itself uses `git add -- <path>` / `git add -u`, and any conforming tool receives it via `--path`, so neither fixture construction nor a correct tool can misparse it as an option. (Unlike a top-level `-runner.py`, this spelling is inert.)
2. **Expected/token mapping correct for this cell:** `unrelated` → expected 0, token `EXECUTOR_SOURCE_BOUND`, checked as substring over combined stdout+stderr with a 30 s timeout. Deterministic under the counter's scrubbed env.
3. **Fixture fidelity independently verified** (table above): declared blob sha-equal to trusted at the unrelated candidate, unrelated side change present in the same commit. No cross-commit contamination (each candidate is a distinct commit sha in one repo).
4. **Discrimination probe:** `git diff --quiet trusted unrelated` → exit **1**, while `git diff --quiet trusted unrelated -- tools/-runner.py` → exit **0**. So the cell actively catches whole-tree comparators: a tool that fails to restrict comparison to declared paths emits DRIFT here and is correctly scored as failing by the counter. A declared-path-only tool is not misclassified on this cell.
5. **Residual limitation (declared, out of scope):** the counter measures the CLI contract surface only. A tool that hardcoded exit 0 + `EXECUTOR_SOURCE_BOUND` without inspecting the repo would pass all 24 — that is the contract's stated trust boundary ("checks declared Git blobs only… binding prerequisite, not certification"), not a defect of this cell.

Conclusion: for path `tools/-runner.py`, class `unrelated`, the frozen counter cannot misclassify a conforming declared-path-only tool; the fixture provably encodes the intended semantics.
