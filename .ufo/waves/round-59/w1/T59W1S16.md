## Can the frozen counter misclassify this cell?

The counter hardcodes `expected=0`/BOUND for `unrelated`, so the expected side
cannot flip. What can go wrong is the *tool* being failed or passed wrongly on
this cell. Concrete mechanisms, all checked against the fixture:

1. **Worktree/index confusion (real risk for this class).** measure.py builds
   all six commits first, then runs the tool per class. The fixture worktree
   is left in the `symlink` construction state — `tools/日本語.py` is a
   *broken symlink* to `elsewhere.py` on disk during EVERY tool run, and the
   index's last staged entry is that symlink. A tool that reads the worktree,
   `git diff --cached`, or `git status` instead of the candidate commit's
   objects sees a symlink at the declared path for the `unrelated` run and
   would return DRIFT/unavailable instead of BOUND. The frozen counter would
   then record `ok=false` for a compliant fixture — a false negative rooted
   in tool behavior, not fixture construction. The contract's "declared Git
   blobs only" wording is the guard; my oracle reads objects only.
2. **Whole-tree diff scope creep.** `unrelated.txt` is added at the candidate.
   A tool diffing the full trees `trusted..candidate` instead of declared
   paths finds a delta and returns DRIFT → false negative on this cell.
3. **Path encoding/normalization.** The path is non-ASCII NFC. A tool that
   NFC/NFD-normalizes, or parses `git ls-tree` output without `-z` (quoted
   `"\\346..."` form), can fail to match the declared path and report missing →
   false DRIFT. Oracle passes the path as raw bytes with `-z`.
4. **Mode strictness.** Fixture uses mode 100644. A tool requiring executable
   mode 100755 would flag this cell (and `equal`) as DRIFT → false negative.
5. **Token/exit agreement.** Counter requires BOTH exact exit code and token
   substring in stdout+stderr. A tool printing BOUND but exiting non-zero is
   correctly failed; oracle matches both.
6. **Degenerate always-accept tool.** An always-BOUND/exit-0 tool passes THIS
   cell but fails changed/missing/symlink/unresolvable cells; the 24/24 claim
   cannot be gamed through this cell alone. Conversely a tool ignoring the
   path entirely and always exiting 0 still fails 4/6 classes. No
   single-cell gaming path exists within the frozen 24-cell matrix.

No fixture-side false-positive path found: construction is deterministic,
blob hashes verified byte-identical, and the `unrelated` delta is exactly the
unrelated file the class intends.
