## Misclassification review — can the frozen counter misclassify this cell?

By its own construction: **no** (empirically confirmed above). Specifics:

1. Leading-dash safety, counter side: every counter git invocation guards the path with `--`
   (`git add -- path`); the tool receives `--path tools/-runner.py`, whose value starts with `t`, so
   argparse never sees an option-like token. Observed: this row behaves identically to the other three paths.
2. Env hygiene: `GIT_*` stripped, global/system gitconfig nulled → no user alias/filter can alter blobs or
   command semantics; deterministic content confirmed by matching blob id across independent constructions.
3. Candidate for `equal` is always the resolvable `trusted` commit; no non-commit/hash ambiguity in this cell.
4. Conservative-direction hazard, tool side only: after fixture build the *worktree* file is the `120000`
   symlink; a tool reading the worktree instead of the candidate commit would false-**fail** this cell
   (DRIFT). Verified end-state worktree is the symlink. Commit-reading tools are unaffected.
5. Undetectable-at-single-cell hazards (aggregate-claim level, known boundary): a skipped-work or
   always-accept tool (print BOUND, exit 0 without comparing) passes this cell; the equal cell also cannot
   catch a tool that compares trusted-to-itself and ignores `--candidate`. The 24-cell aggregate (changed/
   missing/symlink rows) is what catches those; the claim's separate skipped-work/always-accept controls are
   outside this frozen `measure.py`. This cell contributes no false-pass path of its own beyond that shared boundary.
6. Token check is substring-based (`token in stdout+stderr`); combined with the exact exit-code equality it
   is adequate here since exit 0 is additionally required — a token-negating message without exit 0 cannot pass.
