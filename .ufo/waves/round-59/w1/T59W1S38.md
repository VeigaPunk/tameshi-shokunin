## Claim-boundary determination for non-UTF8 blob contents

- **Strictly outside the frozen 24-fixture claim.** Every fixture blob the counter commits is ASCII by construction (cited literals above); non-UTF8 content is never generated, so a gate that crashes or mis-verdicts on non-UTF8 blobs still passes 24/24. The frozen claim does not bind this surface.
- **Inside the design boundary implied by the contract.** Git blob identity is byte-exact (SHA-1 over `blob <len>\0<bytes>`), and the trust boundary says the gate "checks declared Git blobs only". A gate that decodes blob content to `str` does not check declared Git blobs; it checks a lossy text projection. On this surface the frozen skipped-work control has a hole: its `changed` fixture drifts ASCII text, so a text-projecting gate passes the frozen control while remaining exploitable on non-UTF8 drift.

## Attacks (scratch demonstration, receipt `T59W1S38/receipts/probe-full.log`)

Fixture repo `demo/` under seat scratch (root asserted via `git rev-parse --show-toplevel` before any mutation; `git -C` only; `TMPDIR` set to seat scratch):

- trusted `T`: blob bytes `ff fe 00 65 78 65 63 0a` at `tools/runner.py` (`printf '\xff\xfe\x00exec\n'`)
- candidate `CE`: identical bytes, drift only in unrelated file → same blob OID `7716e9ef…`
- candidate `CD`: single-byte drift `fe→fd` in the non-UTF8 region → distinct blob OID `b9ed894c…`

**A. Strict-UTF8-decode gate crashes on a BOUND non-UTF8 case (availability / wrong verdict).**
Comparator reading blobs with `text=True` (strict locale decode): `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xff` on the *equal* case. Such a gate exits 1 with a traceback and no `EXECUTOR_SOURCE_*` token → false DRIFT on content that is byte-identical to trusted. Design-boundary defect; invisible to the frozen 24.

**B. Lossy-decode (`errors='replace'`) gate turns non-UTF8 DRIFT into false BOUND (skipped-work channel).**
`b'\xff\xfe\x00exec\n' != b'\xff\xfd\x00exec\n'` (git truth: distinct blob OIDs), but both decode to `'\ufffd\ufffd\x00exec\n'` under `errors='replace'`. A text-projecting comparator prints `EXECUTOR_SOURCE_BOUND` and exits 0 on the drifted candidate. This is a genuine counterexample to the *stated purpose* of the skipped-work control for any declared source whose bytes are not valid UTF-8 — a class the frozen counter never constructs.

**C. Counter measurement-availability: `run(text=True)` crashes on non-UTF8 tool output.**
Stub tool writing raw `b'\xff…'` to stdout, run through the counter's exact capture discipline (`capture_output=True, text=True`): `UnicodeDecodeError` propagates out of `subprocess.run`; the counter dies before printing any `C1_R59` verdict line. A buggy or adversarial tool can thus unverifiably abort judging. Independent of gate design; a counter robustness defect.

## Failed / out-of-scope attacks (preserved)

- **Non-UTF8 path bytes**: contract freezes `paths` to four UTF-8 spellings; the counter passes them as argv `str`. Outside boundary — rejected without demonstration.
- **Locale-dependent counter fixture writes**: fixture contents are ASCII literals; `write_text` encoding is irrelevant for ASCII on any locale. Not a defect.
- **Counter JSON print of non-UTF8**: `json.dumps(..., ensure_ascii=False)` + `print` is safe on this host (Python ≥3.13 UTF-8 mode default; observed 3.14.8). Only tool-stdout decode (attack C) is fragile. Low residual risk.

## Smallest sound behavior (proposed, verified)

Per declared `--path`: resolve `<commit>:<path>` to a blob OID in trusted and candidate via `git rev-parse` and compare OID strings. Content is never read or decoded → encoding-agnostic by construction. Ordering: validate trusted commit and resolve its declared source(s) first (failure → exit 2, per exit_map "invalid trusted commit/source"); validate candidate commit (failure → exit 2); per-path candidate resolution failure or OID mismatch → exit 1; all equal → exit 0 with token `EXECUTOR_SOURCE_BOUND`.

Verified in receipt §8–§9: OID semantics reproduce the frozen six-class expected exits exactly (`equal=0, changed=1, missing=1, unrelated=0, unresolvable=2, symlink=1` — `ALL_FROZEN_CLASSES_REPRODUCED`), and yield BOUND on the equal non-UTF8 case and DRIFT on the one-byte non-UTF8 drift. Note the frozen `symlink` fixture (trusted regular file vs candidate symlink) is caught because a symlink blob's content is its target path — OIDs differ naturally. A directory at a declared path (tree OID vs blob OID) also mismatches → DRIFT, matching "missing/nonregular".

```sh
python3 tools/executor-source-pin.py --repo "$R" --trusted "$A" --candidate "$E" --path tools/runner.py   # expect exit 0 + EXECUTOR_SOURCE_BOUND

```

## Critic verdict

- **Counterexample**: gate designs that decode blob content to text (strict or `errors='replace'`) mis-verdict non-UTF8 blobs — crash/false-DRIFT (A) or false-BOUND skipped-work acceptance (B); the frozen counter's ASCII-only fixtures cannot detect either, and its `text=True` capture lets a tool abort judging outright (C).
- **Evidence**: `T59W1S38/receipts/probe-full.log` §§4–9 (blob OID truth, decode crash, replace-collapse, counter crash, OID-correct verdicts, six-class reproduction); driver `T59W1S38/receipts/probe.sh`.
- **Impacted axes**: soundness of the skipped-work control on the design boundary; gate availability/operability on legal Git blobs; measurement availability of the frozen counter.
- **Smallest safe correction**: implement OID-only comparison (never decode content); harden counter capture to bytes with explicit decode for token matching; add the two non-UTF8 CLI checks above as a separate, non-frozen guard. Do not widen the frozen claim.
- **Boundary ruling**: attacks A/B are inside the design boundary, strictly outside the frozen 24-fixture claim (no frozen-credit impact); attack C is a counter robustness defect for L1 disposition.
