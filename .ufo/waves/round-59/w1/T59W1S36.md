## Verdict in one line

GIT_DIR poisoning is a real, demonstrated soundness break of the gate's **standalone
CLI contract** (false BOUND via ref candidate; verdict flip to UNAVAILABLE via full
hash), but it is **outside the frozen claim boundary**: the frozen counter scrubs all
`GIT_*` variables from the environment before every git call and before invoking the
tool, which I verified empirically end-to-end. The frozen gate design is therefore not
broken by this surface; a conforming tool must still defend itself because its exit map
makes no environment caveat.

## Claim-boundary determination

- **Inside the claim** ("gate passes exactly 24 independently executed committed-object
  fixtures"): immune. `measure.py` builds `env = {k:v for k,v in os.environ.items() if
  not k.startswith('GIT_')}` and passes that same env to every fixture `git` call and
  every tool invocation, then sets `GIT_CONFIG_GLOBAL=/dev/null`,
  `GIT_CONFIG_NOSYSTEM=1`, `TMPDIR=<work>`. Probe C0: I ran the frozen counter (from the
  evidence path, read-only) with ambient `GIT_DIR`, `GIT_OBJECT_DIRECTORY`,
  `GIT_CEILING_DIRECTORIES` all pointing at nonexistent paths, against a scratch stub
  lane. Its own fixture builds completed and all 24 tool invocations ran; the stub's
  env canary observed exactly `{GIT_CONFIG_GLOBAL: /dev/null, GIT_CONFIG_NOSYSTEM: 1}`
  on every run — attacker-supplied `GIT_*` never crossed. (`passed=12/24` in that run
  is stub artifact: the stub always exits 1, so only the 12 expected-1 fixtures score.)
- **Outside the claim, inside the tool contract**: the exit map is phrased purely over
  `--repo/--trusted/--candidate/--path` with no environment caveat, so a tool
  whose git subprocesses inherit ambient env violates its own contract under poisoning.
  That is where the demonstrated attacks land. The contract's `trust_boundary` fields
  (verifier-supplied trusted revision, declared-blobs-only scope) do not mention the
  invocation environment; the counter's scrub is harness behavior, not tool behavior.

## Git primitive facts established (git 2.56.0, receipts in `evidence/`)

- P0/P1/Q1: `GIT_DIR` is honored over `git -C REPO` —
  `GIT_DIR=<mirror>/.git git -C victim rev-parse --absolute-git-dir` prints the
  **mirror** gitdir. Worse, `rev-parse --show-toplevel` still prints **victim** (cwd),
  because with `GIT_DIR` set and `core.worktree` unset the work tree defaults to cwd.
  Consequence: a toplevel-identity assertion alone is **blind** to this redirect
  (P1 log); identity must be checked via `--absolute-git-dir`, or the env must be scrubbed.
- Q2/Q3/Q4: under the redirect, victim-only commit hashes stop resolving ("Needed a
  single revision"), while ref names like `HEAD` resolve in the attacker's repo and
  `git show HEAD:tools/runner.py` serves attacker content.

T9 is the complete false-BOUND chain: attacker mirror contains the public trusted
commit and a clean HEAD; verifier runs the gate on the lane with `GIT_DIR` exported
(attacker-set CI env, confused-deputy operator); the gate reads blobs from the mirror
and attests `EXECUTOR_SOURCE_BOUND` (exit 0) about a repo whose actual HEAD is forged.
This requires a ref-style candidate (`HEAD`/branch); with strict full-hash candidates
poisoning degrades to verdict-flip/DoS (T2/T7), never false credit — and the frozen
counter always passes full hashes, inside its scrubbed env.

## Smallest sound behavior (proposal, staged)

1. **Scrub, don't inherit**: every git subprocess runs with
   `env = {k:v for k,v in os.environ.items() if not k.startswith('GIT_')}` plus
   `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1` — byte-for-byte the frozen
   counter's own env construction. One filter covers `GIT_DIR`, `GIT_WORK_TREE`,
   `GIT_COMMON_DIR`, `GIT_NAMESPACE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`,
   `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CONFIG_COUNT/KEY/VALUE`, `GIT_EXEC_PATH`,
   etc. `HOME`/`XDG_CONFIG_HOME` gitconfig is simultaneously neutralized by
   `GIT_CONFIG_GLOBAL=/dev/null`; system config by `GIT_CONFIG_NOSYSTEM=1`.
2. **Defense in depth (optional but cheap)**: after scrubbing, assert
   `git -C REPO rev-parse --absolute-git-dir` equals `realpath(REPO)/.git` (or equals
   `realpath(REPO)` for a bare repo); exit 2 `EXECUTOR_SOURCE_UNAVAILABLE` on mismatch.
   Do not rely on `--show-toplevel` — P1 proves it is blind to the redirect.
