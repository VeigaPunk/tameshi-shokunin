# T59W1S35 — Adversarial item: Git config poisoning (round-59 executor-source-pin gate)

**Verdict:** Config poisoning is a live, in-boundary soundness surface. Two distinct
always-accept subversions of implementation families that satisfy the frozen
24-fixture behavior shape were demonstrated on scratch fixtures (git 2.56.0):
**textconv poison** (self-contained adversarial candidate commit) and **commit-level
replace refs** (subverts even OID-compare plumbing gates). A third family
(diff.external) subverts porcelain-diff gates but not `--quiet`. One anticipated
blade was **refuted empirically**: repo-local aliases cannot shadow builtins on git
2.56.0. The smallest sound behavior is identified and verified under simultaneous
full poison. Staged CLI test discriminates: porcelain family fails 2/11 fixtures,
sound shape passes 11/11 with zero attacker command executions.

  this is a gap statement about implementation soundness, not a counter defect.

## Counterexample (strongest, local evidence)

A gate can satisfy every frozen-fixture behavior class and still be flippable to always-accept by
repo-carried state. Receipt: `receipts/cli-test-vs-porcelain.txt` — a porcelain-diff mock
(`receipts/mock_porcelain_gate.py`, exactly the contract exit semantics) prints
`EXECUTOR_SOURCE_BOUND` rc 0 on forged candidates under:

- `textconv+gitattributes-candidate` — candidate commit carries `.gitattributes` mapping declared
  paths to a driver + repo-local `diff.<drv>.textconv` rewriting content to a constant. Porcelain
  `git diff --quiet T C -- path` returns **0 with textconv executed** (A1: human rc 0, quiet rc 0).
  Fully self-contained: no `.git` write access needed beyond what any committed repo has.
- `replace-refs-commit-level` — `refs/replace/<candidate-commit> → trusted commit` makes even
  `git ls-tree <candidate>` show **trusted oids** (P2/P5: `all_paths_show_trusted=true` for all four
  path spellings); `git diff` resolves the candidate to the trusted tree. OID-compare and content
  gates both print BOUND. Blob-level replace equivalently subverts `cat-file` content reads (A9).

Impacted axes: soundness (always-accept), claim-boundary precision (candidate repo is adversarial
input inside the trust boundary), operability (test exists).

## Boundary statement

- **Inside claim boundary:** the candidate repo is adversarial input the gate must read soundly; the
  frozen claim's skipped-work/always-accept controls fail if the gate can be flipped to BOUND by
  repo-carried config/refs. Poisoning lives exactly in the gate's blob-reading machinery.
- **Outside (unchanged):** the scored 24 fixtures and the frozen counter (e9cc34b) — no counter edit
  proposed; L1 owns measurement. Verifier-side env is already sanitized; residual exposure is
  repo-local only.

## Smallest sound behavior (design constraint for the candidate tool)

1. Validate both revs: `git --no-replace-objects rev-parse --verify <rev>^{commit}`; any failure → exit 2
   (covers unresolvable candidate and invalid trusted).
2. Per declared path compare `(mode, oid)` tuples from
   `git --no-replace-objects ls-tree <rev> -- <path>` for trusted vs candidate; any mismatch/absent → exit 1
   (covers changed/missing/symlink via mode 120000 vs 100644); all equal → print `EXECUTOR_SOURCE_BOUND`, exit 0.
   Never read blob content for the verdict; never touch the worktree.
3. Invocation discipline: argv only (no shell); builtins only; `--` before paths; `--no-replace-objects` on
   every call; belts `-c core.hooksPath=/dev/null -c core.fsmonitor=false`; optionally
   `-c safe.directory=*` for cross-uid repos.
4. Never porcelain diff/show/log; never checkout/archive (smudge filters); map unexpected git errors to exit 2.
