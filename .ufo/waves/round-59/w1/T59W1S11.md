## Can the frozen counter misclassify this cell?

- **Fixture-construction risk: none.** The candidate is the constant `'0'*40`; expected `(2, EXECUTOR_SOURCE_UNAVAILABLE)` does not depend on repo state, build order, or any prior cell. Verified empirically: rc 128 in original and content-mutated states.
- **False-pass vector (real):** exit 2 / `EXECUTOR_SOURCE_UNAVAILABLE` is also the tool's argument-error and trusted-unavailable exit. If the tool mis-parses the space-containing `--path` value or fails to resolve `trusted:path`, it emits the same exit+token, and the counter — which checks only `(returncode, token substring)` — scores the cell ok. The counter cannot distinguish *why* the tool was unavailable.
- **False-fail vector (low):** under the counter's sanitized env, `rev-parse --verify 000…0^{commit}` deterministically fails; a tool would only exit non-2 here if it maps any candidate git error to DRIFT(1), which is a genuine tool defect the counter correctly flags.
- **Env/quoting risk: none observed.** argv list form means the space needs no quoting; `TMPDIR` confined to `--work`; 30 s timeout ample.
