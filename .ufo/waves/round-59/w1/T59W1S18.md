## 4. Can the frozen counter misclassify THIS cell?

Review of `measure.py` grading for path index 2, class `symlink`:

- Expectation arithmetic: `symlink` ∉ {equal, unrelated}, ≠ unresolvable → `expected=1`;
  token `EXECUTOR_SOURCE_DRIFT`. Faithful to contract `exit_map.1`
  ("missing/nonregular at candidate" → DRIFT). Grading is `exit == expected and token in
  stdout+stderr`. **No counter-side path found that misclassifies a conforming tool on
  this cell.**
- Dangling-link build succeeds (verified §2); if `core.symlinks=false` leaked in, git
  would store a regular blob with content `elsewhere.py` — outcome for this cell would
  still be exit 1 (content differs from trusted), so even that misconfiguration would
  not flip the expected verdict here. Config isolation confirmed anyway.
- **Low discriminating power (coverage note, not a defect):** the symlink blob content
  (`elsewhere.py`) differs from the trusted blob, so a pure-content-comparing tool that
  never inspects mode also exits 1. This cell alone does not force mode inspection; it
  does catch existence-only tools (`git rev-parse candidate:path` succeeds → spurious
  exit 0 → correctly failed by the counter).
- **Sharpest edge:** a tool that resolves the symlink through the *working tree* hits
  ENOENT (dangling) and may map the failure to exit 2. Per contract, nonregular-at-
  candidate is DRIFT (exit 1), so the counter would fail such a tool — the counter's
  verdict would be correct; the tool is nonconforming. The fixture worktree is left at
  the symlink commit for all 24 runs, so any worktree-keyed tool also misjudges the
  other classes of this path (e.g. `equal` would see a symlink). By design the counter
  catches this; oracle §3 demonstrates commit-keyed behavior.
- **Unicode handling:** counter passes the path as argv text; round-trips via
  fsencode/surrogateescape; Python 3.14 FS encoding is UTF-8 here. `ls-tree` output
  quotes the name (`"tools/\346\227\245…"`, core.quotepath) — a tool parsing `ls-tree`
  *output* to recover names could misparse; tool-side hazard only, counter unaffected.
- Env isolation (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, stripped
  `GIT_*`, `TMPDIR=work`, 30 s timeout) verified clean; `unresolvable` candidate
  `0{40}` fails rev-parse (rc=1) as required.

Verdict: **the frozen counter cannot misclassify a conforming implementation on this
cell; the cell's expected outcome (exit 1, `EXECUTOR_SOURCE_DRIFT`) is exactly what the
committed git object (mode 120000) mandates, and the grading logic is faithful to the
contract.**
