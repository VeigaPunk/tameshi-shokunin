## Connection
The round-58 false PASS was an **execution-honesty** failure: the measurement executed claimant-authored bytes with no source-identity binding. The round-59 contract closes that specific hole at the declared-source level as a **pre-execution admission filter**: before any counter runs a claimant's executor, the verifier can require exit 0 of the pin gate over the candidate revision for every declared executor-source path. Byte-inequality (BENT_RC vs trusted), absence, or nonregularity of any declared executor source at the candidate each force non-admission, so the r58 "swap the runner, keep the registry honest" attack stops at the gate. The connection is one-directional and must not be overstated (see boundary).

## What this bounded gate can reject (exactly)
- Candidate revision whose declared source blob differs in raw bytes from the trusted blob → exit 1 `EXECUTOR_SOURCE_DRIFT` (the round-58 bent-runner/cheat-gate case).
- Declared source missing at candidate → exit 1.
- Declared source nonregular at candidate (symlink, gitlink, directory) → exit 1 (symlink class).
- Candidate revision unresolvable → exit 2 `EXECUTOR_SOURCE_UNAVAILABLE`.
- Bad arguments; invalid/unresolvable trusted commit; missing/nonregular trusted source → exit 2 ("invalid trusted commit/source", contract exit_map).
- Scope is deliberately narrow: only declared paths are compared — unrelated tree changes at candidate do **not** trip it (unrelated class → exit 0).

## What this bounded gate cannot certify
- **No execution attestation.** Exit 0 attests only that declared committed blobs equal trusted blobs at the candidate commit. It never runs the candidate source; it says nothing about whether any executor ran, whether the runner used was those bytes, or whether tallies (rows held, mutants killed, verdicts) reflect real execution. The round-58 false PASS was produced by a counter running bent bytes; this gate would have kept that counter from starting, but it is not evidence that any later execution was honest.
- **No closure completeness.** Undeclared paths are unexamined: a bent helper, an undeclared cheat gate, config, or a wrapper earlier on PATH all pass if the declared paths match. "Complete source closure" is supplied by the verifier; the gate cannot verify the declaration is complete.
- **No dependency or interpreter identity.** Blobs are compared, not the Python binary, git binary, libc, PATH, or environment that interprets them.
- **No author-independent trust of the trusted revision.** If the trusted revision itself contained a cheat gate, byte-equality would certify the cheat. The trusted revision must be established by other means; per the contract this is "a binding prerequisite, not round-58 C2 certification."
- **No distinction between forgery and legitimate update.** Any byte difference is DRIFT; honest executor updates must be re-trusted by the verifier.
- It does not re-admit round-58 C2, does not score or admit round-59, and (observed) the tool is absent at the freeze — this seat drafted no implementation (that is seat T59W1S49).

## Honest boundary paragraph (staged fragment)
Staged at `stage/fragments/executor-source-pin-boundary.md` in this seat's stage root; verbatim:

> `tools/executor-source-pin.py` is a bounded source-identity prerequisite, not an execution attestation. Given a verifier-supplied trusted commit and a candidate commit, it compares the raw Git blobs of declared regular executable-source paths and exits 0 only when all declared blobs are byte-equal, 1 (`EXECUTOR_SOURCE_DRIFT`) when a declared source differs, is missing, or is nonregular at the candidate, and 2 (`EXECUTOR_SOURCE_UNAVAILABLE`) on bad arguments, an invalid trusted commit/source, or an unresolvable candidate. It exists because round 58's C2 falsification showed a claimant-swapped executor (`tools/registry-check.py`) fabricating held/mutant tallies while the frozen counter still printed PASS: nothing bound the executed bytes to a trusted revision. Applied pre-execution, this gate rejects that forgery class at the declared-path level. It certifies nothing about execution, dependency or interpreter identity, completeness of the declared closure (undeclared bent helpers pass), or the trustworthiness of the verifier-supplied trusted revision itself; a cheat baked into the trusted bytes would be certified, not caught. Exit 0 authorizes the declared sources to be treated as the trusted sources for subsequent measurement; the honesty of that subsequent measurement remains the verifier's separate responsibility.
