## Frozen-counter misclassification review (this cell)

- **Space-in-path handling is sound on the counter side.** `grep shell= measure.py` → no
  occurrences: every subprocess call is an argv list (`shell=False` default), so
  `git add -- 'tools/space name.py'` and `--path 'tools/space name.py'` are single argv
  elements and never word-split. Empirically confirmed with `git ls-tree -z ... -- 'tools/space name.py'`.
- **Token/exit scoring** requires both the exact exit code and the token as a substring of
  stdout+stderr — strict by design; a tool emitting the wrong token with exit 0 fails the cell.
- **No counter-side defect found for this cell.** The `unrelated` expectation (exit 0) is
  computed from the run's own freshly built trusted hash, so per-run commit-hash variation
  (committer timestamp) cannot flip the verdict.
- **Intended discrimination:** a tool that checks the whole tree (fails because
  `unrelated.txt` exists at candidate) scores fail here. That is the contract's designed
  anti-enlargement check, not a misclassification.
- **Residual (tool-side) hazard:** an implementation that internally shell-splits the path
  would observe a missing/different source at candidate and exit 1; the counter would then
  correctly score the cell failed, pinning a real tool bug on a legitimate fixture.
