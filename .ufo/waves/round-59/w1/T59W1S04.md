## Frozen-counter misclassification review (this cell)

- **Expected mapping is object-level sound.** For `unrelated`, measure.py expects
  exit 0 + `EXECUTOR_SOURCE_BOUND`; the candidate tree provably carries the
  trusted blob at the declared path (verified above), so any conforming
  commit-tree gate must pass this cell. No counter-side arithmetic or fixture bug
  observed for this cell: construction is deterministic (ASCII bytes, explicit
  `git add -- path unrelated.txt`, identity and `commit.gpgsign=false` pinned,
  `GIT_CONFIG_GLOBAL=/dev/null` + `GIT_CONFIG_NOSYSTEM=1`, `GIT_*` env stripped).
- **Working-tree hazard (confirmed empirically).** measure.py builds all six
  commits first, then runs the tool. At tool-run time the fixture working tree
  sits at the last-built state — the SYMLINK (`tools/runner.py -> elsewhere.py`,
  clean index). A tool that reads the working tree or index instead of the
  candidate commit would see the symlink for all six invocations and would fail
  the `unrelated` cell (false DRIFT) — and would coincidentally "pass" the
  symlink cell. The counter cannot distinguish wrong-source (working tree) from
  wrong-commit reads; both just fail. This penalizes working-tree-based tools by
  design (the contract pins commits), but it is the one place this cell can
  produce a surprising failure that is the tool's fault, not the counter's.
- **Strictness note.** The token requirement (`EXECUTOR_SOURCE_BOUND` substring
  in stdout+stderr) is enforced by measure.py in addition to the contract's
  exit_map. A tool exiting 0 silently, or printing a different success string,
  fails this cell despite satisfying the JSON exit_map text. Conforming lane
  tool must emit the token.
- **No path-quoting hazard here.** `tools/runner.py` is plain ASCII, no spaces,
  no leading dash; `git add --`/`ls-tree --` handle it identically in fixture
  and oracle. (The other three seat paths carry the quoting risk; out of scope.)
