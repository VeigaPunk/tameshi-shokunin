## Can the frozen counter misclassify this cell? — No (on examined evidence)

1. **Expectation equals independent ground truth.** Counter expects exit 1 + `EXECUTOR_SOURCE_DRIFT`; `ls-tree` independently proves the source object is absent at candidate `5a62d71f` and contract `exit_map[1]` covers "missing/nonregular at candidate". The oracle — built without reference to the tool — lands on the same verdict.
2. **Token check is stream-agnostic** (substring over stdout+stderr), so a correct tool can't fail on stream choice.
3. **Env isolation** strips `GIT_*`, nulls global/system config, sets `TMPDIR` to the empty-checked work dir, `PYTHONDONTWRITEBYTECODE=1`; 30 s timeout per invocation; fixture root asserted before mutation.
4. **Leading-dash basename is safe at the counter layer**: the value passed is `tools/-runner.py` (does not begin with `-`), all fixture git calls use the `--` separator, and a clean argparse probe of the exact CLI shape parses it fine (receipts/argv_probe_clean.log). A basename-first `-runner.py` value *would* be an argparse hazard ("expected one argument"), but that is not this cell's spelling.
5. **Identical expectations for `changed`/`missing` (both 1/DRIFT)** mean the counter cannot distinguish a tool that conflates "content differs" with "absent" — but the contract maps both to the same exit/token, so there is no cell-level misclassification.

Risk surface this cell exercises (tool-side failure modes the counter correctly scores as failure — not counter bugs):

- **Worktree confusion**: disk state is the dangling symlink for all six invocations; a tool reading the worktree instead of commit objects emits the same verdict for every class and fails `equal`/`unrelated`.
- **`<commit>:<path>` disambiguation pitfall**: `git rev-parse 5a62d71f:tools/-runner.py` fails rc=128 with "exists on disk, but not in '<sha>'" and still echoes `<sha>:tools/-runner.py` on stdout (git 2.56.0). A tool mapping any such failure to UNAVAILABLE emits exit 2 for this cell instead of 1; the counter then correctly fails the tool. Object-level probing (`ls-tree`, empty output = absent) is the sound method — the oracle demonstrates it.
- **History walking**: the path exists in ancestors of the missing commit; a tool keying on history instead of the commit tree would wrongly bind and be correctly failed by the counter.
