## Misclassification review — can the frozen counter misclassify THIS cell?

Outcome check is `out.returncode == expected and token in (stdout+stderr)`. Findings:

1. **Cause-agnostic pass (main risk).** ANY exit-2 invocation whose combined output
   contains the substring `EXECUTOR_SOURCE_UNAVAILABLE` passes. Demonstrated with
   `receipts/T59W1S17-fake-tool.py`: a tool that exits 2 and merely prints the token
   in a usage banner for a *resolvable* candidate still satisfies the cell's check
   (observed exit=2, token present → counter would count OK). The counter verifies
   rejection outcome, not rejection reason; an always-reject tool is
   indistinguishable from a correct one on this cell alone (the other 23 cells
   disambiguate in aggregate).
2. **Substring, not exact token.** Output like `EXECUTOR_SOURCE_UNAVAILABLE_OR_DRIFT`
   would also match. Low practical risk but loose.
3. **Fallback tool caught.** At the unresolvable invocation HEAD=UNRELATED whose blob
   equals trusted (`74e4df76…`); a tool that silently falls back to HEAD/worktree when
   the candidate fails to resolve would exit 0 (BOUND) and be correctly FAILED by the
   counter (expected 2). Verified blob equality above.
4. **Crash-on-unicode correctly failed.** A tool raising on the non-ASCII argv exits 1
   with a traceback lacking the token → `ok=False` (expected 2). No misclassification.
5. **Environment parity is enforced.** Counter strips `GIT_*`, sets
   `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, runs `sys.executable -I`,
   `TMPDIR=<work>`, 30 s timeout. A tool relying on global git config behaves
   identically for all seats; a hang raises uncaught `TimeoutExpired` (crashes counter,
   denial not misclassification). Reproduced the sanitized env in all probes.
6. **All-zero SHA is robustly unresolvable** under git 2.56.0 (`rev-parse --verify`,
   `cat-file -e/-t` all fail); no special-casing of `0`*40 as null object was observed
   in the resolution path. Candidate class is unambiguous.

Verdict: the counter cannot be made to PASS this cell via a wrong-mechanism exit 2 +
token more than any other cell (inherent to outcome-only checking), and it correctly
fails the plausible wrong behaviors (HEAD fallback, unicode crash, treating
unresolvable as clean). No cell-specific misclassification path found beyond the
general cause-agnosticism noted.
