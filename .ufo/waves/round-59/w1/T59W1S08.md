## Frozen-counter misclassification review — this cell

Counter-side mechanics for `path='tools/space name.py', class='changed'` are sound; no counter defect found:

- Path is passed as a single argv element (`subprocess` list, no shell) → the space cannot split; verified same invocation shape in this probe.
- Expected mapping `expected=1`, token `EXECUTOR_SOURCE_DRIFT`, checked against `stdout+stderr` — correct per contract exit map.
- Env sanitization (`GIT_*` stripped, `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `TMPDIR=work`) mirrored here; fixture commits use explicit `-c user.*` so no global-config dependence.
- Fixture construction is deterministic; `versions['changed']` is a real descendant commit, and the trusted/changed blobs were verified above.

Residual false-result vectors are tool-side, not counter-side, for this cell:

1. **Shell interpolation**: a tool building `git show <candidate>:<path>` via shell would split at the space → could map to exit 2 (false fail) or, if it then reports "missing" with exit 1, a **false pass** (token matches without comparing the real path). The counter cannot detect a tool that emits DRIFT for the wrong reason.
2. **`-I` isolation**: the counter runs the tool with `sys.executable -I`; tools needing `PYTHONPATH`/site packages will crash — an uncaught crash exits 1 without the DRIFT token, so the token check correctly counts it as fail.
3. An always-DRIFT tool would falsely pass this cell but is caught by the `equal`/`unrelated` cells in the same 24-cell grid; the counter's control structure covers this.

Verdict: the frozen counter classifies this cell correctly for any tool that itself satisfies the CLI contract; misclassification requires a tool defect (space mishandling being the only path-specific hazard), which the other 23 cells and the claim's controls are designed to surface.
