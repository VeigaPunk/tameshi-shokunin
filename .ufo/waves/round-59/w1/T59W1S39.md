## 2. Git primitive facts (scratch-verified, `receipts/git-facts.log`)

- Empty blob OID is universal: `git hash-object -t blob /dev/null` →
  `e69de29bb2d1d6434b8b29ae775ad8c2e48c5391`.
- A committed empty file is a **regular** blob: `100644 blob e69de29b… 0`.
- `git cat-file -t/-s` → `blob` / `0`: empty is resolvable, distinguishable from
  missing (no tree entry) and from symlink (`120000`).
- `.gitattributes` (`*.py text eol=crlf`) does **not** alter the empty blob.
- An empty-target symlink cannot be created (`os.symlink('', x)` → ENOENT).

## 3. Failed attacks (preserved)

1. **Spelling confusion**: the four contract spellings of an empty file all hash
   to the same OID; the equal-empty 4-path case (`EE4`) passes on the sound
   reference. Equality cannot be broken by path spelling.
2. **Filter smuggling**: `.gitattributes` clean/smudge filters cannot resurrect
   content from a 0-byte blob (receipts/git-facts.log).
3. **Empty-target symlink** to defeat the regularity check: not creatable at the
   OS level; the symlink class is unaffected.
4. **Injecting empty fixtures into the frozen counter**: rejected — the counter
   is frozen/read-only and modifying it would void the measurement. The attack
   was demonstrated instead through the counter's documented `--tool` control
   override against a scratch clone of the lane at the freeze rev.

## 4. Claim boundary

**Inside.** An empty committed file at a declared path is a *declared regular
executable-source blob* (mode 100644, type blob, size 0); the contract exit map
applies to it unmodified. Out of scope per the trust boundary: whether a trusted
revision *should* ever declare an empty source — the trusted revision is
verifier-supplied, and the skipped-work control is a separate verifier control.
The gap is in counter **coverage**, not in the claim text.

## 5. Smallest sound behavior

No size-0 special case. Per declared path:

1. Resolve both commits: `git rev-parse --verify <rev>^{commit}`; failure →
   exit 2 `EXECUTOR_SOURCE_UNAVAILABLE`.
2. Trusted entry must exist as a regular blob (`git ls-tree -l <trusted> -- <path>`;
   type `blob`, mode `100644`/`100755`); otherwise exit 2 (invalid trusted source).
3. Candidate entry missing or not a regular blob (symlink `120000`, gitlink
   `160000`, tree `040000`) → exit 1 `EXECUTOR_SOURCE_DRIFT`.
4. OID inequality → exit 1 `EXECUTOR_SOURCE_DRIFT`.
5. All paths equal → exit 0 `EXECUTOR_SOURCE_BOUND`.

Empty blobs flow through identically to non-empty ones. (Scratch `ref-sound.py`
classifies symlinks via OID difference; the spec above checks regularity
explicitly — identical exits on every case tested.)
