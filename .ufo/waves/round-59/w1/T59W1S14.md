## Misclassification review for this cell

**False pass — confirmed (case 5).** The frozen counter builds the entire version chain for a
path first, then runs all six class invocations; the worktree is therefore in the *symlink*
state (`tools/日本語.py -> elsewhere.py`, dangling) for every run of this cell. A tool that
decides by opening the worktree path (never resolving the candidate commit) hits the dangling
symlink, fails, and — if it maps any read failure to `EXECUTOR_SOURCE_DRIFT`/exit 1 — matches
this cell's expected outcome exactly. The strawman in `receipts/strawman-worktree-tool.py`
(proof of behavior, not a submission) is scored `ok=true` by the counter's exact rule
(`returncode == 1 and token in stdout+stderr`) while inspecting zero committed objects.
Scope of the hazard across cells: same false-pass pattern covers `missing` and `symlink`
(expected 1); `equal`/`unrelated` (expected 0) and `unresolvable` (expected 2) reject the
strawman, so whole-claim gaming needs more than worktree reading, but **this cell alone is
misclassifiable**. Mitigation for the integrating seat: the production tool must resolve
`<candidate>:<path>` objects (e.g. `git rev-parse`/`cat-file`/`ls-tree`), never the worktree;
a reviewer can detect worktree dependence by nothing more than this cell's dangling-symlink
setup.

**False fail — not found on this host.** Vectors checked: non-ASCII path is passed as a
Unicode argv (NFC from frozen PATHS) and round-trips fine under both host locale
(`en_US.UTF-8`) and the counter's inherited env; `git ls-tree` quotes the filename in output
(`core.quotepath`), which affects only naïve full-line parsers, not `--path`-filtered use;
fixtures are same-user (no `safe.directory` trip); `python3 -I` isolated mode and the 30 s
timeout are benign; both blobs are mode `100644`, so no mode-only flips. A conforming,
object-based tool is scored correctly (cases 1 and 4).
