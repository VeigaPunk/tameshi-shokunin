## Verdict

The absolute-path surface splits cleanly at the claim boundary:

- **Inside boundary — `--repo` absolute: required and safe.** The frozen counter always passes `--repo` as an absolute path (`str(repo)`), so a gate that rejects absolute `--repo` fails scoring. Observed: absolute and even symlinked absolute `--repo` resolve correctly through `git -C` (receipt `abspath-repo-probe.txt`).
- **Outside boundary — `--path` absolute: unscored, but the unscored branch is safety-critical.** The 24 fixtures send only four repo-relative spellings, so absolute `--path` handling cannot move any of the 24 verdicts either way. However, a gate that resolves `--path` through the filesystem for absolute inputs — a plausible hybrid implementation — passes all frozen-style relative fixtures **and** is false-boundable: `--path /abs/evil.py`, an external file byte-equal to the trusted blob, returns `EXECUTOR_SOURCE_BOUND` / exit 0 while the declared in-repo source drifted. Demonstrated end-to-end against a strawman (receipt `strawman-demo.txt`). The frozen counter cannot see this branch because it never sends an absolute `--path`.

No change to the contract, the target 24, or the frozen counter is *required* for the claim to be decidable. The finding is a hardening requirement on the implementation L1 admits: fail closed on absolute `--path`, with no filesystem resolution of declared paths.

## 1. Git primitive confinement (git 2.56.0, counter-style fixture)

Receipt `git-probes.txt`. Fixture built exactly as the counter builds fixture-0 (`tools/runner.py`, trusted blob `print("real executor")`, candidate forged):

| `--path` spelling | `git show TRUSTED:PATH` result | object-space effect |
|---|---|---|
| `tools/runner.py` (baseline) | blob content, rc=0 | reference |
| `/tools/runner.py` (absolute anchored) | `fatal: path '/tools/runner.py' does not exist in '…'` rc=128 | **no root-anchoring**; leading `/` is a literal tree component |
| `./tools/runner.py` | blob content, rc=0 | `./` resolved inside object space |
| `tools/../tools/runner.py` | `fatal: path … exists on disk, but not in '…'` rc=128 | `..` never traverses trees |
| `/../tools/runner.py` | does not exist, rc=128 | parent-of-root meaningless |
| `../../etc/passwd` | `fatal: '../../etc/passwd' is outside repository at '…'` rc=128 | **git explicitly refuses the escape** |
| `/etc/passwd` | `fatal: path '/etc/passwd' exists on disk, but not in '…'` rc=128 | confined, but see failed-attack A1 |
| `tools/runner.py/` (trailing slash) | does not exist, rc=128 | — |
| `` (empty) | `git cat-file -t` → `tree` | empty path = root tree (non-blob) |
| `git ls-tree TRUSTED -- /tools/runner.py` | `fatal: Invalid path '/tools': No such file or directory` rc=128 | ls-tree pathspec ≠ object-name syntax; a gate mixing the two APIs gets inconsistent absolute-path behavior |

Key observations:

1. Git object-name syntax (`rev:path`, `cat-file`) is **self-confining**: absolute, traversal, and trailing-slash spellings all fail; they cannot name a blob outside the tree. A gate that hands `--path` **verbatim** to object lookup and never touches the filesystem for path resolution is sound on this surface by construction.
2. Failure classification is unambiguous for a verbatim gate: miss at *trusted* ⇒ "invalid trusted source" ⇒ exit 2 (`EXECUTOR_SOURCE_UNAVAILABLE`); miss/non-blob at *candidate* ⇒ exit 1 (`EXECUTOR_SOURCE_DRIFT`); miss at both lands on the trusted check first ⇒ exit 2. Observed against the sound reference for all six hostile spellings (receipt `verbatim-absolute-cases.txt`): every one exits 2 with `EXECUTOR_SOURCE_UNAVAILABLE`; `./tools/runner.py` exits 0 (`EXECUTOR_SOURCE_BOUND`).
3. The dangerous implementation is the one that **normalizes or filesystem-resolves** before lookup: `os.path.normpath`, stripping a leading `/`, `str(Path(repo)/path)` — the last is catastrophic because `os.path.join('/repo', '/etc/passwd') == '/etc/passwd'` (observed, receipt `strawman-demo.txt`).

## 2. Successful attack: hybrid gate false-binds absolute paths (preserved)

Strawman `naive-hybrid-gate.py` (receipts + staged copy): relative paths via git objects, absolute paths via `open()` when the file exists — the minimal plausible pattern that passes the frozen fixtures while adding an "absolute path convenience".

Observed (receipt `strawman-demo.txt`):

1. Frozen-style relative fixtures behave per contract: equal → 0 `EXECUTOR_SOURCE_BOUND`; changed → 1 `EXECUTOR_SOURCE_DRIFT`. A hybrid implementation therefore passes the 24 fixtures indistinguishably from a sound one — the counter is blind to the branch by construction, since no fixture sends an absolute `--path`.
2. Attack, all against the same repo (trusted = equal commit, candidate = forged commit):
   - `python3 naive-hybrid-gate.py --repo fixture-0 --trusted $TRUSTED --candidate $CAND --path $PWD/evil-equal.py` where `evil-equal.py` (outside the repo) holds the trusted bytes → **rc=0, `EXECUTOR_SOURCE_BOUND`** — a false bind in the presence of declared-source drift, read from outside the repository.
   - `--path /etc/passwd` → rc=0 `EXECUTOR_SOURCE_BOUND` (system file exists and is byte-stable across the two reads).
   - `--path /tools/runner.py` and traversal spellings → rc=2 here only because those absolute files do not exist on disk; the branch is "exists on disk → read it".

Impact: in production use of the gate as a binding prerequisite, an executor that can influence a declared path string could substitute an external byte-equal file and certify a source the repository does not contain. Within round-59 scoring: **no impact** — see §4. This is a fixable implementation defect class, not a tradeoff.

## 3. Failed attacks (preserved, with reasons)

- **A1 — filesystem-existence oracle.** `git show rev:/etc/passwd` replies `fatal: path '/etc/passwd' exists on disk, but not in '…'` while a nonexistent absolute path gets `does not exist in`. Git's stderr leaks whether the path exists on the *verifier's* filesystem. Not a false pass: the exit is failure either way, and the contract's token check is satisfied by the gate's own message. Informational hardening: gates should emit their own reason line, not relay raw git stderr as the sole diagnostic.
- **A2 — symlinked `--repo` / fixture-root confusion.** `git -C symlinked-repo` resolves transparently (rc=0 observed); the counter already neutralizes symlinked parents via `Path(a.work).resolve()` plus its `rev-parse --show-toplevel` equality assertion. Verifier-controlled inputs; not attackable by an executor.
- **A3 — pure-traversal escape via git.** `rev:../../etc/passwd` is refused with "outside repository" (observed). Escaping the tree through object-name syntax is impossible in git 2.56; a gate would have to reimplement filesystem resolution to be vulnerable — which is exactly the strawman defect of §2, demonstrated there instead.
- **A4 — absolute `--path` moving a frozen verdict.** All 24 fixtures use repo-relative spellings, so no absolute-path input reaches the gate during scoring. Confirmed by reading the frozen counter source; no run needed.

## 4. Claim-boundary statement

- **In boundary:** `--repo` absolute path handling (the counter passes absolute `--repo` in every one of the 24 invocations). Must exit 0 on the equal class. Also in boundary: everything the 24 fixtures exercise.
- **Out of boundary (unscored):** every absolute/traversal/trailing-slash/empty `--path` spelling, symlinked `--repo`, and the oracle of A1. None of these can change `passed/24` under the frozen counter.
- Claim text check: the claim is scoped to "24 independently executed committed-object fixtures … with a skipped-work and always-accept control failing". Absolute paths are not among the "four path spellings"; requiring the gate to reject them does not enlarge the claim, and the contract's exit map already covers the behavior (`2` = "bad arguments, invalid trusted commit/source"). The trust boundary line ("checks declared Git blobs only") supports verbatim object lookup and nothing filesystem-based.

## 5. Smallest sound behavior (proposal)

1. Treat each `--path` as an opaque string handed **verbatim** to git object lookup (`cat-file -t`/`show`) against both revisions. Never call `os.path.*`/`pathlib` on `--path`; never join it to `--repo`; never normalize (no `normpath`, no leading-slash strip).
2. Map: not a blob at `--trusted` ⇒ exit 2 `EXECUTOR_SOURCE_UNAVAILABLE` (names the path); not a blob at `--candidate` ⇒ exit 1 `EXECUTOR_SOURCE_DRIFT` (missing/nonregular); unequal blobs ⇒ exit 1; all equal regular blobs ⇒ exit 0 `EXECUTOR_SOURCE_BOUND`.
3. Optional belt-and-suspenders argument validation (reject leading `/`, any `..` component, empty string, NUL) is compatible with this mapping — under verbatim lookup every rejected spelling was already exit 2 via the trusted-miss path, so validation changes no scored verdict. If validation is added, apply it before any git call and emit the same exit-2 token.
4. `./` components: verbatim git accepts `./tools/runner.py` (observed rc=0). Pin whichever L1 prefers; the recommendation is to accept (it is git-object-resolved, confinement-preserving) and record it, so the behavior is decided rather than accidental.
