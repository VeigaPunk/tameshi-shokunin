# T59W1S62 — Attack: 24-case fixture independence

Seat role: UFO-FSD critic, leaf. Scope: adversarial review of the frozen
round-59 counter's discriminative power. No production mutation; all fixtures
built under `/fast/scratch/hyaku/tameshi-r59/T59W1S62` (deleted after receipts
were copied to this report directory).

## Question

Can a tool pass 24/24 by discriminating path/class from revision hashes and
fixture fingerprints **without comparing declared source blobs to the trusted
revision** — i.e., is "24 independently executed fixtures" actually
independent, or is it one deterministic transcript a white-box submission can
key on?

## Findings

1. **Hash-only discrimination is bounded at 20/24.** The four `unrelated`
   fixtures (candidate ≠ trusted, declared path byte-identical) are the sole
   cases that force any tree/blob comparison. Revision-hash *syntax* —
   including the all-zeros unresolvable sentinel — cannot split `changed` from
   `unrelated`. So the counter does discriminate "compares revisions" from
   "compares hashes" on one axis.

2. **But the counter cannot distinguish "compares blobs" from "recognizes the
   transcript."** Two mutually independent cheats pass 24/24:
   - *Sequence cheat*: the 24 invocations are one fixed, ordered, same-process
     transcript with a shared writable `$TMPDIR`. A stateful tool needs ~15
     lines and no git access. Note the state channel survives even a
     per-invocation TMPDIR hardening: the tool also receives `--repo`, a
     directory it may write; the counter never checks fixture-repo integrity
     after the run.
   - *Fingerprint cheat*: all fixture constants are frozen and public — commit
     message `fixture`, author `fixture@example.invalid`, content strings
     `print("real executor")` / `print("forged success")`, repo names
     `fixture-<ix>`, fixed class order. A tool that pattern-matches these and
     ignores `--trusted` entirely passes. Because fixture hashes are
     timestamp-nondeterministic, the only stable key material is exactly these
     public constants.

3. **"Independently executed" is the weak word in the claim.** The 24 cases
   are not independent draws; they share trusted commits, repos, content,
   ordering, and environment. The counter certifies behavior-on-this-transcript,
   not the general capability "compare declared executor source blobs to a
   trusted revision." This is a white-box overfit limit of any frozen public
   counter, not an implementation defect in the submitted tool.

4. **Fixable vs tradeoff.** The gap is fixable by the verifier (blind/hidden
   fixtures); it is not something the submitted `tools/executor-source-pin.py`
   can repair, and demanding it from the executor would enlarge the claim.

## Blind probes proposed for L1 final review

Cheap, all verifier-side, none changes the frozen counter for other lanes:

1. **Permute class order per fixture** (random shuffle seeded per run) and
   randomize path↔fixture assignment. Kills the sequence cheat outright.
2. **Per-invocation fresh `TMPDIR`** and post-invocation fixture-repo
   integrity check (e.g., `git status --porcelain` + no new files at repo
   root, or rebuild+hash comparison). Closes both state channels.
3. **Randomize fixture constants**: payload bytes (not the two known
   strings), commit messages, author, repo dir names. Kills the fingerprint
   cheat; forces content-generic logic.
4. **Content-invariance probe**: fixture where trusted/candidate blobs are
   equal but hold random nonce content; require exit 0 regardless of content.
   Detects tools that accept only recognized strings.
5. **Hidden negative controls** (not in the 24): candidate==trusted but path
   absent at trusted (invalid trusted source → 2); declared path is a tree at
   candidate (→1); mode-only change `100644→100755` (→1, since mode is part
   of the blob record); candidate an ancestor of trusted where the path
   differs; extra `--path` flags including a matching and a non-matching path
   in one invocation (multi-path must still exit 1 if any declared path
   drifts).
6. **Double-run requirement**: run the blind counter twice with different
   seeds and require identical pass/fail, so a tool cannot pass by luck of
   one ordering.
7. **Trusted-neglect canary**: include one fixture whose trusted blob equals
   the forged-content blob and candidate differs — a `--trusted`-ignoring
   tool keys on content and fails.

Axis impact: operability (C1) measurement validity; no contract, route, or
trust-boundary change proposed.
