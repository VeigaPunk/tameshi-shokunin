## 24-case failing discriminators

### always-accept fake → 8/24, 16 failing rows

Failing rows (all 4 path spellings each): `changed` (exp 1/DRIFT, got 0/BOUND),
`missing` (exp 1/DRIFT, got 0/BOUND), `unresolvable` (exp 2/UNAVAILABLE, got
0/BOUND), `symlink` (exp 1/DRIFT, got 0/BOUND). Only `equal` and `unrelated`
false-pass — the fake indiscriminately blesses drifted, missing, symlinked, and
unresolvable candidates.

### always-unavailable fake → 4/24, 20 failing rows

Failing rows (all 4 path spellings each): `equal` (exp 0, got 2), `changed`
(exp 1/DRIFT, got 2/UNAVAILABLE), `missing` (exp 1/DRIFT, got 2), `unrelated`
(exp 0, got 2), `symlink` (exp 1/DRIFT, got 2). Only the 4 `unresolvable` rows
match, and solely because the fake's constant exit-2/token output coincides with
that class's expectation.

### Cross-fake conclusion

The two fakes false-pass on disjoint classes (accept: equal+unrelated;
unavailable: unresolvable) and each is caught on ≥16/24 rows. No constant-output
gate can reach 24/24; a correct gate must emit all three exit codes and produce
`EXECUTOR_SOURCE_DRIFT` vs `EXECUTOR_SOURCE_UNAVAILABLE` path-dependently
(drift/missing/symlink → 1, unresolvable → 2, equal/unrelated → 0). Full 48-row
per-case table with observed stdout/stderr: `stage/receipts/discriminator.json`;
raw counter receipts: `stage/receipts/measure-{accept,unavailable}.{out,err}`
(counter stderr empty in both runs).
