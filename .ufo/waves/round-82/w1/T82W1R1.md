## D. Findings by severity

### D1 — MEDIUM: the regular-blob guarantee covers 2 of the 5 row kinds; three register rows are mode-blind
`check_receipt_tokens` (L242), `check_sources_cell` (L283) and `check_doc_contains`
(L317) call `blob_bytes` directly and never consult `regular_file_state`. A
**120000 symlink closes them**:

- `R-link-tokens` — `receipt` = symlink whose target string is `24/24 17/17`:
  `state=closed detail=tokens-in-span-and-receipt`.
- `DOC-SYM` — `doc` = symlink whose target carries the span:
  `state=closed detail=tokens-in-span-and-receipt`.
- `R-link-doc` — `doc` = symlink: `state=closed detail=section-carries`.
- `S-link` — `corpus/SOURCES.md` (the fixed `SOURCES_PATH`) replaced by a
  120000 symlink whose target is a valid `| S289 | … |` row:
  `state=closed detail=cell-carries`.

The register's **D2, D4, D6** rows use exactly these kinds. Today they are
closed by regular blobs, so the counted line is honest, but the instrument does
not enforce "closed on regular blobs" for them: a symlink at D2's receipt path
(long enough to carry `24/24` and `17/17`) or at `corpus/SOURCES.md` still
measures `closed`. The base instrument showed the same four closures, so this
is the pre-existing class the plan's sentence says it closes, closed only for
the two `tree-*` kinds.

**Judgment:** if "a path row" in the plan means the `tree-*` kinds only, the
sentence is implemented as written and this is a scope limit to record; if
"closed on regular blobs" is read over all six rows (it names the register, and
the kill rule says "a directory or symlink satisfying a path row"), the counter
implements a **narrower** sentence. Recommend either extending
`regular_file_state` to `doc`, `receipt` and `SOURCES_PATH` (three call sites)
or narrowing the landing record to "`tree-*` path rows" so the guarantee is
stated at its actual width. A directory in a token row is not a false close: it
raises `blob-unresolvable` (exit 2), consistent with the L40 contract.

### D2 — LOW: bind and population are two reads; a writer between them yields `manifest=bound` on narrowed rows
`bind_manifest` reads the disk manifest at L441 and returns after the byte
compare; `sweep` then re-reads the path at L456 (`load_manifest`). Deterministic
in-process demonstration (mutation injected between the two reads): sweep prints
`DEFECT_BIND: rows=1 closed=1 open=0 unexpected=0 manifest=bound`, exit 0 — the
exact cheat the claim forbids, with a "bound" line. A real exploit needs write
access to the manifest path during the run, which in a fleet means a sibling
process. Fix is local: parse the rows from the already-read bound blob
(`json.loads(proc.stdout)`) instead of re-opening the path.

### D3 — LOW: the bind is type-blind on its own manifest
`bind_manifest` uses `cat-file blob REV:path` with no `regular_file_state`.
Fixture: commit `symmanifest.json` as a **120000 symlink** whose target string
is a valid one-line manifest; replace the worktree entry with a regular file of
the same bytes → `manifest=bound`, rows measured (exit 0). The register at the
declared revision is then not a regular file, which is the class the round
closes for rows. Byte-identical storage makes the line literally true, but the
instrument should apply its own boundary to the population's own path (two
lines: `regular_file_state(repo, resolved, path)` before the compare).

### D4 — INFO: `manifest=bound` does not name the resolved revision
Binding at rev2 while HEAD=rev4 with identical manifest bytes is accepted (P8).
That is honest — the bind is byte-addressed (same blob id at both revisions),
and the rows' revisions are declared separately inside the manifest — but the
summary cannot be re-derived to a commit, and the plan's after-line has the
same shape. Not a defect; record as a reporting limit if the receipt is ever
read as "bound at HEAD".

### D5 — INFO: relative `--manifest` resolves against cwd, absolute against realpath
From a cwd outside the repo, `--repo D --manifest manifest.json` binds an
identical-bytes copy (exit 0) and refuses a narrowed copy (exit 2). Honest by
bytes (the loaded population equals the committed population), but the
`--manifest` path is not proven to be the repo's path. Consequence asymmetry:
`lnk/manifest.json` relative is refused (`manifest-rev-unreadable`), the
absolute name of the same file is accepted. No false bound.

### D6 — INFO: pathspec-magic text in a row path
`:(glob)…` aborts the sweep (`ls-tree-failed`, exit 2); `:(literal)…` and
`:(icase)…` measure `missing` (false open). Never a false close; no register
path carries pathspec syntax.

### D7 — CONFIRMED declared limit (S311)
`text eol=crlf`, worktree CRLF, blob LF, `git status` **clean** for the
manifest → `manifest-rev-mismatch`, exit 2. The declared limit is real and
bounded: conversion can only produce a false **refusal**, never a false
`bound`. `tools/defect-bind.json` carries no conversion attributes
(`git check-attr -a` prints nothing), so today's line is unaffected.

## E. Verdict on the sentence

The counting-command clauses are implemented **exactly**: `rows=6 closed=6
open=0 unexpected=0 manifest=bound` at exit 0 with the population byte-frozen at
both revisions, and the narrowed manifest is refused at the register's own
path before any row prints. The "closed on regular blobs" clause is implemented
for the two `tree-*` kinds only: **3 of the register's 6 rows (D2, D4, D6) sit
on kinds that still close on a 120000 symlink**, and the binding is not atomic
with the population it measures and does not type-check the manifest object.
So: **exact for the line, narrower than the sentence for the guarantee** —
unless "path row" is read narrowly, in which case the line is exact and D1 is a
statement-width note for the landing record.
