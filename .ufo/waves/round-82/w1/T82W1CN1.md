Scope: item asks (1) which sibling lanes bind a manifest/register to a revision or to
committed bytes, (2) whether R82-C1's `--manifest-rev` is new in kind, under tameshi
PROVINCE's rule that **"a pattern is admitted from evidence in TWO independent lanes

reuse recommendation. Findings only; nothing absorbed.

## Verdict

**R82-C1 is not new in kind.** The device — *a declared population is bound to a
declared revision, and any difference between the measured bytes and the committed
bytes is a REFUSAL rather than a pass* — is already implemented in full in **two
independent lanes** (souji r19/r20, tabi r16) and in byte-pin form in a **third**
(kumitate r54). PROVINCE's two-lane test is satisfied **before** tameshi's round 82.

What *is* new in R82-C1 is narrower and should be stated that way: the **register
shape** (six rows each carrying its own `expect`/`state` predicate) and the
narrowed-population cheat refused as a *population-level* event. The binding kernel
beneath it is prior art.

## 2. Is `--manifest-rev` new in kind, or a lane-specific encoding?

**A lane-specific encoding.** Nearest prior art and the one-sentence difference for each:

- **souji `souji-rev-pin.py::input_snapshot` (r20) — the same triangle, complete.** It
  binds a declared regular-file/directory path set to a declared revision, hashes both
  sides, refuses on `missing/added/changed`, and refuses a non-blob mode or a symlink.
  Difference: its population is a caller-supplied path list with **no per-row state
  predicate** — it yields byte equality only, never `closed`/`open` rows.
- **tabi `check-measurement-binding.mjs` (r16) — the same triangle, independently.**
  Counter bytes sha256 × declared `countedInputs` × `measuredRevision`, with drift
  between the measured and audited revision refused. Difference: the population is a
  **counter's input set**, not a defect register, and its drift leg compares two
  *revisions* rather than the worktree to a revision.
- **kumitate `counter-pins.mjs` (r54) — the byte half.** Refuses a name in place of
  bytes (symlink) and refuses an empty pin set. Difference: the expected digest is a
  **registry constant**, so there is no `--rev` and no declared revision at all.
- **kumitate `gate-mutants.mjs --rev` (r43) — the type/mode half.** Refuses any
  non-regular tree entry when loading a population at a revision. Difference: it never
  reads the worktree, and its manifest is a **source constant** hashed by
  `manifestSha256()`, not a file read at a revision.

So the honest claim for R82-C1 is adoption + one new binding *target* (a defect
register rather than an input set), not the invention of revision-bound populations.

## 3. Contested scope, and reuse recommendation

**Contested scope — names, not surface.** Three lanes already carry a *named*
capability row for this pattern, each scoped to its own object:

- souji `SCORECARD.md:167` `durable revision stamps (r19)` and `:172` `blob-bound receipts (r23)`;
- tabi `SCORECARD.md:744,754` the enforced measurement-binding contract;
- kumitate `SCORECARD.md:1957` `counter-pins`.

None of them owns `closure-defect bind`, and none can measure tameshi's register. So
there is **no tool-level collision** — but a tameshi capability row named generically
(e.g. "register binding") would collide with all three. Keeping the row name
`closure-defect bind` and naming this prior art in the row's evidence cell is the
non-contested framing. No sibling's gate code may be edited from this lane.

**Reuse recommendation (one bounded move, later round — not this one).** Two of
tameshi's own older binding instruments still carry the exact defect class A12 closes,
and both are cheaper to fix than to re-derive:

1. `tools/receipt-revision-gate.py::drifted_paths` (`:75-84`) never asserts entry
   type — it takes `--paths` and runs `git diff --name-only A B -- <paths>`, so a
   listed **directory** whose subtree is unchanged reads as "content-identical" and
   satisfies the row; its `gone` leg uses `git cat-file -e A:<path>`, which accepts a
   tree. Measured in a throwaway fixture (below): `cat-file -e <rev>:<dir>` → rc 0;
   `diff --name-only <rev> <rev> -- <dir>` → empty, rc 0.
2. `tools/receipt-bytes-bind.py::blob_at` (`:120-121`) uses `cat-file blob <rev>:<path>`.
   Measured: a **tree** is rejected (rc 128), but a **symlink is accepted** and its link
   text is hashed (rc 0, printed `a.txt`) — the same "symlink target string" defect the
   round-82 plan quotes. The A12 allowlist (`ls-tree` mode ∈ {100644,100755} **and**
   type == blob, before hashing) is the drop-in fix.

Applied to both, the mode/type guard would then exist in tameshi, souji and kumitate
against three different objects — which is what makes it general rather than local.

**Cross-lane note (report only, never absorb).** souji `input_snapshot` compares
worktree bytes to blob bytes by sha256 with no attribute-conversion guard — the same
`text`/`eol`/filter limit R82-C1 declares as S311, undisclosed in souji. Routed to
souji, not fixed here.
