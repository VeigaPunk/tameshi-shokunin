### 1.2 Pin-audit semantics

`pin_audit` is exactly `settled := blob(rev,path) == blob(pin_rev,path)` per row (`pin_audit` at
`tools/selfstate-freshness.py:1216-1246`), so a row is settled at tip `T` iff its pin names a commit
whose instrument blob is byte-identical to the blob at `T`. Consequence that the plan text never
states: **the commit carrying the manifest cannot name itself when it also changes an instrument.**
The manifest's bytes are part of the commit id; writing that id into the manifest changes the id
(fixed-point impossibility). I measured the two halves in a throwaway fixture repo under my scratch
root (`mktemp -d`, `git init -q`, `rev-parse --show-toplevel == $D` asserted; the real
`pin_audit` was used, not a re-implementation):

| fixture state | measurement |
|---|---|
| r1 = instrument v1; r2 = records commit (manifest pins r1, instrument untouched) | `SELFSTATE_PINS: rows=1 settled=1 stale=0` exit 0 |
| r3 = a landing commit that also edits the instrument | `SELFSTATE_PINS: rows=1 settled=0 stale=1` exit 1 |
| r4 = records commit naming r3 (manifest only) | `settled=1` exit 0 — r4 ≠ r3, so no self-pin |
| r5 = manifest naming r4 | r5 ≠ r4; naming a prior instrument commit is always possible |

So the rule is not "two commits" but **"the manifest commit must postdate the last commit that
changes each pinned instrument"**; "instrument commit first, records commit second" is a sufficient
instance of it. The plan does not state this order anywhere (only "measured at the records commit"
and "unchanged after this declaration"), so it is L1 procedure, not a frozen sentence — and the
watchdog that enforces it is `--pin-audit` itself (a violated order reads `stale`, exit 1).

## 2. R82-C3 — what `SELFTEST_TEXT_SHA256` covers, and what it misses

### 2.1 Digest, region, and the constant's position

Independent computation on the landed bytes (`b6658e7a`):

- `sha256(inspect.getsource(selftest).encode('utf-8'))` =
  `f74f2d4e3dc4ebe91da91aa7b2cf515af6ee217e6deddc8c7ac52011fa2dbb85`
  = the in-file `SELFTEST_TEXT_SHA256` (match).
- The region is file lines **586–832**, 247 lines, first line `def selftest(out=sys.stdout):`, last
  line `    return 0 if (passed == total == SELFTEST_ARMS) else 1`.
- The constant's **literal** is at module line **92**, outside the region; the function only
  references the name (`… measured == SELFTEST_TEXT_SHA256 …`). So a deliberate recompute is
  possible in one place — proved by the two-edit probe below and by the in-history recomputes
  (`72832c94`, `ea618593`), where the digest/constant pair changed together
  (`ea618593`: `9d9dcf373be1f13795c6382d39e36551e04bf9ceadf3de375158beb23e78e8a7`, match).
- Coverage: 14 distinct arm names / 15 `arm("A…` call sites (A14 appears twice, try and except) —
  every arm's **inline text** is inside the digest. But two arms delegate their predicate to
  module-level `_expect_setup` (A8, A13) and several use module-level `Fixture`/`run_git`. A single
  module-level edit `return str(exc)…` → `return True` in `_expect_setup` leaves the digest
  **unchanged** and the suite at **14/14, exit 0** (measured). So the pin covers every arm's text,
  not every arm's predicate; "module-level edits stay outside the class" is declared, and this is
  the concrete instance of it.

### 2.4 Finding C3-F2 (plan sentence false) — the vacuous comment is detected, not outside the class
