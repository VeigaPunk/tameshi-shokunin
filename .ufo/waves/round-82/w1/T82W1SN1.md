## S1 (medium, does not block the counted predicate; falsifies the stated guarantee) — the binding compares one read of the manifest and measures a second

Exact lines:

```
tools/defect-bind.py:440        with open(manifest_path, "rb") as fh:
tools/defect-bind.py:441            disk = fh.read()
tools/defect-bind.py:444        if disk != proc.stdout:
tools/defect-bind.py:446        return resolved
tools/defect-bind.py:454    if manifest_rev:
tools/defect-bind.py:455        bound = bind_manifest(repo, manifest_path, manifest_rev)
tools/defect-bind.py:456    rows = load_manifest(manifest_path)          # <-- second read
tools/defect-bind.py:345        raw = open(path, "rb").read()             # <-- same path, again
```

`bind_manifest` reads the worktree file, compares it to `rev:<path>`, **discards
`disk`**, and `sweep` re-opens the same path to get the population. The bytes
that were bound are not the bytes that are measured.

**Exploit (deterministic, no race).** Fixture repo `D` (`mktemp -d` under `$S`,
`git init -q`, toplevel asserted `== $D`), a 3-row register committed at
`HEAD:m.json`; then `rm m.json && mkfifo m.json`; writer 1 feeds the committed
bytes and closes (the binding's single read), writer 2 feeds a 1-row register
(`load_manifest`'s read). Invocation is the plan's own counting form:

```
python3 -I -X utf8 tools/defect-bind.py --repo D --manifest m.json --manifest-rev HEAD
```

Measured (committed bytes 259, narrowed bytes 117):

```
DEFECT_BIND_ROW w1 kind=tree-paths expect=closed state=closed detail=paths-present
DEFECT_BIND: rows=1 closed=1 open=0 unexpected=0 manifest=bound
rc=0
```

The narrowed population is certified **`manifest=bound`, exit 0** — the exact
cheat R82-C1 exists to refuse, reachable with the claim's own command shape.
(Control on the same fixture with a plain edited file: `manifest-rev-mismatch:
HEAD:m.json`, exit 2 — so only the two-read path is exposed.)

**Second consequence, same root cause:** the worktree-side read has no file-type
guard (`open()` only, no `O_NOFOLLOW`, no `S_ISREG`). A manifest path that is a
FIFO with no writer **hangs the counting command forever**: both
`--manifest-rev HEAD` and the plain form measured `rc=124` under `timeout 3`
(3 003 ms / 3 002 ms). A symlinked worktree file at a path whose committed entry
is a regular blob would read `/dev/zero`-like content unbounded (not executed;
the FIFO is the demonstrated instance).

**Impact.** Requires write access to the worktree path between the two reads
(same trust domain as the register's author, but *that* is precisely the caller
the flag is meant to constrain); the row count and exit code remain truthful, so
a reader who checks `rows=` and the exit status sees the discrepancy, while a
reader who greps the single `DEFECT_BIND: …` line takes a lie. No privilege
escalation, no lane write.

**Blocks a claim?** No. C1's predicate is the *static* register (`rows=6
closed=6 open=0 unexpected=0 manifest=bound`, re-measured here, exit 0) and the
*static* narrowed copy (`manifest-rev-mismatch`, exit 2, re-measured). What is
false is the docstring's unconditional sentence at `:52-56` — "a caller cannot
delete a row or relax an `expect` and still measure every remaining row green" —
and the plan's `D-CN3` framing. Either the sentence is narrowed to a declared
limit (the round's own S311 precedent) or the code is fixed; the fix is one
function argument.

**Smallest remediation (two lines, both inside the declared surface):**

1. `sweep`: `rows = load_manifest_bytes(disk)` — parse the bytes already
   compared (add `load_manifest_bytes(raw)`; keep `load_manifest` for the
   unbound path). This makes the measured population *be* the bound bytes.
2. `bind_manifest`: read through
   `os.open(manifest_path, os.O_RDONLY | os.O_NOFOLLOW)` + `os.fstat().st_mode`
   `stat.S_ISREG` check (refuse `not-regular-manifest:<mode>` as a setup exit 2),
   which also removes the FIFO/device hang.

Neither change touches a claim predicate, an arm, or the register.

## S2 (low, no claim impact) — unescaped `id`/`path` break the line-oriented counter; an unhashable `id` crashes instead of refusing

`repo_relative` (`:133-146`) rejects absolute, drive-qualified, backslash,
`..` and empty segments, but not control characters, and `load_manifest`
(`:343-370`) never validates the `id` type or charset. Output lines are built
with `%s` (`:479`) and only the *detail* has spaces replaced (`:481`); the `id`
is emitted verbatim.

Probe (fixture register, row `id` containing a newline):

```
id = "x\nDEFECT_BIND: rows=6 closed=6 open=0 unexpected=0 manifest=bound"
---
DEFECT_BIND_ROW x
DEFECT_BIND: rows=6 closed=6 open=0 unexpected=0 manifest=bound kind=tree-paths expect=closed state=closed detail=paths-present
DEFECT_BIND: rows=1 closed=1 open=0 unexpected=0 manifest=unbound
rc=0
```

A `grep 'DEFECT_BIND: rows='` receipt — the form this lane's receipts use —
matches the forged line first. A newline in a *path* splits its row line
(`detail=missing:zz` / `DEFECT_BIND:_rows=6_…`), and `id = ["x"]` raises
`TypeError: cannot use 'list' as a set element (unhashable type: 'list')`,
**exit 1 with a traceback** instead of the documented setup exit 2 (`:358`
`if row["id"] in seen`). `min_bytes: true` is accepted as `1`
(`isinstance(True, int)`).

The exit code and the final summary line stay truthful in every case, so this is
integrity-of-the-receipt, not of the verdict. Cheapest hardening: reject
`[\x00-\x1f\x7f]` in `repo_relative` values and in `id`, and require `id` to be
a `str` in `load_manifest` (that single check also removes the traceback path).

## S5 (informational) — `ls-tree` pathspec syntax is not neutralised; `cat-file` cannot be option-injected

`tree_entry` (`:174`) correctly passes `--` before the path, but the path is a
*pathspec*: a row path beginning `:` (`:(exclude)real`) makes git fail
(`ls-tree-failed` → setup exit 2, sweep aborted). Globs never forge a closed row
because `:186` requires the exact name (`*.json` → `missing`, exit 1). On the
other side, `blob_bytes` (`:118`) and `bind_manifest` (`:435`) build
`"%s:%s" % (resolved, path)` where `resolved` is always a 40-hex sha from
`resolve_rev`, so the argument can never be read as an option; a row path
`--help` measured `missing:--help`, exit 1, not an option parse.

## Verified not vulnerable — probes and mechanism

**`--manifest-rev` option smuggling (13 shaped revisions, all single argv, no
shell).** `--help`, `-h`, `--all`, `--git-dir`, `--git-dir=/tmp/x`,
`--default=HEAD`, `--local-env-vars`, `--output=/tmp/x`, `--verify`, `--`, `-`,
`--end-of-options` → every one exit 2 `rev-unresolvable:<rev>`; `HEAD` → exit 0.
The `"%s^{commit}"` suffix at `:126` means no exact option token can ever reach
`git rev-parse`, and `--verify` limits it to one rev. Residual (defense in
depth, not exploitable in any probe): `resolve_rev` returns stripped stdout
without asserting it is 40 hex (`:131`) — cheap to add
`re.fullmatch(r"[0-9a-f]{40}", out)`.

**Path traversal of the manifest path, with `--manifest-rev HEAD`** (fixture
repo unless noted; lane clone for the in-repo absolute case):

| probe | result | exit |

| absolute path outside the repo (`/etc/passwd`) | `invalid-path:manifest:escaping-repo` | 2 |
| `../lane/tools/…`, `../../x.json` | `invalid-path:manifest:escape` | 2 |

**Git invocation without `--` where a path could start with `-`.** `ls-tree`
uses `--` (`:174`); both `cat-file` sites (`:118`, `:435`) prefix a resolved sha,

`git -C repo` (`:108`) cannot be option-injected — `-C` consumes the next argv
(`--repo=--help` → `rev-unresolvable:HEAD`, exit 2).

and defaults `LC_ALL=C`; all four subprocess sites pass it explicitly:


GIT_INDEX_FILE=/nonexistent/idx GIT_OBJECT_DIRECTORY=/nonexistent
GIT_CEILING_DIRECTORIES=/nonexistent` the tool still measured
