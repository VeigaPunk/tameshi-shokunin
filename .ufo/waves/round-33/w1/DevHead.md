wrong verdict.

## Equivalence method — why each survivor is a real defect

For every survivor, `sim.py` asserts the extracted tally block is **byte-identical** to
pristine's (`assert block(mtext) == B`), then runs a capture-stage model in bash under
`set -u -o pipefail`: the nine `local st_*` declarations exactly as `run_regression` makes them,
then per position `st_ret ${R[i]}; st_<leg>=$?` (or the mutant's replacement lines), then the
verbatim tally block with the nine statuses passed as arguments. Pristine runs the same model
with the unmodified capture stage. Compared value = exit code + first stdout line.

Sweep: every status 0–255 at each of the 9 positions (2304), the (failing, setup) count pairs
(1,1),(1,2),(2,1),(2,2),(1,5),(3,3),(2,0),(0,2),(5,4) forward and reversed, plus nine-leg and
boundary vectors: 2450 vectors. Model caveat: the nine `regression_case_git` invocations are
omitted; their only contract-relevant product is the exit status, which is injected.

## Root cause (frozen tool)

- `tool.py:255` `all_assigns` and `tool.py:262` non-bare scan are line-anchored:
  `re.finditer(r'^[ \t]*(st_[A-Za-z0-9_]+)=(.*)$', head, re.M)`. `(( st_mado = 0 ))`,
  `printf -v st_checklist …`, `read -r st_claims …`, `unset`, `local`, `export`, `declare`,
  `{ …; }`, `for …; do st_x=0; done`, `! st_x=0` and helper-call bodies contain no
  line-initial `st_x=`, so they are never seen.
- `tool.py:262` also only inspects captures the regex found as bare, so `names` shrinks when a
  capture is masked and the masked name is not examined at all (m01–m06 are still killed by
  static/runtime, but `CHECK head` alone rides on `nonbare`, not on name identity).
- `tool.py:309` `check_runtime` executes only the extracted tally block; the head is never run.
- `tool.py:447` `check_harness` re-runs the runner's own selftest panel, which is block-only.
- `tool.py:273` applies the same line-anchored regex inside the tally block, so a hidden
  in-block assignment would escape as well (not exercised by this family).

## Smallest safe correction (validated on a scratch copy, not applied to the freeze)

Replace the non-bare scan in `check_head` with a name-occurrence scan: in the head, each leg
name may appear exactly twice — once on the `local st_…` declaration line and once on its own
bare `st_x=$?` line. Any other occurrence is a post-capture write and fails closed.

```python
nonbare = []
decl = None
for m in re.finditer(r'^[ \t]*local[ \t]+[^\n]*\n', head, re.M):
    if any(re.search(r'(?<![A-Za-z0-9_])%s(?![A-Za-z0-9_])' % n, m.group(0)) for n in names):
        decl = m.span(); break
for nm in sorted(set(names) | set(all_assigns)):
    for m in re.finditer(r'(?<![A-Za-z0-9_])%s(?![A-Za-z0-9_])' % nm, head):
        if decl and decl[0] <= m.start() < decl[1]:
            continue
        line = head[head.rfind('\n', 0, m.start()) + 1:].split('\n', 1)[0]
        if re.fullmatch(r'[ \t]*%s=\$\?[ \t]*' % nm, line):
            continue
        nonbare.append(line.strip()[:60])
```
