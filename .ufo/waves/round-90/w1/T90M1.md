## Method

1. **Defect spec written before any run**: `T90M1-defects.txt` declares 20 single-line
   defects `D01`–`D20`, each weakening exactly one conjunct or check of the counter
   (two-run requirement, timeout class, witness rule, duplicate-row refusal, S-id novelty
   guard, figure denominator, `bash -n`, canary, green token, `trivial0`, `mismatched0`,
   `coverage`, gate pin, spec pin, occurrence count, no-op refusal, UNSTABLE derivation,
   `n_min`, verdict-cell count, `invalid0`).
2. Each defect is applied to a scratch copy of the counter by exact single-string
   replacement; the harness asserts the `old` string occurs **exactly once**, that the
   line count is unchanged, and that the result compiles. Mutant sha256 (first 12) is in
   the results JSON.
3. The detector is the committed battery, driven by a scratch copy of `controls.py` with
   **exactly two lines changed** (documented below): the `measure` path is redirected to
   the mutated copy, and the receipt directory is redirected into scratch so the frozen
   receipts are never written. Every control state is therefore the same committed lane
   state the frozen receipts were produced from.
4. Three detector levels are reported, because they answer different questions:
   - **L2 (pre-registered, full receipt text)**: any difference in exit, `C1_R90_PASS`,
     `C1_CONJUNCTS`, `C1_ROW` lines or summary counts on any control state.
   - **L1 (check-level)**: same, but the `runs=` print column is excluded from row
     comparison — a row's *derived verdict, note agreement, invalid set, trivial flag and
     witness result* must change, not merely how many runs are echoed.
   - **L0 (verdict-only)**: a control's PASS/FAIL outcome or exit code changes.
5. **Baseline**: two pristine batteries (`BASE-A`, `BASE-B`) plus a comparison against the
   frozen receipts. All three agree on **all 16 control states at L2** (only the per-clone
   `rev=` field differs, and it is normalised). The battery is deterministic on this host,
   so a mutant difference is attributable to the defect, not to run noise.
6. **Concurrency disclosure**: the seat budget asked for at most 3 defect batteries at a
   time; the 19-defect run was launched at `--par 6` (`--jobs 3` each, 18 measure processes
   at peak) on a 32-core host. No control timed out: every battery exited 0, no
   `inconclusive0` conjunct flipped anywhere, and the two pristine baselines are identical,
   so the higher concurrency did not contaminate a verdict.

## Survivors — reachability by a real forgery

A defect is *reachable* iff some committed lane state (note / README / SOURCES / spec) is
rejected by the pristine counter and accepted by the mutated one. Probes ran both counters
on the **same clone revision** (`T90M1-reach.py`), so the comparison has no run noise.

| id | survivor | reachable? | proof / reason |
|---|---|---|---|
| D04 | duplicate note rows | **YES** | note with a duplicated `C02` row: pristine `exit=1` (ids), mutant `exit=0` |
| D05 | any S-id accepted | **YES** | note cites `S315`, `corpus/SOURCES.md` S315 flipped to `mined` with the note in used-by: pristine `exit=1` (source), mutant `exit=0` |
| D06 | figure numerator only | **YES** | note prints `measured: 5/9 killed` (right numerator, wrong denominator): pristine `exit=1` (figure), mutant `exit=0` |
| D19 | two verdict cells in one row | **YES** | row `\| C02 \| … \| SURVIVED \| KILLED \|`: pristine `exit=1` (ids, mismatched0), mutant `exit=0` |
| D01 | one run per verdict | no | needs a gate whose `selftest` is nondeterministic; gate bytes are pinned by the spec sha256 and the spec by `SPEC_SHA`, so no committed lane state can make it flaky. Latent: a flaky gate would be reported as stable |
| D02 | timeout → SURVIVED | no | needs a mutant whose `selftest` exceeds `timeout_s=180`; the mutant list is pinned. Latent: a hanging mutant would be reported SURVIVED (under-claim, inflates survivors) |
| D08 | canary hard-wired | no | canary is a harness self-check on the materialised copy; the gate is pinned. Latent: a harness that ran a different gate would go unnoticed |
| D09 | green without `selftest ok` | no | needs a gate that exits 0 without the token; the gate is pinned. Latent |
| D15 | duplicate `old` string | no | needs a spec whose mutant `old` occurs twice; the spec is pinned. Latent |
| D17 | UNSTABLE dropped | no | same as D01 — needs gate nondeterminism |
| D18 | `n_min` dropped | no | needs a spec with < 10 mutants; the spec is pinned. Latent |

So **4 of 11 check-level survivors are exploitable today** (D04, D05, D06, D19) and **7 are
latent** — blocked only by the gate pin, the spec pin, or gate determinism.

Four killed defects were also probed, to show their kills are not cosmetic: D11 (note row
disagreeing with the derived verdict), D12 (README without the note) and D14 (spec with a
killed mutant swapped for a survivor, note claiming `4/12`) are all **reachable forgeries**
that the pristine counter rejects and the mutated counter accepts. D13 (gate pin dropped)
is **not** reachable alone: its forgery needs a spec edit, which the spec pin still
rejects — its L1 kill is defence in depth.

## Findings

1. **The battery is a weak verdict-level detector.** Comparing only PASS/FAIL, 17 of 20
   single-edit weakenings are invisible; only the three that let a negative control flip to
   PASS (D11 via CTL2, D12 via CTL15, D14 via CTL5) are caught.
2. **Check-level comparison is stronger but still misses 11/20.** The six extra kills
   (D03, D07, D10, D13, D16, D20) appear only as a conjunct flag flipping on an existing
   control; every one of those controls still exits 1.
3. **Four checks are load-bearing and unguarded by any control**: duplicate note rows
   (D04), S-id novelty (D05), the figure denominator (D06) and ambiguous verdict cells
   (D19). Each admits a committed note/registry forgery today, proven above.
4. **Seven surviving defects have no control that responds to them**, and are defended
   only by pins or determinism: two-run/UNSTABLE (D01, D17), timeout class (D02), canary
   (D08), green token (D09), duplicate `old` (D15), `n_min` (D18). They are latent, not
   safe: they would matter the moment a gate is flaky, hangs, or the spec pin is relaxed.
5. **The controls that do exist are well aimed.** Every control state except
   `CTL1-nowork-base` (which refuses at `spec-absent-at-rev` before any check runs) changed
   under at least one defect, and the baseline reproduced all 16 receipts exactly
   — so the battery is sound, just narrow: it exercises the note-table, README, source and
   pin paths but not the note-format edge cases (duplicate row, ambiguous cell, wrong
   denominator) or the gate-behaviour edges (flaky, hanging, token-less, canary-proof).
6. **Suggested additions for the L1's case note** (not executed here, L1 owns the case):
   four control states mirroring the proven forgeries — a duplicate `C02` row, a row
   `| C02 | … | SURVIVED | KILLED |`, `measured: 5/9 killed`, and a note citing `S315`
   with S315 flipped to `mined` — would raise the battery's check-level detection of these
   20 defects from 9/20 to 13/20 at the cost of one battery run.

## Reproduction

```sh
S=/fast/scratch/hyaku/tameshi-r90/T90M1
# 1. pristine counter copy (byte-identical) and the two-line-redirected driver
cp .ufo/evidence/round-90/c1/measure.py            $S/bin/measure-pristine.py
cp .ufo/evidence/round-90/c1/controls.py           $S/bin/controls-driver.py
#    edit only: measure = os.environ.get("T90M1_MEASURE") or <frozen path>
#               outdir  = os.environ.get("T90M1_OUT")     or <frozen receipts dir>
# 2. defect spec (pre-registered) and the harness
#    T90M1-defects.txt, T90M1-mutate.py, T90M1-reach.py (this directory)
python3 -I T90M1-mutate.py --lane <lane> --scratch $S --spec T90M1-defects.txt \
    --counter $S/bin/measure-pristine.py --driver $S/bin/controls-driver.py \
    --out $S/results.json --par 6 --jobs 3
python3 -I T90M1-reach.py --lane <lane> --scratch $S --driver $S/bin/controls-driver.py \
    --pristine $S/bin/measure-pristine.py --mutants $S/mut --out $S/reach.json --par 4
```

Battery cost: one defect = 16 control states ≈ 4–5 min at `--jobs 3`. The 19-defect run
(plus the D13 battery from the smoke run) took 925 s wall at `--par 6`; the two pristine
baselines took 285 s in a separate run.
