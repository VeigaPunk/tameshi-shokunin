## Kill findings (rule a: a committed state reaches PASS with a non-true verdict)

### K1 — duplicate row with two verdict cells is silently dropped; PASS=true with a false row
- Code: `measure.py:218-226`. A row whose body has `len(vs) != 1` (two verdict tokens) hits
  `continue` at 223–224 with no record; the duplicate guard `dup = True` (226) only fires for rows that
  *did* parse. So a second row for the same id, carrying a contradicting verdict, is invisible.
- Evidence: `T90R1-probe-defects.out`, V1-dup-row: the honest fixture plus the single extra line
  `| C02 | fixture arm | KILLED | SURVIVED |` → `C1_R90_PASS=true`, `mismatched0=true`, `ids=true`,
  `figure=true`. V0-pos (same fixture, no extra line) → PASS=true (sanity).
- Why it is a kill: the committed note states `C02 = KILLED`, which is not the true verdict
  (SURVIVED), and the counter prints PASS. Frozen kill (a) and the reviewer's target both apply.
- Fix direction (not applied; the counter is frozen): count every `| Cnn |` line that carries a
  verdict token, and set `dup` or refuse when any such line is ambiguous.

### K2 — repository reads are not sealed against replace refs; a local `refs/replace` makes a non-true committed tree print PASS
- Code: `measure.py:53` (`git` inherits the caller's environment), `:59-61` (`blob` = `cat-file blob
  rev:path`), `:74` (`git archive` for fixtures). Git honours `refs/replace/*` for these reads unless
  `GIT_NO_REPLACE_OBJECTS=1` is set; the counter does not set it and does not check `git replace -l`.
- Evidence (reproduced, scratch clone only): `T90R1-probe-defects.out`:
  - V4-replace-env: committed tree at REV has `C02 = KILLED` (wrong); a local `refs/replace` maps the note
    blob to the honest note → `C1_R90_PASS=true`.
  - V4-replace-sealed: same committed tree, same replace ref, `GIT_NO_REPLACE_OBJECTS=1` → `C1_R90_PASS=false`,
    `mismatched0=false`.
  - Independent fixture (scratch repo, commit-level `git replace <commit> <commit>`): `git cat-file blob
    REV:path` returns the replacement commit's file and `git archive <rev>` carries it too; with
    `GIT_NO_REPLACE_OBJECTS=1` the original file returns. `git rev-parse --verify REV^{commit}` still
    prints the original id, so a reviewer checking the id alone sees nothing.
- Why it is a kill: the PASS printed by a repo that holds the wrong note in its committed tree is a
  false green; the replace ref lives outside the commit graph, so the author sees PASS and a non-author
  clone without the ref sees FAIL. The lane currently has no `refs/replace` (`for-each-ref refs/replace`
  empty), so the landing is unaffected unless a seat creates one; the defect is in the counter.
- Fix direction: `GIT_NO_REPLACE_OBJECTS=1` in `env` for every git call (and `GIT_DIR`/`GIT_*` unset) and
  refuse when `git replace -l` is non-empty.

### D3 — honest note refused: a drafted-arm result column reading KILLED on survivor rows
- Code: `measure.py:222-224`, the same rule as K1 seen from the honest side. The plan says the case note
  carries "a survivor table with a witness and a drafted killing arm per survivor"; a column recording

- Evidence: R1-draft-column (`T90R1-probe-refusal.out`, rerun from saved bytes): honest verdicts, a fifth

- Fix direction: accept a verdict token only in a column named `verdict`, or read the verdict from a
  designated column index taken from the header row.

### D4 — fixtures are not pinned by hash; fleet-side reads are not sealed
- Code: `measure.py:71-81` (materialize; fixtures from `git archive` at 74; gate blob pinned at 136, fixtures

- Fix direction: pin `git rev-parse f47ad6ba:scripts/fixtures/sources-census` to the expected tree oid (or
  hash the extracted tree) and use `GIT_NO_REPLACE_OBJECTS=1` for fleet reads too.

## Notes (not kills, not defects; for the L1)

- N1. Refusal diagnostics are not specific. `ids=false` / `figure=false` / `source=false` print no row; a
  note author cannot see which line failed. Consider printing the offending line numbers.
- N2. Honest-but-strict shapes refused by design: R2 verdict cell `SURVIVED (non-equivalent)` → `ids=false`
  (`measure.py:222`, exact-token rule); R3 rows with one leading space → `ids=false` (218, column-0 regex);
  R4 `measured: 5/12 killed (5 KILLED, 7 SURVIVED)` → `figure=false` (230, `\s*$`). Each is a choice; the
  plan should say which shapes the note must use.
- N3. The `source:` line must be the single column-0 line starting `source:` (232–233). A bolded
  `**source:**` is refused.
- N4. Plan kill (d) (the cited S-id was opened this round, with URL, access date and ≤25-word quote) is not
  a counter conjunct; the counter checks only "mined and lists the note" (238–241). A non-author check is
  still required.
- N5. `trivial` (169) fails only on exit 2 / timeout / gawk or syntax text on the clean lane; a mutant that
  makes `validate` exit 1 on the clean lane is not flagged. This narrows the trivial class; it does not
  create a false green.
- N6. Witnesses run once (186–188), not twice. The validate/census/overdue outputs are deterministic (no
  mktemp or time output), so this is safe today; a witness that became time-dependent would manufacture
  `differs`.
- N7. `run()` (84–90) kills only the direct child on timeout (`subprocess.run` does not kill grandchildren).
  No hang; orphaned processes possible.
- N8. The gate's per-check labels are inverted relative to the case note vocabulary: `SURVIVED\t<label>`
  is printed for a *failing* check (`check()` in the selftest, fail=1), while `killed\t<label>` is a passing
  check. The mutant verdict is consistent with this (KILLED iff some check fails; rc≠0). The note's survivor
  table must not copy the per-check labels as verdicts.
- N9. `gate.repo` in the spec is an absolute host path (`/home/vgpnk/Projects/shokunin`); on another host
  the pin fails at `gate-blob-unreadable` (exit 2). Portability note only.
- N10. The canary (148–150) shows the copy runs, not which selftest arm executed a mutated line (declared).
