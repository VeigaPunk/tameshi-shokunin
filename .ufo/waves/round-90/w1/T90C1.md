## 3. Why this is a kill

### 3.1 Prompt §9, do-nothing control (binding)

`/home/vgpnk/Projects/shokunin/.ufo/prompts/tameshi-round-90.md:556-560`:

> A target must be one a do-nothing control cannot reach … build the cheapest control that
> skips the claimed work, score it with the frozen counter, and commit that receipt: if it
> meets the target, the counter or target is wrong — fix it before data.

Probe A is that control, and it meets the target. The plan's committed controls only test
"no note at all" (`CTL1b`; `CTL1` is the base-rev setup refusal) and single-change states over
the positive fixture (`CTL2`–`CTL16`), each named after the one conjunct it must fail. None of them is "the cheapest state that produces the after-state
without the round's work", which §9 mandates. Had it been built, it would have shown that
the after-state is reachable from bytes committed three commits before the freeze.

### 3.2 The plan's own defense is self-defeating

`plans/round-90.plan.md:18-20`: "the counter executes the fleet gate itself … the only lane
bytes it compares against are the case note's verdict cells. A counterfeit that passes must
contain the true verdicts, which is the claim." This is true only if the true verdicts are
not already in the repository. They are: `pre-freeze/expected.tsv` was committed *alone* at
`33dd6e47` ("round-90: pre-registered expectations and C1 mutant spec (alone, before any
verdict receipt)"), and the plan itself discloses "12/12 predictions held" before the freeze.
So "must contain the true verdicts" reduces to "must copy 33dd6e47". A pre-registration
instrument that is required to be committed before data became the counterfeit's oracle —
the lane's own separation-of-data rule manufactured the counterfeit.

### 3.3 The plan already has a PASS receipt of the same class

`c1/controls.py:19-22` hardcodes `DERIVED` (the twelve cells from the 33dd6e47 no-work run);
`:31-40` generates the note from that dict (`| id | arm | verdict | witness |`, where the
witness cell is the invented literal "differs"); `:42-52` appends an S999 row pointing at
`https://fixture.invalid/r90`. `pre-freeze/controls/CTL14-pos.out` shows this PASSes, and the
plan calls it a positive control. That is the same state as probe A with the same unopened
source; it was scored pre-freeze and did not trigger a counter fix.

### 3.4 Reading of kill rule (a)

`plans/round-90.plan.md:56-57`:
"(a) any committed state … that does not hold the true verdicts of these mutants under the
gate's own selftest reaches `C1_R90_PASS=true`".

- **Textual reading** (the plan's gloss): the state's cells equal the derived verdicts →
  (a) does not fire. Probe A "holds" the verdicts; it is the *plan's* expected.tsv that is
  the problem.
- **Evidential reading** ("holds the true verdicts **under the gate's own selftest**" = the
  state carries verdicts produced by that execution): probe A holds no such verdicts — its
  own text says no mutant was executed — and reaches PASS. (a) fires.

The counter cannot tell the readings apart; a closure that admits C1 on the textual reading
admits a state that contains no measurement of the mutants. That is why the finding is a
kill under §9 regardless of which reading the closure adopts.

## 5. Claim sizing and axis review

### 5.1 Axis: coverage
The claim is labelled coverage (`plans/round-90.plan.md:24`). The round changes the lane
corpus (one note + two registry/index rows); the surface it measures — the fleet gate — is
not changed at all (read-only, correct). Prompt §9 (`:565-569`) says a coverage claim names
the surface it moves and "the command that would show it unmoved"; the counter does that
(PASS=false at base). But the lane's own coverage instrument is the replay ledger: R88-C1, the
precedent for this claim shape, moved `declared=10→11` ledger legs; R90-C1 explicitly does
not ("The case is NOT added to `tools/mutate-and-run.sh`", `:30`). So the round's own
counted surface set does not move; only the corpus does. That is defensible as "a new class
of surface documented", but it is one PROVINCE/Core append and one SCORECARD coverage row
away from being *governed* — neither is planned.

### 5.2 Province
The fleet root's `scripts/sources-census.sh` is within the lane's method surface (it is the
fleet's own registry gate, not a sibling lane's product gate, and the lane measures it
read-only from scratch copies — no Refuses clause is touched). But `PROVINCE.md` Core
enumerates only the sibling-lane gates and the lane's own runner/registry; the fleet-root
gate appears nowhere. The lane's own precedent is an appended Core block with the gate's
pinned commit and blob sha256 (round-16 append, round-88 append `## Core — round 88 append`).
The plan has no such append, so as frozen the claim adds a measured surface the province does
not name.

### 5.3 Thinness of the case
Twelve single-edit mutants, one suite (`selftest`), 5 KILLED / 7 SURVIVED. The seven
survivors are all of one class — no committed fixture reaches the edited arm — and all seven
witnesses are behavioural differences on the same fixture tree. That is a legitimate case at
the lane's usual size (R88: 10 mutants, 5/10), and the arm set is real (E10, E04 boundary,
due-day boundary, opening-date boundary, 3-space indent, missing-registry exit, used-by
`-e` vs `-f`, fragment normalization, symbolic cadence spaces, separator alignment, comma
list trim). What is thin is not the mutation population but the *note* the predicate demands:
the case's only lane-authored content is a checksum of the counter's own derivation. If the
landing note is the plan's survivor table plus arm/witness/output evidence, the case is fine;
if it is probe A's shape, the claim's noun ("case") is false while the predicate is green.

### 5.4 The source and README conjuncts are bookkeeping, not provenance
- `source`: probe A cites `https://probe.invalid/never-opened`; the plan's own CTL14-pos
  cites `https://fixture.invalid/r90`. Both pass. The conjunct cannot tell an opened source
  from a placeholder; kill rule (d) is the only real check, and it lives outside the counter.
- `coverage`: any line in `README.md` starting with `|` that contains the note path passes —
  it need not be in the `## Coverage map`, and a fenced example line would do. R89's routed
  defect 1 was exactly a missing coverage-map row; the counter does not enforce the map.

### 5.5 Predicate identity
Plan sentence, `measure.py` conjuncts and the `C1_R90_PASS` label are the same condition
(checked clause by clause against `:253-256`) — no defect here. The defect is what the
predicate omits, not that it drifted.
