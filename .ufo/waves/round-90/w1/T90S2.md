The gate's `usedby_findings` function, lines 560–569:

```sh
560:    usedby=$(trim_cell "${cells[11]}")
561:    paths=()
562:    IFS=',' read -r -a paths <<< "$usedby"
563:    for path in "${paths[@]}"; do
564:      path=$(trim_cell "$path")
565:      [ -n "$path" ] && [ "$path" != "—" ] || continue
566:      if [ ! -e "$dir/$path" ]; then

```

* **C08** swaps `-e` (file exists) for `-f` (file exists **and is a regular
  file**) at line 566. The two operators disagree on a path that exists but is
  not a regular file — a directory, a socket, a fifo — which is exactly what a
  `used-by` cell naming `corpus/knowledge` (a directory) is.
* **C12** drops `trim_cell` at line 564. Line 562 has already split the
  comma-separated `used-by` cell on `,`; the second field therefore keeps its
  leading space, and without the trim the existence test at line 566 asks
  about `" corpus/b.md"` — a path that does not exist — and prints a false E11.

Both are Bash *language-semantics* questions: what `-e`/`-f` mean, and what
`IFS` does to a `read` line. The right source is the normative manual text.
