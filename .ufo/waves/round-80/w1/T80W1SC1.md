### Exactly what it grounds for arm17

Two clauses, both load-bearing:

1. `enabled by the POSIX locale` → under `LC_ALL=C`/POSIX, UTF-8 mode is ON
   **without** `-X utf8`. An arm that ran under the POSIX locale would print
   `utf8_mode=1` either way, so the mutation `python-utf8-dropped` (the python
   tuple loses `-X utf8`) would **survive** — the arm cannot discriminate.
2. `disabled by default` → under a UTF-8 locale (not POSIX), UTF-8 mode is OFF
   unless `-X utf8` / `PYTHONUTF8=1` is passed. Pinning a UTF-8 locale therefore
   makes `sys.flags.utf8_mode` a faithful witness for "did the tuple carry
   `-X utf8`" — exactly the arm17 kill predicate in the frozen matrix
   (`plans/round-80.plan.md:131-134`, `| python-utf8-dropped | arm17 only |`).

So the sentence grounds the arm's **locale-pinning requirement**, not merely the
option's existence. Secondary ground for the option itself: lines 216–219 ("Add the
new `-X utf8` command line option and `PYTHONUTF8` environment variable …").

### Measurement confirming the requirement (host `python3 -VV` = 3.14.8)

`env -u PYTHONUTF8 -u PYTHONCOERCECLOCALE LC_ALL=<loc> LANG=<loc> python3 [-X utf8] -c '…sys.flags.utf8_mode…'` — all exit 0:

| LC_ALL | no flag | `-X utf8` |
|---|---|---|
| `C` | **1** | **1** ← non-discriminating |
| `C.UTF-8` | **0** | **1** ← discriminating |
| `en_US.UTF-8` | **0** | **1** ← discriminating |

`sys.getfilesystemencoding()` was `utf-8` in every cell, so fs-encoding is NOT a
usable witness; `sys.flags.utf8_mode` is. The attribute the arm prints exists in the
same round-80 snapshot: `sys.flags.utf8_mode`, `sources/sys315.html:919`.

## Findings routed to the L1 (no claim falsified)

**F1 (routing, low risk) — `blob <rev>:<path>` is a two-source ground.**
cat-file(1) never defines `:<path>`; `<rev>:<path>` appears once (line 2194) and only
in the `--textconv|--filters` synopsis, while `<object>` (2228–2230) explicitly
delegates object-name spelling to **gitrevisions[7]** (S091). A C3/S289 sentence
saying cat-file(1) alone defines `blob <rev>:<path>` would overstate the page. The
accurate wording: `<type>=blob` + `<object>` per cat-file(1), `:<path>` per
gitrevisions[7]. Confidence: high (grep of all `<rev>` and `blob` literals; 1
occurrence of `<rev>`).

**F2 (arm-design note, precedent) — the sys page carries no flag semantics at all.**
Both `flags.isolated` (833) and `flags.utf8_mode` (921) have empty `<dd></dd>` and an
unlabelled table. Useful for the SOURCES row text: the sys page grounds *existence
and mapping* only; behaviour always sits in cmdline.html / PEP 540. Confidence: high.

**UROs:** none. Every URL opened (3 distinct, 9 curl invocations incl. two refetch
modes), all `HTTP/2 200`.

**Not checked (outside seat):** whether `arm17`'s actual bytes pin `C.UTF-8` (it names
"an explicit UTF-8 locale" in the plan); whether a `PYTHONUTF8`/`PYTHONCOERCECLOCALE`
export in the harness could mask the mutation — the arm should `env -u PYTHONUTF8`,
which my matrix did.
