## D2 — frozen exactly-once predicate is not enforced

**Evidence:** the C1 after description requires the figure regex to match exactly once on each surface and stdout. `_declared_doc` checks multiple matches (`registry-figure-bind.py:165–170`), but `_declared_registry` returns all `stdout_contains` strings joined without a figure uniqueness check (`189–196`); `_live` accepts any positive number of matches and returns `matches[-1]` (`209–213`). `measure` uses substring membership (`224–225`).

**Counterexample, statically derived, not runtime-tested:** a registry row with `stdout_contains=["WAVE_RECONCILE_SELFTEST: 19/19 pass", "WAVE_RECONCILE_SELFTEST: 24/24 pass"]`, measured against live 24/24, is classified `match` while still carrying the stale assertion. A tool printing an old figure then the expected figure also passes because only the last match is used. Neither needs `expect=stale`. The current 11-arm selftest covers duplicate row names but not either duplicate-figure case (`selftest:337–461`).

**Impacted axes:** calibration (ambiguous self-description accepted), depth of the frozen predicate. **Smallest safe correction:** require exactly one full figure match in both registry declaration and live stdout, then compare extracted tokens for equality. Preserve refusal, not last-token selection. This is an implementation defect fixable without accepting a trade; L1 must reconcile any changed selftest total with the frozen 11/11 rule rather than rewrite it after measurement.

**`expect=stale` attack:** changing one of these seven manifest expectations to stale can make a stale row expected, but cannot produce the required `match=7 stale=0`; the full frozen summary catches it. Checking exit 0 or `unexpected=0` alone would not. Keep all summary fields and the seven-row population check. A row with no recognizable declared token is also classified stale, so a future standing red row must not be described as proving the specific obsolete token still exists.
