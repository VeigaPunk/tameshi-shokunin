## Findings / defects seen in the tool

1. **Hardcoded `/tmp` in the self-test** — `tools/repeat-control.py:597`
   `tempfile.mkdtemp(…, dir="/tmp")` ignores `TMPDIR` (docstring `:66-67` says so). Observed: with
   `TMPDIR=<scratch>/tmp` the selftest left that dir empty and used `/tmp`, then removed its scratch on
   pass (`:859`); `ls -A /tmp | grep tameshi-r12` → none afterwards. Consequence: in a sandbox that
   forbids `/tmp`, `--selftest` fails at the first case (crash → `SELFTEST: COULD_NOT_EVALUATE` 2),
   which is why the row's Write scope states the literal `/tmp` prefix rather than `TMPDIR`.
2. **No timeout or supervisor** — stated limitation (docstring `:84-88`): a hanging command yields no
   verdict; the verdict map cannot express it because no code is returned. Callers must wrap the
   command in `timeout`.
3. **`--help` exits 0** (`:882-886`), and the map's `0` means `clean`; a help invocation is therefore
   classified clean. Harmless for the counter (the usage probe passes `--r51-no-such-flag`, which
   exits 64) but it is a 0 that is not a verdict.
4. **Snapshot digests live inside the directory they validate** (`:573-588`, docstring `:89-92`):
   accidental drift is caught, a coordinated edit of observation + digest is not; the external anchor
   is committed history. Not fixable by a registry row; recorded as a known limit.
5. The row's Write-scope cell intentionally keeps the literal `--out DIR` and `/tmp/...selftest.*`
   strings: neither is a pinned path, so no path existence is implied.
