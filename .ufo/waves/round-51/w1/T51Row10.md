## Findings / defects of the tool

1. **Hardcoded `/tmp` ignores `TMPDIR`.** `tools/pin-disposition.py:706`
   (`tempfile.mkdtemp(prefix="tameshi-r13-pin-disposition-selftest.", dir="/tmp")`) — every selftest run
   builds its git fixture tree under `/tmp`, even when `TMPDIR` points elsewhere; the C3 counter sets
   `TMPDIR=<work>/tmp` and is silently bypassed. Show:
   `grep -n 'mkdtemp' tools/pin-disposition.py` → `706: ... dir="/tmp")`.
   Harmless for the counter (it only needs exit 0 and a finding id, and PASS removes the tree), but it is a
   scratch-hygiene defect and the row's Write scope states it explicitly rather than claiming TMPDIR
   isolation.
2. **Failure path leaves fixtures behind in `/tmp`.** `tools/pin-disposition.py:1314` prints
   `fixtures kept at <scratch>` and returns 2 without cleanup; a red selftest therefore leaves a git repo
   tree in shared `/tmp`. Not exercised this seat (selftest green both runs); cited from source.
3. **Not a defect, recorded because it shapes the Pinned values cell:** the compared expectations are the
   caller-supplied manifest's `pinned_commit`/`expected_sha256`, and the committed
   `.ufo/evidence/round-13/pin-manifest.json` is the recorded configured pin authority, not a
   digest-authenticated baseline (`tools/pin-disposition.py:24-34`). Every pathish backticked token in the
   row's Pinned values cell exists at REV (verified with
   `git cat-file -e 84aa673a…:.ufo/evidence/round-13/pin-manifest.json` → present), so the counter's
   existence rule holds.
4. No undeclared exit code: the tool's `0`/`1`/`2` are all in the verdict map, and `--help`'s `0` is
   already covered.
