## Why `probe`, not `gate`

`tools/trace-inputs.py` cannot return a conformance verdict about the lane. `run_trace()` returns
`0` once a receipt is written (`tools/trace-inputs.py:693`) and preserves the traced command's own
status *inside* the JSON (`"exit": cmd_exit`, `tools/trace-inputs.py:644-664`), never as its own
exit. Direct run, receipt written while the traced command failed:

```
$ TMPDIR=$S/tmp python3 tools/trace-inputs.py --root $S/lane --out $S/rcpt/out.json -- \
    python3 -c "open('SKILL.md').read(); import sys; sys.exit(3)"
EXIT=0
{"schema": "tameshi-trace-inputs-v1", "exit": 3, "tracked_filter": true, "rev_reason": null}
rev 195503cf92d992d3f0235c9a6b5b21a3b3f841bb   inputs["SKILL.md"] = 1dc7abac…
```

PROTOCOL §Gate standard: "A tool that cannot fail is a probe, and is registered as one." The only
`1` this tool exits is its own selftest regression (`tools/trace-inputs.py:967`), which is why the
verdict map declares `1 failed (selftest check)` rather than a lane verdict.

## Tool defects observed while reading (report only; no edits made)

1. **Hardcoded `/tmp` fallback.** `tools/trace-inputs.py:577-578`:
   `cands = [tempfile.gettempdir(), "/var/tmp", "/dev/shm", os.path.expanduser("~/.cache"), "/tmp"]`.
   With `TMPDIR` unset, `gettempdir()` already resolves to `/tmp`, so the literal adds nothing except
   a second attempt at a path the operator may have deliberately excluded from a scratch regime. It
   is guarded only against being under `--root` (`:588-591`). Observed: no write under `/tmp`
   happened in my runs because `TMPDIR` was set (`$S/tmp` was empty after the direct run except my
   own subdir).
2. **Host- and lane-specific defaults baked into the tool.** `tools/trace-inputs.py:70-72`:
   `DEFAULT_FLEET = "/home/vgpnk/Projects/shokunin"`, `DEFAULT_LANE = <fleet>/tameshi-shokunin`,
   `DEFAULT_HOME = "/home"`. A reader running the tool from another host silently gets empty
   `external`/`live_lane_reads` buckets instead of an error; the defaults are documented
   (`:26-34`) but not validated against existence.
3. **`--home-prefix` drops reads silently.** `:311-315` counts non-fleet `/home` opens in
   `dropped_home_count` and never names or hashes them — deliberate (credential safety, `:29-33`),
   but it means a command whose only evidence lives under `/home` exits `0` with an empty `inputs`
   map; only the counter distinguishes "no inputs" from "no evidence".
4. **Exit `1` is overloaded.** Besides a selftest regression, any uncaught exception exits `1`; the
   tool declares only `0/2/64` for tracing in its docstring (`:50-52`). The row maps `1` to
   `failed (selftest check)`, which is what `:967` returns; a crash is indistinguishable from a
   regression by exit code alone.
5. **Write scope is genuinely outside the traced tree.** Receipt at the caller's `--out`, with the
   parent directory created (`:687-691` — observed: `$S/rcpt/` did not exist and was created), and
   the strace log + pycache prefix inside a private `trace-inputs-run-*` tempdir outside `--root`,
   removed in `finally` (`:695-696`). No lane write was observed in any run.
