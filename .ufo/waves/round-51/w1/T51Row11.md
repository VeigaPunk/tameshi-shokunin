## Defects and observations

- **D1 (classification).** An unresolvable revision is graded `failed`, not could-not-evaluate.
  Fixture: a `git init -b main` repo with one commit. `python3 tools/receipt-measure.py --repo <fixture> --json`
  → `exit=1`, JSON `"revision": "master"`, six `FAIL` items; and
  `--rev deadbeef` → `exit=1`, `"revision": "deadbeef"`, six `FAIL` items
  (`T51Row11-norev-probe.out`, `T51Row11-badrev-probe.out`). Cause:
  `git -C <fixture> rev-parse master` prints `master` and exits 128, so `rev` at
  `measure.py:104` is non-empty and the `could-not-evaluate` branch `measure.py:105-107` is dead;
  `blob()` returns `None` for every path (`measure.py:47-49`) and the tally reports `failed`.
  PROTOCOL §Gate standard maps an ungradable revision onto could-not-evaluate. The row states
  this rather than claiming code 2 for it.
- **D2 (diagnostics).** Because arguments are delegated, a typo produces the instrument's usage
  line (`usage: measure.py …`, not `receipt-measure.py`), which names a file the reader did not
  invoke (tools/receipt-measure.py:310-314 + `measure.py:97`).
- **D3 (interface).** The runner performs no mapping of delegated codes: whatever
  `measure.py` exits is returned verbatim (:314). Today that set is `{0,1,2}`
  (`measure.py:107`, `:264`, argparse), so the declared map is complete; a future instrument
  code would surface undeclared.
- Not a defect: the selftest writes only under `TMPDIR` (two fixture trees, one per case) and
  leaves no lane artifact; `--check` is deliberately unsupported (`exit=2`, selftest case 10).
