## Defects of the tool seen (reported, not fixed — only the runner is editable this round)

1. **The audit deletes a fixed literal `/tmp` path.** `CONFIGS` line 265 pins the second sweep
   configuration to `('/tmp/tally-audit-work', '1', '0')`, and the reference tally block performs
   `rm -rf "$root"` in its PASS branch (line 101). Every PASS vector under that configuration
   therefore deletes `/tmp/tally-audit-work` — a path the tool does not create, does not clean up
   safely and does not document. Demonstrated:

   ```
   $ mkdir -p /tmp/tally-audit-work && printf 'marker\n' > /tmp/tally-audit-work/marker.txt
   $ cd <clone>; python3 tools/tally-audit-v2.py --runner tools/mutate-and-run.sh; echo $?
   … TALLY_AUDIT: PASS …  0
   $ ls -d /tmp/tally-audit-work
   ls: cannot access '/tmp/tally-audit-work': No such file or directory
   ```

   Two consequences: a caller whose `TMPDIR` is a sandbox still loses that literal path (write
   escape from the declared scope), and two concurrent audits race on one fixed name. Cost of a fix
   belongs to a round that owns the tool. The row's Write scope states the behaviour rather than
   hiding it.

2. **The reference leg panel is hardcoded, which couples this gate to the runner's leg count.**
   `REF_NAMES` (line 107, nine names) and `check_harness` (lines 536-537: `if names != REF_NAMES:
   return False, 'leg names differ from the reference panel'`) reject any other leg set, and the
   selftest seeds are anchored on the literal line `local nlegs=9 npass=0 nfail=0 nsetup=0 st`
   (line 614), so a tenth leg makes most seeds "edit did not apply". Simulated C2's tenth ledger leg
   in a scratch clone at `84aa673a` (added `st_driftpins=$?`, extended the `local st_…` declaration
   at runner line 1385, `nlegs=10`, tenth loop operand):

   ```
   $ python3 tools/tally-audit-v2.py --runner tools/mutate-and-run.sh; echo $?
   CHECK head PASS legs=10
   CHECK static PASS legs=10 operands=10 nlegs=10
   CHECK runtime PASS vectors=18288 mismatched=0
   CHECK harness FAIL leg names differ from the reference panel (… st_driftpins)
   TALLY_AUDIT: FAIL (head=pass static=pass runtime=pass harness=fail)
   1
   $ python3 tools/tally-audit-v2.py --selftest; echo $?
   CASE pristine FAIL (exit 1)
   CASE dup-drop operand FAIL (edit did not apply)
   …
   TALLY_AUDIT_V2_SELFTEST: 14/22 pass
   1
   ```

   Receipts `T51Row19/sim-tenthleg-audit.out`, `T51Row19/sim-tenthleg-selftest.out`. This is the
   round's cross-claim hazard, raised to the L1 separately: if C2's tenth case is wired into
   `run_regression` as a tenth leg (the runner's own header says `--regression` "replays every
   recorded mutation case as a leg", `tools/mutate-and-run.sh:215`) before the deciding run, this
   tool's self-test exits 1 and the row reads MISSING. Either the tenth case stays out of the leg
   loop, or `REF_NAMES` and the seed anchor line are updated in the same change.

3. **No committed expected-verdict snapshot for the audited surface (PROTOCOL "Two evidences").**
   The audit recomputes an oracle instead of comparing against a frozen `expected.json`, so nothing
   pins the digest of the runner revision it graded; a later edit of `tools/mutate-and-run.sh`
   silently redefines what "PASS" means. The repo does pin the *tool's* digest history
   (`.ufo/evidence/round-35/pin-reconciliation.json` entry for `tools/tally-audit-v2.py`), not an
   expected verdict. The row therefore claims `none` under Pinned values instead of pointing at a
   baseline that does not exist.

4. **Dead code**: `brace_depth_at` (line 135) has no caller (`grep -n brace_depth_at

5. **`--then-regression` forwards the runner's exit code verbatim** (line 596) after only checking
   that the REGRESSION line names `cases=nlegs`. The runner's documented map is 0/1/2, which the row
   declares; a future runner exit code would leak through as an undeclared code (reads
   could-not-evaluate fleet-wide per PROTOCOL, never as clean). Bounded, recorded, not a defect today.
