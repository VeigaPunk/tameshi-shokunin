## Kind: gate, not probe

PROTOCOL §Gate standard (`/home/vgpnk/Projects/kimi-shokunin/skills/shokunin/protocol/PROTOCOL.md:397-437`):
a gate "reads surfaces, compares them against expected values persisted in its own repo, and returns a
verdict. A tool that cannot fail is a probe."

* It fails: `tools/mte-interop.py:343-347` prints `MTE_INTEROP: FAIL` and returns 1 when any leg's
  four checks do not hold; the selftest returns 1 at `:444` when a negative control is not rejected.
* Expected values are persisted in the repo, not recomputed: the vendored report schema and metrics
  library are `sha512`-pinned in source (`:61-67`) and re-verified before use (`:176-183`), and the
  per-defect expected verdicts come from the runner's committed `TABLE_*` literals read from

**D1 (setup reported as failure).** `--selftest` with the metrics tarball absent/exotic raises an
uncaught `FileNotFoundError` and exits **1** instead of 2, because `official_metrics()` is called in a
`try` that catches only `Setup` (`tools/mte-interop.py:426-430`; the raise comes from
`verified_tarball` → `(VENDOR / filename).read_bytes()`, `:176-181`). Receipt:

```

$ python3 tools/mte-interop.py --selftest < /dev/null

```

A torn/corrupt pin is fine (integrity mismatch raises `Setup` → 2, `:180-183`); only a *missing* file
escapes. Inside `--check` the same condition is `SETUP` (the whole block is guarded by
`except (Setup, OSError, ValueError, KeyError)`, `:322-324`), so the two modes disagree. No exit code
is *undeclared* (1 is in the map), but a setup failure is mis-classed as `failed` on the self-test
path — worth routing to the lane owner; I did not change the tool.

**D2 (misleading usage message, cosmetic).** `--r51-no-such-flag` reports the missing required group
rather than the unknown flag (`:455-466` + `Parser.error` `:447-450`). Exit 64 correct.

**D3 (scratch left behind on non-PASS).** The regression workdir made at `:309` survives FAIL *and*
