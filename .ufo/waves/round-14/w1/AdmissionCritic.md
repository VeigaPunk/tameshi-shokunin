## Counterexamples against the C1 contract

1. **The shared context says "All13 expected rows", but there are 12.** If 13 is taken literally, one of two things happens: a non-expected receipt row (e.g. `pin_env_scrub`) gets fabricated, which is an unknown row, or 12 rows are flagged as "missing one". Impacted axes: calibration and provenance. Correction: the report and claim must say **12 expected rows, 13 pinned inputs**. DispositionSpec has been messaged.
2. **Rebinding bypasses supersession.** Suppose an effective `producer_before` row selects `producer-oracle-repair.json`/`producer_before_oracle`. That check has exit 1 and its stdout contains the stale literal (it is followed by `FAIL`), so the original expectation is satisfied with no supersession at all. "Unique selection" alone does not stop this; one variant also relocates the oracle row. Correction: require **check name == row name** for every effective row, and bind the raw `producer_before` to `verification.json`. This is feasible because all 12 names exist exactly once. Gate has been messaged.
3. **Laundering through a generic supersession rule.** If any row may be superseded by any passing effective rows, then `witness_check superseded_by [pin_selftest]` would be accepted. Correction: allow exactly one supersession, `producer_before → {producer_before_oracle, producer_after_oracle}`. Bind it mechanically to `producer-oracle-repair.json.supersedes` (which begins `verification.json producer_before`) and to `oracle_sha256 == expected.inputs[producer-oracle.py]` (both `d5ae0bd4…`). Also require that the superseded raw check is present and **still observed failing** its original expectation; emit that failure as a disclosed finding rather than deleting it.
4. **Self-reported receipt fields.** `exit_matches` and `expected_exit` were written by the lane. The gate must recompute exit equality from `expected.json`, and reject a bool where an int is required (`True == 1` in Python). For `pin_live`, `Counter(leg.content_status)` has no `unavailable` key; compare against zero-filled statuses. Also require `len(legs) == counts.legs == 6` and every leg `result_reuse == not_established`, not just the top-level field.
5. **`contains` semantics differ between authorities.** Round-14 `measure.py:40` searches `stdout + stderr`. The spec says "parsed check.stdout". Python tracebacks echo source lines, so stderr can contain an expected literal without the assertion ever running. Correction: the gate uses stdout only and documents it. measure.py should either match or label its field as a broader text-presence count. For `producer_before` both give `false` today, so the outcome is unchanged; the risk is in the stated semantics.
6. **"Original expectations" are not preregistration.** The oracle expectations and their receipts were committed together in `4acc607`. The claim and report may say the replacements pass "expectations committed in round 13". They must not say "pre-registered" or "blind". The round-13 verdict program is not retained, so "effective" means **under the round-14 gate's semantics**, not a reproduction of round 13's unretained verifier.
7. **Duplicate authority.** After this round, `verification-verdict.json` (which drops `producer_before` and records an `excluded_initial_failure` string) and `dispositions.json` (which supersedes it) both make dispositions. Correction: state a precedence rule. `dispositions.json` is the round-14 effective ledger; the verdict remains historical. Optionally the gate checks agreement: for the expected_checks names, verdict `matched=true` ⇔ effective, and "absent from the verdict" ⇔ superseded. The claim's "before" text should acknowledge the verdict as a prior *partial, non-runnable* ledger, so "No complete ledger" is true but not misleading.
8. **"Same command, sole fix" needs to be exact.** The before/after differential is only meaningful in three conditions. First, the two files differ only in the `producer_before` row. Second, the before run exits **1** (semantic), not 2. Third, its findings list holds exactly one failing expectation (the `producer_before` contains mismatch). Without these, "rejects old unresolved row and accepts sole disposition fix" is unproven.
9. **Coverage measurement is loose.** `measure.py:38` computes `disposition_name_coverage` as a set intersection. It hides duplicate names and silently ignores unknown names. Counting is fine, but exactness must come from the gate; otherwise make it Counter-exact and report unknown names (owned by L1).
10. **Defect 2 scope bleed.** The gate covers only expected_checks rows. `pin_env_scrub` is outside its scope and must not become an effective or superseded row, nor be "repaired" by `context-receipt.json`. Per the spec, the context receipt is new evidence, not a retrospective fix. Harness risk: if the baseline inherits ambient `GIT_*` variables (GIT_DIR, GIT_WORK_TREE, GIT_INDEX_FILE), the baseline itself is poisoned. Build the baseline env explicitly with every `GIT_*` removed, and record the variable *names* passed to both runs. Tradeoff to disclose: a `/nonexistent` poison catches a loud failure, but not a silent-wrong-repo read.
