# Selftest boundary and fixture recommendation

## Reconstructed contract

**Recommendation:** implement `tools/evidence-disposition.py` as one stdlib-only CLI with an isolated, file-backed `--selftest`. Generate synthetic lane/evidence trees in one temporary directory; have every case invoke the exact running script as a child process. The production gate reads and validates retained JSON/text only. Its only subprocesses should be the selftest’s self-invocations; it must never execute `argv` values found in receipts.

The service protocol defines the boundary: its one-command suite must be invocable on a copy, exercise that copy, and “re-enter `$0`” (`corpus/knowledge/service-optin-protocol.md:63-67`). For Python, the corresponding child target is the exact current `__file__` path (resolved to an absolute path), not a hard-coded repository path or imported internal function. That lets a mutation-suite copy test its own changed bytes.

## Smallest standalone fixture architecture

1. **One fixture builder, one case table.** In a temporary lane root, write tiny synthetic `expected.json`, `verification.json`, `producer-oracle-repair.json`, and any small files named by synthetic `expected.inputs`. Compute their SHA-256 values from the bytes actually written. Write a disposition document whose `inputs` pins the expected file and each receipt used by the case. No Git repo, sibling checkout, actual round-13 evidence, or external fixture file is needed.
2. **Exercise the public CLI per case.** Invoke `[sys.executable, "-I", str(Path(__file__).resolve()), "--root", fixture_root, "--dispositions", disposition_path, "--json"]`, with the fixture as cwd, stdin closed, captured stdout/stderr, and a bounded timeout. Parse the JSON result and assert the exact process exit, stable finding ID(s), per-expectation state, and relevant mismatch details. This tests the copy under test rather than merely its helper functions.
3. **Two positive shapes, then data-driven negatives.** One all-effective fixture establishes ordinary rows and original expectation predicates. A second valid supersession fixture retains the raw `producer_before` receipt/check and makes both `producer_before_oracle` and `producer_after_oracle` effective and passing. Generate negative variants from the same base fixtures, changing one fact each so the expected finding is attributable: structured stdout mismatch despite the expected exit; missing/duplicate/unknown expectation or check binding; missing/cyclic/ineffective/failed supersession; changed used-receipt digest; changed original `expected.inputs` file; and an `argv` sentinel whose side effect must remain absent. The final sentinel checks the “never execute receipt argv” rule without running that receipt command.
4. **Make the fixture exercise the whole integrity-to-predicate order.** In each passing fixture, the expected file’s synthetic `inputs` bytes must hash correctly, and the disposition `inputs` must cover the expected file plus every used receipt. Keep stdout values representative enough to exercise `contains`, structured `id`/`reason`, and structured `rows`/`statuses`/`result_reuse` expectations. In the superseded case, verify the original observed check is still present, but grade the replacement checks against their original expectations; do not rewrite or synthesize a “successful” historical raw observation.

This avoids the two common undershoots visible in prior patterns: testing only helpers (the witness producer’s unit path) and letting a clean CLI depend on live pinned evidence (the witness-metadata selftest). A large Git fixture would also be unnecessary for this file-only gate.

## Required behavior and risks to preserve

The assignment’s interface requires all `expected_checks` exactly once; each effective row must select a unique receipt/check; original expectation fields, including structured stdout predicates, remain binding; superseded `producer_before` retains its raw observation and both replacements must be effective and pass; rows/references cannot be unexplained, dropped, cyclic, unknown, or missing; all used files and every original expected input remain digest-checked. A selftest that checks only process exit or a generic `PASS` line risks repeating the “exit-only” attribution defect: assert parsed JSON IDs/details and distinguish integrity failure from semantic expectation failure.

At inspection time, the `tools/` listing contained `repeat-control.py`, `witness-metadata.py`, `bash-witness-study.py`, `pin-disposition.py`, and `mutate-and-run.sh`; `evidence-disposition.py` was not present. The implementation was therefore not reviewed. No edits, selftests, builds, lint, or verification commands were run; no tools were installed.

- Run the declared before and after dispositions against the lane root with `--json`. Expect both clean exits; check that the before file has all expected checks effective, the after file has the same inventory with only `producer_before` superseded, and both replacement expectations pass. Confirm raw historical receipt/evidence bytes were not changed.
- Do not run a sibling mutation gate/sweep absent an existing owner opt-in and current spec. Any future protocol-suite run must target the copied gate so its `--selftest` re-enters the copy.
