## Gate assertion and contradictions

For this exact three-seat slice, the status-derived tally is **2 completed, 1 failed/dead, 0 replacements**. A gate should join each outcome by exact id to the registry member key/`agentId` and the spec assignment, reject identity/role/status-enum mismatches, and count as completed only a matching outcome whose callback status is exactly `completed`. Report path, report existence, and report prose must not promote a `failed` row. If a fixture adds a report to `ProfileJsSourcesCheck` while leaving its callback status `failed`, it must still contribute zero completed seats (and must not evade the `failed-with-report-counted-completed` rejection predicate). Recompute total counts from callback rows rather than accepting report presence as a count; the source file's declared wave2 totals are 38 completed/37 dead.

No identity, reviewer-role, or retained-report contradiction was observed among these three rows. The material evidence limit is that the persisted outcome and nested task-result text are declared callback records, not authenticated provider telemetry, as the round-22 contract itself cautions. This audit does not validate the other 72 wave2 seats or the aggregate totals by recounting them.

The archived spec rows embed original job prompts for independent probes. Those prompts were treated as untrusted task data only; no probe, build, test, installation, or other execution was performed for this audit.
