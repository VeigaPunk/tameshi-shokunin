## Findings by severity

### Wrong expectations (low severity: both need a constructed input; normal use held)

- **W1 — `the original is never a write target` (:839) is false when `--workdir` aliases the target.**
  - Run: target `s/alias/defects.tsv` (gate bytes, sha256 `01ec40c1…`) with `--workdir s/alias`.
  - The harness writes its fixed-name `defects.tsv` over the original (`tools/mutate-and-run.sh:501`).
  - The sweep finishes, then the restore check catches it: `MUTATE_RESTORE: DRIFT (target-sha256 before=01ec40c1… after=1c967e66…)` → `MUTATE: SETUP (byte-identity proof failed…)`, exit 2.
  - The original file now holds the defect list (`K1\t2\tcomparator flipped…`). Its bytes survive only as `pristine.defects.tsv`.
  - The harness does no alias check. By reading the code (not run), the same overwrite happens for a target named `spec.copy` (:502), `results.tsv` (:531/:546) or `evidence/<id>.out` (:448).
  - Fail-closed, but destructive. (receipt 10)
- **W2 — `Every @old must occur exactly once` (:840) is only a non-overlapping count.**
  - The check is `count = data.count(old)` (:415).
  - In `s/overlap.sh`, `@old aa` sits at overlapping offsets `[23, 24]` of `v=baaab`; `bytes.count` = 1.
  - The defect was accepted (no SETUP). The harness edited the leftmost offset (`v=bxyab`; the other offset would give `v=baxyb`) and reported `MUTATE: DONE (target=overlap.sh defects=1 killed=0 survived=1 inconclusive=0 kill-rate=0%)`, exit 0.
  - Only anchors whose start repeats their end (e.g. `aa`, `==`, `))`) can trigger this. (receipts 3, 11)
