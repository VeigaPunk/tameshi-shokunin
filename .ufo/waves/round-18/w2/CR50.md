## Findings by severity

**W1: wrong expectation (low impact; the code behavior is safe).**

The `evidence-disposition` row says "a jj-colocated repo with no `lane.branch` → 2". At the read rev:

1. `git clone <lane>` (HEAD attached to master), then `jj git init --colocate` (jj 0.45.1).
2. `python3 tools/evidence-disposition.py --root . --dispositions .ufo/evidence/round-18/dispositions.json` → **exit 0**, `EVIDENCE_DISPOSITION: clean …`. `lane.branch` is unset and `.jj` exists.
3. The result is still 0 after `git switch master` and after `jj log`. Only `jj new`, which moves `@-` and detaches HEAD, yields `2 historical_input_unavailable: jj workspace without a lane.branch binding has no authoritative tip`.

Receipts: r15, r24.

The code refuses an **unbound** workspace, meaning one with no `lane.branch` *and* no attached branch (`tools/evidence-disposition.py:51-53, 466-496`). Its own selftest fixture detaches HEAD on purpose (`_setup_hist_jj_unbound`). The page's "no lane.branch → 2" contradicts its own "or attached branch" clause in this reachable state.

Suggested repair: "a jj-colocated repo with neither `lane.branch` nor an attached branch (jj's working state: `HEAD` detached at `@-`) → 2".

**M1: residual of the timeout defect class.** `timeout_s` values from 2147483.648 upward pass the "finite positive number" validation, then crash inside `selectors.poll`:
- 3000000 and 2147484 → `OverflowError: timeout is too large`.
- 1e10 and 1e300 → `timestamp out of range for C PyTime_t`.

In every case registry-check exits **1**, which is the exit map's "any differs" code, prints a traceback, and emits no ROW or REGISTRY_CHECK line, so the row is not named. 2147483.647 runs and exits 0 (r12, r23).

Suggested fix: refuse `timeout_s > 2147483` at validation, so it exits 2 naming the row, or catch `OverflowError`. Realistic timeouts (≤ 300 s) are unaffected.

**M2: operability.** Under the trace-every-command cold-read protocol, `defect-probes.py --rev REV` exits **2**. P05–P07 run `trace-inputs.py --selftest` inside the traced tree, nested ptrace is refused, and the result is `pristine selftest failed (exit=1): SELFTEST: 5/30` (r6). Neither the defect-probes row nor the trace-inputs row warns about this. The measured exit-0 line is only reachable untraced.

**M3: wording.** "`--carry` copies prior entries verbatim" is not byte-exact: each entry gains, or has overwritten, `carried_from`. Assemble's own `--help` already says "retaining their original evidence and adding carried_from" (r21).

**M4: documentation mismatch, not exercised.** "every descendant … is killed" omits residuals that `tools/registry-check.py:39-44` documents itself: UID-changing descendants may be unkillable, and same-tick PID reuse remains. Exercising this needs a setuid descendant, so I did not run it.
