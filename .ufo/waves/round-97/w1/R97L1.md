## 1. Probe contract and fixture

Reconstructed contract (from the checker's docstring and code at `07e50d6d`): the checker
is a claim about what the counter measures. For every conjunct key the counter prints, the
manifest must have a row that is a committed battery state whose receipt shows the conjunct
FALSE, or a committed setup refusal whose receipt prints the named `C1_SETUP` token, or an
`unfalsifiable` reason that names a mechanism and a committed state or a digest. Receipts are
read as blobs at `--rev`; `counter_sha=` is bound to the counter blob's sha256; the manifest
is bound to the sha256 the round's claims file names; git runs under a scrubbed environment.

Method, per guard: pick one guard site → one exact-string edit whose anchor occurs exactly
once → a state that should distinguish pristine from mutant → build a fresh fixture store in
the checker's layout (a counter stub printing `C1_CONJUNCT_KEYS alpha beta gamma`, a
manifest, `.ufo/waves/round-96/claims.json` with `manifest_sha256`, receipts under
`.ufo/evidence/round-96/pre-freeze/controls/` in a real git repo) → run pristine and mutant
with the same `--lane/--rev` and the same environment → classify.

Classification rule (mine, not C2's): `killed` when the pristine run reproduces the declared
exit and token and the mutant changes the exit or loses the token; `identical` when the
pristine baseline is reproduced and the mutant's exit, token and full stdout are unchanged;
`inconclusive` when the pristine baseline is not reproduced, the anchor is not unique, or the
mutant does not compile. Each mutant is `compile()`d before it runs.

Fixture fidelity check: the pristine checker, run on the **real lane** at `07e50d6d`, prints
`DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0`, exit 0
(`R97L1-receipts/real-lane-at-base.out`) — the round-96 disposition predicate, through the
same code path my three-conjunct fixture exercises.

Harness: `R97L1-receipts/independent.py`; it extracts the checker blob from the lane and
verifies it against `02a5482a…` before any row runs. It requires `R97L1_SCRATCH`; it writes
only under that directory.

Two mechanisms I measured directly, because C2's row lines are terse:

- `rev-unresolvable`: `git rev-parse <unknown-40hex>` prints the argument and exits **0**, so
  the mutant proceeds past the resolve and later exits 2 at `counter-absent-at-rev`. The kill

  branch cheat, it lands in a different setup refusal.
- `verify-quiet`: `git rev-parse --end-of-options <40hex>^{commit}` exits **128**, and adding
  `--verify --quiet` exits **1**; the checker only tests `returncode != 0`, so the tokens are
  inert on this state. C2's stated mechanism (surviving `^{commit}` suffix) is correct.

## 7. Limits of this probe

- The fixture store is synthetic (three conjuncts, two or three receipts, one commit). A guard
  whose effect needs the real 50-state receipts is out of scope. The real-store baseline run
  shows the same code path on the real 19-row store, but it does not measure guard edits there.
- One exact edit per guard. Combination effects are out of scope, and I demonstrate why that
  matters only for G3+G4: the single `GIT = "git"` edit is inert, the two-edit variant is not.
- The kill criterion is exit/token/stdout difference, not semantic correctness. A mutant that
  crashes would count as `killed` by difference unless the pristine baseline failed first;
  none of my six crashed (each mutant compiles and every mutant run produced a full
  disposition line or a setup refusal).
- I did not re-derive R96L1's guard-only variant construction. I verified that the report and
  its 280-file receipt tree are committed, that the cited receipt line prints `matched=44`,
  and that the report predates the plan freeze. That is evidence of a committed measurement,
  not a re-execution of it.
- Fixture commit hashes are nondeterministic (timestamps); the row classes are not. The full
  run was repeated and the six classes were unchanged.
