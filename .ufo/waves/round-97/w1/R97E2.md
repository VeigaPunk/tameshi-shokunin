  checker's PATH pin *also* removed: shim invoked **1 time**, mutant exit 2 vs pristine exit 0.
  The mechanism sentence ("equivalent unless the PATH pin is removed too") is measured, not

## Findings (non-kill; for the reviewer/scribe)

**F1 — the plan's "instrument commit" label is stale for C2 (calibration).**
`git cat-file blob 917d7109:.ufo/evidence/round-97/c2/guard-inertia.py | sha256sum` =
`880bc4d6ab85…`, **not** the claims' `instrument_sha256` `96c3829d8a70…`. The pinned bytes first
appear at `997ce0c4` ("repaired guard-inertia"), and the freeze commit `e72a0c8b` carries them.
Behavioural consequence, measured on the same no-op manifest commit (`4932f878…`, same
`--checker-sha`):
* tool at `917d7109`: stdout empty, **stderr** `GUARD_SETUP edit-no-op:rev-hex`, **exit 1**;
* pinned tool: **stdout** `GUARD_SETUP edit-no-op:rev-hex`, stderr empty, **exit 2**.

So a reader who follows the plan's instrument commit to `917d7109` gets a tool that does not
satisfy the frozen refusal sentence. The claims are internally consistent at R (they pin the
repaired digest), so this is not a C2 kill; it is a provenance-label defect worth recording or
amending in the plan. I did not edit the plan or the claims.

**F2 — `--selftest` is not hermetic (operability limit).** `selftest()` calls
`tempfile.mkdtemp(dir=<SCRATCH_ROOT>/tameshi-r97)` (`guard-inertia.py:247`) before `sealed_env()`
creates that parent. On a fresh scratch root the battery crashes with `FileNotFoundError`, exit 1,
and never prints `GUARD_INERTIA_SELFTEST`. The main command does not have this problem (it calls
`sealed_env()` first, which creates the parent as a side effect), so the C2 predicate is
unaffected; the declared battery passes on this host only because
`/fast/scratch/hyaku/tameshi-r97` already exists. A one-line `os.makedirs(..., exist_ok=True)`
would fix it, but that changes the frozen tool digest, so I did not touch it. Flagged for a
follow-up instrument revision.

**F3 — in-band pin asymmetry (residual limit).** The counter command pins the checker
(`--checker-sha`) but not the tool or the manifest; those digests live only in `claims.json`
(`instrument_sha256`, `manifest_sha256`). The tool would run a tampered manifest at R. A reader
must compare the claims pins. Not a kill (the claim surfaces the committed manifest and the claims
pin it), but the matrix's own bytes are not self-verified.

**F4 — nested checker scratch dependency (fails closed).** The tool's `sealed_env()` drops
`HYAKU_SCRATCH`, so the nested round-96 checker always uses
`/fast/scratch/hyaku/tameshi-r96` for its `TemporaryDirectory` (checker `:417`). That path exists
on this host. I measured the absent-path case by copying the pinned tool blob to scratch and
injecting `"HYAKU_SCRATCH": "<no-such-root>"` into its `sealed_env()` (the lane file untouched):
the matrix printed `rows=10 killed=3 limits=1 survived=6 unmet=6`, exit 1, and no predicate — it
fails closed, not open. The traceback crash is why the four `pristine` runs that reach the counter
read become `pristine-unmet`. Recorded as an environmental reproducibility limit, not a wording
failure. Transcript in `R97E2-repro.txt` §11.

**F5 — a token can be injected by the runner's file path (safe-direction artifact).**
`run_checker()` returns `r.stdout + r.stderr`, and the mutant file is named
`checker-<row-id>.py` inside `row<NN>-<row-id>/`; a crashing checker's traceback embeds that path.
Two manifest tokens equal their row ids (`no-flip`, `unknown-key`), so in the clean-host
simulation (F4) those mutants reported the token present although they crashed before
`report()`. The artifact can only turn a lost token into a present one (killed → survived), never
the reverse, and the frozen run has no crashing checker, so the predicate is unaffected. It
matters only for a future state that legitimately crashes.
