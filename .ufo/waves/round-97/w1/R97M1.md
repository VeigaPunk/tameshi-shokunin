## 2. Method

* **Pre-registration first.** `R97M1-prereg.json`
  (sha256 `0fadb10e34bb66bc45010a0dbef525e3611d9b24cc33f77cf43cdd2804b0e97c`) fixes the 12
  rows (exact `old`/`new`, class, `expect`, and a per-detector green/red prediction) and was
  written before any mutant ran. The driver asserts each anchor occurs exactly once in the
  committed bytes (`anchor_count=1` in `R97M1-results.json`), that `old != new`, and refuses
  to start unless the pristine hashes equal the freeze pins.
* **One edit per mutant.** Each row is a single exact-string replacement on the committed
  text; no mutant has a second edit. The two tool copies are independent, so `M03`/`M06`
  share an anchor without interacting.
* **Two detectors per mutant**, both from the frozen declarations:
  the tool's `--selftest` (battery) and the tool's main command at the freeze rev with the
  pinned driver/checker digest.
  * green = exit 0 **and** the frozen summary line present
    (`BATTERY_SELFTEST: 7/7 pass`, `BATTERY states=50 matched=50 mismatched=0 missing=0`,
    `GUARD_INERTIA_SELFTEST: 7/7 pass`,
    `GUARD_INERTIA rows=10 killed=8 limits=2 survived=0 unmet=0`);
  * red = anything else (nonzero exit, a different predicate line, a setup refusal, or the
    predicate line absent).
* **Verdict rule (seat spec).** `killed` = selftest red **or** main red, and the tool still
  executes and prints its own verdict (no interpreter crash); `survived` = both green with
  the same line; `inconclusive` = a traceback before a verdict. No mutant crashed; all 12
  produced tool-authored output, so every row is classified.

## 4. Survivor — the one coverage gap

**M06 — `battery-bind.py:159` in `bind()`**, the grading call
`ok = drv.grade(name, code, body, expectations[name])`, escalated to

```python
try:
    ok = drv.grade(name, code, body, expectations[name])
except Exception:
    ok = True
```

Both detectors stay green (`BATTERY_SELFTEST: 7/7 pass`; main prints the frozen predicate,
exit 0). The reason is not that the edit is inert: neither the fixture driver nor the 50
committed receipts ever make `drv.grade()` raise, so the permissive handler is never
executed. It is reachable, which I confirmed with a bounded side fixture (not part of the
matrix; `R97M1-probe-m06.log`): a scratch git repo with one receipt whose driver
`grade()` raises `RuntimeError('driver-grade-boom')`:

```
pristine  exit=1  last: File ".../controls-under-test.py", line 5, in grade
                        RuntimeError: driver-grade-boom
M06       exit=0  last: BATTERY states=1 matched=1 mismatched=0 missing=0
```

So the defect converts a crashing reader into a green 50/50-shaped verdict (here `states=1
matched=1`) whenever a driver's `grade()` raises — exactly the class of failure (an
unexpected receipt shape) for which a reader should go red. Neither the selftest nor the
main run at R exercises that path, so the pair cannot kill it. This is a coverage finding
about the C1 instruments' self-detection, not a falsification of C1's wording: no kill rule
claims the reader is robust to a raising oracle. It should be recorded as a declared-limit
sentence or closed by a selftest arm with a raising `grade()` (the fixture driver in
`selftest()` is fully under the tool's control, so the arm is cheap).

## 6. Limits of this matrix

* One exact edit per row, applied to one blob; two-edit combinations, deleted functions and
  whitespace-only variants are out of scope, as are edits to the manifest
  (`guard-inertia.json`) or to the round-96 driver/checker (not this seat's targets).
* The detectors are the tools' own selftest and main run; no third-party grader was used.
  The main detector's green condition is the frozen predicate *line*, not exit 0 alone —
  deliberately, because M04 and M08 exit 0 with a wrong line (and M01/M02/M10 exit 0 with a
  right-looking line).
* The selftest-detected rows (M01, M02, M10) show the division of labour the claims rely on:
  the claim's *counter* alone is blind to them; the claim's *battery* (kill rule d for C1,
  C2's selftest) is what kills them. A grader that runs only the counter command would see
  M01 as a survivor.
* M08's defect is a lost enumeration; it is killed because the tool still printed a
  summary, and that summary (`rows=0`) differs from the frozen line. Had the mutant exited
  silently, the row would have been classified the same way (M12 shows that case).
* `battery-bind.py:46` defines `SELF_LINE`, which nothing references. It is dead bytes, not
  a guard; it was deliberately not used as a mutant (an inert constant would survive for the
  wrong reason).
