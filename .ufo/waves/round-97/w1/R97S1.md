**M-8 — the freeze's four C1 body-edit controls are byte-identical; the
`exit=` and payload controls do not discriminate their clause at all.**

This is the most consequential finding, and it is a **fixture-craft** defect,
not a wording defect. The pre-registered control table (freeze plan) lists
`c1-forge-counter-sha`, `c1-forge-exit` and `c1-forge-payload` as three
*separate* attacks, each expected to print `mismatched=1`, rc 1. The committed
receipts are the **same bytes**:

```
$ for f in c1-forge-counter-sha c1-forge-exit c1-forge-payload c1-forge-conjunct; do
    git show e72a0c8b:.ufo/evidence/round-97/pre-freeze/$f.out | sha256sum; done
1c9754f32a016b05  c1-forge-counter-sha
1c9754f32a016b05  c1-forge-exit
1c9754f32a016b05  c1-forge-payload
1c9754f32a016b05  c1-forge-conjunct
```

and every one carries the same reason string:

```
BATTERY_ROW pos-real:MISMATCH(counter-sha)
BATTERY states=50 matched=49 mismatched=1 missing=0
rc=1
```

**Cause** (frozen `controls97.py:113-150`, visible at the freeze commit): the
builder reuses one clone and does `git(st, "reset", "-q", "--hard", r)` where
`r` is **reassigned to the previous forgery's commit** before the next
forgery is built. Each forgery is therefore applied **on top of** the previous
one, not to a pristine receipt:

```
# (b) counter_sha edit
git(st, "reset", "-q", "--hard", r)     # r = the "drop pos-real" commit
... r = commit(st, "counter-sha edit") # r is REASSIGNED
# (c) exit edit
git(st, "reset", "-q", "--hard", r)     # r = the "counter-sha edit" commit
... body = open(...).read()            # body STILL carries counter_sha=000…0
```

So the "exit edit" receipt carries **both** the bogus `counter_sha=` **and**
`exit=7`, and the binder's digest check (`battery-bind.py:154-157`) fires
**first** and `continue`s — the `exit=`/`grade()` path at `:159` is never
reached. The receipt therefore reports `MISMATCH(counter-sha)` for a forgery
whose name says it is an exit edit. The payload control is worse still: it
stacks a third edit on top, and it also asserts `C1_R96_PASS=true` is present
in a body that has been rewritten twice.

**Measured discriminating power.** I rebuilt the freeze's exact stacked
forgeries against a **mutant binder whose `grade()` conjunct is dead**
(`ok = True  # MUTANT: grade() never consulted`) in a scratch clone at the
freeze rev. The mutant still prints, for the forgery the freeze calls
`c1-forge-exit`:

```
BATTERY_ROW pos-real:MISMATCH(counter-sha)
BATTERY states=50 matched=49 mismatched=1 missing=0
RC=1
```

— **byte-identical to the pristine receipt**. That is the definition of a
control with zero discriminating power: the `c1-forge-exit` and
`c1-forge-payload` receipts would be unchanged if the `grade()` conjunct — the
very thing those two clauses name — were deleted from the instrument. A
control that cannot fail is exactly what C1's kill rule (d) forbids ("the
selftest cannot fail"), applied to the control battery rather than the
selftest.

For contrast, the **isolated** exit edit (counter_sha intact) does name a
different reason, proving the clause *is* enforced in the instrument and that
it is the *control construction* that destroys the discrimination:

```
$ # isolated exit edit only, counter_sha intact
BATTERY_ROW pos-real:MISMATCH(exit=7)
BATTERY states=50 matched=49 mismatched=1 missing=0
RC=1
```

Full receipt: `.ufo/waves/round-97/w1/R97S1-receipts/R97S1-control-discrimination.txt`.

**Consequence for the frozen sentence.** The sentence's clauses "an `exit=`
edit … print a nonzero `mismatched` count and exit 1" and "a
`C1_R96_PASS=true` payload edit … print a nonzero `mismatched` count and exit
1" are **true of the instrument** (measured in isolation, above) but the
committed control battery **does not evidence them**: the receipts that claim
to evidence them carry a different clause's reason string and would survive
the removal of the code they name.

**Status at HEAD.** Not fixed. `controls97.py` at HEAD still carries the same
`reset --hard r` / reassigned-`r` pattern (same 4 body-edit receipts still
byte-identical, sha `1c9754f32a016b05`), and HEAD's `pre-freeze/` directory
has grown to 17 receipts — including `c2-forge-manifest-empty.out` and
`c2-forge-manifest-subst.out` — while the driver's `add()` calls still emit
**16**; `c1-forge-conjunct.out` is present in the directory at both the freeze
and HEAD but is emitted by **no** `add()` call in either driver (the freeze
driver emits 14 named states against 15 files present; HEAD emits 16 against
17). The orphan `c1-forge-conjunct.out` is a stale receipt from an earlier
control set whose name no longer matches any emitted state.

This is a `falsifies-wording`-adjacent artifact of the round's own control
evidence: it does not falsify the *sentence* (the instrument behaves as
claimed) but it does falsify the *evidence* for two of the sentence's clauses.
The repair is a control-construction fix (reset to a pristine rev before each
