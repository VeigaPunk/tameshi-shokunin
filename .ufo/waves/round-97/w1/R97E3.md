## Verdict

1. **The declared limit holds as declared** for step 1 (hand-written receipt), step 2's swap and
   fabricated-conjunct variants, and step 3 (the oracle boundary). The reader never re-executes a
   state; a receipt is accepted iff its `exit=`/payload satisfy the committed driver's `grade()` and
   (for non-mutant receipts) its `counter_sha=` equals the frozen counter digest. The driver itself
   is never checked against truth, only against a caller-supplied digest.
2. **One `FALSIFIES-WORDING` (FW-C1-1)**: the frozen universal clause "a `counter_sha=` edit …
   print[s] a nonzero `mismatched` count and exit[s] 1" is false for a `mutant=` receipt —
   demonstrated on `D01.out`; `D02`–`D05` carry the same `mutant=` header and the same exemption
   path. A pure `counter_sha=` edit on `D01.out` is counted **matched**: the reader prints
   `BATTERY states=50 matched=50 mismatched=0 missing=0`, exit 0.
3. **One under-declaration advisory (HIGH)**: a hand-written receipt carrying a *wrong*
   `counter_sha=` (64 zeros) **plus a producer-controlled `mutant=D99` line** is also accepted
   (`matched=50`, exit 0). The declared limit's precondition ("carrying the right `counter_sha=`")
   is therefore narrower than what the reader actually enforces: any receipt can opt out of the
   digest check with one line.
4. Step 3's answer: the reader **accepts a tampered driver as the oracle** when the pin passed on
   the command line matches the new blob — it regrades the affected state against the new
   expectation, and with a hand-written matching receipt it prints the full predicate at a revision
   whose driver the forger wrote. `claims.json` is **not read by the tool** (measured: the pin is
   purely caller-supplied; E3d reproduces the tampered-oracle acceptance with `claims.json`
   untouched). The claim's wording **does say so**: `C1.limits[0]` = "the reader trusts the
   committed driver as the oracle; it verifies that the receipts satisfy it, not that the driver's
   expectations are the right ones", and the operative wording says expectations come "from the
   committed driver's `states()` and `EXPECT_EXTRA` at R". No wording contradiction on step 3.

## Step 1 — the hand-written receipt is accepted

`pos-real.out` was replaced in a scratch clone with a 431-byte hand-written body: the frozen
`counter_sha=`, `exit=0`, two `C1_ROW` lines, a deliberately false `C1_SUMMARY`
(`rev=000…`, `n=2`, `verdict_tables=0`) and `C1_R96_PASS=true`. No state was executed. Committed
in the clone (`83c616e6…`), read by the binder at that commit with the frozen pin. The exact line:

```
BATTERY states=50 matched=50 mismatched=0 missing=0
```

exit 0. The reader accepts it. `grade()` for a `__pass` state only requires `exit == 0` and the
substring `C1_R96_PASS=true`; nothing parses the `C1_ROW`/`C1_SUMMARY` numbers, and nothing
re-executes the state. This is precisely `C1.limits[1]` ("a hand-written receipt carrying the right
`counter_sha=` and payload cannot be distinguished from a real run without re-executing the
state"). **accepted — limit-as-declared.**

## Step 2 — stronger forgeries: which the reader accepts

- **Swap (E2a)**: the bodies of `hidden-c001.out` and `hidden-x.out` were exchanged verbatim; the
  body at `hidden-c001.out` now carries `control=hidden-x` (and vice versa). Both states expect
  `exit=1` with `verdict_tables=false`, so each payload satisfies the other file name's `grade()`.
  Reader: `matched=50`, exit 0. The in-body `control=` header is never parsed; a receipt is bound
  to its file name and expectation class only. Accepted, limit-as-declared.
- **Fabricated but conjunct-consistent (E2b)**: a hand-written `hidden-c001.out` whose
  `C1_SUMMARY` says `verdict_tables=1`, `badrows=0`, `n=12`, `killed=12` and `C1_R96_PASS=true`
  while `exit=1` — internally contradictory — but whose `C1_CONJUNCTS` line carries
  `verdict_tables=false`, the only key the oracle checks. Reader: `matched=50`, exit 0. Accepted,
  limit-as-declared. `grade()` reads only `exit=` plus the expected conjunct keys.
- **Cross-class swap control (E2c)**: the same `hidden-x` body placed in `pos-real.out` (which
  expects `exit=0`) is refused: `pos-real:MISMATCH(exit=1)`, `matched=49 mismatched=1`, exit 1.
  The exit check binds; the swaps are not universal.
- **Mutant-header swap (E2h)**: `D02.out` receives `D01.out`'s body verbatim (`mutant=D01`).
  Reader: `matched=50`, exit 0. The `mutant=` header is not checked against the file name either.
- **Mutant-label counter bypass (E2d)**: on the *non-mutant* `pos-real` state, a hand-written body
  with `counter_sha=` = 64 zeros and a `mutant=D99` line is accepted (`matched=50`, exit 0).
  `battery-bind.py:153-155` skips the digest comparison whenever the body matches
  `^mutant=D[0-9]+`; the label is producer-controlled and not tied to the D states. This is
  **broader than the declared limit**, which phrases the indistinguishable forgery as "carrying
  the right `counter_sha=`". See advisory 1.

In a scratch clone the driver blob `.ufo/evidence/round-96/c1/controls-v96.py` was edited with one
exact-string flip in `states()`:

```

+                         expect=(1, {"verdict_tables": True}))
```

new driver sha256 `c563d2e2aca0fab8e22ca7d76fa02f63d4fcbae9a15be2ac2fb6ad64d4e29560`;
`claims.C1.driver_sha256` was updated to the same digest in the clone and the reader was invoked
with `--driver-sha c563d2e2…`.

- **E3a**: `BATTERY_ROW hidden-x:MISMATCH(exit=1)`, `BATTERY states=50 matched=49 mismatched=1 missing=0`,
  exit 1. The reader took the expectations from the tampered driver — `hidden-x`, and only
  `hidden-x`, moved class. The tampered driver was accepted as the oracle; the stale receipt is
  what the run refuses.
- **E3c**: the same revision read with the original frozen pin is refused

- **E3b**: with the flip still in place, `hidden-x.out` was replaced by a 266-byte hand-written

  `BATTERY states=50 matched=50 mismatched=0 missing=0`, exit 0. The full predicate is reproduced

- **E3d**: the same driver mutation with `claims.json` left at the frozen `88bcc…` and the new

**Does the claim's wording say so?** Yes. `C1.limits[0]` declares exactly this: "the reader trusts
the committed driver as the oracle; it verifies that the receipts satisfy it, not that the driver's
expectations are the right ones". The operative sentence likewise takes expectations "from the
committed driver's `states()` and `EXPECT_EXTRA` at R". No falsification on step 3.

## Step 4 — FALSIFIES-WORDING

### FW-C1-1 — a `counter_sha=` edit on a mutant receipt is not refused

Frozen sentence (`claims.json` at the freeze rev `e72a0c8b`; the `counter_sha=` clause is unchanged
at HEAD after amendment A1 rewrote only the de-index clause):

> "a receipt deleted from the index (but left in the working tree), a `counter_sha=` edit, an
> `exit=` edit and a `C1_R96_PASS=true` payload edit each print a nonzero `mismatched` count and
> exit 1"

Artifact (receipt E2e): clone `e72a0c8b`, `D01.out`'s first `counter_sha=` line rewritten from
`812d74286de911a94fd5136dd85ad228adb2a4e8928a4ecf12dfe852742b4247` to 64 zeros, nothing else
changed (body sha256 `e46e886d231ca9e6061bb31689f7f8c0c813eb8fd07267a77f78305d0fd4f310`), committed
as `03839e7a7b071c11772db2e71fddfbcce5401e52`; reader invoked with the frozen pin:

```
BATTERY states=50 matched=50 mismatched=0 missing=0
rc=0
```

Cause: `battery-bind.py:153-155` — `is_mutant = re.search(r"^mutant=D[0-9]+", body, re.M)`; the
digest comparison is skipped for every `mutant=` receipt, and all five D receipts name a mutant row.
The exemption is intentional and documented in the tool's own docstring ("… while the receipt does
not name a `mutant=D<nn>` row"), and the frozen 50/50 positive **depends on it**: D01's receipt
carries the mutant counter digest `812d…`, not the frozen `69ee…`; deleting the `mutant=` line from
D01 makes the reader print `D01:MISMATCH(counter-sha)` (E2g). The sentence therefore needs the same
pre-data narrowing the plan already gave the de-index half under A1 — scope the refusal to
*non-mutant* receipts. Suggested amendment (for L1; I did not edit `claims.json`): replace
"a `counter_sha=` edit … each print a nonzero `mismatched` count" with "on a receipt that does not
name a `mutant=D<nn>` row, a `counter_sha=` edit (like an `exit=` or `C1_R96_PASS=` payload edit)
prints a nonzero `mismatched` count and exits 1". Per the plan's §Kills, this wave artifact should
be folded into §Amendments rather than treated as killing the wider sentence.

## Advisories (not claims of wording falsification unless stated)

1. **HIGH — the counter digest check is producer-opt-out.** Any receipt body can add `mutant=D<nn>`
   and skip the `counter_sha=` comparison; E2d shows `pos-real` (a non-mutant state) accepted with
   a zeroed digest. If the intent is "a receipt is bound to the frozen counter unless it is one of
   the declared mutant runs D01–D05", the reader does not enforce the second half (the label is
   not matched against the state name and `D99` is not in `EXPECT_EXTRA`). This also sits close to
   C1 kill rule (a) as worded ("its `counter_sha=`/`exit=`/payload does not satisfy the committed
   driver's own `grade()`"): `grade()` has no `counter_sha=` input, so the counter binding is
   purely the binder's separate clause. I record the artifact and do not claim the kill; the
   judgement belongs to L1/the critic.
2. **LOW — docstring/code divergence in the reader.** The docstring (lines 18–20) says a receipt
   whose `counter_sha` differs from the counter blob's sha256 "is `missing`"; the code counts
   `mismatched` (`battery-bind.py:154-155`; observed as `MISMATCH(counter-sha)` in E2c/E2g). The
   frozen wording says `mismatched`, so the code matches the claim; only the docstring is stale.
3. **Observation — the pre-registered control does not cover the mutant path.** `c1-forge-counter-sha`
   edits `pos-real.out` (`controls97.py:115-133`), a non-mutant receipt, so the frozen positive and
   pre-freeze control suite never exercised a `counter_sha=` edit on a `mutant=` receipt. That is
   why FW-C1-1 was invisible until this probe.
