## Falsified spans (wording defects)

### F1 — HIGH — a `counter_sha=` edit on a mutant receipt is not `mismatched`; the exemption is forgeable

- **Span:** claims + plan: “a `counter_sha=` edit … each print a nonzero `mismatched` count
  and exit 1”.
- **Enforcing line:** `battery-bind.py:153–154` —
  `is_mutant = re.search(r"^mutant=D[0-9]+", body, re.M) is not None` / `if not is_mutant and
  got_sha != counter_sha: mismatched`. The exemption is keyed on the receipt's own text, not
  on the state name.
- **Case 06** (`D01.out` counter_sha → `0…0`, commit `71405c54f94e0ea04d7a62450843548be6d97a0a`):
  `BATTERY states=50 matched=50 mismatched=0 missing=0`, rc 0.
- **Case 28** (`pos-real.out` counter_sha → `0…0` plus a `mutant=D99` line, commit
  `127a7f651c1e50c7948c3442008a5b0a37ca2f6c`): `BATTERY states=50 matched=50 mismatched=0
  missing=0`, rc 0. A receipt can disable its own `counter_sha` check by asserting a header
  that need not match its state.
- **Repair (narrowing, pre-data):** “a `counter_sha=` edit **on a non-mutant receipt**” — and
  the forged-header case belongs in the declared limits (a header is a producer's claim, not
  evidence).

### F2 — MEDIUM — an empty `--driver-sha` is not refused

- **Span:** claims + plan: “a `--driver-sha` value unequal to the driver blob's sha256 is
  refused `BATTERY_SETUP driver-sha-mismatch`, exit 2”.
- **Enforcing line:** `battery-bind.py:125` (`if driver_sha_pin and …`): `None` and `""` are
  both falsy, so an explicitly supplied empty value is treated as “no pin”.
- **Case 13** (`--driver-sha ""` at the clean fixture base): `BATTERY states=50 matched=50
  mismatched=0 missing=0`, rc 0.
- **Risk:** a wrapper that passes `--driver-sha "$PIN"` with `PIN` unset silently loses the
  digest check. **Repair:** distinguish absent (`None`) from empty and reject an empty or
  non-64-hex pin at setup.

- **R does not exist yet.** The records revision is not committed at review time; the exact

  and on the fixture (case 00) — all `BATTERY states=50 matched=50 mismatched=0 missing=0`,
  rc 0; the reader blob is `34d5aa…`, driver `88bcca…`, counter `69ee…` at both revs. If the
  records commit changes the reader, driver, counter or any receipt blob, the predicate must
  be re-run at R; the `--driver-sha` pin in the claims' counter covers only the driver.
- **Fixture equivalence.** The fixture is a re-commit of a minimal tree (692 KB) extracted
  from `43acfe81`; the driver reads only the included paths, the driver/counter shas equal the
  claims pins, and the fixture reproduces 50/50. A future driver that reads another path would
  need the fixture extended.
- **Cost.** The reader archives the whole lane at `--rev` (730 MB at `43acfe81`, ~20 s per
  full-lane run); the fixture runs are ~0.3 s. No functional difference observed.
- **Counter pinning.** The command pins the driver only. The counter is implicitly pinned by
  the receipts' `counter_sha=` lines; a changed counter blob at R makes every non-mutant
  receipt mismatch (exit 1), so it cannot produce a false predicate. The mutant exemption is
  the hole (F1).

- **Scope of the attack.** I did not re-execute a state (round-96 F1); receipts remain
