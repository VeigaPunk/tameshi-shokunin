# R97E3 — executor — probe C1's declared limit (a hand-written receipt) and the oracle boundary

## Target
C1's declared limits in `claims.json` (`C1.limits`): the reader trusts the committed driver as the oracle and cannot distinguish a hand-written receipt carrying the right `counter_sha=` and payload from a real run.

## Steps
1. In a scratch `git clone --shared` at the freeze rev, replace one receipt (e.g. `pos-real.out`) with a **hand-written** body that keeps the same `counter_sha=`, `exit=`, `C1_ROW …` rows (or a plausible subset) and `C1_R96_PASS=true`. Commit inside the clone only. Run the reader. Does it print `matched=50` (i.e. is the hand-written receipt accepted)? Record the exact line.
2. Build a stronger forgery: a receipt whose payload satisfies the driver's `grade()` while its `control=`/`mutant=` header names a different state (a swap), and one whose rows are fabricated but conjunct-consistent. Record which the reader accepts.
3. Measure the oracle boundary: edit the **driver blob** in the clone (e.g. flip one expectation in `states()`) *and* update the `claims.json` `C1.driver_sha256` to the new digest. Does the reader accept it? This is the declared limit (the reader checks receipts against the oracle, not the oracle's truth) — confirm it, and state whether the claim's wording says so.
4. If any step contradicts the frozen wording, write `FALSIFIES-WORDING` with the sentence and the receipt.
