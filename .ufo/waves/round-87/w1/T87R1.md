FINDING M1 .ufo/evidence/round-87/measure.py:249-257 weak — Seven of eight cases are satisfiable WITHOUT reading committed bytes: `carried` (`:250`, cand_rev=base) has worktree bytes identical to the candidate content (tools unchanged between base and receipt_rev, and the worktree is checked out at receipt_rev, `:208`), so hashing on-disk files reproduces the expected rows; the six exit-2 cases (`:252-257`) are decidable from argv plus worktree receipt bytes alone (marker absent, `deadbeef` sha, mixed headers, zero population, absolute root, all-zeros candidate). The entire anti-oracle margin is the single `mixed` case (`:251`), whose expectation (different/absent/nonregular) is only derivable from the candidate tree. No frozen control reaches 8/8 (pre-freeze max 1/8), so the kill rule is not triggered; [INFERENCE] the 1/8 control (`ctl-cn1-oracle-worktree`) passes exactly the `carried` case. Recorded as margin, not defect: one more candidate-only case would remove the single point of discrimination.

FINDING M2 .ufo/evidence/round-87/measure.py:208-210 note — The "worktree forced off the candidate" invariant is asserted via `rev-parse HEAD` only; no per-blob assertion that on-disk bytes differ from the candidate tree. In a fresh fixture `checkout --detach` cannot skip files, so there is no exploit path today; a byte-level spot check would make the guard independent of checkout semantics.

FINDING M3 .ufo/evidence/round-87/measure.py:65 note — Off-contract exit paths that print no `C1_R87` line: git-unresolvable raises `SystemExit` → exit 1, while the docstring (`:35`) promises exit 2 for setup refusal; likewise a non-UTF8 child output (text-mode decode inside `subprocess.run`, `:98/:262-266`) raises `UnicodeDecodeError` (a ValueError, outside the `:283` except tuple) → traceback, exit 1. All are honest stops (never a false PASS), but they bypass the documented exit contract and the predicate line.

FINDING M4 .ufo/evidence/round-87/measure.py:269 note — Boundary record for check (c): exit-2 stderr is compared by prefix only, so anything after `design-blob-audit: setup refusal` on the first line, and all subsequent lines, are unconstrained. This matches the plan's own spec for exit-2 cases; a refuse-everything counterfeit still fails `carried`/`mixed` on exit code, so no 8/8 path exists through this tolerance.

FINDING C1 tools/capability-census-v2.py:190 weak — Citation matching is not "exact" as the plan sentence says ("requires a pin … named by its own row, and matches citations exactly"): the directory-prefix rule binds ANY regular blob under a cited `dir/` token (empirical capC: row citing `` `r/` `` binds pin `r/b.txt`, `bound=yes`), and the whole-word rule (`:186-189`) binds a pin appearing as an argument inside a cited command. The frozen docstring (`:26-29`) discloses the three-way rule, so instrument and claim text differ in strictness. Predicates still hold (overreach population refuses 30/30 at the citation gate; tree/symlink/shape gates are independent, so even an exactly-cited `.ufo`/`tools` pin is refused by `:226-227`), hence weak, not kill.

FINDING C2 tools/capability-census-v2.py:276 weak — Live binding has a None-id hole: `wanted = entry.get('selfstate_row')` (`:276`) is None when the manifest entry omits the key, and `live_rows` stores `row.get('id')` unconditionally (`:254-255`), so a selfstate capability row lacking `id` puts None into the set and `wanted not in live_rows[name]` (`:281`) passes → `bound=yes reason=selfstate:None`.
