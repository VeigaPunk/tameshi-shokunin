## 4. Empirical Vulnerability Discovery: The Worktree-Reading Heuristic Cheat

### 4.1. The Vulnerability in `measure.py`
In `/home/vgpnk/Projects/shokunin/tameshi-shokunin/.ufo/evidence/round-86/measure.py:148-175`:
```python
ok_root = 'pop/ok-%s' % nonce
mx_root = 'pop/mx-%s' % nonce
rf_root = 'pop/rf-%s' % nonce
zp_root = 'pop/zp-%s' % nonce
...
receipt(mx_root, 'ma-%s' % nonce2, tools['a'][0], tools['a'][1])
receipt(mx_root, 'mb-%s' % nonce2, tools['b'][0], tools['b'][1])
receipt(mx_root, 'mc-%s' % nonce2, 'tools/gone-%s.py' % nonce, tools['c'][1])
receipt(mx_root, 'md-%s' % nonce2, 'tools/link-%s.py' % nonce, tools['d'][1])
```
Notice that although `nonce` and `nonce2` are randomized:
1. Every receipt in the mixed case is tagged with an informative prefix: `ma-` is always `carried`, `mb-` is always `different`, `mc-` is always `absent`, and `md-` is always `nonregular`.
2. Refusal cases carry deterministic root suffixes: `-sha`, `-inc`, `-mix`, and zero population carries `normal-`.
3. The counter writes these files directly into the fixture directory `work / 'fixture'`, and commits them, leaving the working tree intact on disk.

## 5. Single Bounded Synthesis Move (Connector Proposal)

### 5.1. The Proposed Move
**"Decouple Ground-Truth State from Fixture Naming via Opaque Nonces, Dual-Mode Seeded Replay, and In-Memory Git Verification"**

Synthesize the strongest mechanisms across Kaidoku, Chousa, and Kumitate to harden the successor counter without expanding the tool's interface surface:
1. **Adopt Kaidoku's Opaque Nonce Pattern (`version-needs-counter.py:120`)**:
   Eliminate semantic root prefixes (`ok-`, `mx-`, `rf-`, `zp-`) and receipt prefixes (`ma-`, `mb-`, `mc-`, `md-`, `rs-`, `ri-`, `rm-`). Name all receipt directories and files with uniform random hex tokens (e.g. `f"pop/{secrets.token_hex(6)}/{secrets.token_hex(6)}.txt"`). Ground truth in `expected_rows()` is already computed dynamically from candidate git trees; stripping filename cues neutralizes worktree-reading cheats entirely.
2. **Adopt Chousa's Dual-Mode Seed Pattern (`argv-witness.py:298`)**:
   Accept an optional `--seed <int>` CLI parameter. When omitted, draw `seed = int.from_bytes(os.urandom(8), "big")`. Seed `random.Random(seed)` and log `"seed": seed` in the terminal JSON object. This preserves complete unpredictability in production certification while guaranteeing 100% deterministic replay when diagnosing failures.
3. **Adopt Kumitate's Git Object Insulation Pattern (`receipt-evidence.mjs:16`) & T86E2's Perturbed Worktree Commit**:
   After committing the candidate tree in the fixture repository, either clean the working tree (`git clean -fdx` / detach) or commit a noise perturbation commit that modifies the worktree files away from the candidate tree state. This ensures that the worktree on disk diverges from every arm's `--candidate-rev` tree, forcing any auditor or test candidate to read blobs strictly from the git object database via `git ls-tree` and `git cat-file`, as declared in `tools/design-blob-audit.py`.
4. **Randomize Unresolvable Revisions**:
   Rather than passing constant `'0'*40`, generate a random 40-hex string that cannot resolve in the repository, closing existence-probe heuristics.
### 5.2. Affected Axes & Second-Order Effects
* **`operability` (Positive)**: Closes the worktree heuristic gap; makes certification counter strictly discriminating against worktree directory inspectors.
* **`calibration` (Positive)**: Eliminates false claims of capability where a tool might accidentally pass due to worktree leakage rather than true git revision parsing.
* **`verification-fixture-craft` (Positive)**: Combines opaque nonces with reproducible seeds and git object boundary enforcement.
* **No Axis Harmed**: The genuine tool `tools/design-blob-audit.py` already resolves blobs via `git ls-tree` and `git cat-file`. It does not rely on filename prefixes or working tree files; therefore, its pass rate remains unaffected.

### 5.3. Risks and Verification
* **Risk**: If the genuine tool had undocumented dependencies on working tree files, clearing the worktree would cause false rejections.
  - *Verification*: Confirmed by inspecting `tools/design-blob-audit.py:60-70`, which uses `git cat-file blob <rev>:<path>` exclusively.
* **Risk**: Introducing `--seed` could violate the frozen contract if made mandatory.
  - *Mitigation*: The `--seed` flag is strictly optional and defaults to cryptographic entropy, maintaining full backward compatibility.
