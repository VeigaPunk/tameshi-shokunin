## (b) Stable-line comparison of run 1 against the committed receipts

Comparator: `R94E3-stable-compare.py` (saved beside this file), output
`R94E3-stable-compare.out`. Compared on the stable lines only —
`C1_ROW`, `C1_CONJUNCTS`, `C1_SUMMARY`, `C1_SOURCE`, `C1_R94_PASS`, `C1_SETUP` —
ignoring the driver header (`control=`, `clone_rev=`, `parent=`, `mutant=`,
`counter_sha=`) and `exit=`.

Result: **`differing_receipts=none`** — 45/45 receipts reproduce.

One honest caveat, stated rather than hidden. `C1_SUMMARY` is a stable line but
it contains one intrinsically per-run token: `rev=<40 hex>`, the *fixture
clone's own* commit. Its hash cannot repeat between two runs because the driver
commits the fixture with a fresh committer timestamp
(`controls-v94.py:347-352`, `--allow-empty -m "r94 control <name>"`). The
comparator therefore reports both readings and proves the scrub is
token-exact-only:

- strict byte comparison of stable lines: 36 of 45 differ — on exactly one token;
- after replacing only the whole-token field matching `rev=[0-9a-f]{40}` with
  `rev=<fixture-commit>`: **all 45 identical, 0 differ**;
- the comparator only accepts the scrubbed verdict when, for every differing
  line, the two token lists have equal length and differ in exactly one
  position, and both of those tokens individually match `rev=[0-9a-f]{40}`. Any
  other difference — a conjunct flipping, a count changing, a row changing — is
  classified `DRIFT`. None was.

Independent proof that this token is the fixture commit and not a lane
revision: in all 41 receipts that carry a `C1_SUMMARY`, the value of `rev=`
equals the same receipt's header `clone_rev=` (0 mismatches across 41). The other
4 of the 45 carry no `C1_SUMMARY` at all (`gate-foreign`, `nowork-base`,
`selfpin-edit`, `replace-honest` refuse at setup before any row is printed), and
`D01`–`D05` — inside the 41 — carry the literal `rev=HEAD` instead of a hash,
because the mutant counters are run in place at the fixture HEAD
(`controls-v94.py:537-543`).

The 9 receipts that are byte-identical, header included, are exactly
`D01`–`D05`, `gate-foreign`, `nowork-base`, `replace-honest`, `selfpin-edit` —
the ones that embed no clone hash.

Beyond the stable lines, the only other differing bytes versus the committed
receipts are the expected `control=… clone_rev=… parent=…` header (37 files) —
the header this comparison is defined to ignore.

## Observations for the L1 (non-blocking, none affect the verdict)

1. **`--jobs` in the plan vs this item.** Plan §Counting command freezes
   `--jobs 6`; this seat's item names `--jobs 4`, and 4 is what ran. The driver
   builds one independent `git clone --shared` + one commit + one counter run per
   state (`controls-v94.py:342-359`); `--jobs` only sizes the
   `ThreadPoolExecutor`, so it cannot change a state's inputs or its receipt
   content. If the L1 wants the literal plan text honoured, re-run with
   `--jobs 6`; the expected result is the same 45/45 with the same stable lines.
   Flagged because the two documents disagree, not because the result is in doubt.
2. **Receipt selection takes the highest index present.** The grading loop walks
   `[name.out, name.rerun-1.out, …, name.rerun-49.out]` and keeps the *last*
   existing (`controls-v94.py:556-561`). A pre-planted high-index
   `X.rerun-9.out` in `--outdir` would therefore be graded instead of the fresh
   `X.rerun-1.out` — the counter's lowest-index policy and the reader's
   highest-index policy disagree. Inert for the frozen command (empty outdir) and
   inert for this replay; worth knowing if a future round grades a
   non-empty outdir under kill rule (d) "the driver's summary counts a state it
   did not write".
3. **Mutant receipts carry no fixture commit.** `D01`–`D05`'s header is
   `mutant=<n> state=<name>` with no `clone_rev=`/`parent=`, and the counter's own
   line reads `rev=HEAD` (`controls-v94.py:537-546`). Their provenance is the
   state name, not a hash; that is also why those five are byte-identical across
   replays. Not a drift — a traceability limit worth one sentence in the round's
   records if the L1 wants the receipts to be individually re-derivable.
