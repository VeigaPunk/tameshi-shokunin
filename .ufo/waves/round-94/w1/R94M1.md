## 1. Axes and how the frontier walked

Three axes, one instrument:

1. **Rule coverage** — which of the reader's rules change the verdict when weakened
   (the 19 conjuncts plus the sub-rules hiding inside them).
2. **Detector faithfulness** — for each rule, does the state the battery pairs with
   it actually isolate it, or does a second rule refuse first (a state that grades
   the right answer for the wrong reason).
3. **Bytes** — mutated bytes must carry an honestly recomputed `SELF_SHA256`, and
   every mutant must be restored to the pristine sha before the next step.

The move that improved all three cheaply: 38 single-edit defects × the battery's
own state set, one counter run each, at `--jobs 12` (105 matrix runs in 9m28s,
plus 18 supplementary runs — six probes, baseline/mutant/restored each). Every
run is graded against the battery expectation
that the frozen pre-freeze receipt already records for the honest counter, so the
"pristine" arm is the committed battery, not an opinion of mine.

**KILLED / SURVIVED / INCONCLUSIVE.** KILLED = the weakened reader no longer
satisfies the battery expectation for its state (exit code or a graded conjunct
moved), i.e. the battery notices. SURVIVED = the weakened reader satisfies it —
the battery cannot tell the reader from the frozen one. INCONCLUSIVE = the honest
baseline itself fails the expectation (none occurred: 28/28 states graded MATCH).

**The self-pin is a seal, not a defence.** `SELF_SHA256` stops accidental
post-freeze drift; it cannot stop a deliberate mutation study, because any mutator
recomputes the line (the battery's own D01-D05 do exactly that). Every defect here
recomputes it, except E01, which leaves it stale on purpose to test the assert.
The gate is still pinned by `pins.json` and by the counter's own `GATE_COMMIT` /
`GATE_SHA256` constants, and neither was touched.

## 4. Answers

### Q1 — are D01-D05 the load-bearing rules for their states?

**Yes, and D05's triple is minimal.** D01-D04 each turn their state's refusal
(exit 1) into the cheat (exit 0, `C1_R94_PASS=true`), exactly the plan's declared
expected result. D05 likewise returns the cheat on `hidden-c001`, but a flip alone
does not say which arm did it, so three supplementary probes (`R94M1-supp.out`):

| probe | arms of D05 removed | baseline | mutant | moved |
|---|---|---|---|---|
| S1 | table-count only | exit 1 | exit 1, `PASS=false` | `verdict_tables` F→T (out-of-set still refuses) |
| S2 | id-set equality only | exit 1 | exit 1, `PASS=false` | none |
| E13 (matrix) | out-of-set only | exit 1 | exit 1, `PASS=false` | none |
| S4 | table-count + id-set | exit 1 | exit 1, `PASS=false` | `verdict_tables` F→T (out-of-set refuses) |
| S5 | table-count + out-of-set | exit 1 | exit 1, `PASS=false` | `verdict_tables` F→T (id-set refuses) |
| S6 | id-set + out-of-set | exit 1 | exit 1, `PASS=false` | `ids` F→T (table count refuses) |
| D05 | all three | exit 1 | **exit 0, `C1_R94_PASS=true`** | verdict_tables, ids F→T |

Every one of the three arms, and every one of the three pairs, still exits 1: each
time the remaining rule refuses, and the conjunct it owns is exactly the one that
moved. Only the full triple returns the cheat. So the plan's "named triple" is the
smallest named removal for that state — observed, not inferred — and the battery's
`hidden-c001` receipt grades only its table-count arm. That is the right
granularity for a flip, but it means the *battery* alone does not prove the
out-of-set and id-set arms are load-bearing; only this mutant study does.

### Q2 — is any rule survivable and unstated (a QUALITY 158 violation C2 would miss)?

Two granularities again, and the distinction still matters.

**Conjunct granularity: no literal violation.** All 19 keys still have a receipt
that shows them false (C2's claim), and every conjunct-level hardwiring in this
matrix moved a graded conjunct or the exit code and was therefore killed (E02,
E03, E06-E08, E11, E12, E17, E21, E24, E27). The exceptions are the two C2
declares: `canary` (E05) and `unstable0` (E09) survive, as reasoned in the
disposition rows — both are constants while the gate is pinned.

**Rule granularity: seven rules are survivable with no discriminating committed
state.** C2 audits conjunct keys, not rules, so it stays green while these are
ungraded:

1. **E13, out-of-set.** The only state that presents out-of-set ids also presents
   a second verdict table, so the table-count conjunct refuses first. A reader
   without the rule passes every committed state.
2. **E15, position.** Worse than unexercised: `sharp-position-nodup` is
   **byte-identical** to `position` (note bytes sha256 `40c2936957717573…`), and both
   carry the extra `| C12 | … | KILLED | MAYBE |` row. Removing the position rule
   leaves only `dup:21:C12` in `C1_BADROWS`, so the duplicate rule refuses. The
   round-94 M8 fix for round-93's px3 probe did not land.
3. **E16, width.** Both width states put two verdict tokens in the over-wide row,
   so the position rule (baseline) or the position rule alone (mutant:
   `C1_BADROWS position:21:C12`) refuses. Neither grades the width rule; it is
   redundant with position/dup for every row those states contain.
4. **E20, figure regex anchoring.** No state embeds `measured: K/N killed` in a
   longer line, so dropping `^…$` is invisible.
5. **E26, coverage own-cell (QUALITY 164).** No state names a longer path
   containing the note path (e.g. `…census.md.bak`); the substring weakening
   passes.
6. **E29, trivial detector's `lrc is None` / `gawk failed` / `syntax error` arms.**
   Only the `lrc == 2` arm is exercised (`trivial-mutant`); the timeout arm would
   need a state whose `validate` dies without rc 2.
7. **E30, one-verdict-column rule.** `sharp-two-verdict-cols` builds a five-cell
   header over `note_text()`'s fixed four-cell delimiter, so the A2 delimiter rule
   refuses first (`C1_BADROWS verdict-cols:7:2 delim:7:header=5,delimiter=4`). Round
   94's new delimiter rule now masks the rule its own sharpened state was added
   for.

Two more survivors that are neither violations nor rules:

- **E04, `green`.** A receipt shows it false (`timeout`), which is what C2 asks,
  but no state's *expectation* grades it: baseline green=false and mutant
  green=true both exit 1 and both MATCH. A reader that hardwires `green=true`
  passes the whole battery. (Under the pinned gate `green` is a constant as long
  as `pin` holds — the same argument C2 uses for `canary` — so a receipt can only
  show it false through the spec knob, not through a lane state.)
- **E10, run count.** Forcing `runs=1` keeps every conjunct identical while the
  rows collapse from `runs=INCONCLUSIVE,INCONCLUSIVE` to `runs=INCONCLUSIVE`.
  `unstable0` is declared unfalsifiable, but nothing states that the *evidence for
  its being true* (two runs) is itself ungraded; a one-run reader cannot observe
  nondeterminism at all.
- **E32, spec-count half** survives because it is redundant with the unique-id
  half and `n_min`; removal loses no stringency. Not a gap.

## 7. Limits

- Single-edit removals only, one state per defect; this is not a claim about
  arbitrary weakenings or about combinations (D05 is the battery's own declared
  exception). A surviving mutant is a coverage finding, not a defect in the
  reader's contract.
- The supplementary probes (S1-S6) are not counted in `killed:26/38`; S3 shows the
  committed `sharp-source-wrongquote` state does grade the occurrence half
  (mutant → exit 0, `source` F→T), which is why the source rule is not on the
  survivor list; S1-S6 are the D05 arm/pair decomposition.
- One state was substituted (E25, inert gate) and one class was not probed at
  sub-rule level beyond E22/S3 (the `norm_text` normalisation of quotes, the
  `split_cells` escape path, and `--conjuncts` were not mutated).
- Host: no settings changed, no services touched; no package installed.
