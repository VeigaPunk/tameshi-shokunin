### 5.2 The one class the reader refuses that the plan does not declare

**A table inside a 4-space indented code block is keyed.** `block_lines()`
implements fenced blocks only (`FENCE_RE` = `` `{3,} `` or `~{3,}`); it has no
indented-code-block rule, while `DELIM_RE` accepts arbitrary leading
whitespace. Measured (V7 / H4): a 12-row verdict table indented 4 spaces gives
`verdict_tables=2 badrows=12`.

Why this matters for the plan, precisely: the plan's limit L1 says "a **fenced**
block is literal text (S322)", and S322 in the lesson is *CommonMark §4.5
Fenced code blocks*. **CommonMark §4.4 Indented code blocks is a different
section** and is not re-opened as a source in the round-94 lesson — S322's
quote is "A fenced code block begins with a code fence, preceded by up to three
spaces of indentation." So the reader's fence rule is exactly as declared for
fences, and the **indented** block is simply not addressed by the plan at all:
the reader treats an indented code block's table as a real table, which GFM and
CommonMark both say it is not (the S322 snapshot's own §4.4: "An indented chunk
is a sequence of non-blank lines, each preceded by four or more spaces of
indentation").

Does this reach the plan's kill rule?

* **Kill (a)** — "an honest note state … is refused by a rule stated in this
  plan". The four honest states the plan names are the committed note, the
  id-keyed-table state, the `verdict`-data-cell state and the fenced inverted
  table. An indented-code-block table is **not** one of them, and the committed
  note contains **zero** 4-space-indented pipe lines (measured: 0 in the note,
  0 in the README). So (a) is not triggered by the committed note.
* **Kill (b)** — the 30 named hostile states all reach `C1_R94_PASS=false` with
  their named conjunct false (the battery's own receipts say so, and the
  reader-level behaviour I measured for each matches: `hidden-*` →
  `verdict_tables=2`, `renamed-result`/`pseudo-row` → `badrows>0`). No named
  hostile state depends on the indented-block class.

So this is an **undeclared class, not a kill** — the same shape of gap that
killed round 92 (a class the reader refuses that the plan does not declare),
but with no committed-note trigger. `[INFERENCE]` it would bite if a future
note parked a verdict table in an indented code block (a common way to show an
example). Flagging it for the L1's round-95 note, not as a round-94 finding.
