## The kill (rule (a))

Two full-counter runs at instrument revision `7084358c732ebe1334c2eb9a352c3ed96b547f7c`
(clone `--shared`, one commit under `ctl <ctl@fixture.invalid>`, counter extracted
from that revision, sha256 `a22563b0…` confirmed; each ~60–70 s):

* **A8** (`R94C1-A8-indented-code.out`): appended block indented 4 spaces under
  "Example: a malformed indented block" — the honest note plus a literal,
  wrong-verdict table. In CommonMark/S322 this is a literal code block, not
  structure; the declared fence limit (S322) never names indented code blocks
  but names "fenced blocks are literal". Counter: `verdict_tables=false ids=false`,
  `C1_R94_PASS=false`, exit 1.
* **A8b** (`R94C1-A8b-indent-token.out`): a single 4-space literal
  `| C01 | KILLED |` line. Counter: `stray-verdict:297`, `ids=false`, exit 1.

A reader of the plan would call both states honest: they assert no verdict in
prose, add literal examples, and leave the twelve measured cells untouched
(`mismatched=0`, all 12 `C1_ROW` lines intact). Rule (a) lists "the committed
note with an id-keyed table that asserts no verdict … is refused by a rule stated
in this plan" — here the refusal is by a rule *stated nowhere in the plan*: the
S322 fence rule is stated for fenced blocks only, and the reader silently
extends keying to indented literal blocks. It is the round-92 A13 failure class
through a new door: keying by shape where the claim keys by verdict content.

Smallest safe correction: exempt 4-space-indented lines (CommonMark indented
code, `^ {4,}` when not inside a list) in `block_lines()` — or equivalently
skip table/stray detection on indented lines — and add one committed control
(`pos-indented-literal`) mirroring `pos-fenced-hidden`.
