## Findings, by severity

### F1 — HIGH (proven): self-pin is defeated by a second `SELF_SHA256` line — the counter does not self-prove its bytes (`measure-v94.py:62,91-92`)

`SELF_PIN_RE = rb'^SELF_SHA256 = "[0-9a-f]{64}"\n'` (`:62`) is applied with
`re.sub(..., flags=re.M)` (`:91`), which strips **every** line matching the pattern.
A second top-level `SELF_SHA256 = "<H>"` line placed before the `__main__` guard
executes during import and wins, while being invisible to the digest. Demo (this dir,
`R94R1-tampered-counter-demo.py` / `.out`, re-runnable):
`EVIL = True` inserted before `self_pin_ok` plus a second pin line
`SELF_SHA256 = "ef190c52..."` (H = sha256 of the tampered bytes minus pin lines)
immediately after the original pin line:
`python3 -I R94R1-tampered-counter-demo.py --conjuncts` → rc 0, keys printed;
full run `--repo <lane> --rev 7084358c... --work <w>` → rc 0 with ordinary
`C1_ROW` output. Control (plain appended comment): `C1_SETUP self-pin-mismatch`, rc 2.
Guard-ordering nuance (also demonstrated): a rebinding line placed *after*
`if __name__ == "__main__": main()` (`:559`) does nothing — `main()` runs first —
so the attack surface is exactly the pre-guard half of the file, which is where the
original pin sits.

Impact: the seal (`selfpin` conjunct, `:359-361`, `:540`) certifies only that the
executed bytes are self-consistent under the strip-all scheme — not that they are the
pinned bytes. An attacker (or a buggy "repair") who can rewrite the counter blob at
the measurement revision can run modified reader logic under `C1_R94_PASS=true`.
The only safeguard is external: `plans/round-94.plan.md` kill rule (c) + `claims.json`
pin the counter blob sha256 `a22563b0...97023010` (independently confirmed by R94R2 §1).
Any consumer who trusts the receipt without re-checking the blob digest is exposed.
Fix is cheap: digest over bytes with pin lines *zeroed* (not stripped), or require
exactly one pin line (`len(findall) == 1`) before stripping. Duplicated/moved identical
pin lines alone are benign (norm unchanged, semantics unchanged) — the flaw needs a
*differing* second line; point's: the scheme cannot distinguish them.

### F2 — MEDIUM: `split_cells` double-backslash divergence from GFM — reader column ≠ rendered column (`measure-v94.py:171-192`)

`split_cells` collapses `\|` → `|` but treats the first `\` of a `\\` pair as literal.
For the byte sequence `\\|` (escaped backslash + separator) the reader therefore
absorbs the pipe into the cell, whereas GFM (and CommonMark backslash processing)
sees `\\` → `\` and then `|` separates. Constructed witness (probe P/Y series, all
probes saved as `R94R1-probe_parser.py`, output `R94R1-probe.out`):
row `| C01 | x \\| y | z | KILLED | w |` → reader cells
`['C01', 'x \\| y', 'z', 'KILLED', 'w']` → `C01=KILLED` with `bad=[]`; under GFM the
same bytes render as six cells `[C01, 'x \\', y, z, KILLED, w]`, and after remainder
truncation to header width the verdict column holds `z`, not `KILLED`. A committed
note could thus display a wrong verdict under a human re-read while the twelve
extracted cells agree with the selftest — the exact false-green class in scope.
`pos-real` cannot fire it: the real verdict table contains zero backslash bytes in
its data rows (verified per-row), so the honest state is safe today. Severity is
medium because the honest authoring pattern (an edit cell literally documenting an
awk/regex replacement such as `sub(/#[^ ]*$/,"&",u)` carries no `\\|`) makes it
unlikely, but the seal is a *checker of human-readable claims*, and the reader and
the renderer disagree on cell boundaries by construction. Note the thematic cousin:
the plan's declared limit "a cell containing an escaped `\|` is one cell (S321)"
(`plan.md:126`) is honoured — the divergence is only for the *double*-backslash
sequence, which S321 backslash parsing resolves the other way.

### F3 — LOW (false-red): delimiter needs ≥3 hyphens; GFM allows ≥1 (`measure-v94.py:79`)

`DELIM_RE` requires `:{3,}`-class runs (`:79`). A table authored with `|--` /
`|:--` delimiters is GFM-legal (GFM requires one or more hyphens) but is not
recognised as a table at all: no header is keyed, every data row falls to the
stray-verdict scan (`:275-280`) and the note is refused with 12 `stray-verdict`
findings (probes P5/P36, `badrows=12`). This is a strictness gap against GFM, not a
false-green: an honest note written with `--` delimiters dies. The committed note
uses `---`, so the honest state is unaffected. In the other direction the reader is
correctly strict where GFM is: a 5-cell header over a 3-cell delimiter adds `delim:`
(`:288-289`, battery `sharp-delim-5-4`) — header/delimiter equality is honoured.

### F4 — LOW (false-red, marginal): id cells must be bare (`measure-v94.py:308,313`)

`first = cells[0]` (`:308`) is compared verbatim against the spec set (`:313`).
`| **C01** | ... |` or `| \`C01\` | ... |` (bold/backtick id rendering) → `out-of-set`.
Renderings are identical to a human reader. The committed note uses bare ids; the
plan's own spec ids are bare. Listed for completeness: a future honest note that
bolds its id column is refused. (By contrast the header `verdict` key is
normalisation-tolerant — `norm_cell` strips `*`/backticks and lowercases (`:195-196`),
so `Verdict`, `**verdict**`, `` `verdict` `` all key, probes P23/P24 — an asymmetry
worth knowing but not a defect on the verdict side.)

### Myths debunked (no finding — tried and cleared)

  refused, via `ids` rather than `verdict_tables`. Not a false-green. GFM-faithful:
  CommonMark also leaves it a code block.
- **Unclosed fence after the table** swallowing `measured:` (`:489-491`):
  `figure` goes false because the block-level `measured:` is missing from
  `block_lines` output (S9 heads=`[]`). Refused, not passed. Fenced `measured:`
  being ignored is a declared limit (`plan.md:119-121`), matched.
- **Fence `~` vs `` ` `` and indent rules** (`FENCE_RE` `:78`, closing matched on
  same char with `len >= opening` and empty info, `:210-211`): tilde-inside-backtick

  CommonMark: closing info strings are not allowed, so swallowing is faithful), a

- **Fence between header and delimiter**: not a table in GFM nor here (`tables()`

  `delim:`/`width:`) or trips the stray check.

## Verdict

One high-severity false-green (F1, proven with re-runnable artifacts, though gated by
the external claims digest), one medium false-green on a divergence the honest note
does not trigger (F2), one GFM-strictness false-red (F3), one presentation-marginal
false-red (F4). On the committed honest state everything measures true and the
reader is table-shape faithful elsewhere. `F1 + F2` are the two in-scope ways a
committed state could print `C1_R94_PASS=true` without the twelve cells being what
a human reads — F1 by rewriting the instrument, F2 by rewriting the table's
backslashes. Both need a deliberate author; neither is reachable by the do-nothing
lane state.
