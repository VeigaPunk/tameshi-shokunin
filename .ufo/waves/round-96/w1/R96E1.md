The F2 attack is dead: the clone's index holds a 12-cell inverted note (`git status`

**Deviation from the seat spec (measured, not inferred).** Item 2 expects
`rev-unresolvable` for `deadbeef…`; the frozen bytes print
`C1_SETUP spec-absent-at-rev`. Root cause, measured at git 2.56.0:

```
$ git rev-parse deadbeefdeadbeefdeadbeefdeadbeefdeadbeef        -> echo, EXIT=0
$ git rev-parse --verify deadbeefdeadbeefdeadbeefdeadbeefdeadbeef -> echo, EXIT=0
$ git cat-file -e deadbeefdeadbeefdeadbeefdeadbeefdeadbeef      -> (silent), EXIT=1
$ git rev-parse --verify 'deadbeef…^{object}'                   -> fatal, EXIT=128
```

`rev-parse` echoes any syntactically valid 40-hex name with exit 0 whether or not the
object exists, so the counter's guard (`_resolved = git(repo, "rev-parse", rev)`;
`if rc != 0: die("rev-unresolvable")`, lines 420–425) does not fire; the run proceeds to
`blob(repo, rev, SPEC_PATH)` and dies there. The refusal still holds in the property that
matters — exit 2, `C1_R96_PASS=false`, nothing graded, work dir untouched —
but the token `rev-unresolvable` is unreachable for a 40-hex input (it can fire only when
git itself fails, e.g. `--repo` is not a repository). This is the same root cause R96C1
found independently on the successor checker (its C1.3); confirmed here for the counter.

## 3. Hostile PATH — the counter never resolves ambient `git` (`R96E1-hostile-path.out`)

**Shim.** A fake `git` (source embedded in the receipt, sha256
`fc38dc2c…`) placed first in the ambient `PATH`. It appends every call to `$SHIM_LOG`
and answers `cat-file blob <rev>:<path>` / `ls-tree -r --name-only <rev>:<dir>` from
`$SHIM_FORGE_DIR`, delegating everything else to `/usr/bin/git`. The counter's own
seal is structural: `git()` (129–133) passes `sealed_env()`
(`PATH=/usr/local/bin:/usr/bin:/bin`, `GIT_NO_REPLACE_OBJECTS=1`, no system/global
config), so the shim cannot be resolved. The runs test that dynamically.

**Fixtures.** Shared clones in scratch. `clone-forged` carries one commit on top of the
freeze rev (`92bbf2b665c6b7187e3bd6706498b2e62a34a504`) whose only change is that every
verdict cell in the single verdict table is swapped (`KILLED↔SURVIVED`, 12 rows,
12+/12−; `measured: 5/12 killed` untouched). `note-honest.md` sha256 `69fc1527…`,
`note-forged.md` sha256 `993be0c0…`. The shim was pointed at a forged directory holding
either note, so it really does answer the note query with the other bytes:

```
$ /usr/bin/git -C clone-forged cat-file blob 92bbf2b6…:<note> | sha256sum
993be0c0…  # committed (inverted) bytes
$ PATH=fakebin:$PATH SHIM_MODE=path SHIM_FORGE_DIR=forge-note-honest git -C clone-forged cat-file blob 92bbf2b6…:<note> | sha256sum
69fc1527…  # the hostile git serves the honest bytes; the shim demonstrably runs
```

`diff` of H2a vs H2b stdout: no output (`STDOUT IDENTICAL`) — the hostile PATH neither

offering the bytes that would make it green, and the green is not produced. H3 is the

directory, and the counter still dies `spec-absent-at-rev` with zero shim calls.

**Conclusion for C1's F1 class:** no counter run — four v96 batteries (174.93 s,

kernel one.

## Findings (evidence only — no instrument, plan, manifest or sibling file was edited)

1. **F-R96E1-a (measured, item 2).** `measure-v96.py`'s `rev-unresolvable` token does not
   fire for a syntactically valid 40-hex id that is not an object; the run refuses later
   with `spec-absent-at-rev` (exit 2, `C1_R96_PASS=false`, nothing graded). Root cause:
   `git rev-parse <40hex>` exits 0 (echo) for non-existent objects at git 2.56.0;
   `cat-file -e` is the check that distinguishes them (exit 1), and
   `rev-parse --verify '<id>^{object}'` fails with 128. The refusal property holds; the
   token does not. Same root cause as R96C1 C1.3 for the checker.
2. **F-R96E1-b (context, cross-instrument).** The frozen successor checker prints
   `DISPOSITION_SETUP counter-absent-at-rev` for `--rev deadbeef…` and exits 64 with the
   usage text for `--rev ''` — not the plan's `rev-unresolvable` / `rev-not-a-commit-id`
   tokens. Independently measured here; agrees with R96C1 C1.2/C1.3. Not fixed (not this
   seat's file).
3. **No defect found in the counter's PATH seal.** Six full battery runs (four v96, two
   round-94-counter) and nine setup refusals: zero shim invocations, byte-identical output with and without the hostile
   `PATH`, and the only `C1_R*_PASS=true` produced under the shim is the honest pass on
   the honest lane.

## What this does not prove

- The seal is userland: a writer to a *sealed* `PATH` directory (`/usr/local/bin`,
  `/usr/bin`) or a replaced interpreter defeats it; the plan declares that limit.
- The counter does not execute the checker; the two instruments are audited separately
  (the checker's rev/empty-lane behaviour is R96C1's and R96R1's scope).
- No attempt was made to grade a rev whose objects are absent; the refusal states
  exercised above are the ones covered.
