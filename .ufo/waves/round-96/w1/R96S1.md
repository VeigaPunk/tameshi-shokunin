### The refused candidate

**`https://docs.github.com/en/rest/commits/commits#get-a-commit`** — *GitHub REST API: "Get a
commit"*.

* Opened this round: HTTP 200, 547 847 B, sha256 `fc8e1251a785b9fdd403df74179f68336e709aa61222855c3ad9b60fe8309d36`,
  HTTP date `Sun, 08 Nov 2026 12:24:50 GMT` (headers and body under scratch).
* It *looks* like it teaches "rev identity". Located in its stripped text (line 733):
  `application/vnd.github.sha  : Returns the commit's SHA-1 hash. You can use this endpoint to
  check if a remote reference's SHA-1 hash is the same as your local reference's SHA-1 hash by
  providing the local SHA-1 reference as the ETag.` (line 733 of 1317 stripped lines.)
* **Refused**, for three measured reasons:
  1. **Not authoritative for git rev resolution.** The sentence is a statement about a
     *GitHub REST API media type* and an `ETag` comparison. It says nothing about how git
     resolves a revision parameter — no `<rev>` grammar, no `^{commit}` dereference, no
     `git rev-parse --verify`. The authoritative grounds for rev resolution already sit in the
     registry as tier-A rows: `S091` (gitrevisions, §SPECIFYING REVISIONS) and `S062`
     (git-rev-parse(1)). This page would be a *second, weaker* account of the same ground.
  2. **A hosted-service API reference is not a git reference.** Its "SHA-1 hash" is the SHA of a
     commit *in GitHub's database*, and the document never states it equals git's object id for
     that commit. Citing it as the ground for "rev identity" would substitute a vendor's REST
     surface for the object-identity semantics the claim actually needs.
  3. **The registry rule.** `corpus/SOURCES.md` follows `CORPUS.md` rule 2 and the S289/S293
     precedent: a URL that is already held is re-opened, not held twice; and the row would in
     any case be a `docs` row for a *hosted API*, not for git.
* **Flip condition:** if a future claim is specifically about *GitHub's REST API* — e.g. "the
  `application/vnd.github.sha` media type returns the commit's SHA-1 so a remote reference can
  be compared to a local one by ETag" — then this page becomes the primary source for that
  scope, tier B (vendor API reference), anchored at §"Get a commit" / media types. It is
  refused *for rev resolution*, not for existence.
