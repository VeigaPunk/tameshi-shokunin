## 1. Positive — exact derived bytes, `PINS_WRITTEN` + `PINS_CHECK OK`

With the destination absent, `--lane <clone> --rev be6c22b6…` printed
`PINS_WRITTEN <lane>/.ufo/evidence/round-96/c1/pins.json`, exit 0; `--check` printed
`PINS_CHECK OK`, exit 0.

The write is *exact*, established three ways by `verify_positive.py` (an independent
derivation that does not call the tool): the written JSON parses to exactly the five derived
values (`dict equality = True`); the written bytes equal the canonical serialization of those
values (`byte equality = True`, sha256 `688fe42a…` both sides); and the written bytes equal the
committed blob at the freeze rev (`equal-to-written = True`). The tool re-derives
`spec_sha256=ce8983d5…`, `gate_commit=f47ad6ba…`, `gate_path=scripts/sources-census.sh`,
`gate_sha256=3fb72615…`, `fixtures=scripts/fixtures/sources-census` and lands on the same
322-byte file as the committed pin.

Read-side note: `--check` grades `cat-file blob --rev:.ufo/evidence/round-96/c1/pins.json`,
not the working tree. With a sentinel in the worktree and the correct blob at the rev it still
printed `PINS_CHECK OK` — the intended binding to the committed instrument, not a hole.

`Durable evidence` — `R96E3-positive.out`.

## 2. `pins-empty-lane` (F6) — refused at setup, CWD repo untouched

`--lane ''` from a CWD that is a git repo (`git rev-parse --show-toplevel` =
`/fast/scratch/hyaku/tameshi-r96/R96E3/cwd96`) printed `PINS_SETUP lane-empty`, **exit 2**.
A sentinel was planted at the path the v95 tool would have hit; after the run its sha256
(`4031fd50…`), size (29) and mtime were byte-identical, and no `pins.json.tmp-pins` existed.
The guard is at lines 58-59, before `os.path.realpath('')` can resolve the empty lane to the
CWD. Whitespace lane (`--lane '   '`) takes the same refusal; `--lane .` is refused with
`PINS_SETUP lane-not-absolute`, and a lane whose `rev-parse --show-toplevel` differs is refused
with `lane-toplevel-mismatch` (line 66).

`Durable evidence` — `R96E3-empty-lane.out`.

## 3. `pins-symlink` (F5) — refused, outside target byte-identical

`pins.json` was replaced by a symlink to `/fast/scratch/…/outside/target.json` holding a
31-byte sentinel (`ff6b4ec0…`). The tool printed `PINS_SETUP pins-symlink-refused`, **exit 2**.
The outside target after the run: same sha256 `ff6b4ec0…`, same 31 bytes, same mtime; the
symlink itself was neither followed, replaced nor removed; no temp file was created. Line 85
uses `os.path.lexists` + `os.path.islink`, so a **dangling** symlink is also refused (measured:
`PINS_SETUP pins-symlink-refused`, exit 2, and the missing target was not created).

`Durable evidence` — `R96E3-symlink.out`.

## 4. Atomicity — temp + `fsync` + `os.replace`, no observable partial

The write path, verbatim (lines 87-101): the destination name is never opened.
`_tmp = out + ".tmp-pins"`; a pre-existing tmp that is a symlink is refused
(`PINS_SETUP tmp-symlink-refused`, exit 2, victim sha256 `480095cb…` unchanged, destination
`688fe42a…` unchanged); a pre-existing regular tmp is unlinked; the payload is written to
`_tmp` via `os.open(..., O_WRONLY|O_CREAT|O_EXCL|O_NOFOLLOW, 0o644)`, flushed and `fsync`'d;
then `os.replace(_tmp, out)` publishes it.

Three independent measurements back "atomic":

- **Rename, not truncate.** With the destination `chmod 444` — and an in-place
  `open(out,"w")` measurably failing on such a file here (`PermissionError 13`, uid 1000) —
  the run still printed `PINS_WRITTEN`, exit 0, and the destination
  inode changed `220542402 → 220558188`, mode `444 → 644`, sha256 unchanged `688fe42a…`.
- **Crash mid-write.** With `json.dump` patched to write the partial payload and then raise,
  the destination was byte-identical before and after (`688fe42a…`, 322 B); the partial bytes
  reached only `pins.json.tmp-pins`.
- **No residual temp.** After a successful write no `pins.json.tmp-pins` exists; a stale
  regular tmp (garbage, `49d81299…`) is unlinked and the run proceeds to `PINS_WRITTEN`,
  exit 0.

`Durable evidence` — `R96E3-atomic.out`.

## Risks and residual gaps (measured, not fixed — out of this seat's scope)

1. **Symlinked parent directory escapes the lane.** If `.ufo/evidence/round-96/c1/` itself is a
   symlink to an outside directory, `pins.json` is written there and the tool prints
   `PINS_WRITTEN`, **exit 0**. Measured on `lane-parentsym` (clone at the freeze rev with the
   `c1/` directory replaced by a link to `.../parent-outside`):

       lrwxrwxrwx 1 vgpnk vgpnk 52 Nov  8 09:30 lane-parentsym/.ufo/evidence/round-96/c1 -> /fast/scratch/hyaku/tameshi-r96/R96E3/parent-outside
       PINS_WRITTEN /fast/scratch/hyaku/tameshi-r96/R96E3/lane-parentsym/.ufo/evidence/round-96/c1/pins.json
       exit=0
       -rw-r--r-- 1 vgpnk vgpnk 322 Nov  8 09:30 parent-outside/pins.json
       688fe42aab453748c0567b114b6e23f8aeb0af04711509fe50255e2fcc4af9a4  parent-outside/pins.json

   The `islink(out)` guard only inspects the final component. This matches the plan's declared
   limit ("does not defend against a writer that already owns the lane's filesystem"), since
   replacing `c1/` needs lane write access — but it is strictly cheaper than owning the root and
   is not covered by any kill rule a–c. Reported, not patched: the freeze rev binds the
   instrument, and rewriting it mid-wave would invalidate the revision identity every receipt
   here is read against.
2. **A symlinked parent also bypasses `--check`'s worktree independence** in the same way it
   bypasses the write guard (not exercised; inferred from the same path construction).
   `[INFERENCE]` — the code path is identical (`out = lane + PINS_PATH`), no separate measurement.
3. **`tmp-symlink-refused` is a hard refusal, not a repair.** A crashed run leaves a regular
   tmp that is silently unlinked (measured), which is fine, but a *planted* tmp symlink blocks
   every later run until an operator removes it. Fail-closed by design; noted because it is a
   denial surface on the lane's own evidence directory.
4. `os.replace` is atomic only within one filesystem; the temp is a sibling of the destination,
   so this holds for every fixture here (same directory). Unchanged if the lane spans a mount.
