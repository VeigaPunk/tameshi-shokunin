## 2. One Non-Obvious Move (Fleet Pattern Synthesis)

### Proposed Move
Synthesize the fleet's mature atomic-write pattern from `kaidoku-shokunin` (randomized `tempfile.mkstemp(dir=dirname, prefix=basename+".", suffix=".tmp")` + `os.replace`) and the revision-peeling commit verification from `souji-shokunin` / `tsukuroi-shokunin` (`cat-file -e "${REV}^{commit}"` or `rev-parse --verify --quiet "${REV}^{commit}"`) into `tameshi`'s instrument surfaces:

1. **In `conjunct-disposition-v96.py`:** Amend the revision resolution check at line 370 from `git(a.lane, ["rev-parse", a.rev])` to `git(a.lane, ["rev-parse", "--verify", "--quiet", "--end-of-options", a.rev + "^{commit}"])`. Bare `rev-parse <40-hex>` resolves successfully if given a 40-hex blob or tree SHA, passing `rev-not-a-commit-id` despite not being a commit. Adding `^{commit}` enforces true commit object typing at the git object database layer before attempting `cat-file blob <rev>:<path>`.
2. **In `make-pins96.py`:** Replace the deterministic temporary path `_tmp = out + ".tmp-pins"` (lines 87–93) with `fd, tmp = tempfile.mkstemp(dir=os.path.dirname(out), prefix=os.path.basename(out) + ".", suffix=".tmp")`. Deterministic `.tmp-pins` introduces a local race and denial-of-service vector where a pre-existing or concurrent file wedges `O_CREAT | O_EXCL` or requires `os.unlink()`. Randomized `mkstemp` inside the target directory guarantees atomic creation under a fresh, unguessable name immune to pre-planting, while retaining identical atomic `os.replace(tmp, out)` replacement semantics.

### Axis Impact
- **Calibration (Improved):** Prevents a 40-hex tree or blob SHA from satisfying the revision preflight, eliminating a latent type-confusion window in the object-store audit.
- **Operability (Improved):** Eliminates predictable-tempfile collision and unlinking races during atomic pins generation without escaping the lane directory.
- **Depth / Zero Harm:** Existing test suites, controls, and frozen 40-hex commit hashes remain 100% compliant and unaffected.

## 3. Second-Order Effects

- **Runtime Surface:** Calling `git rev-parse ... ^{commit}` incurs zero overhead compared to bare `rev-parse`, but fails closed with exit 2 when given valid git objects that are not commits. `tempfile.mkstemp` avoids the `os.path.lexists` + `os.unlink` dance and guarantees POSIX `O_CREAT | O_EXCL` atomicity.
- **Contract Surface:** Aligns `tameshi`'s revision contract with `souji` (`REFUSAL REV-UNRESOLVED`) and `tsukuroi` (`E-REVISION-INVALID`), ensuring cross-lane consistency across the shokunin fleet.
- **Substrate Surface:** Both mechanisms use standard library Python (`tempfile`, `os`, `re`) and standard Git (`rev-parse`), introducing zero external dependencies, no pip packages, and no platform-specific extensions.
- **Verification Surface:** Selftests in `conjunct-disposition-v96.py` and `make-pins96.py` can directly add negative fixtures for: (a) a valid 40-hex blob object SHA passed to `--rev` (must refuse with `rev-unresolvable` / exit 2), and (b) a pre-planted unlinked `.tmp-pins` (must not prevent atomic write).

## 4. Contradictions Stated Explicitly

- **Predictable Temp vs. Unlink Race:** `make-pins96.py` attempts to protect against symlinks by unlinking `_tmp` if `os.path.lexists(_tmp)` is true, but then passes `O_CREAT | O_EXCL`. If an outside actor continuously recreates `_tmp`, `make-pins96.py` fails. `kaidoku-shokunin` resolved this exact contradiction in Round 95 (QUALITY 192) by switching to `mkstemp`.
- **40-Hex Shape vs. Commit Object Type:** `re.fullmatch(r"[0-9a-f]{40}", rev)` validates string syntax, not git object typing. Git stores blobs, trees, tags, and commits with identical 40-hex SHA-1 hashes. Checking only 40-hex regex allows a blob SHA to pass syntax validation.
- **PATH Inclusion Contradiction:** `tameshi` pins `PATH: "/usr/local/bin:/usr/bin:/bin"`, while `kake-shokunin` and `tsukuroi-shokunin` pin `PATH: "/usr/bin:/bin"`. Including `/usr/local/bin` allows local system administrator scripts to precede vendor binaries, whereas omitting it enforces pure distribution packages. However, because `tameshi` also hardcodes `GIT = "/usr/bin/git"` at line 80, the `PATH` value only affects child git sub-invocations.

## 6. Risks

1. **Refusal Divergence Risk:** If `conjunct-disposition-v96.py` is updated to require `^{commit}`, any test fixture that previously passed a tree or blob SHA will correctly fail closed with exit 2. In Round 96's declared test suite, all fixtures pass commits, so this risk is purely additive protection.
2. **Directory Fsync Portability Risk:** Calling `os.fsync(dfd)` on a directory descriptor requires directory read permissions on POSIX. On Linux (ext4/btrfs/xfs), `os.open(d, os.O_RDONLY)` followed by `os.fsync(dfd)` is fully supported, but in restricted sandboxes without directory read rights it could raise `PermissionError`. Handling `OSError` with `pass` (as `kaidoku` does) eliminates this failure mode.
3. **Cross-Lane Leakage Risk:** Sibling lane code must never be imported across repository boundaries. All recommendations are self-contained implementation patterns to be adopted internally within `tameshi`.
