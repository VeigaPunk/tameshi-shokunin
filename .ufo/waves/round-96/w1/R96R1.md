### FALSIFIES-WORDING #2 — unresolvable 40-hex revs are not refused with `rev-unresolvable`; they fall through to `counter-absent-at-rev`

**Frozen sentence:** "the checker refuses with exit 2 and `DISPOSITION_SETUP rev-not-a-commit-id` when `--rev` is not a 40-hex object id and with `DISPOSITION_SETUP rev-unresolvable` when the id does not resolve, and it prints the resolved id in the `DISPOSITION_INSTRUMENT` line."

**Falsified on committed bytes:** `git rev-parse <40-hex>` **echoes the id and exits 0** for any well-formed 40-hex string, even one that resolves to nothing (verified: `0…0`, `deadbeef…`, `1111…1` all exit 0 — `R96R1-revverify-zero.out` and `R96R1-rev-0rev.out`). The checker's `rev-parse` resolution step therefore never trips its `rev-unresolvable` branch; a dead object id proceeds until the counter blob read fails, printing **`counter-absent-at-rev`, not `rev-unresolvable`** (receipts: `R96R1-rev-0rev.out`, `R96R1-rev-deadbeef10.out`, `R96R1-rev-c8de77f3.out`, `R96R1-revspec-deadbeef.out`, `R96R1-revspec-short-40hex-nonexistent.out`). `rev-unresolvable` is **dead code** for every malformed-but-40-hex id, because `rev-parse` without `--verify` is a passthrough. Exit is still 2, but the frozen token is never emitted.

### On the before-witness (F1) — NOT reproduced as claimed

(The v96 sealed design fixes both anyway: object-store reads + pinned `PATH`.)

### Advisories (not falsifications, worth recording)

1. **`rev-parse` must be `rev-parse --verify`.** FALSIFIES-WORDING #2 is the same defect: the freeze at `10d8fa5d`/`be6c22b6` is vulnerable to any 40-hex smuggled through `--rev` that doesn't resolve — it fails later with the wrong token. The fix is one word (`R96R1-revverify-zero.out` shows even `--verify` passes a bare 40-hex id on this git build — need `rev-parse --verify --quiet <rev>^{commit}`.)
2. **Worktree receipt + forged PATH on the v94 checker is the real F1** (v94 reads receipts from `os.path.join(lane, receipts)` worktree). v96 correctly switches to object-store reads + pinned `PATH`, which this adversary confirms per the table above.
3. The frozen manifest's `counter` field names `measure-v96.py`, but the checker's `--counter` default names `measure-v95.py`. Any positive at the instrument rev must pass `--counter` explicitly. Kill rule d (blob == claims sha) holds; the falsification is the counter-pathed default.
