# R96L1 — probe: are the v96 seal guards inert on the honest measurements?

**Verdict: partly refuted.** The two seal guards are *inert* on the twelve `C1_ROW` cells,
on the `C1_SUMMARY` fields, on the whole 19-row disposition body and on the 11-case checker
selftest. They are **not inert on the 50-state control battery**: applying the guards alone
to the round-95 bytes turns `C1_CONTROLS states=50 matched=50` into
`states=50 matched=44 mismatches=6 [D01,D02,D03,D04,D05,replace-honest]`, exit 1. The cause
is the counter's `rev-not-a-commit-id` guard rejecting the literal `--rev HEAD` that the
frozen round-95/v96 driver passes in exactly those six states. Additionally, the frozen
(round-96 freeze-commit) instrument cannot print the frozen green disposition at the freeze
revision at all: its default `COUNTER` path names a file that does not exist, and the
receipts the manifest names are not committed there.

All runs on this host, `python3` 3.14, lane scratch clone at
`be6c22b6d8a94f07eee6b0fa79edab7df228c0b0` unless stated. Every number below is
reproduced by a receipt in `R96L1-runs/`.

  `DISPOSITION_SETUP rev-unresolvable` (exit 2) for an id that does not resolve, and the

The seat's hypothesis: *applying only the seal edits* (counter: the `rev-not-a-commit-id` /
`rev-unresolvable` checks; checker: the sealed environment + the same rev guard) to the
round-95 bytes changes none of those measurements.

## 3. Results — three runs plus the shipped control

### 3.1 Twelve measured cells: guards inert

`diff p1-counter.out p2-counter.out` → **byte-identical** (whole file, not only the rows),
exit 0, `C1_R95_PASS=true` in both. That includes `C1_SUMMARY` with
`rev=be6c22b6… n=12 killed=5 survived=7 … mismatched=0 badrows=0 verdict_tables=1` and the
19-conjunct `C1_CONJUNCTS` line. The frozen v96 counter at the same rev differs from pristine
**only** in the label rename `C1_R95_PASS` → `C1_R96_PASS` (one line); its twelve rows and
summary are identical (`R96L1-runs/head-counter-freeze.out` shows the same rows for the
shipped counter too).

### 3.2 Disposition (guard-only): guards inert

`diff p1-disposition.out p2-disposition.out` → **byte-identical**, both end
`DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0`, exit 0, and both print
`DISPOSITION_INSTRUMENT sha256=5f0d1770… conjuncts=19` (same counter blob read).
`diff p1-selftest.out p2-selftest.out` → identical `DISPOSITION_SELFTEST: 11/11 pass`, exit 0.

### 3.3 Battery: guards MOVE six states

| battery | lane / counter | rev | base | result | exit |
|---|---|---|---|---|---|
| pristine | `lane` (v95) | `be6c22b6` | `02ff6290` | `states=50 matched=50 mismatches=0 missing=0` | 0 |
| guard-only | `lane-guard` @ `2f113e4c`, guard counter | `2f113e4c` | `02ff6290` | `states=50 matched=44 mismatches=6 missing=0 [D01,D02,D03,D04,D05,replace-honest]` | 1 |
| combined, frozen driver+counter | `lane` @ `be6c22b6` | `be6c22b6` | `c8de77f3` | `states=50 matched=44 mismatches=6 missing=0 [D01,D02,D03,D04,D05,replace-honest]` | 1 |
| shipped driver+counter | `lane` @ `8ed9c526` | `8ed9c526` | `c8de77f3` | `states=50 matched=50 mismatches=0 missing=0` | 0 |

The six failing receipts are identical in both 44/50 runs and read
`C1_SETUP rev-not-a-commit-id` / `C1_R95|96_PASS=false`, exit 2:
`D01,D02,D03,D04,D05,replace-honest` (`R96L1-runs/p2b-controls/*.out`, `p3b-controls/*.out`).

**Cause (named guard): the counter's rev guard.** The frozen round-95 and round-96 drivers
invoke the counter with the literal revspec `HEAD` in exactly these states
(`controls-v95.py` / frozen `controls-v96.py` lines 576 and 608: `"--rev", "HEAD"`). `HEAD`
is not a 40-hex object id, so `re.fullmatch(r"[0-9a-f]{40}", rev)` fails and the guard dies
`rev-not-a-commit-id` before the state can be graded. Pristine `measure-v95.py` resolves
`HEAD` through `git cat-file` and grades it. The six states are honest fixture states (D01–D05
are the declared mutant counters; `replace-honest` is the replace-ref refusal state).

The question of attribution is settled by the shipped driver: `controls-v96.py` at the
records rev resolves each clone's HEAD to a 40-hex id (`srev`/`mrev`, lines 602/634) before
calling the counter — that is plan amendment **A6** — and the battery is 50/50 again
(`R96L1-runs/p3e-controls.out`). So the guard is inert on the battery **only after the driver
is changed**; on round-95 bytes + the guards alone it is not.

Base choice matters and is not the guards' fault: the first battery attempt with
`--base c8de77f3` gave 49/50 (kept as `p1-controls-badbase-c8de77f3.*`, `p2-controls-badbase-c8de77f3.*`) because `nowork-base` expects `spec-absent-at-rev` and c8de77f3
is the round-95 tip (round-95 spec present). The canonical round-95 base is `02ff6290`,
recorded in the committed `round-95/pre-freeze/controls/nowork-base.out`; with it, pristine is
50/50. Round-96's analogous base is `c8de77f3` (round-96 spec absent), used for the v96 runs.

### 3.4 The frozen v96 instrument cannot print the frozen green at the freeze rev

- Default invocation (`--lane LANE --rev be6c22b6`): **exit 2,
  `DISPOSITION_SETUP counter-absent-at-rev`** — the frozen checker's
  `COUNTER = ".ufo/evidence/round-96/c1/measure-v95.py"` (line 53) names a file that does not
  exist in round 96 (the file is `measure-v96.py`; the manifest's own `counter` key says so).
- With `--counter .ufo/evidence/round-96/c1/measure-v96.py`: **exit 1,
  `DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=17`**, all seventeen findings
  `receipt-absent-at-rev` — `.ufo/evidence/round-96/pre-freeze/controls/` contains **zero**
  committed receipts at `be6c22b6` (the directory exists only as `pre-freeze/nowork`).
- With `--counter …measure-v96.py --receipts .ufo/evidence/round-95/pre-freeze/controls`
  (diagnostic, not a frozen invocation): exit 1, findings=17, all
  `receipt-counter-sha-mismatch` (round-95 receipts carry the round-95 counter's sha).
- Shipped instruments at the revision that actually carries the 50 receipts
  (`8ed9c526`, the records rev) reproduce the frozen wording exactly:
  `DISPOSITION_INSTRUMENT rev=8ed9c526… sha256=69ee68b6… conjuncts=19` and
  `DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0`, exit 0 — identical to the
  committed `landing/c1-positive.out`.

So the frozen sentence "at the instrument revision the checker prints … findings=0" is false
for the freeze commit `be6c22b6` (both because of the counter path and because the receipts
are not there), and true at the records rev. This is plan amendment **A1**.

### 3.5 The two new selftest cases are inert (frozen bytes)

Frozen `conjunct-disposition-v96.py` lines 334–335:

```
cases.append(("hostile-path-cheat", clean, 0, None))
cases.append(("branch-revspec-cheat", clean, 0, None))
```

Both are byte-for-byte the same `check()` call as the existing `clean` case; neither touches
`PATH`, neither invokes `main()`, neither passes a revspec. Receipt:
`SELFTEST hostile-path-cheat PASS findings=0 want=clean`,
`SELFTEST branch-revspec-cheat PASS findings=0 want=clean`,
`DISPOSITION_SELFTEST: 13/13 pass` (`p3-selftest-fixed.out`). The plan's own §Implications
requires both to produce a finding, and kill rule (c) says "a case that must produce a
finding produces none" — the frozen bytes violate it. (Shipped checker: the two cases now run the real main path; 13/13
with `branch-revspec-cheat … exit=2 (rev-not-a-commit-id)` and a hostile-PATH run identical
to honest — `R96L1-runs/head-selftest.out`.) This is plan amendment **A5**.

### 3.6 Rev-guard branch analysis

- **`rev-unresolvable` is dead in the counter** (frozen *and* shipped): `git rev-parse
  <40-hex>` exits 0 and echoes the id for objects that do not exist. Verified:
  `git rev-parse 0000…0` → exit 0; `git rev-parse deadbeef…` (40 hex) → exit 0, while
  `git cat-file -e deadbeef…:path` → exit 128. Consequently a well-formed absent id falls
  through the guard and dies later with **`C1_SETUP spec-absent-at-rev`**, not
  `rev-unresolvable` (receipts `p2-counter-refuse-*`, `head-counter-rev-unresolvable.out`).
  The checker was repaired with `rev-parse --verify --quiet --end-of-options <rev>^{commit}`
  (A2) and does print `rev-unresolvable`; the counter was not.
- **`--rev ''` on the checker**: frozen bytes exit **64 with usage**, not exit 2
  `DISPOSITION_SETUP rev-not-a-commit-id`, because `if not a.lane or not a.rev` fires before
  the guard. The shipped checker splits the test and returns exit 2
  `rev-not-a-commit-id` (`head-checker-rev-empty.out`). The frozen wording "exit 2 … when
  `--rev` is not a 40-hex object id" is therefore false for the empty string at the freeze
  rev.
- **Abbreviated revs**: pristine grades `--rev be6c22b6` and prints `C1_SUMMARY rev=be6c22b6`
  exit 0; guard-only and both v96 counters refuse it exit 2 `rev-not-a-commit-id`. Same for
  the checker (pristine green, guard-only `DISPOSITION_SETUP rev-not-a-commit-id`). This is
  intended by kill rule (h) but is a behavior change on a legitimate revspec, not only on an
  attack.
- **`--rev master`**: refused exit 2 by both guards (intended); pristine grades the branch.
- **`--rev ''` staged-note witness**: pristine counter grades the *working tree* and prints
  `C1_SUMMARY rev=` (empty) `… badrows=0 … PASS=true`, exit 0; guard-only and v96 die
  `C1_SETUP rev-not-a-commit-id`, exit 2. My staged-row fixtures did not reproduce the plan's
  exact `badrows=1` token (the added rows were not parsed as verdict rows), so I confirm the
  "grades the index/worktree" half of the F2 before-state, not its exact badrow counter.

### 3.7 Hostile PATH: seal effective, verdict unchanged

Shim `git` (logs its argv, then execs `/usr/bin/git`), prepended to the inherited `PATH`:

| checker | shim invocations | verdict |
|---|---|---|

| guard-only | **0** | `findings=0`, exit 0 (identical output) |

So a hostile `git` earlier in `PATH` can intercept every git call of the round-95 checker and
none of the sealed one, and the seal does not perturb the honest verdict.

### 3.8 Environment dependence of the frozen/shipped checker (not in A1–A8)

Both the selftest and `main()` use
`TemporaryDirectory(dir=os.path.join(os.environ.get("HYAKU_SCRATCH", "/fast/scratch/hyaku"), "tameshi-r96"))`.
If that subdirectory does not exist, the checker dies with a `FileNotFoundError` traceback,
exit 1, printing no `DISPOSITION*` line — not a setup refusal. Observed with
`HYAKU_SCRATCH=<seat dir>` (`p3-disposition-explicit.out`, `p3-selftest.out`); it works only
because `/fast/scratch/hyaku/tameshi-r96` happens to exist on this host. The code creates
`…-checker-home/tmp` but never the `tameshi-r96` temp root.

## 5. Kill-rule mapping (C1)

- (a) `findings=0` with a bogus row: selftest cases for no-flip / unknown-key /
  missing-row all produce findings in the frozen and shipped selftests. Not violated.
- (b) ≥17 state rows: 17 of 19 rows carry a state in every run. Not violated.
- (c) selftest "cannot fail": **violated at the freeze rev** — the two new cases are `clean`
  duplicates (D4); repaired by A5.
- (d) blob-at-rev vs `claims.json`: consistent per revision (`claims.json` at `be6c22b6`
  lists `instrument_sha256=6c38dacd…`, the frozen checker's sha). Not violated.
- (g) hostile `git` flips findings→green: not violated; the seal pins `PATH` and
  `/usr/bin/git` (21 shim hits pristine, 0 sealed, same verdict).
- (h) non-40-hex revspec graded: not violated; `master` and abbreviations are refused.
  `--rev ''` on the checker is refused but not with the frozen token/exit at the freeze rev (D6).
