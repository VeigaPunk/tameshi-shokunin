### R56.3 — `14/14` `recheck:` in the knowledge entry; entry not indexed in `corpus/README.md`

Item text: *"Replace the `14/14` `recheck:` in `corpus/knowledge/receipt-revision-binding.md` with
the 19/19 command (as a new superseding entry or errata the `recheck:` line itself points to);
index the entry in `corpus/README.md`."*

Two sub-claims, both failing at base:

1. **The executable `recheck:` still names 14/14.**
   `git show 5e35699:corpus/knowledge/receipt-revision-binding.md | grep -n '14/14'` →
   lines **3, 155, 166, 225, 228**. Line 3 is the frontmatter `recheck:` and still requires
   `GATE_SELFTEST: 14/14 pass`.
   The base gate prints 19/19, not 14/14: `git show 5e35699:tools/receipt-revision-gate.py >
   gate-base.py; python3 gate-base.py --selftest` → 19 `CASE … PASS` lines then
   `GATE_SELFTEST: 19/19 pass`, exit 0. So the `recheck:` as written cannot pass on the base tree.
   The item allowed a fix by "a new superseding entry or errata the `recheck:` line itself points
   to"; line 3 contains **no** pointer to an errata and no `19/19` string
   (`sed -n '3p' | grep -ci 'errata\|19/19'` → 0). The file *does* carry an errata section
   `### ER-R56-K2 — gate count and digest changed in amendment 1` (lines 222-231) that names the
   drift and says "For a current-tree recheck, use 19/19" — but the `recheck:` line does not point
   to it, which is precisely the shape the item rejects. Partial prose mention ≠ the requested
   errata-pointer.
2. **The entry is not indexed.** `git show 5e35699:corpus/README.md | grep -c
   'receipt-revision-binding'` → **0**. The README's own coverage sweep at base lists it as
   unindexed: `for f in corpus/knowledge/*.md; do grep -qF "knowledge/$b" corpus/README.md || echo
   UNINDEXED $b; done` → `UNINDEXED receipt-revision-binding.md` (alongside `r44-anchor-refresh-rule.md`
   and `scratch-root-contract.md`, i.e. it is one of three unindexed entries, not a sweep artefact).

Verdict **open**: both halves of the item still hold at base. No commit changed the cited surface.

### R56.4 — 13 of 18 bound ledger entries carry a false `external_inputs` digest label

Item text: *"The 13 of 18 bound ledger entries whose `external_inputs` digest labels are not the
sha256 of `git show C0:<path>` (lane count: `SOURCES.md` 13, `QUALITY.md` 6): record the referent
or re-bind."*

Re-derived independently in the base clone (script `r564.py`, receipt 06): for every ledger entry
whose traces lie under `rekey-r56-*`, each `external_inputs` key is split into
`<rev>:<path>` (rev stripped of the `tameshi@` prefix) and the labelled digest is compared with
`sha256(git show <rev>:<path>)`:

```
rekey-r56 bound entries: 18
entries whose external_inputs label != sha256(git show C0:<path>): 13 of 18
ledger indices: [591, 592, 593, 594, 595, 596, 597, 598, 601, 603, 604, 605, 608]
mismatched labels by path: {'corpus/SOURCES.md': 13, 'corpus/QUALITY.md': 6} total labels 19
  sha256 c0137451 corpus/SOURCES.md 11c5682902d5564e   <- the label's key says C0
  sha256 c0137451 corpus/QUALITY.md 80792b7d466dfd21
  sha256 c1dd23b3 corpus/SOURCES.md 6c2096d8091f5d5b   <- the label's VALUE is this
  sha256 c1dd23b3 corpus/QUALITY.md 54c49d3873b03acf
```

The count and the per-file split reproduce the item exactly (13 of 18; `SOURCES.md` 13,
`QUALITY.md` 6; 19 labels total; the same ledger indices the lane's own lesson records). The
failure mode is precise: the label's *key* says `tameshi@<C0>:corpus/SOURCES.md` while its *value*
is the digest of the PIN commit `c1dd23b`'s bytes, not C0's — the false statement is in the
committed ledger `.ufo/evidence/round-21/coldread/ledger.json`.

The item's remedy — "record the referent or re-bind" — had not been performed at base:

* no referent record exists: `git grep -n '6c2096d8091f' 5e35699 -- ':!.ufo/evidence/round-21/coldread/ledger.json'`
  returns only the rekey trace files that carry the same label (`…/rekey-r56-c0137451f5b7/traces/section-01.json:63` etc.);
  no file names the digest's referent.
* the lane's own committed lesson says so: `corpus/lessons/round-56.md` lines 307-313 —
  *"fix: not repaired — the ledger is a frozen surface path and a rewrite would invalidate the bind;
  round 57 records the PIN as the digest's referent or re-binds."*
* the ledger's last commit is `c1dd23b round-56: bind cold-read headings at C0`; no commit after the
  spot-check add and up to base touches `.ufo/evidence/round-21/coldread/ledger.json`.

Verdict **open**: the defect holds at base and neither half of the remedy ("record the referent" or
"re-bind") was taken.
