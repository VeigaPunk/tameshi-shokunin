The item's own fix instruction is two-part: **(a)** the deciding gate must compare a receipt's

## Residual risk / verification gaps (for the L1)

1. **R55.4's blind spot survives.** Even after R55.5 lands, nothing at base can falsify a *status
   claim* in a record or report about a receipt. The only seat that audits records against
   receipts (`T56W3RevRecord`) covers "every number, commit hash and quoted verdict line" — a
   status claim is none of the three (`T56W3ScribeRecords.md:148`). The lane's own words at base:
   "no instrument reads prose". If round 57 wants R55.4 closed, it needs either an erratum on the
   round-55 report sentence in the fleet report (blob `c5fe555`) or an instrument that reads prose
   status claims. **The fleet report is outside the lane repo** — the lane clone's
   `.ufo/reports/` holds only `round-1` — so an erratum there is a fleet-side edit, not a lane
   commit. That is an operator/fleet-routing question, not a lane-debt question, and it is worth
   the L1's attention if the ledger's `status_at_base` for R55.4 says anything else.
2. **The gate's `control` role accepts any ancestor, not only the certified revision.** A control
   measured at an *older* ancestor is accepted (`:156-159`). That is the documented rule and the
   round-56 controls rely on it (`CTL_0_c1 rev=981c5e8b20a2`, the base), but it means a control
   scored before the work it certifies is still admissible as a `control`. The strict, drift-based
   check applies to `positive`/`verdict` roles and to the `--paths` surface. My probe 1 confirms
   the *non-ancestor* case is refused, so the R55.5 shape (a `rev=` that is not the revision
   under test) is closed; the "older ancestor" nuance is a separate, narrower question and is
   outside this item's text.
3. **Round-56's own C2 has a documented provenance gap** (the round-56 spot-check §2 and R56.5
   route it): the "own receipts" arm cannot distinguish a genuinely produced receipt from a
   fabricated stub. This does not bear on R55.5's verdict — the R55.5 item is about the *gate
   comparing revisions*, which I falsified directly with three refusal probes — but it means the
   round-56 C2 line should not be read as independently endorsing the gate.
4. **Not consulted (blindness):** `corpus/routed-defects.json`, `.ufo/evidence/round-57/**`,
   `.ufo/waves/round-57/**`. I have no read on the ledger's `status_at_base` for these two ids and
