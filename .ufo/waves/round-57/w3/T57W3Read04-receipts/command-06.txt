310:3. **On substrate drift.** The pin read above reads stale or drift. A moved substrate needs a **re-pin**, never a re-interpretation of the old table — the request shape already carries this (`service-optin-protocol.md:59-62`); both revisions stay in the record.

The run is read-only to the substrate, the note is the only fleet file written, and the outcome lands **as an appended row or errata block in this ledger** — never as an edit of §1–§4. A re-sweep measures the live revision; the old row stands as its revision's record; a rate never travels (per-revision, per-host; §0); `moved=0` is recorded, never manufactured.
