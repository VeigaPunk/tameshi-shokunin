## Method (independent of measure-v91.py)

Driver: `.ufo/waves/round-91/w1/T91E1-repro.py` (stdlib only; full output in
`T91E1-repro.out`). It shares no code path with `measure-v91.py`: the gate
blob is fetched via `git show`, fixtures via `git archive | tar -x`, the edit
via `str.count` + `str.replace(..., 1)`, the verdict via the selftest's own
exit code (`selftest ok` on stdout ↔ rc 0 ↔ SURVIVED; rc 3 with `SURVIVED`
arm lines ↔ KILLED). Read-only git only on fleet/lane repos; all writes under
`/fast/scratch/hyaku/tameshi-r91/T91E1/` (trap `rm -rf` on exit). The sealed
counter is invoked once, at the freeze rev, with an empty `--work` dir under
scratch; its full stdout is pasted verbatim below.

Gate semantics (from the pinned blob): the selftest prints `killed\t<label>`
per passing arm and `SURVIVED\t<label>` per failing arm, then `selftest ok`
and exit 0 iff no arm survived (else `selftest FAILED`, exit 3). So a mutant
is dead iff the selftest exits non-zero — equivalently, whichever of the
spec's arms the mutation breaks flips from `killed` to `SURVIVED` in the
output. The kill-rule question is only whether that flip happens in an
ordinary fleet shell.
