### 2.3 C2 — the `toolpin` conjunct is a tautology — DEFECT

Plan: "the tool blob hashes to its pin" (`plans/round-91.plan.md:102`).
`measure-c2-v91.sh:59-62`:

```sh
git -C "$R" show "ff7a4b06:tools/ledger-witness.py" > "$WORK/blobrun-ledger-witness.py" 2>/dev/null || true
expect=$(sha256sum "$WORK/blobrun-ledger-witness.py" | cut -d' ' -f1)
pinned=$(sha256sum "$WORK/blobrun-ledger-witness.py" | cut -d' ' -f1)
[ -n "$expect" ] && [ "$expect" = "$pinned" ] && toolpin=ok
```

`expect` and `pinned` hash the same file, so the comparison is a tautology: it cannot fail, and
`toolpin=ok` is printed in every receipt (`C2-pos.out:8`, `C2-keepred.out:8`,
`C2-nowork-instr.out:6`). A failed `git show` still leaves a truncated empty file whose digest
is non-empty (`e3b0c442…`), so even a missing blob yields `toolpin=ok`. There is in fact no
sha256 pin to compare against: the registry row's `source` is
`tools/ledger-witness.py@ff7a4b06:1-60` (rev + line span, no digest). The plan's conjunct is
therefore never measured, and the counter prints a label asserting a pin match it did not
perform — the token/print-binding class (QUALITY 141) the round was created to close.

The other four conjuncts hold: manifest sha256 constant checked against bytes from `MSRC`
(`:27-30`), `rows` from the candidate `tools/defect-bind.py` (`:33-37`), `argv` bound to the
hardcoded entry and to the `| ledger witness (not admitted) |` SKILL row (`:49-53`), `blobrun`
running `$WORK/blobrun-ledger-witness.py` — the pinned blob, not the candidate tree — with
`LEDGER_WITNESS_SELFTEST: 21/21 pass` (`:66-69`).
