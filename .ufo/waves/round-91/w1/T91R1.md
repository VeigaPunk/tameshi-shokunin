## 1. Killing findings

### F1 — frozen rev: `parse_note` reads one column too far (`cells[vcol + 1]`)

`measure-v91.py` @ `50e59d59:117,120-122,130` binds `vcol` to the index of the
`verdict` cell in the **full pipe-split** of the header row, then reads
`v = cells[vcol + 1]` (`:130`). A leading-`|` row splits with an empty element at
index 0, so data cells are index-aligned with the header cells; `+ 1` reads the
column *after* `verdict`. Three consequences, all measured
(`T91R1-parser-diff.out`):

- **False-green.** A note whose header-named `verdict` column says `SURVIVED` for
  every id and whose *next* column carries the derived verdicts parses to exactly
  the derived set under the frozen bytes —
  `FALSE_GREEN frozen rows=12 ambiguous=0 equals_derived=True`. With the other
  conjuncts honest, such a committed note reaches `C1_R91_PASS=true` while the
  note's own verdict column is false on all five KILLED rows. That is kill rule
  (a): a committed state that does not hold the true verdicts reaches PASS.
- **Every honest note is refused.** The committed case note
  (`corpus/knowledge/mutation-case-fleet-sources-census.md`, 5-column table) parses
  to `rows=0 ambiguous=12`; `ids_ok` and `mismatched0` are both false
  (`:250-251`). The same holds for a minimal honest table (`HONEST frozen rows=0
  ambiguous=12`).
- **The committed PASS receipt is impossible under the frozen bytes.** The
  controls build their fixture note with a 4-column table (`controls-v91.py:34`),
  so the frozen reader takes the `witness` cell as the verdict:
  `CTL14_NOTE frozen rows=0 ambiguous=12` versus the committed
  `CTL14-pos.out:16 C1_R91_PASS=true`. The receipt therefore certifies the
  post-freeze parser, not the frozen one.

Also in the frozen parser: `vcol` is re-bound by **every** later header line (no
`vcol is None` guard, `:120-122`), so a second header can re-point the column
mid-file; and lines with fewer than five pipe-split cells are skipped before the
id is ever matched (`:117`), so a short contradictory table is invisible. (This
short-row limb is the mechanism T91C1's attack uses.)

The shipped bytes close all of this: `HONEST head rows=12 ambiguous=0 match=True`,
`FALSE_GREEN head … mismatches=5` (refused), committed note `rows=12 match=True`.

### F2 — shipped parser silently skips gate-legal indented id-keyed rows

`measure-v91.py` @ `HEAD:138` matches rows with
`re.match(r"^\|\s*(C\d\d)\s*\|", raw)` — the pipe must sit at **column 0**, while
the pinned gate's own table convention allows `^ {0,3}\|`
(`scripts/sources-census.sh` @ `f47ad6ba:541,615` — the row table regex and the
awk row gate). A row indented 1–3
spaces is therefore not "ambiguous", it is **not seen at all** — no entry in
`ambiguous`, no duplicate detection, no diagnostic. QUALITY 140 as the counter's
own docstring states it (`HEAD:117-119`) is "a duplicate id, a missing/renamed
header, or a row whose cell … makes the note ambiguous -> ids=false, **never a
skip**"; an indented id-keyed row is skipped.

Measured (`T91R1-parser-diff.out`):

- `INDENTED_FALSE_ROW head rows=12 ambiguous=[] C02=SURVIVED equals_derived=True`
  — the honest 12-row table plus a gate-legal `   | C02 | arm | KILLED | invisible |`
  still parses to derived-equal, so the note contains two contradictory C02
  verdicts (one of them false) and reaches PASS. This is the same false-green
  shape F1 shows at the frozen rev, on the bytes that will actually run.
- `INDENTED_3SP … head rows=0 ambiguous=0` — an honest note whose whole table is
  indented 1–3 spaces (legal Markdown and legal for the gate's own parser) is
  refused with no ambiguity recorded; the receipt cannot say why.

Same class, same line: ids of another width (`C013`) and lowercase (`c01`) are
skipped silently. The three-digit case is the one T91C1 names in its correction.

Minimal repair: accept `^ {0,3}\|` for the id match **and** record any row that
looks table-shaped and names a spec id in a non-canonical form as ambiguous rather
than dropping it; or refuse indentation outright with a setup message.

## 3. Surfaces checked and found sound

- **Sealed git environment — every call.** The only git invocations are
  `git()` (`HEAD:46-50`) and `blob()` (`:53-55`), both through `sealed_env()`
  (`:38-43`); no other `subprocess` call passes `git`. `sealed_env` builds a
  fresh dict from a literal, so no inherited `GIT_*` can leak; `GIT_DIR`,
  `GIT_WORK_TREE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`,
  `GIT_CONFIG_COUNT` are all absent. `HOME` is dropped for git reads and
  `git cat-file`/`git archive` still work (`T91R1-seal-probe.out`,
  `sealed_no_HOME_rc=0`; archive rc 0 over the real fleet pin).
- **The seal actually seals.** Fixture repo with a blob replacement: unsealed read
  returns the replaced bytes, `GIT_NO_REPLACE_OBJECTS=1` returns the true bytes,
  and `git archive` honours it too (`T91R1-seal-probe.out`). Round-90's V4 read
  path is closed by construction.
- **Replace gate — both repos, before any read.** Lane at `:168-173`, fleet at
  `:181-185` (after the spec is parsed, before the gate blob at `:186`); both die
  with exit 2. Ordering is sound, and a ref created *after* setup cannot help the
  attacker because every read carries the env seal as belt and braces.
- **Materialize.** `git archive --format=tar <commit> <fixtures>` + `extractall`
  (`:65-75`); extraction happens **before** the gate copy is written, so the
  archive can never overwrite a mutant, and the archive contains only the fixture
  path. Byte fidelity: 8/8 fixture blobs identical to the pinned tree, no
  `.gitattributes` anywhere in the fleet tree, no symlinks or exec bits
  (`T91R1-materialize-probe.out`). `filter="data"` is supported (Python 3.14.8).
- **Canary.** `exit 97` inserted after line 1 of the pristine bytes (`:183-187`);
  a copy that does not execute cannot return 97. (Declared limit stands: it does
  not identify which arm ran a mutated line.)
- **Validity / trivial.** `old` occurs exactly once, `new != old`, `bash -n`
  (`:206-216`); trivial = clean-lane `validate` exit 2 or `None`, or
  `gawk failed` / `syntax error` on stderr (`:219`). Every mutant copy is built
  from the pinned blob, never from the archive.
- **Two-run stability.** `runs_per_verdict` comes from the sha-pinned spec (2);
  disagreement → `UNSTABLE`, timeout → `INCONCLUSIVE`, both force
  `unstable0`/`inconclusive0` false (`:221-229`, `:286-291`). `derived` is the
  counter's own re-execution, so a note cannot steer it.
- **Witness building.** One directory `w-<id>` for both runs, lane rebuilt
  between them (`:234-237`), so pristine and mutant start from identical registry
  state; comparison is `(rc, stdout)` (`:239`), stderr cannot manufacture a
  "differs". `witnessed == survived` (`:255`) means any unreproducible survivor
  refuses the state.
- **Row parsing (shipped).** Duplicate ids are flagged, not skipped (`:149-151`);
  a row whose cell at the bound index is out of vocabulary is flagged (`:146-148`);
  a row short of the bound index is flagged (`:142-144`); a missing header flags
  every id (`:142`); the committed note's other tables (`| C02 · W02 …`,
  `| C12 used-by trim |`, `| C02, C06, C08 |`) do not match the id shape and do
  not collide (`TABLE_SHAPE … rows=0 ambiguous=[]`).
- **Figure.** Exactly one `measured: K/N killed`, compared to the derived
  `killed`/`n` (`:266-267`).
- **Source / README / spec pin.** `source:` must be exactly one line, `S318` must
  appear on it, and `corpus/SOURCES.md` must carry a ≥11-column row with id
  `S318`, status `mined`, and the note path in the used-by cell (`:268-278`).
  README must carry a `|`-leading row naming the note (`:279-281`). Both the spec
  and the gate blob are sha-pinned (`:177`, `:189`), and every conjunct is in
  `ok = all(conj.values())` (`:286-291`) — there is no path to `PASS=true` with
  any check skipped, and no note-dependent conjunct defaults to true
  (`:258`: `ids_ok = figure_ok = source_ok = False`).

## 4. Constraints the landing note amendment must honour

The counter reads the note **at `--rev`**, so these are properties of the
committed landing note, not of a draft:

1. Exactly **one** line starting at column 0 with `source:`; put `S318` into the
   existing round-90 line rather than appending a second one (`:268`).
2. Exactly **one** `measured: K/N killed` in the entire file, including inside
   code fences (`:266`).
3. The twelve C-rows in **one** table, pipes at column 0, ids `C01`–`C12`; no
   second `| Cxx |`-keyed row anywhere, and no 1–3-space-indented variant of one
   (§F2), or the note either refuses or hides the row.
4. Keep ``` fences balanced (the committed note has 6 fence lines) and avoid any
   non-fenced line with ≥2 pipes containing a cell exactly equal to `verdict`
   before the table (§F3).
5. The `corpus/SOURCES.md` row must be an 11-column registry row: id `S318`,
   status `mined`, used-by cell (split index 11, requires `len(cells) >= 13`)
   containing the note path.
6. A `corpus/README.md` table row must name the note path.
