2. **Mutants**: Each survivor is built as a single-edit scratch copy under `/fast/scratch/hyaku/tameshi-r91/T91CN1`; `old` occurs exactly once, `new != old`, `bash -n` clean. All scratch copies deleted on exit.

Class predicates run row by row, with an E04/W04 replay of the gate's duplicate-URL state machine in file order for C03 and C09 to separate mere "shape" hits from "effective" verdict flips.

## Contradictions (stated explicitly, never smoothed)

1. **C09's literal class description contradicts its actual fleet blast radius.** The within-scope class described in the mutation case ("rows whose URLs differ only by #fragment within one scope") is effectively inert (2 rows in 1 lane, 0 flips, because supersession already exempts them). The mutant's actual observable effect is entirely cross-scope `W04` de-duplication across 10 lanes, and even there it produces zero exit-code changes. Quoting either "inert" or "10 lanes affected" without distinguishing within-scope vs cross-scope would be misleading.
2. **C03's raw shape count overstates functional impact 4.3×** (416 rows vs 97 effective rows). Counting every row that contains `supersedes S###` conflates harmless text annotations with operative duplicate-URL exemptions. Only 97 rows actually protect valid entries from false E04 errors.
3. **C02, C06, and C08 are latent, not benign.** A count of 0 on today's fleet registries means "no committed bytes exercise the fault today", not "the gate is correct". The spec witnesses prove that each mutant breaks on valid inputs (e.g. standard GitHub alignment colons in markdown tables, directory paths in used-by, or 7-character rejection explanations). The moment any lane introduces a colon-aligned table or a directory reference, the gate would fail.
4. **Units must not be conflated on C12.** Multi-path used-by cells mean that row count (1247 mined rows) and finding count (1821 fabricated E11 errors) differ significantly.
