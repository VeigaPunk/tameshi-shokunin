## 4. What the page says, and what the counter does with it (observed, not inferred)

Read-only from the sealed counter `measure-v91.py:167-186` and reproduced in a


`git()` runs with `GIT_NO_REPLACE_OBJECTS=1`, `GIT_CONFIG_NOSYSTEM=1`,
`GIT_CONFIG_GLOBAL=/dev/null` and `HOME` popped (`measure-v91.py:36-49`).

**Fixture** (`T91S2-replace-fixture.sh`, output `T91S2-replace-fixture.out`;
every repo created under the seat scratch dir and deleted by an `EXIT` trap;
identity `ctl <ctl@fixture.invalid>`; `git rev-parse --show-toplevel` asserted
against the fixture dir before the first commit):

1. `git replace <blob_a> <blob_b>` in a fresh fixture repo → the ref appears as
   `refs/replace/<blob_a>` whose content is `blob_b` — **exactly the shape the
   page's line 1661/1664–1666 describes** (the ref is *named* for the replaced
   object and *holds* the replacement).
2. `git replace -l` prints the replaced object's SHA-1 on stdout, exit 0 — the
   read the counter makes.
3. `git cat-file -p <blob_a>` returns **`replaced`** without the env var and
   **`original`** with `GIT_NO_REPLACE_OBJECTS=1` — so the substitution is real
   and the env var genuinely disables it for object reads.
4. **`git replace -l` still lists the ref under `GIT_NO_REPLACE_OBJECTS=1`.**
   This is the point worth keeping: the environment variable protects the
   *object read*, but it does **not** make `git replace -l` empty, so the
   counter's "refuse a non-empty `git replace -l`" gate is **not redundant**
   with `GIT_NO_REPLACE_OBJECTS=1`. Both are needed; the counter has both.
5. The **sealed counter refuses** a clone of this lane that carries such a ref:
   `C1_SETUP replace-refs-present:lane` / `C1_R91_PASS=false` / exit 2 —
   reproducing the frozen pre-freeze control
   `.ufo/evidence/round-91/pre-freeze/controls/V4-replace.out` from an
   independently built fixture (that control's line reads
   `C1_SETUP replace-refs-present:lane`, exit 2).
6. **Gate ordering observed:** with the replace ref deleted, the same counter
   on the same clone advances past the replace gate and stops at the *next*
   gate (`C1_SETUP spec-absent-at-rev`, exit 2, with a bogus rev) — i.e. the
   replace-ref refusal fires **before** the spec read, exactly as the source
   order shows.

The fixture is deterministic apart from the scratch directory name (two runs
differ only in the `fx.XXXXXX` path; all hashes, ref names, file contents and
the counter's verdict lines are identical).

**Not claimed:** that `git replace` is the *only* way a replacement ref can
enter a repo, that the counter's refusal is the right policy rather than a
strict one, or anything about the gate's own correctness. This seat supplied
the documentation ground and a reproduction of the setup gate's V4 arm; the
sealing's *adequacy* is the counter-review seat's question.
