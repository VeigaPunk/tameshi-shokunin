## Findings

**F1 — the counter's note-side scans are only half fence-aware.** `parse_note` skips ``` blocks,
but the `source:` scan (`[l for l in nt.split("\n") if l.startswith("source:")]`) and the
`measured:` scan (`re.findall(r"^measured: (\d+)/(\d+) killed\s*$", nt, re.M)`) are **fence-blind**.
Measured on the real note bytes: a second `source:` line (fenced *or* unfenced) makes `len(src)==2`,
so `cited` becomes `set()` and `source` goes false; a second `measured: 5/12 killed` line makes
`len(heads)==2` and `figure` goes false. Only the *table* duplicate is fence-safe
(`A +2nd table (fence)` → `ambiguous=[]`).

**F2 — Part A must be a substitution, never an addition.** The `source` conjunct reads `src[0]`
and only when the note has exactly one `source:` line. Adding the S318 citation as a second line
is the single easiest way to leave `source=false` while appearing to fix it.

**F3 — the note's citation alone does not satisfy the counter.** At lane HEAD the note cites
S001/S316/S317 and `source=false`; with the S318 citation but **no** `corpus/SOURCES.md` row,
`source` stays false too — the conjunct requires a row with `c[1]=="S318"`, `c[8]=="mined"` and
`corpus/knowledge/mutation-case-fleet-sources-census.md` inside `c[11]`. The draft therefore
carries the registry row as a required companion, byte-exact and gate-valid (13 pipe-split cells,
`kind=docs`, `tier=A`, `status=mined`, `opened=2026-11-08`, `recheck=365d`).

**F4 — landing hazard (the round-90 M6 class).** The S318 row's used-by names
`corpus/lessons/round-91.md`; the census gate's `usedby_findings` requires every used-by path of a
**mined** row to exist on disk (`E11`). So the round-91 lesson must land in the **same commit** as
the S318 row, or the lane's own census exits 1 at that commit. Flagged in the draft with the
fallback (drop the lesson path from used-by for that commit; the counter only needs the note path).

**F5 — the S318 URL yields `W04`, not `E04`.** `git-scm.com/docs/git` is already held by S063 with
a different scope, so the gate prints `W04 S318 duplicate url git-scm.com/docs/git across scopes`
(a warning; `W`-codes never change status — the lane already carries 19 `W04` rows and validate
still exits 0). `E04` would fire only if URL *and* scope text both matched an existing
non-rejected row.

**F6 — the note's `verified-at:`/`recheck:` lines still name the round-90 instrument**
(`…/round-90/c1/measure.py`, `C1_R90_PASS=true`). No counter reads them, so this is not a claim
risk, but a reader following the note's own re-check pointer runs the superseded, killed counter.
The draft gives the replacement text as an explicitly optional edit; the live successor is
`measure-v91.py` against `.ufo/evidence/round-91/c1/census-mutants.json` (same bytes, sha256
`ce8983d5…e290`).

**F7 (report-only, counter observation).** The C2 counter's `toolpin` conjunct is degenerate: it
computes `expect` and `pinned` as `sha256sum` of the *same* `$WORK/blobrun-ledger-witness.py`
written from `git show ff7a4b06:tools/ledger-witness.py`, so it can only fail when that file is
empty/unreadable — it never reads the sha256 the registry row's `source:` pin names, although the
counter's own header says it does. `measure-c2-v91.sh` is frozen, so this is recorded for the
round, not repaired here.

**F8 (verified non-hazard).** The note's other tables do not disturb the parser: the §2 survivor
rows (`| C02 · W02 …`), the §2b impact rows (`| C12 used-by trim | …`), and `| C02, C06, C08 | …`
do not match `^\|\s*(C\d\d)\s*\|`, which is why the note parses to exactly 12 rows with
`ambiguous=[]` both before and after the amendment.
