## Method

- The frozen list of 21 single-edit defects was written to `T91M1-defects.txt`
  **before** the first control run. Each edit weakens exactly one conjunct or
  check of the counter.
- `T91M1-probe.py --mode prepare` asserts that every `old` snippet occurs exactly
  once in the frozen counter, applies one replacement, writes
  `…/mut/<id>/measure.py`, and compiles it with `python3 -m py_compile`. Target
  sha vs each mutant sha is recorded in `T91M1-manifest.json`; all 21 differ.
- Each defect is evaluated with the committed control battery: clone the lane at
  `A_REV=ace200b50…`, assert `git rev-parse --show-toplevel` equals the clone,
  write the CTL14-pos fixture files, commit once under a fixture identity inside
  the clone, then run `python3 -I MUT --repo CLONE --rev HEAD --work EMPTY`.
  The 19 control states are exactly those of `controls-v91.py`.
- The scratch copy of the driver differs from the committed file in exactly two
  env-parameter lines — the measure path **and** the receipt outdir
  (`T91M1-driver.diff`). The outdir redirect is required by the lane rule that
  nothing may be written under `.ufo/evidence/round-91/`; without it the driver
  would overwrite the frozen receipts.
- Kill rule (pre-registered in the spec): KILLED iff at least one control whose
  frozen receipt is not `C1_R91_PASS=true` now prints `C1_R91_PASS=true`.
  `CTL14-pos` must keep passing (`pos_ok`).

## Coverage findings (survivors)

These are findings about the committed battery, not proposed contract changes.

1. **The seal is triple-redundant and no committed control isolates either
   guard.** D01 (remove the `git replace -l` refusal) leaves `V4-replace` at
   exit 1 with `mismatched0=false` — the sealed env read the child tree and the
   false note was refused by the verdict comparison, not by the gate. D02
   (remove `GIT_NO_REPLACE_OBJECTS=1`) leaves `V4-replace` at exit 2
   `replace-refs-present:lane` — the gate refused it. The replaced-parent read
   would also fail `source=false` at `A_REV`. So a counter keeping only one of
   the two guards survives the whole battery. A future control needs a state
   that isolates one guard (e.g. a false note that also satisfies the parent's
   source/coverage checks, run with the gate and the env toggled separately).
2. **Every control that exercises `invalid0` / `trivial0` / witness / id-set /
   `n_min` also edits the spec blob, and `spec=false` masks the whole
   conjunction.** D10 (id set not checked), D13, D14, D15 (noop), D16 (witness
   forged), D19, and D12 survive. Evidence: D13 on CTL7 leaves
   `spec=false invalid0=true trivial0=false` (the forged `invalid0=true` does not
   help), D14 on CTL7 leaves `invalid0=false trivial0=true spec=false`, D15 on
   CTL6 leaves `spec=false witnessed=false`, D16 on CTL9 leaves `spec=false
   witnessed=true`, D12 on CTL12 leaves `pin=true spec=false`. A control state
   that changes mutant behaviour **without** changing the spec bytes (or a spec
   pin over a normalized subset) is required to cover those checks.
3. **The figure check is one-sided.** D05 (drop K) is killed by CTL3-figure
   (`measured: 6/12` with `killed=5`), proving K is compared. D06 (drop N)
   survives: CTL3 changes both K and N, and no control has a matching K with a
   wrong denominator. The denominator `N` is never independently exercised.
4. **Harness-invariant checks have no control state that varies them.** D03
   (single pristine run), D04 (canary ignored), D17 (timeout treated as
   SURVIVED), and D18 (fenced rows accepted) survive because every committed
   control state runs a deterministic, fast, fence-free gate; `green`, `canary`,
   `inconclusive0` and the fence rule are always true/never-hit.
5. **Source and coverage are covered at whole-check granularity.** D20 is killed
   by three independent states (CTL1b, CTL10, CTL16) and D21 by CTL15. The inner
   sub-conjuncts of the source check (`c[8]=="mined"`, `NOTE_PATH in c[11]`,
   `SOURCE_SID` restriction) were **not** probed individually by this spec; each
   would need a registry-row fixture that differs on exactly that column.
6. **Parser ambiguity rules are well isolated.** The duplicate-id rule (D08) and
   the out-of-vocabulary-cell rule (D09) are killed by distinct controls
   (VOV1, VOV3), and neither survives the other's control — the two refusal
   branches are independently covered.
