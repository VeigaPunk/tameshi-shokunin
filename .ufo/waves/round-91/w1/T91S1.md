## 3. The committed `.txt` is byte-reproducible — and not by the round-90 stripper

The round-90 stripper (`.ufo/waves/round-90/w1/T90S1-strip.py`) does **not**
reproduce the frozen round-91 `.txt` (it keeps script/style and normalises
whitespace per line; `cmp` differs at char 1, 1664 vs 1646 lines). I recovered
the actual recipe and it now reproduces the committed file **byte for byte**:

```

sha256(out.txt) == sha256(committed git-env.txt) == 43274685e996792d4b3a92fed27cbaea49de1bd9af4f8240e48be85c126b930e
```

Recipe: drop `<script>`/`<style>` blocks → replace every remaining tag with one
space → unescape entities → collapse horizontal whitespace runs to one space →
split on newlines → drop blank lines → emit one leading line holding a single
space, then the surviving lines verbatim, then a final newline.

**Why this matters to the L1:** the frozen `.txt` is sound, but the *stripper
that produced it is not in the repo*. A reader who re-derives the text with the
round-90 stripper gets different line numbers and a different sha256, so the
S318 anchor would look broken to an independent verifier even though the page
is unchanged. `T91S1-derive-committed-txt.py` closes that gap — save it
alongside the row (or cite it in the row's `anchor` cell) so the line range
`1414-1415` is reproducible from the committed bytes.
