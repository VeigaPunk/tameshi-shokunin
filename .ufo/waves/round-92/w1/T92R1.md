## Findings

### Should-fix

**SF-1 — Fenced hiding contradicts kill rule (a); counters disagree with the plan's own limit.**
`parse_note:158-163` skips every line inside a backtick-fenced block. A note
with the twelve true verdicts in the keyed table **plus** a fenced second
table carrying the opposite twelve verdicts measures cleanly: probe yields
`12 [] 1` (fenced-contradiction case, `T92R1-probe.out`), `ids=true`,
`mismatched0=true`. The plan states both that a fenced-table presentation
kills C1 (`plans/round-92.plan.md:86-91` rule (a) lists "a fenced table") and
that fenced blocks "are not Markdown tables the note presents" (limits,
`:101-102`). The counter implements the limit; the kill-rule text implements
the opposite. There is no battery state for a fenced contradiction (no
`*fenced*.out` in `pre-freeze/controls/`), so D-prong coverage is silent. A
reviewer reading rule (a) strictly — as the claim's certifier must — can kill
the claim on a PASSing receipt. Given the limit is declared, the counter is
arguably correct and the plan text is wrong; either way L1 must reconcile
them in the landing record before this is treated as settled. Severity:
**should-fix** (ambiguity between two committed texts, not a false-green of
the measured verdict itself — the twelve cells are still true). (The same
gap covers HTML tables without pipes, declared out of scope at the same
lines; an HTML verdict table renders as a table to every reader but is never
keyed.)

**SF-2 — Honest-note drift: `verdict`-cell substring collision (measure-v92.py:168).**
Header detection is `if "verdict" in low` over **any** row's cells, not only
the verdict-table header. A data row whose witness or arm cell is exactly the
word `verdict` (e.g. `| C01 | … | KILLED | verdict |`) counts as a second
header (`headers=2`, probe `witness==verdict headers: 2`) → `ids=false`
(`:309`). Same for a data row whose first cell is the word `verdict` (probe:
`headers: 2`). An honest note quoting the column name in a cell is refused.
Fail-closed, so no false-green, but it is a needless honest-refusal surface
the kill rule (a) second branch ("an honest note is refused by a rule stated
above") deems a kill. `vcol` is also set from the first matching row only
(`:169-170`); any pre-table prose table carrying the word `verdict` pins it.
Natural fix: only treat a row as a header if it carries `verdict` **and** an
id-shaped first cell is absent **and** the row is followed by a separator, or
simpler — require the header row's first cell to be `id`. Severity:
**should-fix** (fail-closed only; no PASS is produced).

### Notes (informational, no counter change recommended unless L1 tightens)

**N-1 — Self-pin arithmetic preserves digest under dupe/move/zero (measure-v92.py:58).**
`norm = re.sub(SELF_PIN_RE, b"", b, flags=re.M)` removes **every** occurrence
of the pin line, so a file with the pin line duplicated keeps the same
normalized bytes, and moving it within the file also preserves them (verified
arithmetically and at runtime: dup/moved variants pass `self_pin_ok()` and
die later at `replace-list-failed:lane`; `T92R1-probe.out` pin lines). Zeroing
the hex value also leaves the arithmetic "true" (`T92R1-probe.out`), because
the compared value is the runtime binding — zeroing it with the rest of the
file unchanged makes the runtime check `hash == "0…0"` false, so the check
still dies; the probe's phrasing shows only that the normalized digest is
unchanged, which is by construction. The pin is therefore a tripwire against
non-recomputing edits, not an absolute seal: an adversary who recomputes
`SELF_SHA256` over their own bytes passes (exactly what the D-prong mutation
studies do by design, `:152-153`). The certified binding is the plan's
kill rule (c) — the committed blob's sha256 versus the plan — not the
self-pin alone. The header comment "A post-freeze edit is inert" (`:14`)
overstates the mechanism slightly; documented here rather than charged.
Also note `selfpin` in the conjunct (`:195-197, 332`) can never print `false`
— failure exits at `die()` before any conjuncts are printed — so `selfpin=
true` in receipts is structurally vacuous; the refusal is the signal.

**N-2 — `measured:` is fence-blind while the table parser is fence-aware (measure-v92.py:311).**
The figure check scans the whole note text with a regex, including fenced
blocks, while `parse_note` ignores fenced tables. A second `measured:` line
anywhere — even inside a fenced code example in the §Reproduce section, a
quoted example, or a second identical line — makes `len(heads) != 1` and
refuses (`figure=false`). Also strict: double spaces after `measured:` and
`+12/` fail (`T92R1-probe.out` measured lines), while trailing whitespace and
leading zeros (`03`) pass. Fail-closed. The asymmetry with the fenced table
is worth recording so future note authors know fences do not protect the
figure line.

**N-3 — Escaped pipes: strict as declared (measure-v92.py:164).**
Cells split on every `|`, so `\|` inside a cell splits that cell. A `\|`
inside or after the verdict cell shifts the verdict column and `position:`
refuses (probe `escaped-pipe-in-verdict`); a `\|` in the witness cell only
adds a trailing cell and the note still passes. Rows without leading/trailing
outer pipes shift `first` and refuse as `unkeyed:` (probe G). This matches
the plan's declared strictness ("shifts the columns and refuses", `:108-109`)
and is fail-closed. Recorded because the brief asked specifically; no defect.

**N-4 — ID shape and header counting both refuse (with sharp edges).**
`ID_SHAPE` (`:48`) is `^[A-Za-z]{1,4}[_-]?[0-9]{1,4}$`: it matches
`C001`, `X1`, `C-01`, `No12`, and also `S320` (probe 15) — any id-shaped
first cell outside `C01-C12` becomes `out-of-set:` and refuses, so the
S320 registry row, if pasted into the note as a table row, would refuse. The
real note contains no such row (checked: `grep -n S320` on the note → 0
hits). Header counting (`:168-172`) counts a row as a header whenever any
cell is exactly `verdict` (case-insensitive) — including data rows (SF-2)
and short second headers (`| id | verdict |` → `headers=2`, `position:`).
Case-insensitivity is correct. Duplicate C01 rows with the *same* verdict
still refuse as `dup:` (probe H) — stronger than the battery's opposite-
verdict `dup-row` state, which is fine.

**N-5 — Coverage and source conjuncts are substring/existential, not sectional.**
`coverage` (`:326`) accepts any `|…`-starting README line containing the
note path, including inside a README fenced block. `source` (`:319-324`)
finds the S320 row by column position (`c[1]=S320, c[8]=mined, c[11]` contains
the lesson path) in the raw registry text — it does not verify the row sits
inside the `## Registry` section, and the lesson linkage is a substring scan
for `S320` and the URL (the real lesson mentions both, including in the
rejected-candidate paragraph, so the check is weaker than "opened this
round" reads). The gate itself enforces E12 for the fleet side; these are
documentation-linkage conjuncts and the battery's `source`/`coverage` states
mutate the exact fields the counter reads (status value, README line
deletion), so they are not vulnerable to a fake PASS without a committed
S320 row of the right shape. Flagged as note, not defect.

**N-6 — Witness strictly compares (rc, stdout), ignores stderr (measure-v92.py:281).**
`differs` iff `(p1[0], p1[1]) != (p2[0], p2[1])`; stderr is written nowhere
for witnesses. A survivor whose effect appears only on stderr produces
`witness=same` and `witnessed < survived` → `witnessed=false` →
fail-closed (honest-note refusal), never a false-green. The trivial probe
(`:261`) scans stderr of a `validate` run on clean lane `c`, while witness
stderr is unexamined; both directions are conservative in their own conjunct.
Also `runs_per_verdict`/`timeout_s` are read from the sha-pinned spec
(`:233-234`), so the stability rule cannot be weakened without breaking `spec`
as well — correct by construction.
