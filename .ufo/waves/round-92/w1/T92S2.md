## What this seat does and does not claim

**Claims (measured here).**
1. The honest note raises **no** refusal of the frozen parser: `bad=[] headers=1
   ids_ok=True`, and the committed counter prints `C1_R92_PASS=true` with
   `badrows=0 headers=1` at `84904d41`. The parser's premise — one verdict table,
   twelve `C01`–`C12` keys — holds exactly on the real note.
2. The note contains **four** candidate tables and the parser keys exactly **one**;
   the three others (the survivor table at 118, the fleet-impact table at 140, and a
   pseudo-table at line 3) are keyed by nothing. Concrete examples are in §(c).
3. The refusal survives every id-shaped and survivor-row shape the note itself uses
   (§(f)): `dup`, `out-of-set`, `unkeyed`, `position` and a second `verdict` header
   all refuse.
4. Two forms do **not** refuse: a contradicting table inside a fenced code block, and
   a contradicting table whose verdict word is lowercase. Neither occurs in the honest
   note; both are recorded because kill rule (a) enumerates "a fenced table" and "a
   second table" among the forms that must not reach `C1_R92_PASS=true` while the note
   presents different verdicts.
5. The **escaped-pipe** form the plan names but says the note does not explore *is*
   strict, as the plan claims: state D refuses (`ids=false`). This was the plan's one
   unverified prediction about a form and it holds.

**Does not claim.** No kill is asserted here: the frozen rule (a) is the L1's and
T92C1's call, and the two non-refusing forms above need a state that presents
*different* verdicts — my §(f) probes append a contradicting row to an otherwise
honest note rather than standing in for a full adversarial state. The honest note is
not refused and the counter passes on honest bytes; that is what this seat measured.

**Unresolved / routed to the L1.** Two readings the L1 should weigh, neither settled
here because both are readings of the frozen rule rather than measurements:

1. **Fenced form.** The plan's *declared limits* say "fenced code blocks and HTML
   tables are not keyed (they are not Markdown tables the note presents as its verdict
   table)"; its *kill rule (a)* enumerates "a fenced table" among the forms that must
   not reach `C1_R92_PASS=true` while the note presents different verdicts. The parser
   skips fenced content outright (state C: `ids=true`, `C1_R92_PASS=true`). The two
   clauses point in opposite directions for the same form.
2. **Lowercase spelling.** `VERDICTS = ("KILLED","SURVIVED")` is case-sensitive, so a
   contradicting row whose verdict word is lowercase is not a verdict token and is
   skipped (state B: `ids=true`, `C1_R92_PASS=true`). The note's own prose uses the
   lowercase spelling (`measured: 5/12 killed`, "5/12 killed under its own `selftest`"),
   so the spelling is not alien to this note — but the note's *verdict table* uses
   uppercase throughout, and the plan states the rule over the tokens `KILLED`/`SURVIVED`.

Neither is a defect in the honest note; both are the exact places where the frozen
rule's enumeration of forms and the frozen parser's behaviour part company.
