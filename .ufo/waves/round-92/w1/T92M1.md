## 2. Method, and why the pin is recomputed per mutant

- **Single edit per mutant.** Each defect in `T92M1-defects.txt` / `T92M1-defects-2.txt`
  is one replacement whose `OLD` text must occur exactly once in the frozen bytes, and
  whose `NEW` text must differ. The harness refuses otherwise (28/28 and 2/2 verified).
- **The pin is recomputed for the edited bytes.** `SELF_SHA256` is recomputed over the
  mutant bytes with the pin line removed, so each mutant runs under its own verified pin
  (the harness re-derives it and refuses a mutant whose pin does not verify). This is the
  same licence the plan grants D01/D02/D03: *the self-pin is a seal against accidental
  drift, not a defence against a deliberate mutation study.* It also means the pin cannot
  make a mutation study impossible — that must be stated, not implied. The frozen bytes
  are never written; they are read from the lane's object store.
- **States are scratch clones, never the lane.** Each exposing state is a
  `git clone --shared` of the lane at `84904d41…` under
  `/fast/scratch/hyaku/tameshi-r92/T92M1/`, sparse-checked to `corpus/` and
  `.ufo/evidence/round-92/c1/` (12 MB per clone instead of 733 MB), verified with
  `git rev-parse --show-toplevel` before the first commit, one change committed under
  `ctl <ctl@fixture.invalid>`, and the staged path set asserted to equal the intended set
  (so a sparse checkout cannot silently delete files into the state).
- **Detector.** The frozen counter and the mutant counter run on **the same state clone,
  same rev, separate empty `--work` dirs**; the frozen receipt on that state is itself the
  baseline, and it is paid once per state, not once per mutant. Score: `KILLED` iff the
  exit code or stdout differs; `SURVIVED` iff byte-identical. **Baseline discipline:** every state's
  frozen receipt must show its pre-registered refusal (`C1_SETUP <token>`, exit 2) or the
  pre-registered false conjunct with `C1_R92_PASS=false`; a baseline that does not is
  `INCONCLUSIVE` and kills nothing. **Every baseline matched: 23/23 in the scored run,
  and the 2 states of the §5 probe; 0 inconclusive.**
- **23 state builds** in the scored run (21 from batch 1 + `spec-absent` + `fleet-replace`),
  one more (`timeout`) in the §5 probe.

## 4. What the kills say about the battery

The battery is load-bearing wherever a weakening shows up in the **printed receipt**: a
`C1_SETUP` refusal line, a `C1_CONJUNCTS` cell, a `C1_ROW` cell, the `C1_R92_PASS` line,
or the exit code. 25 of 30 weakenings change one of those, and the *smallest* edit is
enough (M16 changes one boolean expression; M10 deletes one clause; M12 deletes one
comparison). Two kills are worth naming to the L1:

- **M04 is the plan's own D01**, re-derived independently: same state class
  (`replace-honest`), same edit, exit 2 → 0 with `C1_R92_PASS=true`. My harness therefore
  agrees with the pre-freeze control receipt `pre-freeze/controls/D01.out` — the
  pre-registered expectation and this re-measurement do not diverge.
- **M27 shows a seam in the receipt**: forcing `sys.exit(0)` leaves the *text* of the
  receipt identical (it still prints `C1_R92_PASS=false`) and only the exit code flips.
  The frozen control driver scores on `exit=` **and** the PASS line, so it catches it —
  but any reader of the counter that trusts the exit code alone would not.

Read together with §4: **every refusal the claim leans on is killed — the self-pin (M01),
the spec pin (M02), the gate pin (M03), both replace seals (M04, M30), the gate-blob and
work-dir guards (M05, M06), the absent-spec receipt (M29) and each id-set rule
(M07–M11)** — while the five survivors are all conjuncts that no state built from the

and `unstable0` are *unfalsifiable as specified* — no control in
`pre-freeze/controls/` can ever refute those four checks, so their presence in the
predicate is an assertion, not a measurement. The `pre-freeze/controls/` table has no
`canary`, `green`, `unstable` or `inconclusive` row, which is the same fact seen from the
battery's side.

## 7. Residual limits of this probe

- **M30's state is not clean.** The fleet seal can only be poisoned in a *clone* of the
  fleet repo, and reaching that clone requires editing `gate.repo` in the spec — which
  changes the spec bytes, so both the frozen and the mutant receipt carry `spec=false`.
  The refusal (`C1_SETUP replace-refs-present:fleet`, exit 2) disappearing entirely is
  unambiguous, but the mutant's exit 1 is partly the spec pin, not only the removed seal.
- **The fleet replace list is empty on this host today** (`git -C
  /home/vgpnk/Projects/shokunin replace -l` → no output), so that seal is vacuous right
  now; M30 shows it is still load-bearing as a refusal.
- Checks **not** mutated, and therefore not claimed: `materialize()` (archive extract and
  `chmod`), `build_witness()`'s registry construction, `env_for()`/`run()` plumbing,
  `note_state`, the `C1_SUMMARY` count derivations (`killed`/`survived`/`witnessed`), the
  note parser's fence-skipping branch (candidate survivor: the frozen note carries no
  fenced verdict table, so no state here could expose it), and `git()`'s error path.
- Defect registration: batch 1 (`T92M1-defects.txt`, M01–M28) was written before any
  counter run. Batch 2 (`T92M1-defects-2.txt`, M29–M30) was written after batch 1 ran and
  before its own run; it is disclosed here rather than folded into batch 1. The `timeout`
  state in §5 is not a new defect — it is a second exposure for the already-scored M19.
- Scores are receipt comparisons, nothing more: a `KILLED` mutant is a control the battery
  would catch, not a statement that the counter is correct. `SURVIVED` is a coverage
  finding and does not license changing the claim.
