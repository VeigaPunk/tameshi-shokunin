## 3. What the matrix says

### 3.1 Branch 1 of (a) is unreachable with the frozen bytes

Kill rule (a) branch 1 requires "a committed state that does not hold the twelve true
verdicts" reaching PASS. With the frozen counter that state is not constructible from
note/README/SOURCES/lesson edits: the spec is pinned by `SPEC_SHA`, the gate by
`spec.gate.sha256`, both read from immutable object stores with `replace` refused, and
the derived column is identical across 14 unrelated commits (§2). The cheapest route to
PASS-with-a-false-note that exists is a *counter* mutant — the committed battery's own
`D01`, `D01D02`, `D03` each print `C1_R92_PASS=true` on a state the frozen bytes refuse
(`pre-freeze/controls/C1-summary.txt`). Those are kill rule (c) territory, not (a): they
require editing the instrument and recomputing `SELF_SHA256`.

A note on the plan's wording: "Any post-freeze edit of the instrument is inert: it
cannot print a verdict" is false as written — the plan's own mutant study recomputes the
pin, and `D03` prints a verdict. The self-pin is an *edit detector* enforced externally
by the sha256 in the plan (rule (c)), not an inertness property. This does not kill C1,
but the sentence should read "cannot print a verdict *unless its bytes also recompute
the pin, which rule (c) detects*".

### 3.2 Branch 1's parenthetical list is incoherent with branch 1's precondition

The list — "a second table, an escaped-pipe row, a fenced table, a hidden duplicate, a
prose verdict" — names presentations that leave the state **holding** the true verdicts.
A1, A2 and A3 demonstrate it: inverted verdicts in a fence, in HTML, and in prose all
reach `C1_R92_PASS=true`, because the keyed table is still true and the state does hold
the twelve true verdicts. So either the parenthetical is a list of non-kills (which
contradicts "any one kills C1") or branch 1's precondition is mis-stated. The plan's
declared limits pick the former for fence/HTML/prose — but then the kill rule and the
limits must not both stand as written. **Small correction:** move the whole parenthetical
into the declared limits, and let branch 1 read "a state whose *derived* verdicts are not
the twelve true ones".

### 3.3 Branch 2 fires — an honest note is refused (the kill)

A13 is the committed note with **its own §2b impact table reformatted** so that the id
is a cell of its own (`| C12 | used-by trim | 20 | 1695 false E11 findings … |`). No
content is added, no number changes, the twelve verdict rows are byte-identical to the
passing note's. The counter refuses it: `ids=false`, `badrows=5`, `mismatched=0`, every
other conjunct true, exit 1. A12 is the same defect with an appended table instead of a
reformat: `ids=false`, `badrows=5`, `mismatched=0`.

The refusal comes from the *stated* id-set rule doing more than keying verdicts: every
id-shaped row must carry exactly one verdict token, so a table that is merely *keyed by
id* and asserts no verdict at all is an error. That is precisely kill rule (a)'s second
clause — "an honest note is refused by a rule stated above". It is not a presentation
dispute about verdicts: there is no verdict in the refused rows to disagree about.

The committed note passes only because its §2b writes `C12 used-by trim` as a joined
cell rather than `| C12 | used-by trim |`. The certificate therefore depends on a
formatting accident of the 2026-11-06 draft, and the next honest note that keys an
impact table by id is refused. (This is the same class as A8/A9 — bold ids and
code-spanned verdict tokens are also honest cells refused — but A13 is the least
contestable instance: nothing is decorated, only column-split.)

A7 is a second, weaker instance of the same over-reach: the note's presented figure line
is correct, and a fenced *example* `measured:` line makes `figure=false`. The plan
declares fence-blindness only for tables, so this strictness is undeclared.

A5 (duplicate header) and A6 (dropped id) are refused honest-*ish* notes but are
malformed presentations; they are recorded, not counted as kills.

- **A11 source decoy passes.** S320 stays `mined` while the lesson's grounding is

- Both are decoy-satisfiable *by construction* of the predicate; neither is a rule (a)

## 4. Smallest safe correction

In `parse_note`, make the refusal key on **verdict content**, not on id shape:

1. A row that carries a verdict token — or any cell matching `(?i)\b(killed|survived)\b`
   — must be exactly one spec id, with exactly one token, in the header-named column
   (unchanged; this is the round-91 defence and must stay).
2. An id-shaped row with **no** verdict content is not a verdict row: ignore it, do not
   refuse it.

That keeps D03-class cheats refused (every lying table necessarily carries verdict
words, including lowercase ones under the new word test) and stops refusing honest
id-keyed impact tables (A12/A13). Alternative, if the strict rule is preferred: widen
the claim and the declared limits to say "any id-keyed table must be the verdict table,
and ids may appear in another table only joined to their description" — but then the
note's own §2b must be declared as the reason it passes, and a future impact table is
constrained.

For the adjacent weaknesses: `coverage` should require the citing row to be the
coverage-map/Core row (e.g. reject a row whose text says "not admitted"), and `source`
should require a quoted grounding phrase from the source in the lesson, not the id+URL
pair.
