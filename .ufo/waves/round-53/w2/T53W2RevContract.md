# Round 53 frozen kill-rule review

**Verdict: KILL-RULE-HOLE.** The negative base controls are evidenced, and amendments 1–5 are implementation/scope corrections, but the frozen C1 counter does not enforce its stated provenance predicate. The deciding run can therefore accept counter-visible evidence that is not the evidence the contract requires.

## Checks and evidence

- **Predicate agreement — not exact.** `contract.json` C1 requires a rekey entry “whose traces lie under” the rekey directory and whose `read_rev` “is the commit named by `<C0>`.” The frozen `c1/measure.py` implements `rekey_prefix()` by returning as soon as *any* trace matches a directory prefix (it never rejects other traces outside it), then checks `str(read_rev).startswith(c0)`, not equality to the commit identified by `<C0>`. It also accumulates every matching `c0` and does not enforce the docstring's “unique” rekey directory. Thus the counter's actual gate is weaker than the contract predicate. The C1 docstring describes the intended all-traces condition, but its implementation does not enforce it. C2 contract and `c2/measure.py` agree on the tool regex, selftests, CR47, and docs checks.
- **Do-nothing controls — hold.** Frozen `control/controls.stdout` records `CTL_C1_BASE ... verdict=false ... expected=false pass` and `CTL_C2_BASE verdict=false ... expected=false pass`, followed by `CONTROLS: total=2 pass=2`. The contract's target cannot be reached at base according to these committed receipts.
- **Amendments 1–6 — amendments 1–5 are scope/implementation-only; amendment 6 remains a hole.** `freeze.json` lists amendments 1–5 as NUL syntax repair / absent-evidence fail-soft behavior / stale-doc pattern correction / grep no-match handling / rekey scope and wording alignment. Their commit stats show changes confined to frozen contract/counter/control metadata as applicable; none changes the C1/C2 target or kill rule. Amendment 6 says it changes C1 to accept multiple rekey directories and bind reader evidence by section SHA only. Its diff modifies `c1/measure.py`, freeze metadata, and adds assimilation inputs; the counter change is within implementation scope, but it explicitly weakens the reader binding by not gating `cand`, and the multi-directory implementation does not enforce that each accepted entry's full trace set belongs to its corresponding rekey directory. (Contract wording already anticipates SHA-only reader binding, so that aspect is not itself a plan/counter mismatch.)
- **Known forgery coverage is incomplete.** `control/break-fixtures.py` covers removal of a trace, wrong reader SHA, altered `read_rev`, planted `/tmp`, and defeated CR47; `deciding-run.sh` runs C1/C2 and the no-harm/frozen-precheck/source-census gates. Those controls do not cover a mixed trace list (one trace under a valid rekey path plus an out-of-directory committed trace) or multiple rekey directories with ambiguous `read_rev` prefixes. These are counter-blind relative to the contract's stronger wording. The C1 code's `rekey_prefix()` accepts the former based on one matching trace, and `startswith(c0)` accepts any non-equal value sharing the abbreviated prefix. The stated attack matrix therefore misses live provenance forgery routes.

## Specific actionable finding

`c1/measure.py`, `rekey_prefix()` and the subsequent `good` filter: require **all** traces to be beneath exactly one accepted rekey directory and validate `read_rev` against the resolved commit identity (not merely a string prefix); add break-one controls for mixed trace sets and ambiguous/multiple rekey directories. Until the frozen counter and control set close this gap, the kill rule is not sound.
