**ADMIT — S304 (Git *git-diff*, the `--ignore-cr-at-eol` option).** Justified on
both halves of the plan's condition: the page is unheld at base (the `0` above;
the single `docs/git-diff` hit is S297's `git-diff-tree`, a different command
page), and the ground the row carries — "a comparison can be told to ignore CR at
end of line" — is unheld at base (`carriage` → 0). It is load-bearing for C2
rather than decorative: the claim has two classes (`append-only-raw` /
`append-only-content`), and the second class is exactly "a comparison that strips
CR"; without this row the lane would be using a git predicate whose semantics no
held source states. Flip to REFUSE: if the lesson stops citing the option as its
class ground (i.e. the `append-only-content` class is retired or re-grounded on a
different source), the row has no mining and must be refused as unmined.

**REFUSE — a new row for *gitattributes*.** Same URL, same document, already held
as S294 since round 63 → within-scope duplicate (the CORPUS rule-2 practice the
S289/S293 pair records). The correct curation delta is the re-open S294 now
carries. Flip: the S294 row is retired, or the page is superseded by a new
document (a successor page would then be a new row).

**REFUSE — a new row for `git-cat-file`.** The sentence under test also says
"`git cat-file` returns raw bytes"; that ground is already held as **S289**
(scope: "`--textconv` and `--filters` transform content, so a raw `cat-file blob`
comparison binds committed bytes"), and S293 is the standing rejection record for
the same URL. Flip: a distinct page whose object-inspection semantics S289 cannot
carry.

The seat's brief asked for one admit and one reject; the pair above is the one
that matters (S304 admitted, the gitattributes duplicate refused), and the
cat-file refusal is recorded because it is the clause of the target sentence that
a reader will look for a row under.

Reading: the rewrite is a byte event (every CR disappears, file shrinks), it is
invisible under the CR-blind comparison for LOG (0 deletions), and it is *not*

the C2 receipt prints (`raw_old_only=3484 norm_cr_old_only=0` vs
`raw_old_only=1593 norm_cr_old_only=5`) and it is derived here by git alone.

Population caveat, stated so nobody conflates them: my `numstat` deletions are
**line** counts at the parent→commit pair (3,759 / 1,920), the tool's
`raw_old_only` is a **set** predicate at the same pair (3,484 / 1,593), and the
lesson's "number note" compares against the round-73 closure's *range-view*
figures (3,759 / 1,915). I did not re-run the closure's command, so I do not
claim to have reproduced its 1,915; my own measurements neither add to nor
