## 3. Spec-format obstacles (measured, not inferred)

1. **The span-rule removal needs a two-line `@old`.** Spec v1 is one directive
   per line, so the guard's two physical lines must be written with `\n`
   escapes. Both forms count==1: with a trailing `\n` (my draft; clean
   deletion, no blank line) and without (what the committed spec uses; leaves
   one blank line inside the mutant body — still one hunk, still valid Python).
2. **The count==1 check is printed only on failure.** On success the helper's
   `APPLY OK id=… old-count=1 …` line is captured and discarded (run_sweep's
   `aout` is only printed in the `fail` branch), so a green sweep asserts
   count==1 implicitly. Failure path demonstrated (receipt
   `T74W1E3/count-check.log`):

```
APPLY FAIL id=count-zero-demo line=1 old-string-count=0 expected=1
MUTATE: SETUP (spec/preparation failed for 1 defect(s); no suite run)      EXIT=2
APPLY FAIL id=count-two-demo line=1 old-string-count=36 expected=1
MUTATE: SETUP (spec/preparation failed for 1 defect(s); no suite run)      EXIT=2
```

3. **Escapes are exactly `\n \t \r \\`.** Any other backslash aborts at parse
   (exit 2, before any mutant build). CR anywhere in the spec is refused, ids
   are `[A-Za-z0-9._-]+`, a description may not contain a tab, a bare `@new`
   line is the empty replacement (used for the span deletion), and `@new ==
   @old` is refused as a no-op. All three `@old` texts here are pure ASCII with
   no backslashes except the intended `\n`, so no escaping traps.

## 4. Fixture craft: which fixture shapes actually discriminate

Two out-of-suite probes import the pristine and each runner-built mutant and
drive the module's own `measure()` over the planned arm inputs (receipts
`T74W1E3/probe-arm-matrix.log`, `T74W1E3/probe2-boundary.log`). This shows the
three mutants are non-equivalent on exactly their named arm and nowhere else —
the property kill rule (ii) needs.

| file | arm13 (`11 reports`, printed 1) | arm14 (`13 seats`, printed 13) | arm15 (nested `.md`, printed 12) |
|---|---|---|---|
| pristine | `setup:printed-not-in-span` | `setup:span-not-in-record` | `meet printed=12 files=12` |
| delimited-tautology | **`drift printed=1 seats=12`** | `setup:span-not-in-record` | `meet printed=12 files=12` |
| span-rule-removed | `setup:printed-not-in-span` | **`drift printed=13 seats=12`** | `meet printed=12 files=12` |
| seat_reports-any-depth | `setup:printed-not-in-span` | `setup:span-not-in-record` | **`drift printed=12 files=13`** |

Two constraints a fixture author must respect, each measured:

- **arm14 must carry `printed: 13`.** Without a `printed` value the
  span-removal mutant does not proceed: it refuses at the next guard
  (`setup:record-printed-absent`), so an arm expecting `setup` passes and the
  mutant is **not** killed. With `printed: 13` (delimited inside `13 seats`)
  the only reason for refusal is the deleted span guard.
- **arm15's listing entries must sit under the row's wave dir.** Top-level
  counting is `p.startswith(prefix)` with `prefix = dir + '/'`, and `GitReader`
  returns repo-relative paths. A listing whose entries are `x/…` under row dir
  `wave` yields `files=0` for pristine **and** for the any-depth mutant (both
  `drift`), i.e. no discrimination. A nested fixture must be
  `wave/…/deep.md` beside 12 top-level `wave/….md`. This is not academic: the
  base suite's `SEAT_FILES` were `x/…` with row dir `wave`, and arm3 measured
  `drift` from `files=0` (probe: `arm3-shape=measured:drift printed=11 files=0`).

arm13 discriminates under either kind (`seats` or `seat_reports`); measured
`setup` on pristine vs `drift printed=1 files=12` on m2 for `seat_reports`.
