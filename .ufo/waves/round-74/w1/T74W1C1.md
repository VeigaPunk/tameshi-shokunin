**Sizing.** 3 new arms on a 12-arm suite, each with a distinct mutant that no

The class name is not a second definition: for `raw_old_only = 0` ⇒
`norm_cr_old_only = 0` (normalization is a function applied line-wise, so

`--require-raw` sum (`raw + norm`) have identical verdicts. Verified on all six
rows (both predicates agree). No duplicate-authority defect there.

What the new tool genuinely adds: **range walk × additivity measurement**, plus
a judged claim class and `expect` per row. Neither existing tool measures that
combination. So the capability row is *conceptually* new. The question is
whether this manifest demonstrates it.

### 2.4 Two derived numbers a reader will get wrong

1. **`ADDRANGE_TOTALS raw_old_only=8561` double-counts LOG.** It sums the
   per-commit row (3484) *and* the pair row (3484) over overlapping ranges. The
   union for the declared files is `3484 + 1593 = 5077`. The docstring and the
   lesson call the line "derived populations"; it is a sum over overlapping
   ranges, not a population. A reader can cite 8561 as "lines the round
   removed" — false by 3484.
2. **`walked=` is the changed count, not the walked count.**
   `row_measure` returns `len(rows)` and `sweep` calls
   `detail_of(measured, m, n, n)` (`tools/additivity-range.py:234,237,268,275`),
   so `walked=` and `changed=` are the same number. Measured on the 24-commit
   range: the tool prints `walked=4` (the changed count) for a walk of 24
   commits. The frozen six rows cannot reveal it (all are width 1). A patched
   copy that returns `(len(revs), len(rows))` prints `walked=24 changed=4` and
   its output on the frozen manifest is **byte-identical** to the committed
   tool's (verified by `diff`), so the fix is inert to every frozen counter.

Also imprecise: the manifest notes say "33 / 20 / 58 new lines" where
`git show --numstat` says `35 / 22 / 70` for the same commits. The metric is the
non-empty **set** difference (`raw_new_only`), which drops blank and duplicate
lines; the note should name the metric, as the lesson's "number note" does for
the removed counts.
