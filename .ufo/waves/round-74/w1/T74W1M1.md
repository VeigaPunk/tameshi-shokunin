## 1. Instrument

`pristine.py` + three arms authored from the plan's frozen table, `SELFTEST_ARMS
12 -> 15`. Diff is additive only (no existing arm line touched):

```python
NESTED_FILES = ['x/nested/deep.md']
REPORTS = (b'- The wave committed 12 reports; one nested note sits under it.\n')
CLAIM = (b'- The wave: 11 reports; 1 seat filed late.\n')
# listing: (REV,'x') = SEAT_FILES + NESTED_FILES

def _arm13():                       # span '11 reports', printed 1 -> setup
    span = '11 reports'
    if span.encode('utf-8') not in REPORT: raise SetupError('arm13-fixture-precondition:span-absent')
    if re.search(r'(?<![0-9])1(?![0-9])', span) is not None: raise SetupError('...:printed-delimited')
    return measure_row(kind='seats', record={'path':'report.md','rev':REV,'span':span,'printed':1})

def _arm14():                       # span '13 seats' absent -> setup
    return measure_row(kind='seats', record={'path':'report.md','rev':REV,'span':'13 seats','printed':13})

def _arm15():                       # 12 top-level .md + x/nested/deep.md -> meet
    return measure_row(kind='seat_reports', record={'path':'reports.md','rev':REV,'span':'12 reports','printed':12},
                       wave={'dir':'x','results':'results.json','rev':REV})
```

Each arm carries an **independent fixture precondition** that re-derives its
input with `re`/byte scans (never by calling `delimited`, so a mutant of that
function cannot satisfy its own precondition). `_arm15` asserts the any-depth
count is 13, so a degenerate fixture fails the arm instead of passing it.

`armed_sharp.py` is identical except `_arm13`'s record is `claim.md` (the base
`REPORT` plus a delimited `1` **outside** the span) — the diagnostic variant in
§4.

## 5. M-C: the surviving mutant, and the fixture change that kills it

M-C is behaviour-bearing, not a no-op — the acceptance widening is real:

```
span='11 reports', printed=12   (12 occurs delimited elsewhere in the record)
pristine  -> SetupError -> printed-not-in-span:sev
M-C-on-15 -> ('meet', 'printed=12 seats=12 records=12')      # a forged row reads green
```

Yet it survives all 15 arms **because of the arm13 fixture, not the rule**:
the base `REPORT` (`- **The wave**: 12 seats, 11 reports; ...`) contains no
delimited `1` anywhere, so on arm13's input M-C raises the *same*
`printed-not-in-span` as pristine and the arm cannot tell them apart. Proof:
asserting the SetupError *reason string* would not close this gap (M-C emits
the identical reason on the base record).

With the sharp record (`- The wave: 11 reports; 1 seat filed late.`) the same
mutant is caught by arm13, with no collateral damage:

```
armed_sharp        -> 15/15 pass
M-C-sharp-on-15    SELFTEST arm13-printed-undelimited-refused    FAIL (got=drift want=setup)   (14/15)
M-A-sharp-on-15    SELFTEST arm13-printed-undelimited-refused    FAIL (got=drift want=setup)
```

**Recommendation for the L1 (fixture-craft, within the frozen plan text):**
arm13's record must carry a delimited occurrence of `printed` **outside** the
span; otherwise the arm only guards "delimited", not "inside the bound span",
and one full rule half stays unmeasured. The plan freezes span/printed but not
the record blob, so this is a fixture choice the L1 can make.
