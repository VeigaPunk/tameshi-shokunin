## 1. Registry schema and field semantics

`tools/registry.json` is `{"schema": "tameshi-entry-registry-v1", "rows": [...]}`,
60 rows (53 `active`, 7 `superseded`; kinds: 31 `selftest`, 25 `gate`, 4 `probe`).
Row fields in use: `name, kind, argv, expect, timeout_s, source, status, tags`
plus optional `scratch_root, superseded_by, external`.

The validator is `registry_errors()` at `tools/registry-check.py:180-306`:

| field | what the checker actually does with it |
|---|---|
| `name` | `^[a-z0-9][a-z0-9-]*$`, unique across all rows (`:210-218`) |
| `kind` | one of `gate`, `probe`, `selftest` (`KINDS`, `:15`) |
| `argv` | non-empty list of non-empty strings; exec'd with `shell=False` (`:222-230`, `:661-668`) |
| `expect.exit` | **required** integer; `bool` rejected (`:239-244`) |
| `expect.stdout_contains` | optional list of strings; each must be a substring of the **whole** stdout, not the tail (`missing = [n for n in needles if n not in stdout_text]`, `:695`) |
| `timeout_s` | finite number in `(0, 86400]`; NaN/Infinity literals refused at parse (`:245-268`, `MAX_TIMEOUT_S`) |
| `source` | **format only**: `SOURCE_RE = ^[^@]+@[0-9a-f]{7,40}:[0-9]+(-[0-9]+)?$` (`:23`, `:257-263`) — never opened, never resolved, never compared to `argv` |
| `status` | `active` / `superseded`; a `superseded` row **also runs** and must carry `superseded_by` naming an existing **active** row (`:270-300`) |
| `tags` | list of non-empty strings, free vocabulary (`baseline`, `new-rNN`, `fleet-live`) |
| `scratch_root` | **documentation prose, never read by any tool.** 8 rows carry it; e.g. `repeat-control-selftest` narrates the round-53 scratch-root refusal grammar. No `scratch_root` string appears outside `registry.json` in `tools/` or `scripts/` |
| `external` | bool; when `true`, a row whose argv names an absolute path under the **live fleet root** is allowed under `--rev`; otherwise it is reported `non-hermetic` and differs (`_argv_outside_fleet`, `:632-646`, `:661-678`) |

Run semantics (`registry-check.py:26-40`): every active **and** every superseded
row runs, `cwd` = lane root (or the `--rev` clone root), stdin `/dev/null`,
shell=False, scrubbed `GIT_*` env plus no-bytecode env, descendants killed at
timeout. Exit map: `0` every row held · `1` a row differs · `2` could-not-evaluate
(registry unreadable/invalid, root/rev miss, clone failure, `--only`/`--tag`
miss) · `64` usage.

**Measured consequence (test C below): the `source` anchor is never checked.**
A row with `source: "SKILL.md@0000000:999999"` — a valid-shaped anchor naming a
nonexistent revision and line — validates and its run reads
`REGISTRY_CHECK: held=1/1`, exit 0. Honesty of the anchor is entirely on the
author; the checker cannot catch a dead one. (The standing `anchor-drift-sweep`
does **not** cover this: it sweeps `corpus/SOURCES.md` HTML heading anchors,
`tools/anchor-drift-sweep.py:1-45`, schema `tameshi-anchor-drift-v1`.)
The only other programmatic reader of the registry, `tools/registry-replay.py`,
projects each active row to `{name, argv, expect}` (`:142-144`) and drops
`source` — so `source` has no consumer anywhere beyond the format check.
