## F4 — absent, false absent from whitespace/locate artefact

Command: `locate` test on FREEZE blob `.ufo/evidence/round-77/sources/s305-ls-tree.html` (receipt `R100E3-receipt-locate-mechanism.out`).
Rendered line 1609: `'directory name (without   -r  ) will behave differently, and order of the'`.
`locate(quote="directory name (without -r) will behave differently")` = `[]`; after collapsing the paren-space only, `locate` = `[(1609, 1609)]`. `_bare(")")` = `''`.
Mechanism: `strip_tags` leaves a lone `)` token (and `,` in round-88:46) separated by spaces from `<code>` boundaries. `locate` splits on whitespace, `_bare` reduces the lone punctuation to an empty string, and the word sequence breaks. The verbatim quote is therefore `absent` though present.
Affected: `round-77.md:70` (quote `directory name (without -r) will behave differently`, cited 1664, present at 1609) and `round-88.md:46` (quote `Return True if the binary data starts with the specified prefix, otherwise return False.`, cited 4175, present at 4145-4147 with a lone `,` token). Both are the same mechanism.
Verdict: the docstring sentence "absent — the quote is not located anywhere in the rendered snapshot" is `falsifies-wording` for the tool (the quote is located nowhere by `locate`, yet is present verbatim). Frozen C2 numbers: `neutral` (in-set absent=0 is unaffected).

## F5 — absent, wrong span and wrong snapshot binding (lesson round-89)

Commands: `python3 -I gate-line-recheck.py ... --record corpus/lessons/round-89.md` (see per-file receipt) and `extract_quotes`/`classify` (receipt classify).
Round-89's Gate table has the S313 (execve), S314 (strace) and S315 (Licker & Rice pdf) rows in one markdown block. Observed:

The intended quote `"many attributes of the calling process remain unchanged (in particular, its PID)"` (12 words, line 463-464) sits before the pointer and is never extracted. The snapshot line 463 holds that quote (receipt handread/locate).
- `round-89.md:20` cited 254: quote `Prints paths associated with file descriptor arguments and with the AT_FDCWD constant.` (an S314 quote) is graded against the S313 html. Absent. The S314 snapshot is `…/sources/strace.1.html`, containing `…`, so `SNAP_RE` does not match it and the binding falls back to the nearest earlier explicit token, S313.
- `round-89.md:21` cited 933 and 865 (S314 quotes; `Prints unabbreviated versions...`, `Detecting Incorrect Build Rules`): absent. Same binding fallback; the second quote is the S315 title, which is not in any html snapshot.
- `round-89.md:23` cited 332: `some edges might be missing from the recovered graph` (S315, a `.pdf` snapshot). The `.pdf` does not match `SNAP_RE`; binding falls back to S313 html; absent.

Root causes (both in the tool's declared grammar, not in the lesson's quote text):
1. Quote extraction takes the span after the pointer, but the round-89 authoring puts each quote before its pointer.
2. A whole markdown table is one block, so one `sid` (first `S###` in the block = S313) and one explicit-snapshot fallback serve every row.
Verdict: the docstring sentence "the last backticked token before the pointer in the block ... ends .html/.htm/.json" and the block grammar together mis-bind cross-row pointers. The tool's `absent` is then not "quote not in the cited source", so this is `falsifies-wording` for the grammar sentences the plan delegates to the docstring ("quote extraction is the declared three-step rule"; "snapshot ... explicit"). Frozen C2 numbers: `neutral` (round-89 is out-of-set).
