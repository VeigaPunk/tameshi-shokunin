## F3 — "4395" vs "4396" for "a single header row": grammar choice, not arithmetic error

Command: `R100RV1-receipts/R100RV1-grammar-4395-4396.py` (output `…-4395-4396.txt`, rc=0). Canonical text:

```
4395 ' A  table  is an arrangement of data with rows and columns, consisting of a'
4396 'single header row, a  delimiter row  separating the header from the data, and'
4397 'zero or more data rows.'
```

- The 13-word quote `a single header row, a delimiter row separating the header from the data` → `locate` = **4395-4396**.
- The 19-word quote (the round-95 Gate's sentence) → `locate` = **4395-4397**.
- The bare phrase `single header row` (3 words) → **4396**.

The tool's declared rule (`tools/gate-line-recheck.py` docstring; the `locate` first-token rule) takes the line of
the quote's **first word**. The first word `a` ends line 4395, so the start is 4395. The closure D1 (round-95
spot-check, `corpus/lessons/round-95-verifier-spotcheck.md:177`) wrote 4396, which is the line of the word
`single`, i.e. it skipped the article. The round-96 lesson's `4395-4396` for the 13-word quote agrees with the tool.

**Verdict:** grammar choice. Both 4395 and 4396 are defensible readings; the tool's declared grammar says 4395.
The lesson and tool agree; the D1 text does not. Not a falsifier of C2's count, since the cited 4393 misses under
either reading.

## F5 — the renderer-choice control: sentence check

Claim sentence (plan §C2 control): "under the round-95 Gate's own literal convention (no script/style removal) all six
are still misses … the miss is not an artefact of renderer choice."

Command: `python3 -I r95-stated-renderer.py <lane> f8f912dfd569a33fade039af605f55cec15b921a`
(`R100RV1-receipts/R100RV1-c2-stated-renderer.txt`, rc=0): `pointers=6 hit_under_stated=0`; stated spans
4512 / 4504-4506 / 4605-4606 / 2723-2724 / 2463-2464 — all miss.

- Supported: the stated convention misses all six, and F1 shows *ten* other renderings (line-based, joined,
  block-to-newline, body-relative, round-93/94 dumps) miss all six too. No renderer reproduces the cited values.
  "Not an artefact of renderer choice" is therefore the right conclusion, and it holds more broadly than the
  control's two renderers.
- Limit: the control proves only that the cited numbers are not recovered by any renderer tried. It does not
  identify where the numbers came from (F1 provenance). The plan's control text should not be read as showing the
  canonical renderer is the one the Gate used.

**Verdict:** `neutral` — the frozen control sentence holds; the limit is the source of the numbers, not the renderer.
