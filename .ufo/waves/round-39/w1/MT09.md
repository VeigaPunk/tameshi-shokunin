## Coverage finding (survives; reported, not fixed)

The truth of "only S105 and S106" is basis-sensitive. Against the *final*
`validated-SOURCES.md` registry (which this round appends `S107`/`S108` to), the
same staged set yields four hits:

```
staged&reg_ids        = ['S105', 'S106']
staged&final_registry = ['S105', 'S106', 'S107', 'S108']
final_registry minus reg_ids = ['S107', 'S108']
```

So the claim holds only against the pre-adoption `reg-ids` snapshot (103 ids),
which is the correct basis — `S107`/`S108` are the ids being assigned *this*
round, and counting them would make the collision file self-defeating. A naive
checker reading the appended registry would report `mismatches=1` on correct
bytes. Not a contract change; the file's own basis is sound.
