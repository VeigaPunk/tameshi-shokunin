## 3. Findings

### F1 — C1 cannot detect the loss of the ninth ledger leg (depth, critical)
`guard/measure.py:73-77` evaluates the *contract* regex and its own hardcoded
`COMMAND_D` (`measure.py:17`) against the *same bytes* and compares only the
counts. Deleting a ledger row moves both sides from 9 to 8 in lockstep, so
`live_agree=1` and `C1_R39_PASS=true` (M5). The frozen C1 predicate
(`contract.json:13`) contains no absolute `depth_score == 9` conjunct — the
"Depth stays 9" assertion lives only in the free-text note at
`contract.json:8`. Consequences, both demonstrated, not inferred:
- the guard is **one-sided**: it rejects a *regex mismatch* (M3), not a depth
  regression; drop a leg and it stays green;
- growth is invisible past the cap: 12 rows read `depth_score=10` (M4, D),
  so unimplemented claimed legs are indistinguishable from implemented ones.

`stripped_agree` cannot fail either: `measure.py:37` strips with the same
`COMMAND_D` whose count it then compares, so that arm is `0/0` vs `0/0` for
every possible runner (MT04's construction, reconfirmed here).

This is a coverage finding against the calibration axis, not a request to edit
the predicate.

### F2 — "canonical SCORECARD command D" is never read
`measure.py:17` hardcodes the pattern; nothing in `guard/measure.py` opens
`SCORECARD.md`. M2 changes the documented command D at `SCORECARD.md:73` so it
prints `recorded_cases=5 depth_score=5`, and C1 still prints
`C1_R39_PASS=true … live_agree=1` with 9/9. The "agrees with canonical
SCORECARD command D" conjunct is therefore agreement with a private constant.
At this rev the constant and `SCORECARD.md:73` do agree byte-for-byte, so the
finding is a latent gamability, not a present mismatch.

### F3 — the score is a comment census; runner behavior is outside it
M-C flips the run path's `exit 0` → `exit 2` (`tools/mutate-and-run.sh:578`,
documented map `:77-79`). Command D prints the byte-identical `9/9`. The
runner's own `--selftest` catches it (33 FAILs, first `FAIL sweep exits 0`,
`MUTATE_SELFTEST: 73/106 pass`, rc=1). So `depth_score` measures documented
ledger breadth — which `SCORECARD.md:66` states — and a depth witness built
only on command D carries no behavioral signal about the runner it scores.

### F4 — stale citation
`SCORECARD.md:66` cites `tools/mutate-and-run.sh:84-89` for the ledger; the
nine rows are at 87–95. The round-31 row (`SCORECARD.md:1536`) cites 87–95
correctly. Documentation drift only.
