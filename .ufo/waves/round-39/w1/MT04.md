## Depth finding — the stripped leg is tautological
1. `.ufo/evidence/round-39/guard/measure.py:36-38` builds the stripped copy by
   deleting every line for which `COMMAND_D.match(line)` is true; `:75` then
   counts the *same* `COMMAND_D` over the remainder. The remainder cannot
   contain a `COMMAND_D` match, so `strip_d=0` for **any** input bytes. The
   `stripped_agree` conjunct (`:100`) therefore only tests "the guard regex
   matches nothing outside the removed lines" — never that the guard tracks
   ledger depth.
2. The contract's `no_harm_guard.depth_command_d_regex`
   (`^#   (?:js|bash)-\S+\s+\S+\s+\d+/\d+`) is **byte-identical** to the
   canonical command D regex in `SCORECARD.md:73`. With `guard_re.pattern ==
   COMMAND_D.pattern`, `live_agree` (`:99`) and `stripped_agree` (`:100`) are
   equality-of-a-count-with-itself and are `1` for arbitrary runner bytes. The
   C1 depth no-harm leg cannot fail on either leg for reasons tied to runner
   content.
3. Consequence: the `0` above is not a property of the runner; it is a
   property of `strip_ledger`. A guard that dropped case lines, or a runner
   whose ledger moved into another form, would still print `0` and still
   "agree." A discriminating control needs an independent strip definition
   (e.g. strip by section boundary/line range, or count a *different*
   predicate), not the pattern under test.

This is a coverage finding about the frozen predicate. Per the contract's kill
rule no predicate text was altered, and no deciding run was made.
