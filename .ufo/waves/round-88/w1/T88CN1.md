### 1.3 Which class repeats, which is new

**Repeats — (a) reported-but-unasserted (`S_OFFSET_EQ`).** The class is the ledger's most
populated one (kimi D2/D10, kagi B10, tsukuroi B9, mado D3/D8, checklist C1/F2, claims D7,
sources-check's count/index fields). The sub-shape is new but cheap: the unasserted value is the
*suit's own diagnostic print* ("first divergence at byte N", `ledger_append_guard.py:114-115`),
not the gate's report. Repair cost is one assertion on a value the selftest already computes —
the cheapest (a) repair in the ledger.

**Repeats — (b) unreached fixture/boundary edge (`S_HEAD_SHORT`).** Exact precedent: cite-check
`S_OOR_EDGE` (`> n` → `> n+1`, survived 62/62, `mutation-case-kumitate-cite-check.md:53`). The
*defect family* — a comparison window one byte short — also appears as kagi-census `B6`
(`head -c len+1` → `len`), which was **KILLED** (`mutation-case-kagi-census.md:72`). So this is
the ledger's clearest instance of an outcome flipping on fixture posture alone: same family,
killed in leg 2, survived in leg 11, because leg 2's fixture carried the length boundary and
leg 11's two fixtures edit interior bytes only.

**New to the ledger — (e) population arity / quantifier width (`S_OK_ALL`, `S_VACUOUS`,
`S_RED_FILES`).** No earlier survivor is an edit to an n-ary fold over a set: the ten legs'
(b) instances are *species/branches* never constructed (exec bit, PCI branch, tomllib arm,
tracked-mode site), (a) instances are values never asserted, (c)/(d) are direction/exit
vocabulary. The closest neighbours are kagi B10 and sources-check `S_ENTRY_COUNT` (a single
counter value) and cite-check `S_STRICT` (a threshold) — none folds a collection. Leg 11's guard
quantifies over `root.glob(GOVERNED_GLOB)` (`ledger_append_guard.py:32,47,78`) and its selftest
builds exactly **one** ledger in **one** tree (`:88-112`), so three separate conjuncts that only
bite at |S|≠1 are inert: the n-ary `and` (|S|=2), the `any(compared)` guard (|S|=0), and the
`files == 1` conjunct in `red` (|S|=2).

**Contradiction, named rather than smoothed.** Under a maximal reading, (b) "unreached
fixture/arm" swallows `S_VACUOUS` (the zero-cardinality input is an arm the suite never builds),
and arguably `S_OK_ALL`/`S_RED_FILES` too (every missing input is an unreached arm). I keep (e)
separate because the **repair recipe differs**: (b)'s documented repair is "add one case per arm"
(`fleet-kill-rate-ledger.md:148-150`), whereas these holes need *population variation plus result
ordering* — and a naive second ledger does **not** kill `S_OK_ALL`: the probe's negative control
F1b (same pair, edited ledger sorting **last**) reads `pp=False` on the mutant too, because
`ok_all = ok` keeps the last verdict. Fixture order is part of the fix. If the L1 prefers the
maximal reading, fold (e) into (b) and keep the ordering rule as the sub-shape note; the
measurements do not change either way.

### 1.4 Cross-leg patterns worth carrying (two, both measured)

1. **Same expression, two asserts, one covered.** `res["files"] == 1` is load-bearing in the
   append check — `K_FILES_EQ` (1 → 2) was KILLED — and merely redundant in `red`, where the same
   conjunct is unpinned (`S_RED_FILES` SURVIVED). The suite pins the fixture's arity in one place
   and leaves the identical predicate free in another. This is a *duplicate-predicate* hole, not a
   new class; the probe shows one two-ledger fixture closes it.
2. **Class concentration tracks suite size, not defect class.** Leg 11's suite is 2 checks — the
   smallest in the ledger (next: drift-pins 13, kagi 16) — and its hole-aimed half all survived,
   exactly as composition predicts. With only two fixture shapes (append / interior edit), the
   survivor set is precisely "everything outside those two shapes": 4 of 5 survivors are input
   shapes, 1 is an unasserted computed value. [INFERENCE] The 50 % rate is therefore not evidence
   about the guard's quality; it is evidence about a two-fixture suite, consistent with the
   fleet's composition rule (`fleet-kill-rate-ledger.md:136-141`).

## 4. Risks and limits

- The probe evaluates the *pristine and mutant functions* on the missing inputs, plus the selftest
  expression for `S_RED_FILES`; it does not run a patched end-to-end selftest. The fix table is
  therefore "the check discriminates the mutant on that fixture", not "the landed selftest prints
  N/N" — the latter is kake's to measure after landing.
- `S_VACUOUS`'s kill depends on a semantic decision about the empty tree; the probe pins today's
  reading. If kake declares emptiness clean, the survivor becomes equivalent and must be recorded
  as an equivalence argument, not counted as a hole.
- The (e)-vs-(b) split is a repair-recipe distinction, not a measurement; §1.3 names the
  contradiction and the fold-in alternative.
- Fixture order is load-bearing for K3 (negative control F1b): a two-ledger fixture whose edited
  ledger sorts last does not discriminate `S_OK_ALL`.
- Suite counts for legs 1–10 are the case notes' readings, not re-measured here; the "smallest
  suite" statement is an [INFERENCE] from those notes plus `sweep.txt`'s `2/2`.
