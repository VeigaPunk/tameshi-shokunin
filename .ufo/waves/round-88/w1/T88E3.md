## 5. Risks and observations

1. **`repo=` echoes the fleet root you pass.** Every `REGRESSION_PIN` line prints the
   resolved repo path, so a receipt taken from a copy of the fleet has different `PIN`
   bytes from one taken at `/home/vgpnk/Projects/shokunin` even when `rev`/`path`/`mode`/
   `sha256` are identical. Harmless for the claim (the counter pins blobs by sha256),
   but any future tool that byte-compares historical `REGRESSION_PIN` lines across
   fleet roots will report a false difference. Normalize before diffing.
2. **Sibling working trees are dirty for reasons outside this seat.** Observed after
   my runs: `kagi-shokunin` 20, `kumitate-shokunin` 19, `tsukuroi-shokunin` 6,
   `mado-shokunin` 5, `kake-shokunin` 0 porcelain lines (plus the lane's own wave
   files). I did not create or attribute them; the ledger reads pinned blobs from the
   git object store (`git show`), so working-tree drift does not touch the ten
   reproduced tables. I wrote only under my scratch and this `w1` directory (no lane
   tracked file was modified by me; two `corpus/` edits by other seats appeared after
   my final provenance reading).
3. **`--regression` leaves ~1 work dir per leg under `--workdir`** (`--keep` was used so
   the leg workdirs stay inspectable; without `--keep` a PASS run removes them). Mine
   were inside the seat scratch and are gone with it, so the `REGRESSION_WORKDIR` paths
   in `T88E3-regression-candidate.out` no longer exist — re-running the harness
   recreates them.
4. **Residual, out of item scope:** the new leg needs `python3` in `PATH` inside the
   `env -i` sandbox; if it were absent the leg would refuse as SETUP and the tally would
   print `cannot-verify`, not PASS. I did not test that path (it is a claim-domain
   question for the counter, not a no-harm question), and nothing here depends on it.
5. **Timing:** one counter/regression replay is ~160–170 s on this host (eleven legs of
   10–15 mutants each, plus the new leg's 20 sandboxed selftest runs). Budget
   accordingly if the L1 re-runs the harness from committed bytes.
