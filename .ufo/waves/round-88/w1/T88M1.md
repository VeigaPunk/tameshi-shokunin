## 3. Which checks are load-bearing, and why

The frozen predicate is a conjunction, `legs=11 ∧ python_legs=1 ∧ prereg=ok ∧ runner=PASS`. A counter
check is only *observable* if some variant satisfies every other conjunct while the check is the sole
refuser. Mapping each check against its analogue inside the runner (`tools/mutate-and-run.sh`, checked
in both the base blob and the candidate `28ec5885`: identical counts of every analogue site) explains
all six kills and both survivors:

| counter check | analogue in the runner (`--regression`) | outcome |
|---|---|---|
| suite allow-list (M2) | none — the runner runs whatever suite the leg names | **load-bearing** → KILLED by the diff-oracle `cmp` |
| duplicate-target (M3) | none | **load-bearing** → KILLED by `dup11` |
| prereg sha256 (M4) | none | **load-bearing** → KILLED by `unprereg`, which is exactly the shape the check exists for |
| `killed >= 1` (M6) | partial: killed-delta is measured against the *recorded* killed count, so an all-SURVIVED table passes | **load-bearing** → KILLED by `inert` |
| `agree == n` (M5) | full: `flips == 0` with `ftol = 0` is the same predicate over the same table | shadowed → only a **lying** runner exposes it (`forged`) |
| pinned-blob sha256 (M8) | full: `regression_case` prints `SETUP (pin mismatch …)` and returns 2 | shadowed → only a **lying** runner exposes it (`lie-badpin`) |
| sibling-repo top-name (M1) | partial: the runner's own scratch fleet has `tameshi-shokunin` as a bare dir, so its repo-identity check refuses lane targets too | shadowed twice (see §4) |
| INCONCLUSIVE ≠ table (M7) | full: `inconclusive > 0` is always a FAIL reason | shadowed and unfundable (§4) |
| repo identity / `rev is a commit` | identical | shadowed |
| `lane-authored-rev` (`%ae` must not contain `tameshi`), `rev on refs/remotes/origin/*` | **none** | load-bearing in principle; **not exercised by any of the eight assigned mutants** (they guard checks my mutants did not touch) |

Two consequences worth carrying into the claim's own record:

1. The counter's independent replay, not the runner, carries the *allow-list*, *duplicate*, *prereg* and
   *kill-floor* checks. Those four are exactly the four fields a forger would have to fake to pass, and
   they are the four the corpus's `forged`/`doctored` controls were aimed at.
2. Conversely, `pin`, `agreement` and `inconclusive` are shadowed by the runner *when the runner is
   honest*. Their value is real but conditional: they are the only defence against a variant like the
   sibling seat's `parked`/`stub` (runner prints the PASS line without executing the leg — see
   `T88E2.md` rows 1 and 3). `lie-badpin` is the minimal composite that demonstrates this: a correct
   prereg leg, a pin that names no blob, and a runner that prints the frozen PASS line. The frozen
   counter refuses it at `pin-mismatch`; M8 prints `C1_R88_PASS=true`. Removing any one of the three
   ingredients (M8-badpin, M8-forgedbadpin) leaves the predicate false.

## 4. The two survivors: no control can be built, not merely none exists

**M1 — the `tameshi-shokunin` top-name check is redundant.** To reach `C1_R88_PASS=true` the counter must
count exactly one Python leg whose spec is the pre-registered spec (`prereg=ok` requires
`spec_sha == PREREG_SHA` = `724beed3…`). That spec's `@old` strings exist once in
`kake-shokunin/scripts/ledger_append_guard.py@e8d3a924` and nowhere else, so the counted Python leg's
target cannot be a `tameshi-shokunin/…` path: a runner variant can add legs but cannot add blobs to the
lane. Independently, the very next check, `real == lane_real`, refuses any `tameshi-shokunin/…` target
because that target resolves to exactly `--repo` (`measure.py:174-178`, `[ANALYSIS]` — the code path is
two lines below the one M1 deletes). The lanetarget run shows the third layer in practice: the leg dies
at `rev-not-commit`, because the kake rev `e8d3a924` is not in the lane's object store
(`git cat-file -t e8d3a924…` in the lane: *could not get object info*). So the check is defence in depth,
not a defence: three independent layers, none of which a counter variant can remove.
*Control that would expose it, if the constraint were relaxed:* a leg whose target lives under the lane
directory and carries the pre-registered spec — impossible without editing the lane or the frozen spec.

**M7 — `INCONCLUSIVE` as agreement cannot be driven.** `verdict()` returns `INCONCLUSIVE` only for exit
124 (timeout, 120 s) or 126/127 (suite not runnable), and the replay environment is the
`sandbox`-prefixed allow-listed suite run through `bash -c`. A mutant's exit code is a function of the
**pinned blob** and the **byte-frozen spec**: the target is materialized from `git show rev:path` and
checked against its pin, so no runner variant can inject a sleep, a missing interpreter, or any other
non-zero-124/126/127 behaviour. Empirically the pinned guard is conclusive on all ten defects in every
counting run (`agree=10/10`, `killed=5` — e.g. `T88M1-out-FROZEN-dup11.txt`), so no `INCONCLUSIVE` ever
arises. And if it did, the runner's own `inconclusive=%s` reason (`regression_case`) would set
`runner=FAIL`, leaving the predicate false.
`T88M1-out-predicate-probe.txt` shows the exact predicate delta M7 introduces:

```
M7 agreement: if v == table[d["id"]] or v == "INCONCLUSIVE":
  INCONCLUSIVE / KILLED     | frozen agrees=False | M7 agrees=True   <-- differs
  INCONCLUSIVE / SURVIVED   | frozen agrees=False | M7 agrees=True   <-- differs
```

*Control that would expose it:* a Python sibling gate, committed at a pinned rev, whose `--selftest`
exits 124 on one mutant of the pre-registered spec. That is a different program, not this claim's gate.

For completeness the same probe shows what M5 and M6 change, and how narrow those inputs are:

```
M5 counting: if out["agree"] <= out["n"] and out["killed"] >= 1:
  agree 0 n 10 killed 5 | frozen=False | M5=True   <-- differs   (doctored/forged input)
  agree 10 n 10 killed 0 | frozen=False | M5=False  (killed>=1 still refuses)
M6 counting: if out["agree"] == out["n"]:
  agree 10 n 10 killed 0 | frozen=False | M6=True  <-- differs   (inert input)
```

## 5. What this does and does not say about R88-C1

Kill rule (b) asks whether a runner variant that does not add a real, independently reproduced Python
sibling-gate leg can print `C1_R88_PASS=true`. Nothing here changes that answer for the frozen counter:
all seven variants that reach `C1_R88_PASS=true` in my matrix do so only under a **mutated** counter, and
each of those mutations removes a check the counter is supposed to own. The finding is a **coverage
finding about the control corpus**, not a contract change:

* the committed corpus discriminates 3 of the counter's 8 probed checks (M2, M4, M5-via-`forged`);
* three more are fundable and are now funded by controls whose source is committed next to this file
  (`dup11`, `inert`, `lie-badpin`);
* two cannot be funded at all while the pre-registered spec stays byte-bound to the kake gate (M1) and
  the replay stays pinned to committed blobs (M7).

No contract was narrowed, no artifact was edited, and no claim was judged: a surviving mutant is a gap in
the corpus, and the corpus is the L1's to change, not mine.
