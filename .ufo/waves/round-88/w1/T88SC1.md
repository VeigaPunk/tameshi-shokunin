### Why these two sentences are the right ground for the two kill-aimed defects

The guard's decision function, read at the pin
(`git show e8d3a924…:scripts/ledger_append_guard.py`, lines 35–44):

```python
def prefix_probe(base: bytes, carrier: bytes) -> tuple[bool, int]:
    cut = base.rindex(b"]") if b"]" in base else len(base)
    head = base[:cut]
    if carrier.startswith(head):
        return True, len(head)
    …
```

- `K_CUT_WHOLE` (`@old cut = base.rindex(b"]") if b"]" in base else len(base)` →
  `@new cut = len(base)`) removes the `rindex` call, so the stable prefix becomes the
  whole base. The `bytes.rindex` sentence is what makes the removed call's contract
  explicit: `rindex` returns the **last** index of `b"]"`, and raises `ValueError`
  when absent — which the guard pre-empts with its own `b"]" in base` test
  (`scripts/ledger_append_guard.py:37`), i.e. the guard never relies on the raising
  behaviour.
- `K_STARTSWITH` (`@old if carrier.startswith(head):` → `@new if carrier.startswith(head[:1]):`)
  narrows the prefix comparison to its first byte. The `bytes.startswith` sentence is
  exactly what changes: the call returns True iff the carrier starts with the given
  prefix, so a one-byte prefix is a much weaker test — the guard's verdict becomes
  "carrier keeps byte 0" instead of "carrier keeps the whole head".

Both defect ids are in the pre-registered spec
(`.ufo/evidence/round-88/c1/py-kake-ledger-guard.defects.spec:14-21`) and both were
independently **KILLED** in the measured sweep
(`.ufo/evidence/round-88/c1/sweep.txt`: `DEFECT K_CUT_WHOLE: KILLED (exit=1 …)`,
`DEFECT K_STARTSWITH: KILLED (exit=1 …)`; final line
`MUTATE: DONE (target=py-kake-ledger-guard defects=10 killed=5 survived=5 inconclusive=0 kill-rate=50%)`).
