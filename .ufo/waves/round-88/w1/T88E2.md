## What each row actually breaks

1. **Governance vs bytes (`parked`, `stub`).** The counter's 11 legs are parsed from the
   runner bytes; the only evidence that the ledger *executes* them is one printed
   `REGRESSION:` line, which the plan already calls "necessary, never sufficient"
   (`forged` control). With honest leg bytes the printed field becomes sufficient: the
   ledger runs 10 or 0 of the 11 legs and still satisfies the frozen predicate. The claim
   under test is "the fleet mutation ledger … **governs** an eleventh sibling gate"; in
   these variants it does not, yet `C1_R88_PASS=true`.
2. **Distinctness (`dupbase`).** Check 7 (`duplicate-target`) keys on
   `(realpath(repo), path-string)`. `git show rev:./corpus/surface-census.sh` and
   `git show rev:corpus/surface-census.sh` are byte-identical blobs, but `./…` is a new
   key, so a dropped gate (`bash-drift-pins`) is silently replaced by a re-declaration.
   `declared=11 legs=11` therefore does not imply 11 distinct governed gates; the ledger
   governs 10.
3. Both holes are outside the counter's replay: the replay itself never failed in any row
   (`agree=10/10` for every leg, `killed` as recorded).

## Reading for the L1 (kill rule b)

The predicate printed `C1_R88_PASS=true` in three new variants, so this seat's mechanical
verdict is **killed**. Under the letter of (b) — "does **not** add a real, independently
reproduced Python sibling-gate leg carrying the pre-registered spec" — the split is:

- `parked` and `stub`: the ledger does not add a leg it executes; the py leg is dead
  declaration and the count is carried by the counter's byte replay plus a forged receipt.
  On the reading "governs = really runs, independently reproduced", these fire (b).
- `dupbase`: the py leg is genuinely executed and replayed, but the declared set covers
  only 10 distinct gates; on the reading "(b) is about the py leg's replay failing",
  `dupbase` does not fire (b) — it is a distinctness/coverage-count defect, and it still
  shows `declared=11 legs=11` is satisfiable with a dropped gate.
- If (b) is read strictly as "the counter's replay of the py leg must fail", **none** of
  these fire: the content-addressed replay is the part that held.

Recommendation: treat the runner field as unproven (it can be forged while all 11 replays
are real), and make `duplicate-target` compare resolved blobs, not raw path strings. If a
landing is to survive, the counter (or an added control) must execute the runner and check
that the executed leg set equals the parsed leg set, not just the printed tally.
