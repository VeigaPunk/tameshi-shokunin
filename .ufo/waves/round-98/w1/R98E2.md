## Findings

**F1 — the frozen After clause "the six per-class runs in the transcript" has no artifact.**
Frozen at `764aca97` (claims.json C2 `after`, and plan C2 `After`). The battery prints
nothing for a successful class (source 213–228), `observations` is collected and never
printed (191, 214), and both committed receipts are aggregate-only (positive 1 line; red
2 lines). The six runs are still enforced in code — `refused` increments only on
`class_token_ok(name, out, rc)` with that class's name — so `refused=6` is an assertion on
six named runs; but no transcript exhibits them. Candidate amendment: narrow the After to
"the summary line at R plus the six per-class receipts", or add
`print("GUARD_REFUSALS_CLASS %s rc=%d token=ok" % (name, rc))` beside source 224 and
re-freeze the positive receipt. My `R98E2-hand-<class>.out` receipts supply the six tokens
today.

**F2 — class-token provenance is line-based only.** `class_token_ok` accepts any stdout
line equal to / prefixed by the class token (source 66–72); it cannot tell the tool's own
refusal from a manifest string the tool echoes at line start (attack B). Kill rule b
("a class token accepted from anything but a line of the tool's own stdout (a manifest
string, …)" in the frozen plan) is not fired on this artifact — the accepted text *is* a
line of the tool's stdout, and the graded base manifest is clean and tree-pinned — but the
grader's provenance test is forgeable by a poisoned base manifest, and C2 pins no
independent base digest (already disclosed as A3 in the worktree). Suggested hardening:
in `fixture_manifest`, reject generated fixture text containing `GUARD_SETUP` or CR/LF in
ids, or grade the refusal line shape exactly (single line, `GUARD_SETUP <class>` +
`[:payload]`, exit 2).

**F3 — the quoted red predicate cannot fail.** The red class's outcome never enters the
summary: source 215–222 `continue`s before `refused` is incremented, and `wrong` is computed
as `len(CLASSES) - refused` (241); the red exit is the literal `1` (245–246). A battery
whose red arm *refused* the substituted positive fixture would print the same summary line
and exit 1, differing only in the unquoted `GUARD_REFUSALS_RED … refused-under-red-run`
line. This is the same "recorded code is not a measurement" class as round-97 D-2 (the
literal `0`), now on C2's red arm. My measured run prints the correct
`GUARD_REFUSALS_RED state-unbuildable missed-as-declared rc=0` line, so the claim is true in
fact; the frozen red predicate should quote that line (candidate amendment A5). Receipt
`R98E2-red-constant.out` (sha256 `15329609…`) shows the committed `class_token_ok` returns
True on a forged token and the loop arithmetic that makes the summary constant.

**F4 — frozen wording vs `manifest-sha-mismatch` digest.** The frozen wording says the
battery runs the tool "once per class with the fixture's own digest"; source 195–201 passes
`sha256(fixture + b"x")` for `manifest-sha-mismatch` (measured: fixture sha
`c63eba3f…`, pin passed `65852017…`). The class requires a mismatched pin. This is exactly
worktree amendment A4 (read-only observation); the freeze blob still carries the
un-narrowed sentence. Predicate and counts unchanged.

**Scope note (not a finding).** The frozen tool emits 13 `GUARD_SETUP` tokens (9 `die(...)`
+ 4 `_setup_text(...)`, measured in `R98E2-token-census.out`, sha256 `67b07368…`); the
