### (c) different committed tool whose digest the caller supplies — **FALSIFIES-WORDING**

Same receipt (`08-attack-c-pin-semantics.txt`) plus `06`. What the pin enforces, exactly:

| arm | result |
|---|---|
| `--tool-sha zz` | `GUARD_REFUSALS_SETUP tool-sha-invalid`, EXIT=2 |
| `--tool-sha 000…0` (64 hex, other bytes) | `GUARD_REFUSALS_SETUP tool-sha-mismatch`, EXIT=2 |
| `--tool <other tool> --tool-sha 634997…` (frozen digest) | `GUARD_REFUSALS_SETUP tool-sha-mismatch`, EXIT=2 |
| `--tool <stub> --tool-sha sha256(stub)` | accepted, `classes=6 refused=6 wrong=0 positive=ok`, EXIT=0 |

So the enforced property is *self-consistency*: `sha256(blob at --tool, --rev) == --tool-sha`.
It is **not** identity with the frozen tool. Frozen wording: "It reads the frozen tool as a blob
at R and refuses a `--tool-sha` that is not 64 hex or does not equal the blob's sha256". The
second half is true; the first half ("the frozen tool") is not enforced — `--tool` is a path
argument (default the frozen path, but overridable) and `--tool-sha` is any caller-chosen
digest. Kill rule **d** ("the tool is read from the worktree or a blob whose sha256 is not the
pinned value") therefore reduces to "the digest matches the bytes the caller named": its first
half holds (the battery only uses `git cat-file blob`, never the worktree), its second half is
self-referential and unfalsifiable by construction.

## Findings by severity

**F1 — HIGH — FALSIFIES-WORDING (kill rule d, sentence "reads the frozen tool as a blob at R").**
The battery accepts any blob whose digest the caller supplies; a stub that refuses every manifest
and runs nothing scores `classes=6 refused=6 wrong=0 positive=ok`, exit 0 (`06`). Neither the
tool path nor the tool digest is pinned inside the battery (`grep 634997` EXIT=1). The wording's
"frozen tool" is an unpinned caller claim; C2's DoD therefore measures "some program with the
class tokens and this argument interface", not the frozen bytes.
Fix shape: bake the expected tool digest (or read it from `claims.json` at `--rev` and require
`--tool` == the frozen path) and refuse when `--tool-sha` differs from it.

**F2 — MEDIUM — FALSIFIES-WORDING (red-arm sentence).** The red summary line and exit cannot
distinguish "red class missed" from "red class refused"; both print `refused=5 wrong=1 positive=ok
red=<class>` and exit 1 (`02` vs `07`). The measured bit is on an un-named line, and the exit is
a literal (`if a.red: return 1`). Kill rule c is not violated — the class is excluded, not
counted — but the wording presents the summary as the evidence.

**F3 — MEDIUM — FALSIFIES-WORDING (After clause, and step-4 expectation).** No per-class
transcript and no per-row transcript is produced by the battery or committed by the freeze: the
success stdout is one line, the committing receipts hold 1 and 2 lines, the ten `GUARD_ROW`
lines the tool emits are discarded, and the round-98 `c2-*` control receipts are byte copies of
round-97's. A wave artifact that dumps the six per-class runs (and the 10 `GUARD_ROW` lines)
would satisfy the clause at R; nothing in the frozen evidence does.

**F4 — LOW — FALSIFIES-WORDING (narrow, "with the fixture's own digest").** For
`manifest-sha-mismatch` the digest passed to the tool is `sha256(fixture + b"x")` (line 201),
i.e. not the fixture's digest. The clause should read "with the digest the class requires".

**F5 — LOW — unenforced clause ("at the records revision R").** `--rev` is validated only for
40-hex form and resolvability; a run at any commit passes (`06`).

**F6 — NOTE.** `state-unbuildable` is a catch-all wrapper (`except Exception`, :227): the class is
the tool's, and the fixture reaches it legitimately, but the battery cannot distinguish "state
unbuildable" from any other exception inside `build_state`. Fixture: `04` token text carries the
raw exception message.

**F7 — NOTE.** C2 `Before` says the round-97 record "receipted four classes"; `edit-ambiguous`
appears only in the round-97 **selftest** output (`12`), not in a receipt file. This matches the
spot-check's own phrasing ("no committed receipt or selftest case"), so it is a loose word, not
a false count.
