## 4. Step 3 — the sentence against the tool, and the five gaps

The exact sentence under test (`plans/round-98.plan.md` §C1):

> counts static `add(...)` call sites (a site inside a loop counts once), and classifies a recorded
> code as measured only when its expression derives from a runner call (`sh`, `git`, `run`,
> `subprocess.run`): a constant, a constant bound through a name, a loop variable, a plain call, or a
> `returncode` attribute on a value not assigned from a runner call is unmeasured.

What the tool enforces (`tools/control-assertion-audit.py:101-166`): bare-name `add` calls only; the
second positional argument or `code=`; assignment collection by **line number only**; a name
resolves to its **last assignment with a strictly smaller line number in the whole file**; an
`IfExp` is measured only if both arms are; all other expressions are `unresolved`; runner calls are
matched by **callee spelling** (`Name` in `{sh, git, run}` or attribute `subprocess.run`), never by
binding.

The five places the sentence claims more than the tool enforces:

1. **Branch reachability / last textual assignment.** f02, f13. One arm binds a literal and the
   other a runner; the later line wins. The recorded value at runtime can be the literal.
2. **Recorder body / shadowing definition.** f08. The call-site argument derives; the value actually
   recorded comes from the effective `add` body, which is never audited.
3. **Runner binding.** f11, f19. Any call spelled `run` is a runner, including a driver-defined stub
   returning a literal. The selftest itself enshrines this: `SELFTEST measured-tuple-run PASS
   got=measured want=measured` on `def run(a): return 1, "o"` (`step1/selftest.txt`).
4. **Attribute assignment.** f12. `p.returncode = 0` after the runner call is invisible to
   `collect_assigns` (only `Name`/tuple/loop targets are collected), so `p.returncode` stays measured.
5. **Function scope.** f17. `p` is a local of `helper()`; the call site in `main()` is a `NameError`,
   yet the file-global line-ordered resolver reports `returncode-of-runner-name`.

Two boundaries that are **not** falsifications but need words in the sentence:

- **Bare-name only.** `c.add(...)` (f15) and `record(...)` (f09) produce `sites=0` and pass. The
  frozen phrase "static `add(...)` call sites" should say "bare-name". (If a method call is counted as
  an `add(...)` site, this would be kill rule d; as written it is a scope statement.)
- **Arithmetic via augmented assignment.** f18: `rc = p.returncode; rc += 7` is measured and records
  7; `AugAssign` is not collected even though the docstring lists "arithmetic" as unresolved. This is
  an internal docstring/behaviour inconsistency, not a frozen-sentence over-claim.

The false-negative direction (c, d, e, f, g and the swapped branch f02b) is real but safe for a
necessary-condition claim: the tool says `unmeasured` where the value may be a measurement.

## 8. Proposed amendment (exact narrowing)

Replace C1's classification clause with (one sentence):

> classifies each bare-name `add(...)` call site by its second positional (or `code=`) argument
> expression, reporting `measured` only when the last textual assignment before the call line to each
> name the expression reads is a call spelled `sh`, `git`, `run`, or `subprocess.run`; the classifier
> does not model function scope, branch reachability, attribute assignment, the `add` definition or
> any shadowing definition, aliases, method calls, or recorders named otherwise, and a driver that
> defines its own `run` — including one returning a constant — is reported `measured`.

The number clause stays as frozen; the axis sentence ("every recorded control code is a measurement")
must be read as scoped to the two committed drivers, not as a property the audit enforces for an
arbitrary driver (f19 is the counterexample to that reading).

## 9. Residual risk and verification gaps

- **R does not exist yet.** The literal "at R" is unexecuted. Re-run at R (same form):
  `python3 -I tools/control-assertion-audit.py --repo . --rev <R> --driver .ufo/evidence/round-98/controls98.py`
  and the `controls97.py` twin; expected 15/15/0/0 rc 0 and 15/14/1/1 rc 1 with line 156 named,
  provided the records commit does not touch the tool or the two driver blobs (their shas at
  `d32043ec`, `764aca97`, `cdaecece` are identical; `step1/*`).
- **False alarms are possible.** A legitimate driver using `try/except` fallback (f03), a literal-last
  branch (f02b), or `rc += n` (f18) is classified `literal`/measured-as-not-the-raw-rc and can make the
  audit exit 1. If the records driver ever uses those idioms, the frozen number would fail for a
  correct implementation. This is the conservative direction, but it is a live risk.
- **Zero-site vacuity.** f09 (`record`) and f15 (`c.add`) print `sites=0 … unmeasured=0` and exit 0.
  The plan declares the `record` case; the method-call case is not declared and should be covered by
  "bare-name" if the amendment lands.
- **Selftest coverage does not include the falsified boundaries.** The 12 arms cover direct literal,
  literal-via-name, runner returncode, tuple-run, rebound, fake `returncode`, constant `IfExp`, loop,
  no-assignment and three counting/exit arms. They do not cover branch order, try/except, getattr,
  attrgetter, subclass, shadowed `add`, other recorder, cross-scope, attribute mutation, dead branch
  or `AugAssign`. The local-`run` case is *enshrined as measured* by `SELFTEST measured-tuple-run`.
- **Tuple-returncode and loop-variable false negatives.** `code, out = run(...); code.returncode` is
  `returncode-of-tuple` unresolved, and a loop variable bound from a runner is `loop-variable`
  unresolved; declared by the plain rules, but worth a note if a future driver uses them.
- **No LSP device.** `xd://lsp` is not mounted in this session (the device read returns "No such
  tool"), so no `references`/`definition`/`diagnostics` claims are made; every finding is either an
  executed command with its observed output/exit or a read of the tool's committed source.
- **No tooling installed.** No pacman transaction (paused host-wide) and no `uv`/`npx`/binary install
  was needed; Python 3 stdlib and the lane's committed tool sufficed.
