## Findings

### F1 — Medium — the battery's tool pin is optional: an unpinned run grades an arbitrary blob and still prints a verdict line

**Exploit path.** `--tool-sha` is `default=None`; with it omitted the battery never compares the
blob it extracts against anything. Anyone who runs the battery without the pin — a copy-pasted
Usage line that drops it, a harness that builds args from the docstring, or a run against a
`--lane` the caller does not control — gets `classes=6 refused=6 wrong=0` from bytes nobody
pinned. C2 kill rule (d) in `claims.json` ("read … a blob whose sha256 is not the pinned
value") is satisfied only because the claim's *counter* passes the pin; the tool's own contract
does not require it.

**Evidence.** A lab commit whose tool path holds a fabricated script that prints all six
`GUARD_SETUP <class>:fake` tokens and exits 2 (a blob that is not `634997d0…`; the same blob with
the pinned sha is refused, second run below):

```
$ python3 -I guard-refusals.py --lane lab --rev d9b7a822… --tool .ufo/evidence/round-97/c2/guard-inertia.py --work …
GUARD_REFUSALS_POSITIVE_FAIL rc=2 last=['GUARD_SETUP manifest-empty:fake']
GUARD_REFUSALS classes=6 refused=6 wrong=0 positive=fail        # rc 1
$ … same, with --tool-sha 634997d0…
GUARD_REFUSALS_SETUP tool-sha-mismatch                          # rc 2
```

Receipts `pin-omitted-fake-tool.out`, `pin-pinned-fake-tool.out`.

**Impact.** The unpinned mode produces the verdict shape (`classes=6 refused=6 wrong=0`) from a
tool that refuses nothing; a consumer that reads the `refused=6` field as the measurement
accepts a fabrication. The claim's frozen wording is not falsified (it names `--tool-sha` in the
invocation), but the tool's default silently weakens the same guarantee. The positive arm is
not a substitute for the pin: it grades the *same* unpinned blob, so a fabricated tool that also
echoes the `GUARD_INERTIA rows=10 killed=8 limits=2 survived=0 unmet=0` line would yield
`classes=6 refused=6 wrong=0 positive=ok` with exit 0 — **[INFERENCE]** from `positive_ok()`
(stdout line + exit only), not run, since the fabricated blob in the receipt was deliberately
made to fail the positive arm.

**Smallest remediation.** Make `--tool-sha` required (`required=True`) or refuse its absence with
`GUARD_REFUSALS_SETUP tool-sha-missing` (exit 2), and add one selftest arm for the omitted case.

### F2 — Medium — the battery writes outside `--work`: its checker grandchild writes to the host-global `/fast/scratch/hyaku/tameshi-r96`

**Exploit path / mechanism.** The frozen tool (`guard-inertia.py`) builds the checker's
environment in its own `sealed_env()` — `PATH`, `HOME`, `TMPDIR`, `GIT_*` — and **does not
propagate `HYAKU_SCRATCH`**. The round-96 checker blob then falls back to its own default:
`_scratch = os.environ.get("HYAKU_SCRATCH", "/fast/scratch/hyaku")`,
`… /tameshi-r96-checker-home` (`:71-76`) and
`tempfile.TemporaryDirectory(dir=<scratch>/tameshi-r96, prefix="disposition-counter-")` (`:417`).
The battery's redirection (`HYAKU_SCRATCH=<work>/tool-scratch`) therefore contains the tool but
not the tool's checker child.

**Evidence** (`R98SN1-strace-extract.txt` §1-§3): one positive run creates, fills and removes 14
`/fast/scratch/hyaku/tameshi-r96/disposition-counter-<rand>/counter.py` files, and probes
`/fast/scratch/hyaku/tameshi-r96-checker-home/tmp` 35 times (`EEXIST`; that directory is
pre-existing round-96 residue at `Nov 8 12:01`). After the run,
`/fast/scratch/hyaku/tameshi-r96` mtime is `13:25` and no `disposition-counter-*` remains.
Attributable receipt: `R98SN1-strace-battery.log.gz`, extract §2/§2b.

**Impact.** (i) The battery is not hermetic: two concurrent runs share `/fast/scratch/hyaku/tameshi-r96`,
and this seat's run mutated a path shared with round-96/97 evidence (`tameshi-r96/` still holds
`R96E2`, `battery-*`, `a9-smoke`, …). (ii) On a host where that path is absent or unwritable
(the lane's own record documents a host class where `/fast/scratch` is absent,
`PROVINCE.md:126-135`), the checker raises inside every row, every `GUARD_ROW` becomes
`survived`, and the positive arm fails for an environment reason that is indistinguishable from
a tool defect. (iii) The C2 wording says nothing about this path, so a reader of the claim
cannot know the run's write set exceeds `<--work>`.

**Smallest remediation.** Declare the limit in C2 ("the frozen tool's checker child allocates
under the host default scratch root because the frozen tool drops `HYAKU_SCRATCH`; the battery
confines the tool and its clone, not the checker's fallback") **and** make the escape visible:
before the run, record `$HYAKU_SCRATCH/tameshi-r96` (default `/fast/scratch/hyaku/tameshi-r96`)
state; after it, assert it is unchanged except for removed `disposition-counter-*`, printing a
named line if not. Editing the frozen round-97 blob is out of scope for a frozen claim.

### F3 — Medium — an unusable `--work` is a traceback and exit 1, not named setup exit 2

**Exploit path.** `work = os.path.realpath(a.work)`; the only guard is
`if os.path.isdir(work) and os.listdir(work)`. A path that exists as a *file*, or whose parent is
not writable, reaches `os.makedirs(work, exist_ok=True)` / `open(tool, "wb")` unguarded.

**Evidence.**

```
$ … --work /fast/scratch/…/R98SN1/wfile        # a regular file
Traceback (most recent call last): … FileExistsError: [Errno 17] File exists: '…/wfile'
# RC: 1                                                     (ex-battery-workfile.out)
$ … --work /fast/scratch/…/R98SN1/ro/w         # ro/ is 0500
Traceback (most recent call last): … PermissionError: [Errno 13] Permission denied: '…/ro/w'
# RC: 1                                                     (ex-battery-workroroot.out)
```

Contrast: `--work <non-empty dir>` → `GUARD_REFUSALS_SETUP work-not-empty`, rc 2;
`--work ""` → usage, rc 64.

**Impact.** An environment fact becomes a *verdict*: `1` is the documented "a class was missed",
so a harness records six missed refusals for a broken `--work`. It also violates the lane's own
scratch rule verbatim — "never a silent `/tmp` fallback, never a traceback, never exit 1"
(`SKILL.md:32-40`, `corpus/knowledge/scratch-root-contract.md` §Three arms).

**Smallest remediation.** Validate `--work` before use: if it exists and is not a directory, or
its creation fails, print `GUARD_REFUSALS_SETUP work-unusable:<path>:<errno-class>` and exit 2
(one line, no traceback); add the three arms to the selftest.

### F4 — Low — `--red` is unvalidated and forces exit 1 whether or not anything was substituted

**Evidence.** `--red state-unbuildabl` (one character short) against the real lane:

```
GUARD_REFUSALS classes=6 refused=6 wrong=0 positive=ok red=state-unbuildabl   # rc 1
```

No class was substituted (`refused=6`), no fixture changed, yet the run exits 1 and the summary
carries a red label — `red-typo.out`. The genuine arm prints `refused=5 wrong=1` plus
`GUARD_REFUSALS_RED state-unbuildable missed-as-declared rc=0` (`battery-red.out`). The exit is
unconditional: `if a.red: return 1`.

**Impact.** A consumer that grades the red arm on exit 1 alone cannot tell a demonstrated miss
from a typo; the red arm's evidence is the `GUARD_REFUSALS_RED … missed-as-declared` line, not
the code. Also, `wrong=1` in the typo run is arithmetic (`len(CLASSES) - refused`), not a
measurement.

**Smallest remediation.** Reject `--red` values outside `CLASSES` with
`GUARD_REFUSALS_SETUP red-unknown:<value>` exit 2, and say in the Usage block that the red arm's
evidence is the `GUARD_REFUSALS_RED <class> missed-as-declared rc=` line, not the exit code.

### F5 — Low — argparse's usage exit (2) collides with the documented setup code in all three tools

**Evidence.** `--bogus` → rc **2** for each tool (`ex-audit-bogus`, `ex-reg-bogus`,
`ex-battery-bogus`, all with argparse's `usage:` banner). The tools' *own* missing-argument
paths do print the doc and exit 64 (`ex-audit-noargs`, `ex-reg-noargs`, `ex-battery-noargs`), so
the map is right everywhere except argparse's rejection path.

**Impact.** `2` no longer means "setup refused": a driver that maps setup-2 to
"could-not-evaluate" will treat a mistyped flag as an environment refusal, and a driver that
treats 2 as a hard failure will read a usage error as a setup defect. The lane convention
(`SKILL.md:1748`) assigns invalid invocation to 64.

**Smallest remediation.** Subclass `ArgumentParser` (or `exit_on_error=False` + `try`) so
`parser.error()` prints usage and exits 64; keep 2 for the tool's own `*_SETUP` lines.

### F6 — Low — the work tree is left non-empty (`tool.py`), so a second run with the same `--work` is refused

**Evidence.** After every successful run `find <work>` shows exactly `<work>/tool.py` (the clone
and `tool-scratch` are removed); rerunning with the same directory prints
`GUARD_REFUSALS_SETUP work-not-empty`, rc 2 (`battery-positive.out` + `ex-battery-worknonempty.out`;
`strace-extract.txt` §7).

**Impact.** A loop/retry harness must mint a fresh directory per run; the residue is also the
one file the battery never cleans, so "the battery removes its scratch tree" is true for the
clone, not for the work root.

**Smallest remediation.** Remove `tool.py` where the clone is removed (or execute the tool blob
from `<work>/tool-scratch/`), so the work root returns to its pre-run emptiness; alternatively
document the residue next to the `<empty dir>` requirement.

### F7 — Low — `--work` is realpath'd, so a symlinked `--work` writes at the link target with no notice

**Evidence.** `--work <link>` where `<link> → <target>` (empty): the run proceeds and
`<target>/tool.py` is created; `readlink -f <link>` = `<target>` (`work-symlink.out`).

**Impact.** The declared path is not where bytes land. A containment assertion phrased over the
declared `--work` string ("nothing outside `${--work}` changed") is defeated by handing the tool
a symlink whose target is elsewhere. Low because `--work` is caller-supplied, but it is the one
attack in step 2 that changes behaviour at all.

**Smallest remediation.** Print the resolved root once (`GUARD_REFUSALS work=<realpath>`) or
refuse a `--work` that is itself a symlink, so the real write root is on the record.

### F8 — Info — no `--outdir` exists; the two audits write nothing, so "symlinked `--outdir`" and "no `/tmp` writes" are clean by construction

Grep of all three sources for `outdir`: none. `strace` of both audits: the only write-mode opens
are `/dev/null` (git's `GIT_CONFIG_GLOBAL`), zero `/tmp` paths, zero network syscalls
(`strace-audit-green.log`, `strace-registry-green.log`, `strace-*-net.log`). The battery writes
to `/tmp` only if the caller points `--work` there (not measured as a refuser: `--work /tmp/x`
is accepted); that is a caller choice, and the lane's `/tmp` rule is about the seat's own scratch
(`SKILL.md:28`).

### F9 — Info — the fixture-setup `git branch -M master` is the only network-syscall source, and it resolves local names

Covered in §5. Zero TCP sockets, zero nonzero remote ports, and the audits' git calls make no
socket at all. The practical note is hermeticity, not egress: `setup_store()`'s
`git branch -M master` reaches NSS (netlink + `systemd-resolved` over AF_UNIX + UDP port-0
probes) on a host with a broken resolver it can stall, and the trace then carries host interface
addresses. `git init`/`git commit` alone make none (`strace-git-init.log`, `strace-git-commit.log`).

### F10 — Info — the audits' sealed env drops `HOME`/`TMPDIR` (and `HYAKU_SCRATCH`) for the git child

`sealed_env()` in both audits returns a fresh dict without `HOME`/`TMPDIR`; any temp file git
might need would land in the platform default `/tmp`. Measured: no temp file is created, so the
lane rule ("never a silent `/tmp` fallback", `SKILL.md:36`) is not violated — but the guarantee
rests on git's behaviour, not on the env. Carrying the caller's `TMPDIR` (or an explicit scratch
root) would make it structural. Low, no action required for this round.
