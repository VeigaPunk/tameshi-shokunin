## 0. What the audit actually guarantees (reconstructed contract)

Command form: `python3 -I tools/control-assertion-audit.py --repo R --rev <40hex> --driver PATH`.

1. It reads `git cat-file blob <rev>:<PATH>` — never the worktree. Proven: append a comment to a
   clone's worktree `controls98.py`; the audit still prints the blob sha `f1c1db0e…` and the same
   `sites=15` (`audit-worktree-vs-blob.txt`; worktree file sha `b84b1973…`).
2. A site is a `Call` whose `func` is `ast.Name` with id exactly `add`. Site code is `args[1]`, or
   the `code=` keyword. The site count is static; one site inside a loop counts once
   (`f6_loop_states.py`: 3 runtime states, 1 site; selftest arm `loop-site-count`).
3. Classification is **lexical and local**: `measured` iff the expression derives, through names
   assigned before the call, from a call whose *name* is in `{run, sh, git, subprocess.run}`; a
   `Constant` (directly, through a name, or both branches of an `IfExp`) is `literal`; everything
   else is `unresolved`. `unmeasured = sites - measured`, so literals are a subset of unmeasured.
4. Exit: 0 iff `unmeasured == 0`; 1 if any unmeasured; 2 setup (bad rev, absent driver, unparsable,
   `add` without a classifiable code); 64 usage.
5. `--selftest` at the freeze blob: `CONTROL_ASSERT_SELFTEST: 12/12 pass`, rc 0
   (`audit-selftest.txt`).

### Other states whose expectation can pass without its mechanism firing

The grading predicate in both drivers is `ok = code == want` (controls97/98, end of `main`); the
payload is written into the receipt but never asserted. Concretely:

1. **All four `want=0` positives are body-blind.** `c1-positive`, `c1-selftest`, `c2-positive`,
   `c2-selftest` pass on any exit 0. Demonstration: replace `battery-bind.py` in a clone's worktree
   with a stub that prints `BATTERY states=0 matched=0 mismatched=0 missing=0` (and
   `BATTERY_SELFTEST: 0/99 pass` for `--selftest`) and exits 0; the driver prints
   `c1-positive MATCH rc=0`, `c1-selftest MATCH rc=0`
   (`stub-binder-run.txt`, bodies in `stub-out/c1-positive.out`, `stub-out/c1-selftest.out`). The
   other 7 forgery states correctly turned `MISMATCH` in the same run
   (`CONTROLS98 states=18 matched=11 mismatched=7`), so the driver is not wholly vacuous — but its
   positives are exit-only. Contrast with the lane's own round-96 driver, whose `grade()` was
   stricter (`C1_R96_PASS=true` / `C1_SETUP <token>` / conjunct maps, `controls-v96.py:445-456`):
   the round-97/98 driver is a **regression in grading strength**, not the lane's best pattern.
2. **`c1-nowork-summary-absent` (`want=128`).** `git cat-file -e` returns 128 both for "valid rev,
   path absent" and for "rev unresolvable": both measured (`exit-code-alternatives.txt`). The state
   cannot distinguish the round-96 summary's absence from a bad pin.
3. **Every `want=2` state** (`c1-forge-driver-sha{-empty,-short}`, `c2-forge-noop`,
   `c2-forge-manifest-subst`, `c2-forge-manifest-empty`): argparse usage errors exit 2
   (`guard-inertia.py --bogus-flag` → 2, observed) and guard-inertia's *other* `die()` refusals also
   exit 2 (`--rev not-a-rev` → `GUARD_SETUP rev-not-a-commit-id`, 2). The control asserts only the
   code, never the declared class token.
4. **Every `want=1` state** (the four C1 body forgeries + `c2-forge-flipped-expect`): an uncaught
   Python exception exits 1 (observed), and `battery-bind` exits 1 for either
   `MISMATCH(counter-sha)` or `MISMATCH(exit=…)`, so a forgery that trips a different check still
   matches. The round-97 M4 note records that this class was already hit once.
5. **The two no-work states' rc=1 means "this pattern has no match"**, not "the token is absent":
   a typo'd pattern (`BATTERY statesX=`) returns rc 1 at the same base (`pattern-identity.txt`).
   Provenance, not command identity — the declared limit, but the same class.

These are weaknesses of the *control driver*, not of the C1 claim's measured predicate (the
driver's summary line and the committed bodies are exactly as claimed). They do not falsify a
frozen sentence; they bound what `CONTROLS97/98 … matched=18` proves.

## 3. Blind-spot fixtures (the audit's class boundary)

Fixtures committed in a scratch repo (commit `33b6e86a…`), copies under `R98L1-receipts/fixtures/`;
full transcript `audit-fixtures.txt`.

| fixture | shape | audit output | exit | true runtime states |
|---|---|---|---|---|
| `f1_alias.py` | `record = add; record("alias-literal", 0, …)` | `sites=0 measured=0 literal=0 unmeasured=0` | **0** | 1 (literal code) |
| `f2_method.py` | `rec.add("method-literal", 0, …)` (attribute call) | `sites=0 …` | **0** | 2 (literal codes) |
| `f3_wrapper_unresolved.py` | `def rec(…): add(name, code, …)`; 2 callers | `sites=1 measured=0 literal=0 unmeasured=1`, `detail=no-assignment-before-call` | **1** | 2 (1 measured, 1 literal) |
| `f4_wrapper_falsegreen.py` | wrapper param `rc` collides with an enclosing `rc = g.returncode` | `sites=1 measured=1 literal=0 unmeasured=0`, `detail=returncode-of-runner-name` | **0** | 2 (both literal `0`) |
| `f5_shadow_runner.py` | driver-local `def sh(argv)` returning a constant `returncode` | `sites=1 measured=1 …` | **0** | 1 (nothing runs) |
| `f6_loop_states.py` | `for name in (a,b,c): code,out = run(…); add(name, code, …)` | `sites=1 measured=1 …`, `name=?` | **0** | 3 |
| `f7_loop_literal.py` | same loop, `add(name, 0, …)` | `sites=1 measured=0 literal=1` | **1** | 3 |

Exact lines:

```
f4: CONTROL_ASSERT_SITE line=23 name=? measured=yes class=measured detail=returncode-of-runner-name
    CONTROL_ASSERT sites=1 measured=1 literal=0 unmeasured=0            (rc=0)
f5: CONTROL_ASSERT_SITE line=19 name=shadow-runner measured=yes class=measured detail=returncode-of-runner-name
f3: CONTROL_ASSERT_SITE line=19 name=? measured=no class=unresolved detail=no-assignment-before-call
```

Findings:

- **Zero-site vacuity** (declared limit): any driver registering through another name (`f1`) or an
  attribute recorder (`f2`) passes vacuously. `f2` is not literally covered by the declared
  sentence ("different recorder name") but has the same effect.
- **Wrapper → one site, no per-call classification** (`f3`): the only static `add` site is the
  wrapper body; its `code` argument is a parameter with no assignment, so it is `unresolved` and the
  driver fails even though one caller passes a measured code. The site count (1) is unrelated to
  the state count (2) and the site is not a recorded code at all.
- **Wrapper false green** (`f4`): a parameter name that resolves lexically to an enclosing measured
  assignment makes the site `measured` while **every runtime call passes the literal `0`**. This is
  the sharpest boundary: the audit's guarantee is per-site lexical resolution, not interprocedural
  data flow. It is outside both the declared limits (which describe zero-site vacuity) and the
  twelve selftest arms. [INFERENCE] whether it falsifies kill rule (a) ("a constant …
  is reported `measured`") depends on whether "recorded code" means the site expression or the
  runtime argument; the runtime argument here is a constant. This is the item the L1 should declare
  or selftest before the records run; I do not edit.
- **Runner-ness by name** (`f5`): a driver-local `sh` that runs nothing is accepted as a runner.
  Same root cause as `f4` (names, not identity).
- **Loop scale** (`f6`, `f7`): a loop site counts once, the label is lost (`name=?`), and a literal
  inside a loop is still caught — the loop handling is correct, but `sites` is not a state count.
- **False red on non-recorders**: any committed file that happens to use a function named `add`
  fails. Measured at `764aca97`: `round-20/stage/measure.py`
  `sites=6 measured=0 literal=4 unmeasured=6`, rc 1;
  `round-29/f6/BuildF6A/gen.py` `sites=6 measured=0 literal=6 unmeasured=6`, rc 1;
  `round-53/.../evidence-disposition.py` `sites=13 measured=0 literal=3 unmeasured=13`, rc 1. Their `add`
  signatures are `add(item, ok, detail)`, `add(rel, kind, mode, content)`, `add(finding_id, detail)`
  — the second positional argument is not a recorded code. **The audit is not a repo-wide gate;
  its verdict is meaningful only for the `add(name, code, body, want)` recorder shape.**
- **Shell drivers** (rounds 49–58, 90–91 c2) exit 2 `AUDIT_SETUP unparsable` — honest refusal, not
  a green.

### Honest class boundary

Covered by construction: static `add(...)` call sites in **one Python blob**; direct constants,
name chains, both-constant `IfExp`; calls named `run`/`sh`/`git`/`subprocess.run` within the same
file; loop sites once; blob-not-worktree.

Not covered: other recorder names/aliases/attributes (`f1`,`f2`); wrapper parameter binding in both
directions (`f3`,`f4`); the runtime value of any argument; local functions that shadow runner
names (`f5`); constants defined across files or via `getattr`; loop multiplicity (`f6`); non-Python
drivers; the lane's own data-table batteries (0 sites); the expectations (`want`) by design.

## 4. Divergences against the frozen C1 wording (at `764aca97`)

Observed exactly as frozen: `sites=15 measured=15 literal=0 unmeasured=0` (rc 0) for `controls98.py`;
`sites=15 measured=14 literal=1 unmeasured=1` (rc 1) for `controls97.py`, naming line 156; selftest
`12/12`; blob read, not worktree; loop site counted once. No kill rule (a)–(f) fires on the
round-97/98 pair as measured. Repaired run can fail (kill f): the crafted-base run prints
`mismatched=1` and the stubbed-binder run `mismatched=7`, both rc 1.

Divergences, all at the level of the **declared-limits sentence**, not the measured predicate:

1. The limit says "a driver registering through a differently named recorder is zero-site and
   passes vacuously". Observed: also true for attribute recorders (`f2`), *not* the whole story for
   wrappers — a wrapper is one-site-`unresolved` and fails (`f3`), and can be **false-green** when a
   parameter name resolves to an enclosing measured name (`f4`). The false green is a *different*
   class from vacuous green and is not declared.
2. "Counts static `add(...)` call sites" is used correctly in the claim, but `sites` is not the
   state set: 15 sites / 18 states here; 0 sites / up to 50 states for the table batteries. A
   reader who equates the two would over-read `sites=15`.
3. "Measured means the expression derives from a runner call somewhere in its name chain" is
   implemented as *a call whose name is in the runner set*: a local `sh` shadow passes (`f5`). This
   is the same "provenance, not identity" limit already declared, but the shadow case shows the
   provenance is purely syntactic.
