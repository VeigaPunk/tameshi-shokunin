## Findings

1. The selftest is strong on the arithmetic core: every mutant of `units` arithmetic, `removals`
   slicing, `subsequence` direction, `Judge.kills` order, cost equality, the N−1 threshold, the
   `mined`/`opened` record checks, the panel sha check and both the generator and guard digest pins
   was killed (13 of 14 kills are behavioral; m25 dies hard as a setup error).
2. The blind spots cluster where the fixture is too narrow: **no map-bearing cases at all** (m04, m07),
   the **non-subset probe is doubly covered** so the subset check is not independently pinned (m09),
   the identity counterexample is **fully 1-redundant** so `any` vs `all` is indistinguishable (m11),
   and **no case misreports `units_before`** (m13) or produces an `unfound` (m28).
3. Two no_reduction mutants (m16, m17) survive because no case combines `ok>0` with `after==before`
   (m16) or asserts `no_reduction` at all (m17 — killable by strengthening the existing LIE case).
4. The records pins are loosening-sensitive only via *negative* fixtures: a `held (round 51)` README
   (m19) and an `F60`-only knowledge file (m18) are the minimal distinguishing fixtures.
5. Asymmetric pin enforcement: `GEN_SHA256` is enforced hard (m25, exit 2), `GUARD_SHA256` is enforced
   (m24 — the fixture's missing BASE commit turns the fallback into empty bytes), but the
   `PUBLIC_SHA256`/`HIDDEN_SHA256` defaults are dead code inside the selftest (m23).
6. Two verdict-equivalent mutants (m01 logger position, m12 redundant `kills` conjunct in `minimal`)
   — the latter is a small counter-simplification observation, not a defect.
