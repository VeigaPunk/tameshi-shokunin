### F1 (minor, non-blocking) — verdict map names no finding ID, and "failed" is the wrong event

Quote: `0 clean; 1 failed; 2 and 64 could-not-evaluate`

`tools/repeat-control.py` at C0 declares `controls_match 0` and `controls_mismatch 1`; exit 2 is
`baseline_nonzero`/`command_unavailable`/`snapshot_tampered`/`setup_error` and 64 is
`invalid_usage`, all five documented as `could-not-evaluate`. So the exit map is right, but the
label is not: exit 1 means *the N controls disagreed*, and the tool's own docstring says of it
"exit 1 says the observations disagreed, nothing about the mutation denominator". A benign stable
nonzero baseline is exit 2, not 1, so "failed" cannot mean "the probed command failed".
Mitigation for the reader: for a gate, "failed" plausibly means "the gate's verdict is failure",
i.e. exactly `controls_mismatch`, which is why this is minor. This is round-27 M3 standing
unchanged at C0. Repair: use the IDs, or write `1 controls disagreed`.
