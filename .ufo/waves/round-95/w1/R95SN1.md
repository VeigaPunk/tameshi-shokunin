## F1 — HIGH — the C2 checker resolves `git` from the inherited PATH; a hostile `git` forges the whole verdict

**Class:** git seal (binary resolution / ambient environment).

**Where.** `.ufo/evidence/round-95/conjunct-disposition-v95.py`:

```python
def sealed_env():
    """No inherited GIT_*; replacement objects ignored; no system/global config."""
    env = {k: v for k, v in os.environ.items() if not k.startswith("GIT_")}
    env["GIT_NO_REPLACE_OBJECTS"] = "1"
    env["GIT_CONFIG_NOSYSTEM"] = "1"
    env["GIT_CONFIG_GLOBAL"] = "/dev/null"
    return env

def git(lane, args, env, text=False):
    return subprocess.run(["git", "-C", lane] + args, capture_output=True,
                          text=text, env=env)
```

`sealed_env()` removes every `GIT_*` variable but keeps **`PATH`**, and `git()` resolves
the bare name `git` through that `PATH`. Compare the C1 counter, which pins it:

```python
def sealed_env():
    return {"PATH": "/usr/local/bin:/usr/bin:/bin", "LANG": "C.UTF-8", "LC_ALL": "C.UTF-8",
            "GIT_NO_REPLACE_OBJECTS": "1", "GIT_CONFIG_NOSYSTEM": "1",
            "GIT_CONFIG_GLOBAL": "/dev/null"}
```

The v95 checker therefore inherits everything the v94 checker inherited **plus** the
new seal, but the seal never covered which `git` runs.

**Reproduction** (`R95SN1-runs/attack_verify.py`, `attack_forgery.py`; the instruments
are extracted from the frozen object store, not from a working-tree copy):

```
$ git -C .../tameshi-shokunin cat-file blob 3ca1981a:.ufo/evidence/round-95/conjunct-disposition-v95.py > checker.py
$ git clone -q --shared .../tameshi-shokunin  $S/verify/lane
$ git -C $S/verify/lane rev-parse 3ca1981a          # -> 3ca1981a2265880ae3ce9b88d316e71741b02426
# a `git` earlier in PATH that answers cat-file/ls-tree from a forged directory
$ PATH=$S/verify/bin:$PATH python3 -I checker.py --lane $S/verify/lane \
      --rev 3ca1981a2265880ae3ce9b88d316e71741b02426 --min-falsifiable 17
DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0
exit 0
```

**Observed** (`R95SN1-runs/R95SN1-verify.json`, key `K1`):

```json
"K1": { "exit": 0,
        "verdict": ["DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0"],
        "committed_receipts_at_rev": "(NONE)",
        "forged_green": true }
```

`committed_receipts_at_rev` is the output of
`git ls-tree -r --name-only 3ca1981a:.ufo/evidence/round-95/pre-freeze/controls` — **empty**.
So the frozen C2 predicate
`DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0` was produced with **no
committed receipt, no committed counter, and no committed manifest**: every byte the
checker graded came from the hostile `git`.

**Control** (same fixture, honest `git`): the checker correctly reports the truth.

```json
"K1_control": { "exit": 1,
  "verdict": ["DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=17"],
  "findings": ["DISPOSITION_FINDING receipt-absent-at-rev selfpin: receipt absent from the
                object store at 3ca1981a2265880ae3ce9b88d316e71741b02426 ..."] }
```

**Expected.** The C2 claim's kill rule (e) — "a receipt that exists only in the working
tree … is accepted" — and kill rule (d) — "the checker or manifest blob at the named
revision differs from the sha256 named in this file" — are both about *which bytes* the
verdict is read from. A hostile `git` in `PATH` answers those questions with bytes the
lane never contained. The C2 predicate is therefore not evidence that the lane's own
bytes say what the verdict says.

**Precondition (stated, not hidden):** the attacker needs write access to a directory on
the invoking user's `PATH`. This is the same class as round-94's F1 (ambient `GIT_DIR`),
which the lane's own sentinel rated HIGH; here the precondition is slightly stronger
(write access to a PATH directory instead of the ability to set one environment
variable) but the consequence is strictly larger, because F1 also defeats the `replace`
refusal and the `counter_sha` binding at once.

**Smallest fix.** Pin `PATH` in the checker's `sealed_env()` exactly as the counter does,
and resolve the binary by absolute path rather than by name:

```python
def sealed_env():
    env = {"PATH": "/usr/local/bin:/usr/bin:/bin", "LANG": "C.UTF-8", "LC_ALL": "C.UTF-8",
           "GIT_NO_REPLACE_OBJECTS": "1", "GIT_CONFIG_NOSYSTEM": "1",
           "GIT_CONFIG_GLOBAL": "/dev/null"}
    return env

GIT = "/usr/bin/git"          # or shutil.which("git", path="/usr/local/bin:/usr/bin:/bin")
def git(lane, args, env, text=False):
    return subprocess.run([GIT, "-C", lane] + args, capture_output=True, text=text, env=env)
```

The same `env` is already handed to the counter subprocess
(`subprocess.run([sys.executable, "-I", cp, "--conjuncts"], env=env)`), so pinning `PATH`
closes that path too.

## F2 — HIGH — the C1 counter with `--rev ''` grades the git index, not a commit

**Class:** file seal (unvalidated revision).

**Where.** `.ufo/evidence/round-95/c1/measure-v95.py`, `main()`:

```python
ap.add_argument("--rev", required=True)
...
rev = a.rev
...
def blob(repo, rev, path):
    p = git(repo, "cat-file", "blob", f"{rev}:{path}", check=False)
```

`--rev` is required but never validated. With `--rev ''` the spec becomes `":<path>"`,
which git resolves against the **index**, not a commit. The C2 checker *does* refuse an
empty `--rev` (its `if not a.lane or not a.rev` sends an empty string to the usage exit,
`exit 64` — probe A15b); the counter does not.

**Reproduction** (`R95SN1-runs/attack_verify.py`, `attack_c1.py`):

```
$ git clone -q --shared .../tameshi-shokunin  $S/verify/lane2
$ printf '| C99 | x | KILLED | differs |\n' >> corpus/knowledge/mutation-case-fleet-sources-census.md
$ git add -A                       # staged, NEVER committed
$ git status --porcelain
M  corpus/knowledge/mutation-case-fleet-sources-census.md
$ python3 -I measure-v95.py --repo $S/verify/lane2 --rev "" --work $S/verify/wk2
C1_SUMMARY rev= n=12 killed=5 survived=7 inconclusive=0 unstable=0 invalid=0 trivial=0 \
           witnessed=7/7 note=present mismatched=0 badrows=1 verdict_tables=1
C1_BADROWS stray-verdict:365:| C99 | x | KILLED | dif
C1_R95_PASS=false
exit 1
```

**Observed** (`R95SN1-verify.json`, key `K2`): `badrows=1` and the `C1_BADROWS` line
names the **staged** row `| C99 | x | KILLED |`. The staged row is in the index, so
`cat-file blob :<path>` returned it.

**Control** (same content, but graded at `HEAD`): `badrows=0` — the committed bytes do
not contain the row. The only difference between the two runs is which revision the
index or the commit tree was read from.

**Expected.** A counter whose own output prints `C1_SUMMARY rev=` (empty) grades
uncommitted bytes while its receipt records an empty revision. The receipt cannot
distinguish the two runs, and kill rule (c) ("the counter blob at the instrument
revision differs from the named sha256, or a receipt was produced by other bytes") is
about the counter, not about the note the counter read.

**Severity note.** The C1 battery always passes a real 40-hex rev, so the shipped path
is safe; the exposure is the standalone command the plan publishes:

```
python3 -I .ufo/evidence/round-95/c1/measure-v95.py --repo <lane> --rev REV --work <empty dir>
```

**Smallest fix.** Validate the revision in the counter (and mirror it in the driver):

```python
if not re.fullmatch(r"[0-9a-f]{40}", rev):
    die("rev-not-a-commit-id")
```

and resolve `rev` to the full 40-hex id before printing it into `C1_SUMMARY`, so a
receipt always names the object it graded.

## F3 — MEDIUM — the C1 driver grades the highest-index `.rerun-N.out`, its writer picks the lowest

**Class:** file seal (receipt selection).

**Where.** `.ufo/evidence/round-95/c1/controls-v95.py`, `receipt_path()` (writer) vs the
grading loop (reader). Both are **byte-identical to round-94's** `controls-v94.py`
(verified by `diff` of the two regions: empty output).

```python
def receipt_path(outdir, name):
    ...
    n = 1
    while os.path.lexists(os.path.join(outdir, "%s.rerun-%d.out" % (name, n))):
        n += 1
    return os.path.join(outdir, "%s.rerun-%d.out" % (name, n))   # LOWEST unused index
```

```python
for cand in [n + ".out"] + ["%s.rerun-%d.out" % (n, i) for i in range(1, 50)]:
    p = os.path.join(a.outdir, cand)
    if os.path.lexists(p):
        found = p          # no break -> the LAST match wins -> HIGHEST index
...
body = open(found, encoding="utf-8", errors="replace").read()
```

The docstring above the writer asserts the opposite of what the reader does:
*"A planted higher-index `<name>.rerun-9.out` no longer outranks a fresh receipt: the
counter picks the lowest unused index atomically."*

**Reproduction** (`R95SN1-runs/attack_driver.py`, `c04_grader_reads_highest_index`;
the committed driver is imported as a module so the committed bytes are exercised):

```
writer run 1 -> ctlX.out
plant        -> ctlX.rerun-9.out   ("STALE-PLANTED")
GRADER reads -> ctlX.rerun-9.out
GRADER content: STALE-PLANTED
```

**Observed** (`R95SN1-driver-results.json`, `C04`):
`writer chose 'ctlX.out', grader read 'ctlX.rerun-9.out' (content 'STALE-PLANTED')`.

**Expected.** The grader must read the receipt the writer wrote. This is the plan's own
kill rule (d) for C1 — "the driver's summary counts a state it did not write" — defeated
by one planted file.

**Smallest fix.** Make the reader agree with the writer: take the **first** existing
candidate in ascending order and `break`, so the fresh `<name>.out` always wins over any
rerun; or have `receipt_path()` return the chosen path and write it into the receipt
body as a `receipt=` line the grader reads back.

## F4 — MEDIUM — the C1 driver grades a symlinked receipt (plain `open()`)

**Class:** file seal (symlink).

**Where.** Same loop as F3: `body = open(found, …)` follows symlinks, while the
candidate scan deliberately uses `os.path.lexists` (which does not follow them). The
write side is hardened (`O_CREAT|O_EXCL|O_NOFOLLOW`); the read side is not.

**Reproduction** (`R95SN1-runs/attack_driver.py`, `c05_grader_follows_symlink`):

```
ln -s $S/atk3/c05_outside.txt $S/atk3/c05/ctlX.rerun-9.out
   (outside file content: "exit=1\nC1_CONJUNCTS selfpin=false\n")
GRADER picks -> ctlX.rerun-9.out
reads        -> exit=1 / C1_CONJUNCTS selfpin=false   (from OUTSIDE --outdir)
```

**Observed** (`C05`): `grader read 'ctlX.rerun-9.out' content='exit=1\nC1_CONJUNCTS selfpin=false'`.
The content that decides MATCH/MISMATCH came from a file outside `--outdir`.

**Expected.** Graded content must come from a regular file inside `--outdir`. The write
side already refuses symlinks; the read side must refuse them too.

**Smallest fix.** Open the graded receipt without following links and refuse a
non-regular file:

```python
fd = os.open(found, os.O_RDONLY | os.O_NOFOLLOW)
with os.fdopen(fd, "r", encoding="utf-8", errors="replace") as f:
    body = f.read()
```

(`O_NOFOLLOW` raises `ELOOP` on a symlink; catch it and treat the state as a failed
grade rather than a pass.) The same `os.open(..., O_NOFOLLOW)` treatment belongs in the
C2 checker if it ever reads receipts from the filesystem again — it does not today (it
reads the object store), so F4 is C1-driver-only.

## F7 — MEDIUM — the C2 checker accepts any revspec for `--rev`

**Class:** git seal (revision pinning).

**Where.** `.ufo/evidence/round-95/conjunct-disposition-v95.py`, `main()`:
`a.rev` flows straight into `GitStore.read_blob` (`"%s:%s" % (self.rev, path)`) and
`store.states()`. No validation that it is a 40-hex object id.

**Reproduction** (`R95SN1-runs/attack_path.py`, `f02_rev_branch_name`):

```
$ git -C <clone> checkout -q -b attacker
$ <forged receipt committed on the branch>
$ python3 -I conjunct-disposition-v95.py --lane <clone> --rev attacker --min-falsifiable 17
DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0

```

**Observed** (`R95SN1-path-results.json`, `F02`): a **branch name** produces the full
green verdict. The revision the audit names can therefore move under the audit's feet
between the run and the reading of the receipt.

**Expected.** The claim freezes a revision; the instrument must read the bytes of that
object, not of whatever a ref currently points at.

**Smallest fix.** Require `re.fullmatch(r"[0-9a-f]{40}", a.rev)` and refuse otherwise;
print the resolved id in `DISPOSITION_INSTRUMENT`.

## F8 — MEDIUM — the C2 checker's `sealed_env()` inherits everything except `GIT_*`

**Class:** git seal (ambient environment).

**Where.** Same `sealed_env()` as F1. Kept: `PATH`, `HOME`, `TMPDIR`, `PYTHON*`,
`LD_*`, `XDG_*`, and every other ambient variable. Dropped: only `GIT_*`.

**Observed.** `PATH` survives → F1 is reachable. `TMPDIR` survives → F11. `HOME`
survives, so `~/.gitconfig` is still read by git (the checker's `GIT_CONFIG_GLOBAL=/dev/null`
catches the global file, but `GIT_CONFIG_SYSTEM` is not set to `/dev/null`; `GIT_CONFIG_NOSYSTEM=1`
covers `/etc/gitconfig`, so that path is closed).

**Expected.** The C1 counter replaces the environment wholesale; the C2 checker filters
it. A seal that keeps the ambient `PATH` is not a seal against the ambient `PATH`.

**Smallest fix.** Same as F1 — build the environment explicitly:

```python
env = {"PATH": "/usr/local/bin:/usr/bin:/bin", "LANG": "C.UTF-8", "LC_ALL": "C.UTF-8",
       "HOME": work, "TMPDIR": os.path.join(work, "tmp"),
       "GIT_NO_REPLACE_OBJECTS": "1", "GIT_CONFIG_NOSYSTEM": "1",
       "GIT_CONFIG_GLOBAL": "/dev/null"}
```

This closes F1, F8 and F11 together.

## F9 — MEDIUM — a receipt whose `counter_sha=` is copied from the honest counter is accepted

**Class:** counter-sha binding.

**What the plan declares.** §C2 *Declared limits*: "authenticity of a hand-written
receipt that carries the correct `counter_sha=` is not certified by this checker — the
`counter_sha=` line binds the receipt to the counter blob, not to the driver run."
Kill rule (e) is narrower: it fires only when a receipt "exists only in the working
tree, or carries a wrong `counter_sha=`".

**Reproduction** (`R95SN1-runs/attack_supp.py` `d01`, `attack_c2b.py` `a07`,
`attack_forgery.py` `h02`): the whole 17-receipt set, hand-written, each carrying the
honest counter blob's sha256 and a `C1_CONJUNCTS` line with every conjunct false —
no clone, no counter invocation, no counter bytes anywhere:

```
$ python3 -I conjunct-disposition-v95.py --lane <clone> --rev <rev> --min-falsifiable 17
DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0
exit 0
```

**Observed** (`D01`): exit 0, `findings=0`, with no counter run behind the receipts.
`A07` shows the same for a single row: a hand-written `renamed-result.out` containing
only `C1_CONJUNCTS ids=false` satisfies the `ids` row.

**Expected.** The declared limit names this. The consequence for the C2 *calibration*
claim is the point: the C2 predicate
`DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0` certifies that a
**committed text file** says the conjunct is false. It does not certify that a counter
run ever moved it.

**Smallest fix** (beyond the declared limit): require the receipt to carry provenance
the forger cannot invent from the public bytes — e.g. the battery's own driver digest
plus the parent revision and the driver's stdout hash, and have the checker recompute
the expected `counter_sha` from the **mutant** counter blob each state actually ran
(the D01–D05 receipts already carry the mutant's digest; the `run_ctl` receipts carry
the frozen counter's digest, which is the same public value for all 17 rows).

## F10 — MEDIUM — a counter edited to force `ok = True` with a recomputed pin passes the self-pin

**Class:** pin/identity.

**What the plan declares.** §C1 *Declared limits*: "the self-pin certifies one and only
one pin line before hashing, **not** that the executed bytes are the pinned bytes
(identity stays bound by kill rule (c))".

**Reproduction** (`R95SN1-runs/attack_c1b.py`, `i11_recomputed_malicious_pin`):

```
# counter bytes with "ok = all(conj.values())" replaced by "ok = True  # MALICIOUS"
# and SELF_SHA256 recomputed over the modified bytes (the instrument's own algorithm)
$ python3 -I counter-recomputed.py --repo <clone> --rev HEAD --work <empty>
C1_R95_PASS=true
exit 0
```

**Observed** (`R95SN1-c1b-results.json`, `I11`): `self_pin_passed=True`,
`claims_C1_R95_PASS=true=True`. The counter reports a PASS it did not earn.

**Expected.** Accepted by design, per the declared limit. The anchor that must carry the
identity is kill rule (c): "the counter blob at the instrument revision differs from the
named sha256". `.ufo/waves/round-95/claims.json` does name
`instrument_sha256 = 5f0d1770…` and `.ufo/waves/round-95/freeze-rev.txt` repeats it — but
**no instrument checks it**; it is a human/validator obligation. That is a real
dependency the round should state explicitly rather than leave implicit.

**Smallest fix.** Have the counter (or the driver) verify the *committed* blob's sha256
against a value carried outside its own bytes — e.g. the battery already writes
`counter_sha=` in every receipt; the C1 side has no equivalent check that the blob it
executed is the one the freeze names. Add to the driver a refusal when
`sha256(counter blob at --rev)` differs from the expected digest passed on the command
line.

**Defended variants of the same class** (all refused, receipts in
`R95SN1-c1b-results.json`): a second pin line before the `__main__` guard → exit 2
`C1_SETUP self-pin-line-count` (B09); the same after the guard → same (B10); a second
line with the **same** digest → same (I12); a second line the regex does not match
(uppercase hex, single quotes, no spaces, trailing spaces) → exit 2
`C1_SETUP self-pin-mismatch` (I13 ×4). The v95 pin-line-count rule works as advertised.
