## 5. Findings by severity

### No `FALSIFIES-WORDING`

No v95 cell accepted an artifact the frozen C2 sentences say it must refuse. Specifically:

- a receipt present only in the working tree → `receipt-absent-at-rev`, exit 1;
- a committed receipt with `counter_sha=` = 0×64 → `receipt-counter-sha-mismatch`, exit 1;
- a committed receipt with no `counter_sha=` line → `receipt-counter-sha-mismatch`, exit 1;
- a `refs/replace` entry naming the counter blob, the manifest blob, or the audited commit
  → `DISPOSITION_SETUP replace-refs-present`, exit 2;
- ambient `GIT_DIR` → no effect (the run is byte-identical to the untainted run);
- a committed symlink receipt → refused (`receipt-counter-sha-mismatch`), never followed;
- `--receipts` traversal → 17 × `receipt-absent-at-rev`, exit 1.

The v94 before-column is reproduced without exception (`findings=0` on both receipt
forgeries; it reads the substituted counter blob and the forged manifest under replace refs
and ambient `GIT_DIR`).

### Medium — the manifest is not authenticated, and the checker does not pin it

`seal/forged-manifest-reasons-v95.out` is exit 0, `findings=0` on a *committed, replace-ref
free* rev (`01b58421`) whose manifest is forged three ways:

1. an `unfalsifiable` reason whose only “digest” is `000000000000` (12 hex, not a pin digest);
2. an `unfalsifiable` reason naming `state fake-never-run`, a committed `.out` file that the
   battery never produced (`present_states` is “any `.out` in the receipts tree”);
3. a state row pointing at `bogus-pins.out`, a hand-written receipt with the correct
   `counter_sha=`.

No sentence in §C2 claims manifest authenticity, and the plan's kill rule (d) puts the
manifest digest comparison in the round's external validation (`claims.json`). But at
`2026-11-08T07:48:18-03:00` **`claims.json` does not exist** (`.ufo/waves/round-95/claims.json`
absent), and the checker never reads it: the only in-tool protection is the caller's `--rev`,
which names an object, not a digest. An audit that takes a written verdict from an arbitrary
`--rev` therefore inherits whatever manifest is at that rev. Evidence that this is real (not
theoretical): `seal/posthoc-commit-replace-v94-nomin.out` shows the same forged manifest being
accepted by v94 through a replace ref (`falsifiable=0 unfalsifiable=19 findings=0`).

### Low/medium — the `unfalsifiable` reason test is weaker than its docstring

The checker's own docstring says a reason must name “a declared battery state or a pin
digest”. The code accepts (a) any 12+ hex substring as a digest and (b) any `.out` filename
in the receipts tree as a state. Both are demonstrated by `01b58421` above. This is inherited
from round 94's A4 test and is not exercised by the real manifest (its two reasons name
`state timeout` and the real `GATE_SHA256`), so it is a calibration gap in the *test*, not a
falsification of the frozen bytes. Fix direction: require a 64-hex digest that equals
`GATE_SHA256` (or another pinned digest), and require the state name to be in a battery
manifest (e.g. `census-mutants.json`/`pins.json`), not merely `ls-tree` output.

### Low — the printed verdict does not name the audited paths

`DISPOSITION_INSTRUMENT` prints the counter sha256 and conjunct count, then the rows and the
summary. It does **not** print `--rev`, `--receipts`, `--counter`, or `--manifest`. Because
`--receipts` is caller-controlled, a run with `--receipts .ufo/evidence/round-95/alt-controls`
prints the same `DISPOSITION rows=19 … findings=0` as the default run
(`seal/alt-receipts-v95.out` vs `seal/clean-v95.out`). The frozen command does not pass
`--receipts`, so the claim is safe as frozen, but a reader of a pasted transcript cannot tell
which evidence root produced it. Recommendation (report only; no lane edit): print
`rev=`/`receipts=` on the `DISPOSITION_INSTRUMENT` line.

### Informational — selftest case label

`SELFTEST a4-mechanism-word-cheat` fails on `reason-too-short` (the reason is 26 chars), not
on the state/digest branch; the branch is covered by `a4-prose-state-word-cheat`. The selftest
still prints 11/11 and exits 0. Cosmetic, but a future editor could mistake the first case for
coverage of the mechanism-word test.

## 6. Residual risk and verification gaps

- **R-limit (declared):** a hand-written receipt carrying the correct `counter_sha=` passes.
  Demonstrated constructively: the `4138ff0c` positive is 16 hand-written receipts and prints
  `findings=0`. The `counter_sha=` line binds the receipt to the counter **blob**, not to a
  driver run; driver-produced provenance remains the declared gap (plan §C2 Declared limits).
- **R-manifest (not declared):** manifest authenticity is unpinned in the checker; kill rule
  (d) depends on a `claims.json` that is absent at writing. If the round's validator does not
  compare the manifest/counter blobs to `claims.json`, a forged manifest committed at the
  verdict rev is undetectable by the checker.
- **R-caller (not declared):** `--receipts`/`--counter`/`--manifest` are caller-controlled and
  unrecorded in the output.
- **V1:** the real round-95 battery receipts (`pre-freeze/controls/`, 0 files at
  `2026-11-08T07:48:18-03:00`) and `corpus/lessons/round-95.md` were absent, so the battery
  could not be run and the 17/17 real-receipt provenance check is **not run**. The synthetic
  set exercises the same code path; the real set must be re-run at the integrated instrument
  revision with the command in §3 and the §2 matrix repeated.
- **V2:** the v95 instruments are uncommitted at writing; the matrix's `--rev`s are scratch
  commits built from byte copies. The final lane instrument revision must reproduce the five
  frozen cells; a byte-diff of the integrated files against the hashes in §1 is the check.
- **V3:** the v94 checker extracted from `6a2a1fdd` is the rev-3 checker named by the plan;
  the lane worktree copy `.ufo/evidence/round-94/conjunct-disposition-v94.py` has the same
  sha256 (`6d4d2706…`), so the seed for this seat is exactly the committed `6a2a1fdd` bytes,
  as specified.
- **V4:** the `git replace` probe and fixtures assume `git` honours replace refs in
  `cat-file` without `GIT_NO_REPLACE_OBJECTS`; that was probed and confirmed with git 2.56.0,
  and the counter's own internal `sealed_env()` already sets the variable (the leak is in the
  *outer* checker's `cat-file`, which v95 seals and v94 does not).
