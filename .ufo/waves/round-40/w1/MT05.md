## Depth finding — the `0` is a name artifact, not a scratch-guard test

On pristine bytes the trace shows the same line scoring 0 for a different reason:

```
pristine_fixture_line = "os.replace('/tmp/a', '/tmp/scratch-out.json')"
pristine EXPECTED_RE -> None
pristine SCRATCH_RE  -> <re.Match object; span=(12, 17), match='/tmp/'>
pristine classify_text = (1, 0)
```

`EXPECTED_RE` misses because `scratch-out.json` carries no `.expected` / `expected.txt` /
`expected.json` / `golden` / `snapshot` token, so the scratch branch is never the deciding
factor. Consequence, verified by direct execution rather than inference — neuter the guard
(`SCRATCH_RE = re.compile(r'(?!)')` in a copy of the pinned v2, fixtures unchanged):

```
$ python3 /tmp/tameshi-r40-MT05/v2-noscratch.py --selftest --fixtures /tmp/tameshi-r40-MT05/fixtures.pristine.json
WRITE_CENSUS_V2_SELFTEST: bytes_unflagged=1 replace_unflagged=1 bytes_flagged=0 replace_flagged=0 scratch_replace=0
exit=0
```

A v2 with no scratch suppression at all still passes the selftest, so `scratch_replace=0` as
pinned is vacuous with respect to `SCRATCH_RE`. Note also that the mutant is byte-for-byte the
same site as the already-placed `replace_unflagged` fixture (`os.replace(tmp, 'case.expected')`,
quote style only), i.e. the two fixtures collapse onto one class once `/tmp/` is removed. This
is a coverage note only; the frozen predicate is untouched and not rewritten.
No predicate text was edited. `--control` (`C1_R40_CONTROL_PASS=false`, exit 1) is unaffected by
this key: `control()` reads only `bytes_unflagged` and `replace_unflagged`.
