## Depth finding

1. `EXPECTED_RE`'s literal-only rule has **no behavioral test** anywhere in the
   round-40 fixtures. `.ufo/evidence/round-40/census/fixtures.json` contains only
   quoted literals (`'expected.json'`, `'case.expected'`); there is no negative
   fixture where a write line names a bare `expected` variable. Both mutants
   reproduce the pristine `WRITE_CENSUS_V2_SELFTEST` line byte for byte, and all
   five planted classifications plus both `live_*` checks stay green.
2. The only clause sensitive to this mutation is `mutant_json_killed`
   (`measure.py:31,166,178,229`) — a **structural proxy**: it asserts the string
   `expected\.json` is still load-bearing, not that variables are excluded.
   Mutant A dies because the string vanishes; mutant B, which keeps the string
   load-bearing and adds the forbidden branch, passes all eight conjuncts and
   `C1_R40_PASS=true`.
3. Blast radius today is zero, which is why the gap is latent: over the 24
   `tools/*.py` files, mutant A and mutant B produce **0** differing
   `classify_text` results. The only live expected-value write is already a
   quoted literal (`tools/registry-replay.py:123`,
   `(out / 'expected.json').write_bytes(...)`), so no current count moves. The
   defect class is exactly the round-39 pre-run defect ("found before any
   deciding run, so not a scored miss") and it is still not covered by a fixture.
4. Consequence for the claim: the frozen C1 predicate proves `expected.json`
   is recognized and `os.replace` is seen; it does **not** prove the expected
   recognizer stays literal-anchored. Any future edit that adds the bare-word
   branch with quote guards passes the counter silently.
