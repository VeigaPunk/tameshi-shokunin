## 4. Findings (severity-ordered)

No blocking defect; the section is executable from the page at its named pin and every stated
outcome reproduced.

- **M1 (minor, naming):** rules 2 and 7 call `cf41efaa…` a "revision"/"same revision"; it is the
  tool file's sha256, and `git rev-parse cf41efaa` fails in every repo. A cold reader's first
  move fails and the pin is not resolvable without hashing all five historical blobs.
  *Recommendation:* "at tool sha256 `cf41efaa…` (blob `9f1d3c33`)"; keep the word "revision"
  for git revisions (the `REGRESSION_PIN … rev=` fields).
- **M2 (minor, stale count in a rule):** rule 2 states the PASS closing line as
  `cases=4 passed=4`. At HEAD the ledger has six legs and closes `cases=6 passed=6` (observed,
  rc 0). The discipline (`cases == passed`, exact legs) still holds; the literal 4 is
  pin-dated. *Recommendation:* "closing line's `cases=n passed=n` where n is the current leg
  count (4 at `cf41efaa…`; 6 at `75ed934d…`)".
- **M3 (minor, pin-dated selftest count):** rule 7's `MUTATE_SELFTEST: 67/67 pass` is exact at
  `cf41efaa…` but the working tree today reports `80/80` (rc 0 both). Not a wrong expectation
  because the sentence names the pin, but a reader executing against the tree sees a different
  number. *Recommendation:* state both, or say "the count is pin-bound".
- **M4 (minor, dead evidence anchor):** `/tmp/w7-tameshi-1/flip-run.out` (rule 3) is gone; the
  negative-run example cannot be opened, only regenerated. Regeneration succeeded exactly, so
  non-blocking. *Recommendation:* cite an in-repo evidence path (or the `--workdir` receipt
  filename) so the quoted rows stay re-openable.
- **M5 (minor, block-shape precision):** rule 1 enumerates one `REGRESSION_WORKDIR`; the real
  block carries one per leg plus a closing `REGRESSION_WORKDIR: <root> (kept|removed on PASS)`
  — 5 for 4 legs in the observed receipt. A reader parsing the block should not assume one.
  *Recommendation:* "per leg one `REGRESSION_WORKDIR`, plus the closing root line".
- **M6 (minor, citation precision):** rule 6's parenthetical `plans/round-7.plan.md:11-15`
  supports read-only attestation ("reproduced … or its missing piece named") but does not
  contain the rule's "the sibling's note is never edited" clause. Executable as written;
  the citation is simply narrower than the sentence.
- **R4 (bounded recommendation, adjacent record):** `fleet-kill-rate-ledger.md:45` says the
  kumitate pin is "unchanged r2 → today"; measured at HEAD it changed after the pin
  (`1a8eed5`). Rule 5's own warning is what makes this harmless for the rate, but the ledger's
  present-tense cell should be phrased as an as-of date ("unchanged at the r7 read,
  2026-10-14") so the standing view stops decaying.
