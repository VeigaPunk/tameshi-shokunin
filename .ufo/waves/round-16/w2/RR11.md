## Findings

### Minor 1 — four "Snapshot line" pointers do not resolve to the old wording (non-blocking)
Rows 61, 269-270, 277-279, 1388/1392. A reader doing `git show e69b488:SKILL.md | sed -n
'269,270p'` sees the item header, not the quoted "different mutant" wording. The wording itself is
present at the snapshot (grep-findable) and the repair is present and line-neutral, so this is
navigation debt, not a broken repair. Evidence: diff old-side numbering above; `awk` output of
`SKILL.old.md` lines 61/63, 269-272, 277-280, 1388-1393.

### Minor 2 — the `${n}` repair is self-contradictory (wrong expectation, non-blocking)
`SKILL.md:278` now reads: "`${n}`, `slice(0, 6)`, `[[ "$got" -ge "$floor" ]]` appear in the
manifests (…; `${n}` in Appendix A's D4 below)". The main clause still asserts `${n}` appears in
the manifests, but grep -F finds `${n}` in neither census note; it occurs only in Appendix A's D4
on the page (`SKILL.md:575`). The errata's "Now" cell says "the notes carry the other three
tokens", which the repaired sentence never states — it parenthesises the correction while leaving
the false attribution in the main clause. A reader copying the token list for regex scoping is
still told the wrong provenance. (The sentence's practical instruction — literal replacement,
escape metacharacters — is unaffected.)

### Minor 3 — `git show 97cf436b…3580` is not executable (wrong retrieval instruction, non-blocking)
`SKILL.md:1715` offers `git show 97cf436b…3580` as the way to reach the old wording. That sha256 is
a content hash, not a git object id: the full literal argument exits 128 with
`fatal: ambiguous argument … unknown revision or path not in the working tree`. The equivalent that
works is `git show e69b488:SKILL.md` (verified: hash `97cf436b…3580`). The errata's own minor-gaps
paragraph already names "anchors written as tool sha256 values rather than git revisions" as debt;
this row repeats the pattern in a command position.

### Minor 4 — the named ledger does not exist (dangling evidence path)
`SKILL.md:1711`-`1712` names `.ufo/evidence/round-16/coldread/ledger.json` and says minor gaps are
"kept as named debt in the ledger". At c699c8c the path is absent (`git cat-file -e` fatal) and it is
absent on disk now (`find` empty). `assemble.py:59` has that exact `DEFAULT_OUT`, i.e. the file is
the assembly output, presumably produced later in wave 2; at the named revision the pointer does not
resolve, so the debt record is the errata prose, not the ledger.

### Minor 5 — "six-leg registry" left stale beside the repaired row (unrepaired count)
`SKILL.md:1391` (visible as unchanged context in the `@@ -1387,10` hunk that row 1388/1392
repairs) still says `(six-leg registry, git-materialized replay)`. At c699c8c
`tools/mutate-and-run.sh` registers seven ledger legs (the seven `regression_case_git` calls only;
the other seven occurrences are selftest fixture calls), and the errata itself dates four at r7-1
and seven since round 16 at row 925. Historical states confirm the drift: 4 legs at `9f1d3c3`,
6 at `606716f`, 7 at c699c8c. The full-page report repaired the notes' "(six)" at 1390 but left the
registry count one line below, so the same table now carries "seven since round 16" and "six-leg
registry" at the same commit.
