## F1 — HIGH — the `pin` / `pins` seal is self-referential: a lane commit can redirect the measurement to a foreign gate and still report `pin=true pins=true green=true`

**Where.** `measure-v93.py`:
`pin = gate_sha == g.get("sha256")` (L~370) and `derived = {… "gate_commit": g.get("commit"),
"gate_path": g.get("path"), "gate_sha256": gate_sha …}` compared against the committed
`pins.json` (L~375-385). `g` is the spec blob read from the lane at `--rev`; `gate_sha` is
the sha256 of the blob that same spec points at. Both conjuncts therefore compare the spec
**to itself**. `gate.repo` (`g.get("repo")`) is an arbitrary path taken verbatim from the spec
(L363, L391).

**Exploit path.** One lane commit that (a) edits `census-mutants.json`'s `gate` block to name
a different repo/commit/path/sha256 and (b) regenerates `pins.json` with the lane's own
committed `make-pins.py` (which re-derives from the *same* spec, so `--check` also passes) is
enough. The counter then materialises and **executes** the foreign gate.

**Evidence** — `R93SN1-probe18.log` (canonical repro, script `R93SN1-probe18.sh`):
```
PROBE F1.pins-now-name-the-foreign-gate  "gate_commit": "672d640b…", "gate_sha256": "e9b363bd…"
PROBE F1.pin-pins-green-canary            pins=true pin=true green=true canary=true
PROBE F1.FOREIGN-gate-EXECUTED            YES - the FOREIGN gate bytes were executed
PROBE F1.executed-bytes-digest            e9b363bd5a465776 vs foreign e9b363bd5a465776…
PROBE F1.control-executed-gate-has-marker no marker - the real fleet gate ran
```
The control arm (same counter, untouched lane at `855f0c1c`) shows the marker is absent, so
the foreign execution is caused by the spec+pins swap and nothing else.
`R93SN1-probe9.log` (K1) reproduces it with a different fixture and also shows
`pins=true pin=true green=true` after the swap.

**Impact.** The plan's declared limit — "`green`, `canary` and `unstable0` are declarations
where C2 says so: the gate bytes are pinned, so no committed lane state can falsify …" — is
false as written: a *committed lane state* (the spec+pins pair) does falsify the pin.
The counter certifies that "the gate is the fleet gate at `f47ad6b`" only by self-consistency.
**The frozen claim at `855f0c1c` is not falsified** (at that rev the spec is the plan-stated
`ce8983d5…`); the defect is in the *instrument's seal*, so any re-run at a lane rev whose
spec was repointed silently measures the wrong gate and prints `pin=true`.

**Smallest remediation.** Anchor the gate identity in something the counter reads that the
spec cannot rewrite — e.g. compare the derived `gate_commit`/`gate_sha256` against constants
compiled into the counter's own self-pinned bytes, or against a `pins.json` whose digest is
pinned by the counter; and refuse (`die`) rather than report `pins=false` when the derived
gate identity does not match that anchor.

## F2 — HIGH — the M4 receipt guard is defeated by a pre-existing dangling symlink in `--outdir`: the receipt write lands outside the outdir

**Where.** `controls-v93.py` `receipt_path()` (L252-260) uses `os.path.exists(p)`, which
**follows** symlinks, to decide whether a receipt already exists; then the caller does
`open(receipt_path(outdir, name), "w")` (L278, L359, L369, L384, L415), which also follows
the symlink.

**Exploit path.** Plant a **dangling** symlink `pos-real.out -> /anywhere/else` in `--outdir`
before the run. `os.path.exists` reports False (the target does not exist), so the guard
believes there is no receipt and picks the symlink path itself; `open(..., "w")` then creates
the *target* of the symlink. The receipt content is written outside `--outdir`, at a path the
caller never named, and the outdir is left holding only the symlink — which the summary scan
later resolves and grades as if it were a receipt.

**Evidence** — `R93SN1-probe3.log` (X3, real driver):
```
PROBE X3.escape-file-created   YES
PROBE X3.escape-content        control=pos-real clone_rev=2df4bb3b37e3e4efd316d803f55903111
PROBE X3.outdir-listing        C1-summary.txt pos-real.out
```
`R93SN1-probe.log` (E5) shows the same via the function in isolation:
`chosen_is_symlink=True`, `payload-written-outside-outdir=YES`.
`R93SN1-probe5.log` (D) shows the same via `make-pins.py --lane ""` (F10 context).

**Impact.** A write escapes the directory the operator constrained the run to; and because
the outdir entry is a symlink, the evidence that the summary grades is attacker-chosen
content, not what the driver produced. This is the item's "M4 receipt guard cannot be
defeated by a pre-existing symlink" — **it can**.

**Smallest remediation.** Use `os.path.lexists()` (not `os.path.exists()`) in
`receipt_path()`, and open receipts with `O_NOFOLLOW|O_CREAT|O_EXCL` (or write to a temp
name and `os.link`/`os.replace`), so a symlinked entry can never be the write target and
never the graded artifact.

## F3 — MEDIUM — a planted higher-index receipt outranks the driver's own fresh receipt in the summary

**Where.** `controls-v93.py` summary scan (L426-434): for each expected control it walks
`[n+".out"] + ["n.rerun-1.out" … "n.rerun-49.out"]` and **overwrites** `found` on every
hit, so the *highest* rerun index wins — a pre-planted `n.rerun-7.out` beats the driver's
own freshly written `n.out`.

**Exploit path.** Plant `nowork-base.rerun-7.out` containing `exit=0` before the run. The
driver writes its own correct `nowork-base.out` (`exit=2`); the summary then grades the
planted file.

**Evidence** — `R93SN1-probe19.log` (T1/T2/T3) and the planted-receipt run:
```
PROBE T2.chosen-for-nowork-base  nowork-base.rerun-7.out
summary: nowork-base MISMATCH exit=0     (the driver's own receipt says exit=2)
```
**Impact.** The summary can report a state the driver never produced, in either direction
(forged `exit=0`/`C1_R93_PASS=true` would flip a MISSING/MISMATCH to MATCH). The plan's
M1/QUALITY-152 property — "the summary is derived from the receipts on disk" — holds only if
the receipts on disk are the driver's own; the scan prefers whatever is newest by index,
not by authorship.

**Smallest remediation.** Have the driver record the exact receipt path it wrote for each
control (in memory, and/or stamp each receipt with the driver's own run id) and grade that
path; treat other files as untrusted and report them separately.

## F4 — MEDIUM — `--rev ""` is accepted and silently measures the git INDEX, not a commit

**Where.** `measure-v93.py` `blob()` builds `f"{rev}:{path}"` (L~125) and passes `rev`
straight through from `main()` (`rev = a.rev`, no validation). With `rev == ""` the spec is
`:path`, which git resolves against **the index** (stage 0), not a commit.

**Evidence** — `R93SN1-probe10.log`:
```
PROBE L1.commit-versions      COMMITTED
PROBE L1.index-version(:path) STAGED-BUT-NOT-COMMITTED
PROBE L2.PASS                 C1_R93_PASS=true
PROBE L2.summary-rev-field    rev=
```
and `R93SN1-probe17.log` (S2) for the **driver**: with `--rev ""` the driver extracted a
modified, index-only counter blob and ran it —
```
PROBE S2.index-counter-has-marker    1
PROBE S2.commit-counter-has-marker   0
PROBE S2.driver-saw-the-INDEX-counter CONTROL_INSTRUMENT sha256=e97e2080d9d8…  (≠ 18903602…)
```
**Impact.** A blank or missing `--rev` yields a **passing** receipt whose provenance is the
index — including uncommitted staged bytes — and whose summary line reads `rev=` (empty), so
the receipt cannot even name what it measured. The driver's `--rev ""` path extracts the
instrument from the index rather than from the commit it claims to certify.

**Smallest remediation.** Validate `--rev` as a full 40-hex object name (or at least
non-empty) in both the counter and the driver, and refuse otherwise.

## F5 — MEDIUM — `gate.repo == ""` makes the counter run `git -C ""`, i.e. read and EXECUTE the process CWD repository

**Where.** `measure-v93.py` L358 `git(fleet, …)` and L363 `blob(fleet, …)` with
`fleet = g.get("repo","")` taken verbatim from the spec.

**Exploit path.** `git -C ""` does not error: git treats the empty path as "no `-C`", so the
command runs against the **process current working directory's** repository. The lane's
host guard makes the process CWD the fleet root — precisely the 2026-11-06 incident shape
named in my brief.

**Evidence** — `R93SN1-probe.log` (E1) and `R93SN1-probe9.log` (K3):
```
PROBE E1.git-C-empty.toplevel   rc=0 out=/…/cwdrepo
PROBE E1.git-C-empty.commit     rc=0 out=[main 7005ffe] x        (it COMMITTED there)
```
`R93SN1-probe12.log` (N1) and `R93SN1-probe13.log` (O1): with a spec whose `gate.repo` is
`""` and `gate.commit` names an object in the CWD repo, the counter read that repo's gate
blob and **executed** it —
`PROBE O1.CWD-gate-executed  YES - gate bytes came from the CWD repo and were EXECUTED`,
with the executed digest equal to the CWD repo's digest.
`R93SN1-probe14.log` (P2) shows the same with the spec+pins swap.

**Impact.** A committed spec can make the counter execute shell code out of an unrelated
local repository (whatever is the CWD at run time) while `pin=true` and `green=true` — the
gate bytes are run through `bash gp selftest` / `bash mgp validate` (L126, L~409-415).

**Smallest remediation.** Validate `gate.repo` as a non-empty absolute path before any
`git -C` call (and refuse `""`), and pass `-C` only with a validated absolute path.

## F6 — MEDIUM — `controls-v93.py` mutating git calls inherit the ambient environment: `GIT_DIR` diverts the fixture commit into another repository, and ambient git config executes a hook during the commit

**Where.** `controls-v93.py` `sh()` (L52-56) and every bare `subprocess.run([...])` in that
file (L274, L337, L357, L367, L376, L379, L382, L413) pass **no `env=`**. The counter, by
contrast, scrubs: `sealed_env()` (L87-90) replaces the whole environment with a fixed dict
(`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_NO_REPLACE_OBJECTS=1`), which is
why the counter is unaffected (probe8 `J5` → `C1_R93_PASS=true` with a hostile ambient env).
The asymmetry is in the driver, which is the component that mutates repositories.

**Exploit path / observed effects.**
1. *Ambient `GIT_DIR`* — the driver's fixture commit lands in the GIT_DIR repository instead
   of the scratch clone it created and whose toplevel it asserted.
   `R93SN1-probe11.log` (M2): `PROBE M2.hijack-has-r93-control-commit 1` while
   `PROBE M2.intended-clone-has-commit` is empty. The `clone_at()` toplevel guard does not
   catch it: `R93SN1-probe9.log` (K2) shows `git -C <dir> rev-parse --show-toplevel` still
   reports the `-C` directory under a hijacked `GIT_DIR`, so
   `PROBE K2.guard-would-pass  YES - show-toplevel reports the -C dir, so the guard PASSES
   while the commit lands elsewhere`.
2. *Ambient `GIT_INDEX_FILE`* — `git add -A` writes the index to an arbitrary path outside the
   clone (`R93SN1-probe2.log` H3, `R93SN1-probe6.log` H3:
   `PROBE H3.redirected-index-created YES`).
3. *Ambient `GIT_CONFIG_GLOBAL` with `core.hooksPath`* — a hook **executed** during the
   driver's fixture commit: `R93SN1-probe8.log` (J4)
   `PROBE J4.hook-executed  YES - ambient git config drove a hook during the fixture commit`
   / `PROBE J4.marker  HOOK-EXECUTED pid=2071835`.

**Impact.** Ambient configuration decides where the battery's commits and index writes go,
and can run arbitrary code inside the operator's session during a verification run. This is
the same class as the 2026-11-06 `git -C ""` fleet-root commit.

**Smallest remediation.** Route every git invocation in `controls-v93.py` through one
scrubbed-environment helper (the counter's `sealed_env()` pattern), extended to drop
`GIT_DIR`, `GIT_WORK_TREE`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`,
`GIT_ALTERNATE_OBJECT_DIRECTORIES`, and to set `GIT_CONFIG_GLOBAL=/dev/null` +
`GIT_CONFIG_NOSYSTEM=1`. Additionally assert, after `clone_at`, that the clone's git dir is
the one expected (`git -C dest rev-parse --absolute-git-dir`) rather than trusting
`--show-toplevel`.

## F7 — MEDIUM — `--work` / `--outdir` are not validated: relative or empty values write into the process CWD

**Where.** `controls-v93.py` `main()`: `os.makedirs(a.outdir, exist_ok=True)` (L332) and
`work = os.path.realpath(a.work)` (L333) — `realpath("")` is the CWD. `measure-v93.py`
`main()`: `work = os.path.realpath(a.work)` (L~338) — same.

**Exploit path.** `--outdir relative-receipts` and `--work relwork` write into the CWD; the
lane's host guard makes the CWD the **fleet root**. `--work ""` makes the counter
materialise its entire working tree (the extracted gate, the canary, per-mutant witness
lanes) into the CWD.

**Evidence** — `R93SN1-probe8.log` (J3, M4) and `R93SN1-probe3.log` (X2, X4):
```
PROBE J3.cwd-tree   . ./relwork ./relwork/pristine ./relwork/tmp ./relwork/canary ./relwork/w-C01 …
PROBE M4.written-into-process-cwd  . ./relout ./relout/nowork-base.out ./relout/C1-summary.txt ./relwork …
PROBE X2.receipt-landed-in-cwd     YES
PROBE X4.cwd4-tree   . ./pristine ./pristine/scripts ./pristine/scripts/fixtures ./pristine/scripts/sources-census.sh …
```
**Impact.** Files land outside the scratch directory the operator chose, in a directory that
may be a tracked repository. Exactly the "no write can land outside the scratch dir" property
my brief asks about.

**Smallest remediation.** Require `--work` and `--outdir` to be non-empty absolute paths;
refuse (exit 2) otherwise; and re-`realpath` + assert containment after creating them.

## F8 — MEDIUM — the disposition checker's "names the seal that forbids the falsifier" test is a substring match: a contentless reason containing "pin" passes

**Where.** `tools/conjunct-disposition.py` `check()`: the mechanism test is
`any(tok.lower() in reason.lower() for tok in MECHANISM)` with
`MECHANISM = ("pin", "sealed", "seal", "gate bytes", "GIT_", "pinned", "replace")`, and
`MIN_REASON = 40`.

**Exploit path.** A reason of ≥40 characters that names no mechanism at all but happens to
contain the substring `pin` passes as a legitimate mechanism declaration.

**Evidence** — `R93SN1-probe4.log` (P8) and `R93SN1-probe2.log` (E11):
```
PROBE P8.contentless-with-shipping  len=61 findings=0
PROBE P8.contentless-with-pin-word   len=58 findings=0
PROBE P8.genuine-mechanism            len=82 findings=0
```
("the shipping manifest was never checked by anyone at all here" — contains "shipping".)
**Impact.** The C2 kill rule (a) — "an `unfalsifiable` reason … names no mechanism" is a
finding — is defeated by filler text. A manifest could declare all 19 conjuncts
unfalsifiable with contentless 40-character reasons and still print `findings=0`. (The
round's own all-unfalsifiable cheat receipt
`.ufo/evidence/round-93/pre-freeze/c2-cheat-all-unfalsifiable.out` exercises the counting
side of this, not the reason-quality side.)

**Smallest remediation.** Require a whole-token mechanism match (`\b(pin|pinned|seal|sealed)\b`
against a curated list, excluding `pinned`/`shipping` accidents) **and** require the reason to
name a concrete artefact (a file path, a conjunct key, or a `C1_SETUP` token); raise
`MIN_REASON` and add the mechanism check to the selftest's "must produce a finding" cases.

## F9 — MEDIUM — the frozen C2 counting command does not reproduce at the frozen revision

**Evidence** — `R93SN1-probe4.log` (P7):
```
PROBE P7.at-855f0c1c.rc     2
PROBE P7.at-855f0c1c.output DISPOSITION_SETUP manifest-absent-at-rev
PROBE P7.at-HEAD.rc         0
PROBE P7.at-HEAD.output     DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0
PROBE P7.selftest           DISPOSITION_SELFTEST: 6/6 pass
```
The C2 instrument (`tools/conjunct-disposition.py` and `.json`) was added in commit
`9bf52b03`, which is a **descendant** of the frozen instrument revision `855f0c1c`
(`git merge-base --is-ancestor 855f0c1c 9bf52b03` succeeds). At `855f0c1c` the manifest does

**Impact.** The C2 frozen command as stated — `… --rev 855f0c1c59ee2af7f184d8de62d02cdd576eb94e`
→ `DISPOSITION rows=19 falsifiable=17 unfalsifiable=2 findings=0` — exits 2 with
`manifest-absent-at-rev` instead. The stated output is only reproducible at `HEAD` (or at
`≥9bf52b03`). The C2 instrument revision must be named explicitly and separately from the C1
instrument revision.

**Smallest remediation.** Amend the plan's C2 counting command to name the C2 instrument
revision (`9bf52b03` or later) and state the C1 and C2 revisions separately; or re-commit the
C2 instrument so it exists at the frozen rev.

## F10 — LOW — `make-pins.py`'s default (write) mode overwrites the frozen `pins.json` in place, with no `--check` gate

**Where.** `make-pins.py` `main()` L74-77 writes `os.path.join(lane, PINS_PATH)` — the
committed `pins.json` under `.ufo/evidence/round-93/c1/`, which the brief lists as a frozen
artifact — whenever `--check` is not passed. The `--check` path is separate (L60-72) and does
refuse drift (`PINS_DRIFT`).

**Evidence** — `R93SN1-probe17.log` (S3): the write-mode run rewrote the file in place
(`PINS_WRITTEN …`); bytes were identical only because the derivation was unchanged.
`R93SN1-probe5.log` (D): with `--lane ""` the tool resolved the lane to the CWD and, had the
derivation succeeded, would have written `pins.json` there.

**Impact.** A committed tool can silently replace a frozen evidence artefact; a drifted
derivation would rewrite `pins.json` rather than refuse. (Not triggered in the frozen state —
the committed `pins.json` is correct and `--check` reports `PINS_CHECK OK`.)

**Smallest remediation.** Make write mode require an explicit `--write` flag and refuse when
the target file already exists and differs; keep `--check` as the default.

## Verified safe (no finding)

* **No hardcoded `/tmp`** in any of the four drivers (`R93SN1-probe2.log` E12: `matches=0` for
  all four). The counter's gate subprocess gets `HOME` and `TMPDIR` under `--work`
  (`env_for()`), so the gate's own `mktemp -d "${TMPDIR:-/tmp}/…"` lands inside the scratch
  dir and its own `trap 'rm -rf "$test_root"' EXIT` removes it.
* **Tar extraction is hardened**: `measure-v93.py` uses `t.extractall(dest, filter="data")`
  (L117). `R93SN1-probe.log` (E6) and `R93SN1-probe4.log` (P6): a `../` member and an
  absolute-path member are both refused (`OutsideDestinationError`, `AbsoluteLinkError`), and
  an absolute symlink target is refused. Nothing escapes `dest`.
* **`git replace` creation stays inside the scratch clone**: `R93SN1-probe.log` (E9) — the
  clone's `replace -l` lists the ref, the lane's stays empty, the lane has no
  `.git/refs/replace`, and the `--shared` clone's `hash-object -w` does **not** write the
  object into the lane (`LANE-HAS-OBJECT: no-leak`). The lane's HEAD, `status` and object
  count are unchanged after a normal driver run (`R93SN1-probe7.log` I7).
* **The counter's own seal is sound**: `sealed_env()` replaces the whole environment, so
  ambient `GIT_DIR`/`GIT_CONFIG_GLOBAL` do not reach it (`R93SN1-probe8.log` J5 →
  `C1_R93_PASS=true`); `git replace -l` still lists refs under `GIT_NO_REPLACE_OBJECTS=1`
  (`R93SN1-probe.log` E2), so the `replace-refs-present` refusal works; the seal covers both
  the lane and the fleet repo (`measure-v93.py` L344-362).
* **The disposition checker's selftest uses a `TemporaryDirectory`** and deletes it (both
  `selftest()` and `main()`), and it never writes outside it.
* **`git rev:path` rejects traversal** (`R93SN1-probe15.log` Q2): `scripts/../../x` and
  `/tmp/evil.sh` are both refused by git, so `gate.path` cannot make the counter write
  outside `--work` via the extracted tarball.
* **`--rev`/`--base` are otherwise validated**: `--base` at a rev without the spec refuses
  (`C1_SETUP spec-absent-at-rev`, exit 2) — the do-nothing receipt; `--work` must be empty
  (`work-not-empty` / `work-not-empty-dir`).
