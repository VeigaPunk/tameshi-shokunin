## Hardening-lint

Flag note (read the docstring, then ran it): `hardening-lint.py` takes the
counter path as a positional argument (`usage: … hardening-lint.py
<counter.py> [--json]`); it has neither `--selftest` nor `--counter` —
both forms traceback with `FileNotFoundError: '--selftest'` / `'--counter'`
(exit 1). What I ran instead (twice, same result — lane bytes and
blob-extracted bytes):

```
python3 -I tools/hardening-lint.py /home/vgpnk/Projects/shokunin/tameshi-shokunin/.ufo/evidence/round-93/c1/measure-v93.py
HARDENING file=… defences=4/8 missing=pinned-spec,header-named-verdict,refuse-out-of-set-ids,refuse-unkeyed-verdict   (exit 1)

git cat-file blob 855f0c1c:.ufo/evidence/round-93/c1/measure-v93.py   # sha256 18903602…094c2d, matches the frozen plan
python3 -I tools/hardening-lint.py <extracted counter>
HARDENING file=… defences=4/8 missing=(same four)                    (exit 1)
```

Lint bytes are identical at both revs (`tools/hardening-lint.py` sha256
`4ef121698cca90c441f7f6d6acc9f4011e1c5ce9c5edc54f53182f39baf84eb2` at
base and landing). Baseline for comparison — the round-92 counter
(`.ufo/evidence/round-92/c1/measure-v92.py`, extracted at the landing rev)
scores `defences=8/8 missing=-` (exit 0) under the same lint bytes.
So the new counter *does* regress the lint headline 8/8 → 4/8, while the
lint itself has not moved. The gap is form-shape, in all four cases the
defence is present in the counter bytes under a form the committed lint
does not admit:

1. `pinned-spec` — lint wants `SPEC_SHA\s*=` (absent: the round-93 design
   deliberately derives the digest from `pins.json` instead of a hand-copied
   hex, round-92 M5). The counter carries `"spec_sha256"` + `sha256(spec_bytes)`
   (verified present at byte offset 14748), which the committed lint pattern
   list does not include as an alternative.
2. `header-named-verdict` — lint wants `"verdict" in low` form; the counter
   enumerates header cells (`vcols = … if c == "verdict"`, line 249), which
   is the admitted second form in the lane's docstring gloss but not in the
   lint's pattern list.
3. `refuse-out-of-set-ids` — lint wants `ID_SHAPE` + `out-of-set:`; the
   counter has `out-of-set:` (line 284) but **no** `ID_SHAPE` — QUALITY 154
   retired the shape-keyed rule, so this pattern can never match a v93
   counter by design.
4. `refuse-unkeyed-verdict` — lint wants `unkeyed:`; the round-93 counter
   states the rule once as `stray-verdict:` (line 262).

Net for this row: the four missing defences are not missing *defences* —
each is implemented in the frozen counter under a round-93 form (pins-derived
digest, enumerated header cells, content-keyed out-of-set refusal, single
`stray-verdict:` rule) that `tools/hardening-lint.py` at both revs does not
yet recognise. The lint needs a round-93-aware pattern revision; until then
any v93 counter certifying the honest form will read 4/8. I did not edit the
lint (out of my read-only lane scope) — named here for the L1.
