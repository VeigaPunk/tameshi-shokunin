## 1. Method

- **Spec first.** 30 single-edit defects, one rule each, with a predicted
  verdict, were written to `R93M1-defects.txt` before any clone, state commit or
  counter invocation. The plan's own D01-D05 were re-run separately from
  `controls-v93.mutant_edits()`.
- **Pin recomputation.** Each mutant's `SELF_SHA256` line was recomputed for the
  edited bytes with the driver's `recompute_pin()` (normalise the pin line away,
  sha256, write the line back). The pin is a seal against accidental post-freeze
  editing, not a defence against a declared mutation study — the plan does the
  same for D01-D05. The frozen bytes were never modified: the pristine copy and
  the git blob at `855f0c1c` both hash to `18903602…4c2d` after the run.
- **Fixtures.** Every state is a `git clone --shared` of the lane at `855f0c1c`,
  checked out detached, one state edit committed under `ctl <ctl@fixture.invalid>`
  inside the clone only, and read by the counter extracted from that revision's
  object store. `git rev-parse --show-toplevel` was asserted equal to each clone
  before the first commit. The saved harness also refuses a drifted driver or
  state input (`DRIVER_DRIFT`/`INPUT_DRIFT`); `--dry` on the saved bytes prints
  `INPUTS driver_sha=400d8e0f… state_inputs=rev-identical`. No lane file was written; the only lane writes are the
  nine deliverable files named above.
- **Detector.** KILLED = the battery state's graded expectation (exit code plus
  the state's named conjunct, `controls-v93.grade()`) fails on the mutant;
  SURVIVED = it still matches; INCONCLUSIVE = no committed state exercises the
  rule, or the baseline failed. "delta" is a raw-output change in a committed
  receipt that the grade does not look at.
- **Baselines.** All 19 pristine baselines reproduce their committed expectations
  (`base-*.rerun-1.out`, all MATCH; `base-selfpin-edit` exits 2 with
  `C1_SETUP self-pin-mismatch`). Every verdict below is therefore a real kill, not
  a baseline failure. The first pass of the harness had two defects of its own
  (plan mutants graded against the hostile expectation; delta compared receipt
  headers). Both are fixed in the committed source and the authoritative pass is
  the `.rerun-1` set; the receipts are non-overwriting (`<name>.rerun-<n>.out`).
- **Cost.** 54 matrix jobs at `--jobs 10`, 278 s wall; 13 sharp-probe jobs,
  100 s wall.

## 4. Survivors and inconclusive rows

### 4.1 `green` is falsifiable only as receipt content, never as a graded expectation (D05)
On `timeout` the frozen receipt prints `green=false` (the C2 row is honest), and
the mutant prints `green=true`; every other line is identical and the state's
graded conjunct is `inconclusive0=false`, so the battery's `grade()` still
matches. A green-forcing edit therefore passes every control. This is stated in
C2 (green's row), but the grade never looks at green: the green conjunct has no
state whose *expectation* names it.

### 4.2 `canary` (D06) and the run count / `unstable0` (D10)
D06 is byte-identical on `pos-real`: `canary=true` either way. D10 changes the
`runs=` field of every `C1_ROW` (one verdict instead of two) but leaves every
conjunct, including `unstable0`, true; on `pos-real` the counter still prints
`C1_R93_PASS=true`. Both are declared unfalsifiable in C2 with the pin/constant
mechanism, and the mutation matrix agrees.

### 4.3 The out-of-set rule (D14) and id-set equality (D19)
On `hidden-c001`, D14 removes all 12 out-of-set findings (`badrows 12→0`) but
`verdict_tables=false` and `ids=false` (24 row keys vs 12 spec ids) still refuse,
exit 1. D19 is byte-identical: the out-of-set rule refuses before the set
equality is reachable. The plan's "named triple" in D05 acknowledges exactly this
non-independence.

### 4.4 The position rule (D16) — the committed state is non-discriminating
The `position` state moves the `verdict` header to the last column and appends a
second C12 row. All 12 base rows and the appended extra row fail the position
check in the frozen counter (13 badrows, `position:9…position:21`), but when the position check is
removed the 13th row is caught by the duplicate rule (`C1_BADROWS dup:21:C12`),
so `ids` stays false and the grade still matches. The state cannot distinguish
"position removed" from "position present"; it only changes the badrow label and
the per-row note cells. The sharpened `px3-position-nodup` state (same note
without the extra C12 row) kills the mutant: `ids` false→true.

### 4.5 The source occurrence half (D22) — the most consequential gap
`source-noquote` deletes the S322 lesson line, so `quotes["S322"]` is empty.
D22 (`quote_ok = bool(quotes.get(sid))`, i.e. keep "a located quote exists" and
drop "it occurs in the committed snapshot") is **byte-identical** on that state:
`source=false` both. No committed state carries a located quote that does not
occur in its snapshot. The plan's QUALITY 157 says the reader requires a quote
that occurs in a committed source snapshot; the battery does not discriminate
that half of the rule. The sharpened `px1-source-wrongquote` state (S322's quote
replaced by a 17-word span absent from the snapshot) kills D22: `source`
false→true, `C1_R93_PASS` false→true.

### 4.6 `figure` exactly-one guard (D26) and the spec count (D28)
Every committed state has exactly one block-level `measured:` line, so dropping
`len(heads) == 1` to `>= 1` is byte-identical on `figure`. A two-line state
(`px6-figure-two`) kills D26 (`figure` false→true, PASS true). D28 removes the
`len(mutants) == N_MIN` guard but the unique-id guard still fails on `short-spec`
(11 ids), so the output is byte-identical; the count guard is redundant with the
uniqueness guard and `n_min`.

### 4.7 The width rules (D17, D18) — and a code defect, not just a coverage gap
No committed state varies any table width, so both width mutants are identical
on `pos-real`. Reading the code explains more: `tables()` starts rows at
`i + 2` (`measure-v93.py:216`), so the delimiter row is **not** in `drows`;
`parse_note` then names `delim = drows[0][1]` (`:269`) — the *first data row* —
and emits `width:…:header=…,delimiter=…` (`:271`). The real delimiter cell count
is never compared with the header; the block duplicates the per-row width check
(`:275-276`) for the first data row only.

Evidence, frozen counter, no mutant: `px2-delim-only` is the honest note with a
5-cell verdict header over a 4-cell delimiter (GFM/S321 would not recognise the
table). The frozen counter prints `C1_R93_PASS=true`, exit 0, with no
`C1_BADROWS` line. The documented "header width == delimiter width" rule is not
implemented as documented; the battery has no state that could notice.

The row-width rule is real: `px2-width-lastrow` (last data row loses its witness
cell) makes the frozen counter refuse (`ids=false`, `badrows=1`) and D17 return
`C1_R93_PASS=true`. `px2-width-firstrow` shows the duplicated check: frozen
`badrows=2` (`width:68:header=5,delimiter=4` and `width:70:cells=4`), D18
`badrows=1`, `ids=false` both — the block's only observable effect is the double
report of the first row.

### 4.8 The fence rule (D29) and the verdict-column count (D30)
No committed state carries a fenced verdict table or a header with two `verdict`
cells, so both mutants are identical on `pos-real`. `px4-fenced-hidden` (the
hidden C001-C012 table inside a fence — the plan's own S322 declared limit) makes
the frozen counter pass and D29 refuse (`verdict_tables=false`, exit 1).
`px5-two-verdict-cols` (header `| id | arm | verdict | verdict |`) makes the
frozen counter refuse (`ids=false`, `badrows=1`) and D30 pass.

## 6. Answers

### Q1 — are D01-D05 the load-bearing rules for their states?
**Yes.** Each frozen counter refuses its state (exit 1, `C1_R93_PASS=false`) and
each removal (single rule, or the named triple for P05) prints `C1_R93_PASS=true`
with exit 0 (P01-P05 above;
receipts `base-renamed-result`, `base-coverage-denial`, `base-pins-mutated`,
`base-figure`, `base-hidden-c001` versus `mut-P01…P05`, all `.rerun-1.out`).
D05 is correctly a named triple: D12 alone moves `verdict_tables` but `ids`
still refuses, and D14/D19 alone leave the refusal intact. No single one of the
three returns the cheat.

### Q2 — is any rule of the reader survivable and unstated?
Two granularities, and the distinction matters for QUALITY 158:

- **Literal QUALITY 158 (conjunct granularity): no violation.** I rebuilt the
  conjunct×receipt matrix from the committed receipts (`R93M1-conjuncts.py`;
  `INDEPENDENT_CONJUNCT_CHECK rows=19 falsifiable=17 unfalsifiable=2 findings=0`): every one of the 19 keys
  is false in a named receipt (`selfpin` via the `selfpin-edit` setup token,
  `pins` in 9 receipts, `spec` in 2, `pin` 1, `green` 1, `valid0` 2, `trivial0` 2,
  `inconclusive0` 1, `note` 1, `verdict_tables` 3, `ids` 10, `mismatched0` 7,
  `figure` 5, `witnessed` 2, `source` 2, `coverage` 2, `n_min` 1) or declared
  unfalsifiable with a pin-naming reason (`canary`, `unstable0`). The C2 checker's
  `check()` compares `CONJUNCT_KEYS` against receipt files and has no notion of
  the reader's sub-rules, so its claim is exactly this conjunct-level statement.
- **Rule granularity: yes, several rules are survivable and unstated.** The
  battery's 35 pre-registered controls (4 positive, 23 hostile, 3 setup, 5
  removal mutants) do not discriminate them, and neither the plan's
  Declared limits nor C2 names them:
  1. `source`'s **occurrence-in-snapshot** half (QUALITY 157): D22 is
     byte-identical on every committed state (4.5). This is the most consequential:
     the certification of QUALITY 157 is narrower than the property it states.
  2. **width**, both halves (4.7). The delimiter half is worse than unexercised:
     the code never reads the delimiter row, and the frozen counter accepts a
     5-cell header over a 4-cell delimiter (`px2-delim-only`). That is a
     code-vs-documentation defect in the frozen reader, not merely a missing
     state.
  3. the **position** rule, because its only committed state also trips the
     duplicate rule (4.4);
  4. the **figure exactly-one** guard (4.6);
  5. the **verdict-column count** rule (4.8);
  6. the **fence** rule: the S322 limit is declared, but no committed state
     demonstrates it (4.8);
  7. the **spec count** guard, redundant with the unique-id guard and `n_min`
     (4.6);
  8. `green` cannot be falsified by any *graded* expectation, only by a receipt's
     conjunct content (4.1) — stated in C2, but not graded by any state.

  The sharpened probes show every one of these rules is load-bearing when a
  minimal state exists: the gap is the battery's state set, not the rules'
  reality. A rule-level reading of QUALITY 158 is therefore not satisfied, and
  C2 would miss it because it audits conjunct keys, not rules. No claim wording is
  falsified by this matrix — the honest note still passes and all 23 hostile
  states still refuse — but the certification's discriminating power is narrower
  than the rule set it certifies.
