## What this seat established

### 1. The drafted note block is safe against the reader it documents

The block carries S320/S321/S322 quotes, prose, and bold markup. It carries **no pipe
table**, so it cannot add a second verdict table; **no line with two or more pipes**, so
it cannot add a stray verdict row; and **no line beginning `measured:`**, so it cannot add
a second figure. Verified by construction, not by assertion: applying the block to a
clone of `855f0c1c` and running the frozen counter gives `C1_R93_PASS=true`, exit 0,
`verdict_tables=1 badrows=0 mismatched=0`, all nineteen conjuncts true — in both the
*replace* mode (swap the existing round-93 section) and the *append* mode (add it after
the existing section). Both runs are in the wave dir.

**The L1's decision:** the committed note already carries a round-93 section
(`## Certification attempt (appended round 93) — the verdict-content reader`, lines
277-295 of note blob `b529c3e4`, committed `9cad4f6e`). Block 1 is drafted as a
**replacement** for that section, not as a second round-93 section; it keeps the section's
existing opening and adds the three required elements. If the L1 prefers append-only,
the same text works as an amendment section — the append-mode fixture confirms it.

### 3. The pre-A3 D01 defect is real, and it is the class the item names

The item asks for a lesson row whose class is "a duplicated rule hides which removal is
load-bearing", pointing at `.ufo/evidence/round-93/c1/measure-v93.py` rev `855f0c1c` vs
the D01 run. Reading the history showed the defect sits **before** that revision, so the
A3-vs-D01 pair alone does not show it:

- At `b34c929e` (pre-A3) the reader carried the stray-verdict rule **twice**: once
  inside the table loop (`:260`) and once in the block-line scan (`:266`).
- The driver's `D01` anchor (`controls-v93.py:198-203` at `69d377a0`, identical at
  `b34c929e`) matches **only** the block-line copy. With the in-table copy still live,
  the `renamed-result` state is still refused.
- Re-running the rev-C battery with `--only D01` from committed bytes reproduces it:
  `D01 MISMATCH exit=1`, mutant `counter_sha=162aff7612bb…`,
  `C1_BADROWS stray-verdict:299:C01 stray-verdict:300:C02`, `ids=false`,
  `C1_R93_PASS=false` — the **opposite** of D01's expectation (`C1_R93_PASS=true`).

  `counter_sha=4bd4b77ce8b5…` (recomputed by this seat from the A3 bytes: exact match),

**The lane committed no receipt of the failing pre-A3 run** (the `D01.out` in
`pre-freeze/controls/` is the re-run against the A3 counter). Block 3 therefore cites the
reproduction script and its output as the evidence pointer for the defect, and the

### 4. The disposition checker binds the conjunct VALUE, not the receipt's provenance

`R93SC1-disposition-probe.py` calls the committed checker's own `check()` on synthetic
receipts. Two facts the QUALITY draft states rather than hides:

- **Case D:** a manifest that declares *every* conjunct unfalsifiable, each reason naming
  a mechanism, produces `findings=0` and `report()` exit 0. The per-row audit alone does
  **not** reject it. Only the frozen **count** (`falsifiable=17` of 19) does — which is
  why the count belongs in the claim's predicate, not in a report line. The lane's own
  committed do-nothing control shows the same shape
  (`.ufo/evidence/round-93/pre-freeze/c2-cheat-all-unfalsifiable.out`:
  `rows=19 falsifiable=0 unfalsifiable=19 findings=0`).
- **Case C:** a receipt whose `counter_sha=` is all zeros and whose `clone_rev=` is a
  deadbeef digest is still accepted, because `check()` reads only the receipt's
  `C1_CONJUNCTS` line. The receipts' provenance is bound by the **driver** (which writes
  `counter_sha=` and `clone_rev=` into every receipt) and by the committed
  `C1-summary.txt`, not by the disposition checker. Block 2 does not claim otherwise.

## Findings for the L1 (not fixed by this seat — read-only item)

1. **The frozen C2 counting command names a revision at which the manifest does not
   exist.** `plans/round-93.plan.md` freezes
   `python3 -I tools/conjunct-disposition.py --lane <lane> --rev REV`, and the plan and
   `claims.json` present the C2 instrument revision as `855f0c1c`. But
   `tools/conjunct-disposition.json` was committed at `9bf52b03`, **after** `855f0c1c`, so
   `--rev 855f0c1c` prints `DISPOSITION_SETUP manifest-absent-at-rev` and exits 2 —
   verified. The frozen line `DISPOSITION rows=19 falsifiable=17 unfalsifiable=2
   findings=0` is produced at `--rev 9bf52b03` (and at `978f04bc`, `d5bcf1db`), exit 0.
   The counter blob the checker reads is byte-identical at `9bf52b03` and `855f0c1c`
   (sha256 `18903602aa040b7e…`), so the conjunct key list is the frozen one either way;
   only the manifest's presence differs. **The L1 should record the revision the C2
   receipt was produced at, or amend the plan's counting command to name it** — this is
   the same class as the round-92 M5 defect the round otherwise closed (a named
   instrument revision whose artefacts do not all live there).
2. **The C2 manifest is committed after the freeze revision the claim names.** The
   manifest blob at `9bf52b03` has sha256 `2882a42d20977916…`; the plan names the
   *checker* digest (`1b1c6895ebf1d167…`, confirmed at `9bf52b03` and in the working
   tree) but names no digest for the manifest. A `pins`-style derivation (the pattern
   `make-pins.py` already establishes for C1) would give the manifest a derived digest
   rather than a named-at-freeze one.
3. **The C2 manifest's two `unfalsifiable` rows are not backed by a battery state, and
   the manifest says so.** `canary` and `unstable0` are declared unfalsifiable with
   reasons that name the pin as the forbidding mechanism. That is the intent of QUALITY
   158; Block 2 preserves it and adds the count obligation rather than converting a
   declared row into a manufactured state.
