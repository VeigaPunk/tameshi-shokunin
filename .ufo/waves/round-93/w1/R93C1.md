## Findings (non-killing observations)
1. Delimiter-row width is not checked: `tables()` never returns the delimiter row, and the
   reader's width check compares the header against the first *data* row, so a delimiter row
   with too few/many segments is accepted. Under S321 a width-mismatched delimiter is not a
   table — the reader over-accepts (it can only see more verdicts, never fewer). Smallest
   safe correction: return the delimiter cells from `tables()` and fail when its width differs
   from the header's. Not a kill under the plan's wording (both quadrants accept a valid GFM
   note; no named honest state is refused, no named hostile state passes).
2. HTML-without-pipes (B5) and fenced content (B4) are accepted decoys. The claim explicitly
   keys GFM tables (S321) and declares S322 fences literal, and an HTML table carrying pipe
   tokens IS refused as stray-verdict (`<p>| C01 | SURVIVED |</p>` → refused). No kill.
3. The strongest honest-refusal argument — a prose line containing a verdict token with ≥2
   pipes (`The table for | C01 | KILLED | is given above.`) is refused — is covered by the
   reader's stated rule ("a pseudo-table paragraph is a presented verdict row") and the
   declared limit exempts only prose with fewer than two pipes. A reader of the plan's own
   wording would not call it honest prose. No kill.
