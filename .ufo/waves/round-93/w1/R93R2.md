## 2. Receipt provenance (item 2) — FINDING F1 below

All 35 pre-registered controls have receipts; `C1-summary.txt` derives from them
(35 `MATCH`, 0 `MISMATCH`, 0 `MISSING`; count + summary verified on disk).
Every non-mutant receipt carries `control=<name> parent=855f0c1c…` and its
`C1_SUMMARY rev=<clone_rev>` names the clone revision; clone commits are not
present in the lane repo (unverifiable from here — see F2).

**F1 — no `CONTROL_INSTRUMENT sha256=` line in any receipt.** None of the 35
`.out` files contains `CONTROL_INSTRUMENT` (grep: zero hits). The driver prints
`CONTROL_INSTRUMENT sha256=…` to **stdout** of the battery run
(`controls-v93.py:343`); the per-state receipts capture `control=…` +
counter output only. Item 2's check "every receipt was produced by those bytes
(the `CONTROL_INSTRUMENT sha256=` line)" is therefore unprovable from the
committed receipts. Mitigation (stated, not a full conformance): the freeze-wording
fix `4643b6ff` post-dates the freeze and the plan's kill rule (c) — "the counter
blob at `855f0c1c` differs … or any receipt was produced by bytes other than that
counter and the driver at `69d377a0`" — is only weakly enforceable without that
line. Severity: **the conformance claim in the assignment cannot be confirmed
from committed bytes**. Not a C1/C2 kill under the plan's own wording as written
(the plan never names a `CONTROL_INSTRUMENT` receipt line), but the assignment's
item 2 check fails.

**F2 — clone_rev parentage unverifiable from the lane.** All 25 clone-bearing
receipts print `parent=855f0c1c59ee…` (the instrument rev). The clone commits
themselves are absent from the lane object store (`git cat-file -e` fails), so
"child of the instrument revision" can only be read off the receipt text, not
verified. Same standing as F1: textual conformance YES, cryptographic NO.

**F3 — setup / mutant receipts have no C1_CONJUNCTS line by construction**
(`nowork-base`, `replace-honest`, `selfpin-edit` print `C1_SETUP …`; D01–D05
print mutated-counter output). The disposition checker handles this correctly
(`setup-refusal` mode checks the token). `nowork-base` and `selfpin-edit`
receipts are not referenced by any C2 row (the manifest's `selfpin` row uses
`selfpin-edit` only) — consistent.
