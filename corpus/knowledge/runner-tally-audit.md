# Runner tally audit: fixing a widely read gate from outside it

Round 32 claim C1 (operability, capability acquisition) closes two runner items deferred since round 30: the `--regression` tally had no per-leg presence check, and the runner's own tally selftest left eight real mutants alive (round-30 seat MutateHead, `.ufo/waves/round-30/wC/MutateHead.md`). Both were deferred because `tools/mutate-and-run.sh` is a recorded input of many cold-read ledger entries (282 of 480 at the round-32 content revision `a4f71813`, seat ReviewEntry; the round-31 count was 270 of 456), so any edit to it drifts the credited SKILL.md sections those entries cover. The fix therefore lives in a new versioned tool that reads the runner and never edits it. The runner stays byte-identical (sha256 `a7d3f2dd…2eb9`), which is part of the claim's predicate.

## Three independent checks

1. **Static per-leg presence.** The `st_*=$?` assignments inside `run_regression()` name the legs. The operands of the tally loop `for st in "$st_…" …; do` must equal them as a multiset, and `local nlegs=N` must equal their count. The runner's own run-time guard (`npass + nfail + nsetup != nlegs`) only checks a sum, so a loop with one operand duplicated and another dropped still sums to nine and prints PASS. This check fails it by name.
2. **Runtime tally against an oracle.** The tally block is cut from the runner and run in bash with the nine statuses bound by name. It is run for every exit status 0–255 at the first leg, statuses 1 2 3 4 126 127 255 at every leg, multi-status vectors, and the loop with one operand duplicated or removed at each position. The exact first line and the exit code are both compared with an oracle written from the runner's printed contract: any 1 → FAIL exit 1; else any non-zero → SETUP exit 2; else a count other than `nlegs` → SETUP case-tally mismatch; else PASS. Bash exit statuses fall between 0 and 255 (S097), so the sweep is exhaustive for one leg. `case` runs the command list of the first pattern that matches (S097), so an arm inserted before `*)` reclassifies exactly the statuses it names. A sweep that stops at 3 misses an arm for 4 (MutateHead T08) or for any other value.
3. **Harness against known-faulty blocks.** This is a test of the test, the way a mutation tool judges a suite by the seeded faults it kills (S099). The runner's selftest harness (`local tblock …` through `tblock=$tblock_full`) is run once with the pinned reference block, which it must accept. It is then run once per fault from a panel of 27 faulty blocks built from that reference: a wrong label, FAIL exiting 0, a dropped operand, each of the nine legs ignored, each leg ignored only when it is the single non-zero leg (status 1 or 2; only the one-leg-at-each-position loop can see these), the guard removed or made overcount-only, SETUP checked before FAIL, exactly-one thresholds, and status 3 counted as a pass. A sound harness rejects every fault. A harness that compares exits only, swallows its comparison status, skips a position or a vector, or skips the guard stress accepts at least one fault.

The harness panel uses the pinned reference block, never the audited file's block. A runner whose tally is broken is caught by check 2. A runner whose harness is broken is caught by check 3. Neither check depends on the other.

## Why the counter generates part of its copies

A tool written after its fixtures can memorize them. The frozen counter passes the tool 9 frozen must-kill copies (the 8 MutateHead survivors, byte-identical to that report's mutated SHA-256 column, plus the duplicate-and-drop loop) and 9 more drawn from a fresh seed at measurement time, one per family. It also passes 8 must-accept copies: the pristine runner, the equivalent guard T07, reordered operands, decoy comments that carry every frozen mutant's text, cosmetic edits, a renamed harness variable, a random permutation and nonce comments. A tool keyed on the frozen copies' bytes, text or hashes misses the generated copies or rejects the decoys. This is the holdout idea of S094 used by analogy: a check scored only on cases its author has seen overfits them. The paper proves nothing about this counter.

## Limits

- The generated families cover the eight survivor classes and the per-leg defect. They are not the space of all runner edits. A runner edit outside the tally block and the harness section is out of scope.
- The oracle restates the runner's own printed contract. If that contract is wrong, the audit agrees with it.
- `--then-regression` runs the full nine-leg replay only after the audit passes, then checks that the printed `cases=` equals the number of legs found. It does not re-derive a leg's status.
- The runner's own `--selftest` is unchanged and still passes the eight survivors. The audit is the stronger gate for the tally; the runner's selftest stays the gate for everything else it covers.
