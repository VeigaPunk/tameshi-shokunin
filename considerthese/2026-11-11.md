## Self-improvement ideas (proposals only, not acted on)

1. **Baseline-red ledger for the registry.** Give each persistently differing row (today `sources-census`, `verify-round15`, `mte-interop-check`, `receipt-bytes-tree`) one of three dispositions: `fix`, `waive-with-reason` or `supersede`. Each disposition carries a first-seen round and an age. Report a whole-registry trend line (`held/total` per round) alongside the tag verdict. Then "same four as base" becomes a recorded decision, not a habit, and a regression in a red row shows up as a changed `got=` value.
2. **Claim-shrink meter.** For each claim, record the frozen wording and the final wording after amendments. Score how much was removed: constructs excluded, rows or populations dropped, and verbs weakened (for example "governs" → "registers"). Report it next to the verdict. A verified claim that lost half its scope should read differently from one that survived intact. This complements the bite-rate idea from 2026-11-10 by measuring what the bites cost.
3. **Runtime-budget preflight for wave specs.** Before dispatch, time every command a seat is told to run, using the pre-freeze control runner's own timings. Mark anything above the session limit (about 300 s observed) as `run-detached` in the wave spec, or split it into shards (for example, registry rows by tag). Round 100's 11 m 50 s full-registry run would have been flagged before two seats lost a run to it.
4. **Mutant-survivor → selftest backlog.** Round 100's M1 seat reported that the surviving mutants are "selftest coverage gaps, not wording failures." Turn each survivor into a proposed selftest case, recorded with the mutant's diff and the input that should kill it, and track how many are still open per tool. Survivors then become a measurable coverage debt instead of a one-line note.
5. **Content-normalized source digests.** S327's live re-fetch kept the same length and still carried the quote, but its sha256 differed from the snapshot (`e14b7e4d…` vs `bbd5b0fb…`) because the REST envelope has volatile fields. Alongside the raw digest, store a digest of just the cited field (for example `abstractText`). A recheck could then tell "envelope churn" from "source content changed" with no human reading.
