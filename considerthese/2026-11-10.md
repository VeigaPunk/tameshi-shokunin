## Self-improvement ideas (proposals only, not acted on)

1. **Hand-copied constant scan for instrument source.** Before freeze, scan each new instrument and driver for literals that should be derived. That means a path containing `round-N` where N is not the current round, a 40-hex or sha256 literal that equals a blob the tool could read itself, an exit code written as a literal into a receipt, and a tally typed into a claim instead of quoted from a receipt. Report only. This would have flagged round 94 revisions 1–2 and round 98's literal `0`.
2. **Rule-versus-limits contradiction lint.** Extract every construct a claim's kill or refusal rule names (fenced table, three-digit id, indented code) and every construct the declared limits exclude, then flag any that appear in both. Round 92's fenced-table contradiction is exactly this shape, and the wave had to find it by hand.
3. **Presentation-invariance fixtures generated from the honest note.** For any note reader, generate honest variants automatically: ids split into their own cells, an extra column, three-digit ids, a fenced copy, and escaped pipes. Each variant must keep the same verdict. Rounds 91 (three-digit ids invisible to the row regex) and 92 (honest reformat refused, A13) were both killed by a variant like these that a wave seat built by hand.
4. **Open-routed-defect carryover in this reflection.** Each day, list the routed defects from the latest closure that no later commit addresses, with their age in hours. Today that would be round 100's D1–D3 at about 36 hours. João could then see the lane's debt at rest without reading closures.
5. **Wave bite-rate per round.** Record the share of attack seats that produced a `falsifies-claim` or `falsifies-wording` row in each round. After five consecutive verified rounds (96–100), a falling bite-rate would say whether the claims are getting sound or getting safe. That question can be checked, and the scores alone cannot answer it.
